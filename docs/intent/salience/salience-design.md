# salience

Parent: [high-level-design](../../high-level-design.md). Specs: [salience-specs.md](salience-specs.md). Arrow: [docs/arrows/salience.md](../../arrows/salience.md).

## Context and Design Philosophy

salience is the "attention" region of the brain (amygdala / salience network metaphor, `services/salience/src/index.ts`). It is a standalone Redis-bus service (`@cohost/salience`, `services/salience/package.json`) whose one job is deciding *when* the co-host should speak. It never produces the words: when something is worth a reply it publishes `attention.focus` and the cortex segment takes over; separately it owns a "reflex" fast path that publishes `brain.say` directly with canned lines and no model in the loop (`index.ts`).

Design philosophy as the code shows it:

- Cheap and continuous: scoring defaults to hard-coded rule weights (`scoring.ts`); the region keeps its own small `Context` rather than querying anything (`salience.ts`).
- Timing lives in `Scheduler`, judgement lives in a pluggable `salience.scorer` hook (`rules` / `llm` / `http`, owned by region-hooks) that always falls back to rules (`scoring.ts`, `packages/modules/src/index.ts`).
- Turn-taking is inferred from bus traffic only: `brain.status`, `brain.say`, `affect.state` and, to keep its speaking valve alive while a line plays, `voice.playing` and `voice.done`. The one thing it sends the body is `voice.stop`, on a barge-in; cortex also publishes a `voice.stop` of its own when a mute lands during its reply, which salience does not read.
- Everything is in-process mutable state (muted, paused, arousal, cortex state, cooldown timestamps, score cache); nothing is persisted (`salience.ts`, `scheduler.ts`).

Code layout: `index.ts` calls `runSalience()` (`main.ts`), which runs `salienceMain` on the shared bootstrap `runService`; `salienceMain` wires the scorer, a `Salience` instance and a tick timer. `salience.ts` is event intake + reflex + tick. `scheduler.ts` is the speak/no-speak decision. `scoring.ts` is score input/output types, rule weights and the module factory. `reflex.ts` is the regex rule engine. `health.ts` builds the heartbeat spec from the configuration.

## Event Wiring

`speech.partial` is not subscribed to: an interim transcript is never speech to salience (SAL-IN-007). The early transcript and its withdrawal are a different thing and are subscribed to (Early transcripts). Subscription (`main.ts`): consumer group `salience`, types `chat.message`, `chat.removed`, `speech.heard`, `speech.early`, `speech.retracted`, `vision.summary`, `brain.say`, `voice.playing`, `voice.done`, `brain.status`, `affect.state`, `tool.timer`, `control`, in the event-bus start mode `latest`: the group is moved to the stream tail on every start, so nothing published while salience was down is delivered (SAL-IN-001). Stale chat would otherwise fire reflexes and stale `brain.say` / `brain.status` would corrupt the busy state. The mode is named explicitly (`start: "latest"`) so a plain process restart (for example compose's `restart: unless-stopped`) does not replay the backlog; a control-plane start in `fresh` mode, salience's manifest default (`packages/control/src/manifest.ts`), resets the group to `$` as well. The handler is `salience.onEvent`; the bus catches and logs handler errors and acks regardless (`packages/bus/src/index.ts`), so a failed reflex publish is logged, not fatal. `bus.subscribe` resolves only when the bus stops, so `main()` starts it with `void` after creating the group with `bus.resetGroup("salience")` (see Health and Lifecycle); a rejection of the started subscription is logged as `fatal` and exits 1.

| Event in | Handling (file:line) |
|---|---|
| `chat.message` | `ctx.push`, `scheduler.noteActivity()`, then `reflex("chat", text)` (`salience.ts`) |
| `chat.removed` | `ctx.forget(removal)`, whether or not paused: the removed chat leaves the window, so it counts toward no later decision (Forgetting a removed message) |
| `speech.heard` | `ctx.push`, `noteActivity()`, the barge-in check (Barge-in, SAL-BARGE-001), `reflex("speech", text)`; when no reflex fired and `trigger_on_speech` is true, a speech trigger (Decision and Tick, SAL-TRIG-001) |
| `speech.early` | the early pass, when not paused and `trigger_on_speech` is true: a provisional decision on text that is not in the window (Early transcripts) |
| `speech.retracted` | resolve the provisional focus built on that `seq`, if any: withdraw, or ask for an interjection; another `seq` is ignored (Early transcripts, Interjection) |
| `vision.summary` | `ctx.push`; `reflex("vision", text)` only if `changed`; does NOT call `noteActivity()` (`salience.ts`) |
| `brain.say` (from anyone: cortex, reflex echo, operator) | `scheduler.noteSpoke()` (starts cooldown, resets idle timer), cortex state `speaking` (`salience.ts`) |
| `voice.playing`, `voice.done` | only while the cortex state is `speaking` for the line the event names (the id of the `brain.say` that put it there): restart the speaking valve's age; otherwise ignore the event (Busy Gating and Cooldown) |
| `brain.status` | store `state` (`idle`, `thinking`, `speaking`, `muted`) and timestamp (`salience.ts`) |
| `affect.state` | store `arousal` only (`salience.ts`) |
| `tool.timer` | keep the timer as a due reminder (Reminders) |
| `control` | see Control section (`salience.ts`) |

| Event out | When |
|---|---|
| `attention.focus` `{reason, score, focus?, injected?, remember?}` | tick decides to speak (`salience.ts`); a due reminder becomes one of kind `reminder` (Reminders); a `speech` focus carries the `source` of its `speech.heard`; a speech focus carries the `utteranceId` of its utterance, and a focus on an early transcript is flagged `provisional` and carries its `seq` (Early transcripts) |
| `attention.resolve` `{utteranceId, seq, outcome, reason?, interjected?, …the fields of a focus on a confirm}` | the confirmation or withdrawal of a provisional focus (Early transcripts) |
| `voice.stop` `{reason: "yield", ids: [the interjected line]}` | the final of an interjected utterance, where `interject_yield` is true (Interjection) |
| `brain.say` `{id, text, emotion, gesture?, reason: "reflex: <regex>", injected?, remember?}` | reflex hit (`salience.ts`) |
| `voice.stop` `{reason: "barge-in"}` | a barge-in (Barge-in below) |
| `service.heartbeat` (via `startHeartbeat`) | boot, ready, periodic, stopping (`main.ts`) |

Working memory: `Context` from the working-memory segment, sized `brain.working_memory_events` (default 24, `packages/config/src/schema.ts`). It is private to this process; salience never pushes `self` lines (it does not call `pushSelf`), though the scheduler and `toScoreInput` still defensively skip `self` events (`scheduler.ts`, `scoring.ts`).

## Scoring

`scoreRules` (`scoring.ts`) returns one number per event, in order:

| Event | Score |
|---|---|
| speech | 0.9 |
| chat, mentions co-host and `reply_on_mention` | 1.0 |
| chat containing `?` | 0.55 |
| chat from mod or sub | 0.35 |
| other chat | 0.15 |
| vision, `changed` | 0.3 (unchanged vision: 0) |

These match the weights quoted on the docs site's When it talks page (`docs/guide/tune/talkativeness.md`) and `config/config.example.yaml` and are asserted in `test/salience.test.ts`. `toScoreInput` flattens unseen context events into `ScoreInput.events` (kind, who, text, mention, isMod, isSub, changed) plus the current arousal (`scoring.ts`).

`createScorer` builds `new Module("salience.scorer", cfg.brain.salience.module, cfg.llm, impl, log)` (`scoring.ts`). `rules` uses `reply_on_mention`; `llm` has a JSON-only system prompt naming the co-host and streamer, a user prompt listing arousal and numbered events marked with kind, mention, mod and sub, `maxTokens: 120` (SAL-SCORE-008). The prompt treats chat as viewer text (see Viewer text in the scorer prompt below); `http` and `llm` share `validate`, which accepts only an object with a `scores` array of the same length as the input whose members are all finite numbers, clamping each to 0..1, and otherwise returns undefined so `Module.run` falls back to rules (`scoring.ts`, `packages/modules/src/index.ts`). Module default `timeout_ms` is 8000 (HOOK-CFG-002, `packages/config/src/schema.ts`). Module construction and fallback semantics are owned by region-hooks; salience owns the input/output shapes and weights.

### Viewer text in the scorer prompt

An `llm` scorer reads chat, so its prompt applies the shared untrusted text guard ([shared-runtime](../shared-runtime/shared-runtime-design.md) Untrusted text guard). The system turn carries `untrustedNotice` (subject: what a viewer typed in chat) and says that a score judges how much the event deserves a reaction, so a line asking for a high score or telling the scorer what to answer is not a reason to give one. The scorer prompt builder is the code that renders these lines, so it quotes each chat text exactly once. The user turn is the current arousal followed by one numbered line per event, built as:

`<n>. [<kind><, mentions co-host><, mod><, sub>] <label>: <text>`

where `<n>` counts from 1; `<kind>` is the literal `chat`, `speech` or `vision`, and the marks are spelled `, mentions co-host`, `, mod` and `, sub`; each mark appears only when it holds and sits inside the brackets, before the label, outside any quotes, because the marks come from platform flags and not from the text; `<label>` is `speakerLabel(who, viewer_text.max_name_chars)` and is omitted, with its colon, for a `vision` event; and `<text>` is `quoteUntrusted(text, viewer_text.max_chars)` for a `chat` event and the bounded text unquoted for a `speech` or `vision` event. Each line is one line, so the line count equals the event count and the reply's "one number per event" contract (`validate`) holds whatever a message contains. The number of events one prompt carries is bounded by the working-memory window (`brain.working_memory_events`), from which unseen events come, so no separate line cap exists. The `http` kind receives the structured events with the bounded text the window holds and no markers; the `rules` scorer builds no prompt (SAL-SCORE-009 to SAL-SCORE-014).

A manipulated score is bounded by the burst rule below: however high the scorer rates one viewer's lines, the viewer counts once, and the scorer's output is clamped to 0..1 (`validate`). One event scored 1.0 still clears the threshold alone, as a mention does, so the cooldown and the busy gate remain the limit on how often that can happen.

## Decision and Tick

`Salience.tick()` is one scheduling pass. Two things start it: the poll, a timer every `brain.salience.tick_ms` (default 1500; `main.ts`, SAL-FOCUS-001), and the speech trigger described below. It never rejects: a failure of the decision or of the `attention.focus` publish is logged (`tick failed`) and the next tick runs (SAL-HEALTH-002). Flow (`salience.ts`, `decideAndPublish`):

1. Return immediately if paused or a previous decision is still in flight (`deciding` flag; an llm/http scorer can outlast a tick).
2. `scheduler.decide(ctx, busy(), muted, arousal)`.
3. If it says speak: mark exactly `decision.scored` seen (events that arrived while an async scorer ran stay unseen), set cortex state to `thinking` optimistically (so the next tick does not double-fire), and publish `attention.focus` with the focus mapped to `{kind:"chat", who, text, mention}`, `{kind:"speech", who, text}`, `{kind:"vision", text}` or undefined, plus `propagatedFlags(focus)`. The bus schema fills a missing focus `mention` with `false` (`packages/bus/src/events.ts`).

When the focus is a `chat` event, the published `attention.focus` carries the entry's `platform` and `userId` (when it has one) beside `who`, so the cortex identifies the viewer by them and uses `who` only to render (SAL-FOCUS-003, BUS-EVT-036). When the focus is a `speech` event, the published `attention.focus` also carries `timing`: the focused event's `timing.audioEndedAt`, its `closedAt` when it has one, and `heardAt`, the `ts` of its `speech.heard` envelope (SAL-FOCUS-006), so that cortex's `brain.say` carries `closedAt` and the latency report can show the `endpoint` stage of an ordinary reply. When the focus is a `vision` event, it carries that event's `capturedAt` and `describedAt` (SAL-FOCUS-006). Salience adds no stamp of its own; the `attention.focus` envelope `ts` is the end of the salience stage, and cortex reads it as `focusedAt`. A focus of any other kind carries no `timing`. When several speech events are unseen at one tick they merge into one decision, and only the focus (the top-scoring unseen event) contributes `timing`; the other merged utterances are not measured. With the speech trigger on, the stage's duration is the decision itself plus any wait on an earlier decision, cooldown or busy cortex; with it off, or for a line the trigger did not cover, it includes the wait for the next poll, up to `tick_ms`.

When the decision returns, `tick` re-checks `muted`, `paused` and `busy()` and drops the focus if any holds, and it drops the focus when a `chat.removed` took the focused chat line out of the window while the scorer ran (SAL-FOCUS-007), so a `mute` or `pause` that arrives while an llm/http scorer is running stops that decision (SAL-FOCUS-005). With the `rules` scorer the await resolves before the next bus event is handled, so the window only opens for llm/http scorers.

### Speech trigger

A person who has finished speaking should not wait for the next poll before the co-host starts to answer. When a final `speech.heard` arrives, is not paused, and no reflex fired for the line, `onEvent` starts one pass of the same `tick()` the poll runs, at once (SAL-TRIG-001). `brain.salience.trigger_on_speech` (default true, CFG-SCH-034) turns this off, leaving the poll as the only starter (SAL-TRIG-007). The trigger adds no decision logic: muted, busy, cooldown, threshold, the post-scorer re-check, mark-seen and the optimistic `thinking` marker all apply unchanged (SAL-TRIG-008), so a trigger can only bring forward a focus the poll would have published at its next tick, never one the poll would withhold, and the seen/`thinking` bookkeeping stops a trigger and a poll from both publishing a focus for the same events.

A final `speech.heard` is the only speech event that starts an ordinary decision (SAL-TRIG-002); an early transcript starts the early pass, whose focus is provisional (Early transcripts; an interjection is asked for at a retraction, Interjection). A `speech.partial` is not subscribed to (SAL-IN-007), chat and vision wait for the poll, and a line a reflex answered has already been marked seen and has produced a `brain.say`, so evaluating it would add nothing (SAL-TRIG-003).

`onEvent` is the bus handler, and an `llm` or `http` scorer can take seconds, so the trigger is not awaited: the handler returns and the next event is read while the decision runs (SAL-TRIG-004). The pass never rejects, so an unawaited call cannot leave an unhandled rejection (SAL-TRIG-009).

A decision in flight makes a new pass a no-op (SAL-FOCUS-002), which would leave a second utterance, one that landed while the scorer was running, waiting for the poll. A trigger that lands while a decision is in flight therefore sets a single pending-rerun flag, and when that decision ends salience clears the flag and runs one more pass (SAL-TRIG-005). Triggers that land during the same decision share the one rerun, and a trigger that lands during the rerun sets the flag again, so the number of passes is bounded by the number of utterances, never by a loop of its own. While paused a trigger does nothing and sets no flag, and a pass run for a stale flag returns at the pause check (SAL-TRIG-006).

A trigger that finds the cooldown running or the cortex busy returns no-speak and nothing re-evaluates at the moment the cooldown or valve ends; the next poll does. Expiry timers are deferred (SAL-TRIG-010). The poll stays for that reason, and because it alone starts decisions for chat, vision and idle chatter (SAL-DECIDE-004).

`Scheduler.decide` (`scheduler.ts`) evaluates in this order and returns the first that applies:

1. `muted` -> no speak, reason `muted`.
2. `busy` -> `cortex busy`.
3. `now - lastSpoke < cooldown_ms` (default 6000) -> `cooldown`.
4. No unseen non-`self` events -> `nothing new`.
5. Score only events not already in the `WeakMap` score cache (so an event waiting across ticks is never re-sent to an llm/http scorer), then total the *counted* events (Counting a burst, below): `score` = the sum of the cached scores of the counted events, `focus` = the highest-scoring counted one (`scheduler.ts`).
6. `threshold = max(0.1, speak_threshold - arousal_bias * arousal)`; defaults 0.6 and 0.2. If `score >= threshold` -> speak, reason `mentioned` when the focus is a chat mention and `reply_on_mention` is true, else `engaged` (SAL-DECIDE-008).
7. Else if `idle_chatter_ms > 0` (default 90000) and `now - lastActivity > idle_chatter_ms` -> speak, reason `idle chatter`.
8. Else no speak, reason `score X < Y`.

### Counting a burst

Chat can arrive as a lively room (many viewers, many different lines) or as a flood (one viewer, or one pasted line from many). The first adds up to a reply; the second does not. Every unseen event is scored once and cached; the decision adds up only the counted events. Salience counts and discounts; it never drops a line from the window, never hides one from the transcript and never acts against a viewer (HLD Non-Goal 1).

Counting is one walk over the unseen non-`self` events of this decision, with one `createOnceCounter()` from the shared guard created for the walk (no window). The walk takes the events by cached score, highest first, and among equal scores the later one in window order (arrival order, not a timestamp) first:

- A speech or vision event always counts.
- A chat line counts when `counter.admit(viewerKey, text)` returns true, with `viewerKey` the shared guard's key of the entry's platform and user id, and is discounted otherwise. A discounted line adds nothing to the total and cannot be the focus.
- The total is the sum of the counted scores. The focus is the first counted event: the highest-scoring one, the later in window order among equals.

"Same viewer" is the same platform and the same user id, through the guard's `viewerKey`; "same text" is the guard's `normalizeKey` comparison (`toLowerCase()` with no locale argument, whitespace collapsed, punctuation kept). Both are the functions affect uses. The display name is for rendering and takes no part: a Twitch `Sam` and a YouTube `Sam` are two viewers, two channels that share a display name are two viewers, and one viewer who changes display name is still one. A chat entry with no user id (a test-injected line) is keyed by platform and its lowercased name, the fallback `viewerKey` defines once; every injected line named `unknown` on one platform is therefore one viewer. One viewer's burst counts once, at its best line: a mention anywhere in it makes it a mention, a question outranks plain chat, a mod's or sub's line carries its weight. A pasted line from thirty viewers counts once. Four different viewers with four different plain lines total four plain-chat weights; one viewer's four lines total one.

The walk runs over the events unseen at this decision. Every one of them, counted or not, is reported as `scored` and marked seen when a decision to speak is made (SAL-DECIDE-007). A discounted line that stays unseen across ticks is discounted at every tick, so waiting does not add it up. Once marked seen, a viewer who writes again starts a new burst that counts once toward the next decision. (SAL-DECIDE-009 to SAL-DECIDE-016.) Reflexes are outside the walk: they react to one arriving line under their own per-rule cooldown and the global busy and cooldown gates, so a flood cannot fire one repeatedly (see Reflexes). Mentions and questions keep their weights; a mention that crosses the threshold on its own makes the co-host speak, whoever sent it.

`lastActivity` is reset by chat and speech intake and by any `brain.say` (`scheduler.ts`, `salience.ts`). Because step 4 returns before step 7, idle chatter only fires when at least one unseen event exists: a fully silent stream stays silent (SAL-DECIDE-005), matching the config comment "speak unprompted if quiet this long and there's fresh context" (`config/config.example.yaml`). Breaking a dead stream unprompted is a deferred goal of the project, not current behaviour.

## Early transcripts

Where ears publishes early transcripts ([ears](../ears/ears-design.md) Early transcripts), salience can decide to speak on one before the person has finished, and cortex can prepare the reply, while nothing is spoken until salience confirms. This section is salience's half: the provisional focus and how it is resolved. An early transcript is not pushed into the window; the final `speech.heard` is (an interjection's unfinished line is the one exception, below). salience reads early transcripts only where `brain.salience.trigger_on_speech` is true, since an early pass is the speech trigger taken sooner; with it off, `speech.early` is read and ignored. salience's verbs are **confirm** and **withdraw**, which resolve a provisional focus: it confirms when the early transcript is reused as the final, or, for an interjection, at a retraction; ears' verbs are reuse and retract ([HLD](../../high-level-design.md) Early reply).

**The early pass.** On `speech.early` salience runs one pass shaped like `tick()`, unawaited and never rejecting:

1. Nothing if any of these holds: salience is paused; a decision is in flight (an early pass is itself a decision in flight, so a final that arrives during one records the pending rerun of the speech trigger; the early pass sets no flag of its own); a provisional focus is already held; the text matches a speech reflex rule (checked by a match test that does not stamp the rule's cooldown, so the reflex fires on the final exactly as it does without early reply); or the utterance has a spoken interjection and the text adds fewer than `interject_followup_min_words` words beyond it (rule (b) of [Interjection](#interjection)).
2. The gates, in the order of `Scheduler.decide`: muted, busy, cooldown.
3. The transcript is scored as a transient speech event beside the unseen events of the window, through the same scorer and counting walk (speech always counts). The unseen events' scores are cached as usual; the transient's score is kept by `utteranceId`, `seq` and text, and applies only to a final with the same `utteranceId`, `earlySeq` and text, so such a final is not scored again and an `llm` or `http` scorer is asked once per transcript. The kept score is dropped when the utterance's final has been handled (confirmed, decided or marked seen) and at a withdraw.
4. The same threshold. Below it the early pass ends and the final is decided as an ordinary final. Idle chatter never starts an early pass.
5. **The re-check, once, before publishing.** After the scorer returns, salience checks muted, paused and busy again, that this `seq` was not retracted and that the utterance's final has not arrived. Only then does it record and publish the **provisional focus**. This is the only place the gates are repeated before a provisional focus.
6. The record holds the `utteranceId`, the early transcript's `seq` and text, the score and the events the decision scored. Its **unresolved limit**, `brain.salience.unresolved_limit_ms` (default 4000), runs from the publication of the provisional focus and bounds how long it may stay unresolved. salience sets its cortex state to `thinking` locally, as after any focus, and publishes `attention.focus` flagged `provisional`, with `utteranceId`, `seq`, the focus fields of any speech focus and the early transcript's `timing`. It marks nothing seen, starts no cooldown and does not touch the idle timer: those belong to a decision that is confirmed.

**Always resolved.** salience resolves every provisional focus it publishes with `attention.resolve`, keyed by `utteranceId` and `seq`, and drops the record when it does:

| Event while the record is held | Resolution |
| --- | --- |
| the final `speech.heard` whose `earlySeq` equals the record's `seq` | confirm |
| a final for the utterance with another `earlySeq` or none | withdraw (`resumed`), then the ordinary path |
| `speech.retracted` for the record's `seq` | withdraw (`resumed`), or confirm for an interjection ([Interjection](#interjection)) |
| `speech.retracted` for another `seq` | ignored |
| a `mute` or `pause` at the `control` event | withdraw at once (`muted` or `paused`) |
| `forget_context` | withdraw at once (`forgotten`) |
| preemption: any `brain.say` that arrives while the record is unresolved, whatever its source (a held think publishes none, so it is an operator line or a reflex), or an `attention.focus` salience publishes for something else | withdraw at once (`superseded`); a final never meets a preempted record |
| the unresolved limit passing with no final and no retraction (ears restarted, an event lost) | withdraw (`timeout`) |

A confirm on a final carries everything an ordinary focus carries: `reason`, `score`, the `focus` (kind `speech`, `who`, `text` of the final, `source`), `injected` and `remember` where the final had them, `utteranceId`, `seq` and the final's `timing` (`audioEndedAt`, `closedAt`, `heardAt`). It marks seen exactly the events the provisional decision scored and the final, sets the state to `thinking` and starts nothing else: the cooldown starts, as always, at the reply's `brain.say`. Every withdraw sets salience's cortex state to `idle` at once, without waiting for cortex's `idle`, so a final that takes the ordinary path is decided immediately and is not refused as busy; the one exception is `superseded`, where the state the superseding `brain.say` set stays. A withdraw marks nothing seen, starts no cooldown and drops the cached score of the early text, so the next decision starts as if the early transcript had never been published. A salience restart loses the record and never resolves it; cortex's hold limit then ends the orphan ([cortex](../cortex/cortex-design.md) Provisional think).

**When salience or cortex lost the other's state.** The rule that keeps the co-host from going silent for a confirm on a final is on cortex's side: a confirm for a think cortex does not hold is an ordinary focus, and an ordinary focus for the same utterance and text as a held think confirms it. The cases:

| Case | salience | cortex | Result |
| --- | --- | --- | --- |
| An operator `say` between the provisional focus and the final | withdraws at once (`superseded`); the line sets `speaking` | discards the think; the line is pending | the final takes the ordinary path under the gates (busy, cooldown), as any final that arrives while a line plays |
| salience restarts | the record is gone | the held think waits | the final takes the ordinary path and its focus carries the final's `utteranceId`; cortex finds the held think with that id and the same text and releases it, or, after its hold limit, thinks afresh |
| cortex restarts, or its hold limit passed | the record is held | no think; it published `idle` | the confirm arrives, cortex holds no matching think, treats it as an ordinary focus and thinks on the final |
| `forget_context` | withdraws at once | aborts the think | the final takes the ordinary path |
| cortex's hold limit ends the think before any resolve (a lost withdraw) | the record is held | publishes `idle`; salience takes it as any `idle` | a confirm that arrives later is an ordinary focus, and a final that salience decides as an ordinary focus with the same `utteranceId` and text confirms nothing and thinks afresh |
| an `idle` status that arrives out of order (a stale one, or the abort of another think) | sets the state `idle`, keeps the record | none | the record is not dropped by a status: a decision that finds the state idle may publish an ordinary focus, which preempts the record (withdraw) and discards the think; otherwise the final confirms as usual |

**A slow scorer.** An `llm` or `http` scorer is bounded by its `timeout_ms` (default 8000) and falls back to rules, as for every decision. When the final or a retraction of that `seq` arrives while an early pass is still scoring, the pass is not cancelled: its scores are cached, and when it returns it finds the `seq` resolved at step 5 and publishes nothing. On a final the speech trigger's pending-rerun flag runs the final's pass when the early pass ends, using the cached scores. The cost of a scorer slower than the pause is that the early pass was wasted, never that the reply was late or doubled.

**Busy during a hold.** There is no state of its own: the held provisional focus keeps salience's state at `thinking`, so it is busy on the thinking valve, and the record's unresolved limit (4 s) ends the hold long before that valve (60 s). A provisional think does not keep an ordinary focus out of cortex: cortex discards the think for any other focus ([cortex](../cortex/cortex-design.md) Provisional think).

## Interjection

An interjection is the co-host speaking while the person carries on after a pause, by chance. It is the owner's choice and off by default. Settings under `brain.salience`: `interject` (false), `interject_chance` (0 to 1, 0.15), `interject_min_gap_ms` (120000), `interject_min_words` (4), `interject_followup_min_words` (3) and `interject_yield` (true). With `ears.early.enabled` off there are no early transcripts and none of them has an effect.

**Asking at the retraction.** The reply is being prepared: salience holds a provisional focus for the early transcript, it passed every gate, and the person has resumed. For the `speech.retracted` of the record's `seq`, salience asks for an interjection instead of withdrawing when all of these hold: `interject` is true; salience holds an unresolved provisional record for that `utteranceId` and `seq`; salience is neither muted nor paused; the early transcript has at least `interject_min_words` words, counted as barge-in counts them; at least `interject_min_gap_ms` has passed since the last interjection that was spoken; and a random draw (an injectable source) is below `interject_chance`. Otherwise it withdraws as usual. The request is `attention.resolve` with `outcome` `confirm`, `interjected` true, the `utteranceId` and `seq`, the focus fields of any confirm and the provisional focus's `timing`. salience sets `thinking` and holds the request pending.

**cortex releases it only if the reply is ready.** cortex releases an interjected confirm only when its held think for that `utteranceId` and `seq` is ready at that moment: the reply's first clause is held (the whole reply when it is one clause), the critic has passed it, the repetition check has passed it, and the think is not parked at a tool call. Otherwise, and when cortex holds no matching think, it treats the resolve as a withdrawal: it discards the think and nothing is spoken. An interjected resolve never becomes an ordinary focus ([cortex](../cortex/cortex-design.md) Provisional think). A released interjection is an ordinary released reply: all its clauses are spoken as for any reply, its `brain.say` carries `interjected` true and no `confirmedAt`, and the hold limit is cleared by the release.

**A final that arrives while a request is pending.** salience holds that final, decides it in neither way and refuses it as busy in neither case, until the request is answered or `unresolved_limit_ms` has passed since the request, and then applies the rule set below if the interjection was spoken and the ordinary path if it was not.

**What salience learns.** The lightest signal is the existing pair. When cortex's `brain.say` arrives while the request is pending, the interjection was spoken: salience charges the gap (the time of the last interjection becomes the current time), marks the scored events seen, pushes the early text into its own window as the speaker's **unfinished line** (already seen, appended before anything else the reply adds, [working-memory](../working-memory/working-memory-design.md) An unfinished line), and keeps a record of the interjection (`utteranceId`, the early text, the line's id and the time; the last eight). The cooldown starts at that `brain.say` as for any line, and the state is `speaking`, so when the person's final arrives yield and barge-in can act on a line that started at once. When a `brain.status` other than `thinking` arrives first (cortex's `idle`, or `muted` or `speaking` by its no-line rule), nothing was spoken: the request is dropped, no gap is charged, nothing is marked seen and the events stay unseen. The wait for either signal is bounded by `unresolved_limit_ms` counted from the request: at the limit with neither signal, salience sets its state to `idle`, charges no gap and publishes nothing.

**The person's final.** The final `speech.heard` of an utterance with a spoken interjection is appended to the window as an ordinary line with its full text, after the co-host's line, so the window reads in true order: the unfinished first part, the co-host's line, the whole sentence. One rule set, in this order:

1. **A short continuation.** When the final adds fewer than `interject_followup_min_words` words beyond the early text (the words that follow it when the final begins with it, compared word by word under the shared `normalizeKey`, and otherwise the difference between the word counts, never below zero), the final is marked seen, decides nothing and stops nothing, with `interject_yield` on or off: no stop, no reflex, no barge-in, no speech trigger.
2. **Yield.** Otherwise, when `interject_yield` is true and the interjected line is still playing (the cortex state is `speaking` for the line's id, within its valve), salience publishes `voice.stop` with reason `yield` and `ids` holding that line's id, sets its state to `idle` and clears the cooldown, as a barge-in does, whether or not `barge_in` is on. The final then goes through the ordinary decision (the reflex test and the speech trigger under every gate) with no barge-in check, since the line is already stopped.
3. **Otherwise** the final is an ordinary line, and the ordinary barge-in check applies (`barge_in`, the source, the minimum words), then the reflex test and the speech trigger: this is the case of `interject_yield` false, or of a line that has already ended. The focus of rules 2 and 3 is the whole final, which cortex's repetition check compares against the interjected line.

If the final never arrives, nothing else happens: the unfinished line stays in the window and leaves by count. Rule 1 also keeps an early transcript of that utterance that adds fewer than `interject_followup_min_words` words beyond the interjected text from starting a provisional focus (step 1 of the early pass). A reply the critic vetoed leaves no spoken interjection and charges no gap, so a second early transcript of the utterance is an ordinary early pass and may ask for an interjection again.

**`interject_yield` false.** The co-host then talks over the person, for the length of a short line, unless `barge_in` is on and its conditions hold. It is an owner-chosen exception to Goal 2's "a person who speaks over it can stop it" ([HLD](../../high-level-design.md) Key Decisions, Interjecting).

## Busy Gating and Cooldown

`busy()` (`salience.ts`) looks at the last cortex state seen on the bus and its age:

- `thinking`: busy while age < `brain.salience.thinking_timeout_ms` (default 60000; SAL-BUSY-001).
- `speaking`: busy while age < `brain.cortex.speaking_timeout_ms` (default 20000) - a key owned by the cortex segment's config block (`schema.ts`), read here. Salience remembers the id of the cortex's `brain.say` that set `speaking` (kept apart from the id of a reflex or operator line, which sets its own and does not replace it, so such a line does not stop the renewal of the cortex's). A reply spoken clause by clause is one line with that id, and every `voice.playing` and `voice.done` for it, from any sink, restarts the age while the state is still `speaking` for that id and the line's `brain.say` carried `more` (a line without `more` keeps the built valve: 20 s from when the state was set), so the line keeps salience busy, and barge-in possible, for as long as it is being played, however many clauses were published at once: the valve bounds each wait for playback and not the reply. An event for a line salience has stopped (a barge-in sets `idle`) or that cortex released is ignored, so a clause that was already playing when a stop landed never makes salience busy again. Clause publication (`brain.clause`) does not matter to salience: it is the playback that is busy. The cooldown is measured from the line's `brain.say` and a clause does not restart it, nor the idle-chatter timer: a line is one speaking decision, and the cooldown guards how soon the co-host decides to speak again.
- `idle` and `muted` (and the initial `idle`): not busy. A cortex reporting `muted` does not gate salience; salience's own mute flag (from `control`) does.

Every duration here (both valves, the cooldown, the idle-chatter timer, each reflex rule's cooldown) is measured on one monotonic millisecond clock, `SalienceDeps.now` (default `performance.now`), which `Salience` hands to its `Scheduler` and passes to `Reflexes.test`. A wall clock stepped by NTP or VM time sync therefore neither stretches nor cuts a valve or the cooldown. Tests inject a fake clock to step time.

A tool wait inside a reply is not a gap in either valve: cortex republishes `brain.status` at the start of each wait and each round of its tool loop ([cortex](../cortex/cortex-design.md) The tool loop), and the time of every status restarts the age of the state it names, so the thinking valve and the speaking valve are measured from the latest step of a tool-using reply and not from its start.

Cortex state is set from `brain.status` (`salience.ts`), set to `speaking` on any `brain.say` (`salience.ts`) and set to `thinking` locally after publishing `attention.focus` (`salience.ts`). The return to `idle` depends on the cortex publishing `brain.status idle` (cortex segment); the two valves above are the safety net.

Arousal: `affect.state.arousal` is stored raw; it lowers the speak threshold (step 6 above) and is passed to the scorer as `ScoreInput.arousal` (`scheduler.ts`). Initial arousal is 0 until the first `affect.state` arrives (`salience.ts`).

## Reminders

The co-host can set a timer ("remind me in ten minutes"); when it runs out, [tools](../tools/tools-design.md) publishes `tool.timer`. salience is the one consumer: a timer reaches speech through the same decision as everything else, so it cannot bypass the speaking gates (HLD tenet 4).

- **Due reminders.** A `tool.timer` becomes a **due reminder** in a small list of at most `tools.timer.max_active` (default 5; the most timers the service lets run), oldest dropped first, kept apart from the working-memory window (a reminder is not chat, speech or vision and never enters a transcript). Its age is measured from its `dueAt` on the host clock the services share, not from its arrival, so a timer that came due while `tools` was down is as old as it is.
- **The decision.** A decision pass looks at the due reminders after the gates and before it looks for anything new, so a reminder is spoken when there is nothing else unseen. The gates apply first and unchanged: paused, muted, a busy cortex and the cooldown each return no-speak, and the reminder stays due. When they pass and a reminder is due, the pass publishes an `attention.focus` with the reason `reminder`, the score 1 (so the threshold is cleared whatever the arousal) and a `focus` of kind `reminder` whose `text` is the note (bounded; cortex quotes it), then removes the reminder once the publish has succeeded; the unseen chat, speech and vision events stay unseen for the next pass. At most one reminder is published per pass, oldest first. A reminder pass starts at the next poll; it has no trigger of its own.
- **Expiry.** A reminder whose `dueAt` is more than `brain.salience.reminder_expiry_ms` (default 1800000, 30 minutes) in the past, on arrival or while it waits, is dropped and salience publishes its `tool.timer` again with `missed`, which the dashboard feed shows, so a timer that came due while the co-host was muted or kept busy is not announced hours late and is not lost without a trace. Salience ignores a `tool.timer` that carries `missed`, and one whose `id` it already holds or has spoken, remembering the last 64 ids it has spoken. A restart of salience loses the reminders it holds, with no trace; that loss is accepted.
- **What follows.** [cortex](../cortex/cortex-design.md) treats a `reminder` focus as owner-prompted, offers it read-only tools only, and replies to it as to any focus; the reply is an ordinary think with all of its checks. The focus carries no injection flags and no `timing`.

## Barge-in

While the co-host speaks, a person can stop it by speaking. Salience owns the decision, because it is the region that decides when the co-host may speak, and it owns the busy state that a stop must release. It never stops audio itself: it publishes `voice.stop` and the body obeys ([voice](../voice/voice-design.md) Stopping, [mouth](../mouth/mouth-design.md) Stopping a line, [connections](../connections/connections-design.md) Flush, [cortex](../cortex/cortex-design.md) Interruption).

**Trigger.** The check runs in the `speech.heard` handler, right after the line enters the window and before the reflex test. A line interrupts when every one of these holds (SAL-BARGE-001):

1. `brain.salience.barge_in` is true (default false, CFG-SCH-035);
2. salience is neither paused nor muted (SAL-BARGE-008);
3. the cortex is `speaking` and `busy()` still holds, so a speaking valve that has expired is not an interruption (SAL-BARGE-007);
4. the line that is speaking is not a reflex line (SAL-BARGE-006);
5. the event's `source` is listed in `brain.salience.barge_in_sources` (default `["discord"]`), so an event with no `source` never interrupts (SAL-BARGE-004);
6. the transcript has at least `brain.salience.barge_in_min_words` words (default 2), counting whitespace-separated tokens that contain a letter or a number (SAL-BARGE-005), so a one-word backchannel does not stop the co-host.

A `speech.partial` is never an interruption: salience does not subscribe to it (SAL-IN-007). Partials and voice-activity edges are unstable; the final transcript is the one speech event the brain acts on.

**Effect.** Salience publishes `voice.stop` with reason `barge-in` and no `ids` (SAL-BARGE-001), then in the same synchronous step sets its cortex state to `idle` and clears the cooldown (SAL-BARGE-002), so the reply to the interrupter is held back by neither the busy gate nor the cooldown that the interrupted line started. Control then continues through the handler as for any speech line: the reflex test sees the freed state, so a reflex that matches what the interrupter said can answer, and the speech trigger starts a decision that publishes `attention.focus` for the interrupter under every ordinary gate (threshold, mute, pause; SAL-BARGE-003). When the reply's `brain.say` arrives it starts the cooldown and the `speaking` state as for any line. If publishing `voice.stop` fails, salience logs it and changes nothing else: the line is treated as an ordinary line that found the cortex busy (SAL-BARGE-009).

**A final after an interjection.** The final of an utterance the co-host interjected into is evaluated first by the rule set of [Interjection](#interjection): yield, then a short continuation (which takes no part in barge-in), then this check.

**One stop per speaking episode.** Setting the state to `idle` means a second person who speaks over the same line, or the same person continuing, finds the cortex not `speaking` and publishes no second `voice.stop`; their line takes the ordinary path (SAL-BARGE-010). A new `brain.say` starts a new episode.

**Reflex lines.** Salience remembers whether the `brain.say` that last put the cortex in `speaking` was a reflex line, one whose `reason` starts with `reflex:` (SAL-BARGE-006). A reflex line is a short canned reaction, and cutting it off to answer the interrupter would waste both. A later non-reflex `brain.say` replaces the memory, so a reflex that is followed by a cortex line makes the line interruptible again.

**Echo.** A `speech.heard` that is the co-host's own voice heard back would interrupt itself. The defences are upstream: the Discord connector reads no bot account's audio, and ears drops utterances of sources named in `ears.echo_suppress_sources` while a line plays ([ears](../ears/ears-design.md) Echo gate). `brain.salience.barge_in_sources` defaults to the one source that cannot carry echo.

## Reflexes

`Reflexes` (`reflex.ts`) compiles each configured rule's `match` into a case-insensitive `RegExp` at construction. `test(sense, text, now)` walks rules in config order and returns the first that: lists `sense` in `on`, is past its own `cooldown_ms` (default 30000, per rule, tracked in `lastFired`), and matches. A hit stamps `lastFired`, picks a random `say` entry (`Math.random`), and returns `{text, emotion, gesture, rule: rule.match}`. A second method, `matches(sense, text)`, reports whether any rule that lists `sense` in `on` matches, ignoring cooldowns and stamping nothing; the early pass uses it ([Early transcripts](#early-transcripts)). Config validation guarantees a valid regex and non-empty `say` (`schema.ts`).

`Salience.reflex()` (`salience.ts`) runs inline in the intake handler:

1. Skip if paused, muted, or no rules.
2. Skip if `busy()` or `scheduler.cooling()` - gated BEFORE `test()` so a gated line does not spend the rule's own cooldown.
3. `reflexes.test(...)`; on hit, log, `ctx.markSeenEvents([trigger])` where `trigger` is the entry returned by `ctx.push` for the arriving event (SAL-REFLEX-008; only the triggering event is consumed; other unseen events still count toward the next decision), and publish `brain.say` with `reason: "reflex: <match>"` and `propagatedFlags(trigger)`.

The global cooldown is shared with the main path: any `brain.say` (including a reflex's own echo coming back through the subscription) starts it. A reflex also starts the cooldown and marks the cortex `speaking` locally before it publishes, so no tick or second rule can fire in the window before the echo returns (SAL-REFLEX-007); a reflex whose publish then fails still holds the cooldown.

## Control, Pause and Injection Flags

`control` events (`salience.ts`): if `target` is set and is not `salience`, ignore. `pause` / `resume` set `paused` (intake continues; `tick` and `reflex` return early); the window's arrivals hold (`holdArrivals` on `pause`, `releaseArrivals` on `resume`, working-memory WM-SEEN-004) records the entries taken in while paused, at most one window's worth, and marks them seen on `resume` (SAL-CTRL-007). `mute` / `unmute` set `muted` (decide returns `muted`; reflex returns early). A `mute` or a `pause` also withdraws a held provisional focus at once, at the `control` event, without waiting for a final (Early transcripts). `forget_context` clears the `Context`. `say` and `reload_personality` are ignored. Muting or pausing publishes nothing except the `attention.resolve` withdraw of a provisional record that is unresolved (Early transcripts), and none of this state is persisted: a restarted salience starts unmuted and unpaused (SAL-CTRL-006), even if the dashboard still shows it muted.

Mute and pause are turn-taking controls seen only by the two regions that decide to speak: salience (here) and cortex. voice and ears never subscribe to `control`; an operator `say` goes through cortex and bypasses mute.

Test injection: `propagatedFlags(src)` from working-memory copies `injected: true` (and `remember` if defined) from the focus/trigger event onto `attention.focus` / reflex `brain.say`; real events get neither flag even if a stray `remember` is present (`packages/working-memory/src/index.ts`). Injected events are otherwise scored and reacted to like real ones. A mixed batch follows only the focus event's flags (`test/salience.region.test.ts`).

## Health and Lifecycle

`salienceHealth(cfg)` returns `{ service: "salience", mode, deps: {} }`, the config-derived base, where `mode` is `mock` for an `llm` scorer hook that inherits the mock provider and `live` otherwise (SAL-HEALTH-005). Once `salienceMain` has built the scorer, the heartbeat takes its mode and merges its `deps` from `hookHealth` (`hook.salience.scorer` for an llm or http scorer, nothing for a rules scorer; HOOK-HEALTH-004, SAL-HEALTH-001). A pause shows as the heartbeat `detail` `paused` (SAL-HEALTH-004). `startHeartbeat` emits `starting` at boot; `heartbeat.ready()` follows once the consumer group has been created and the tick timer is set (SAL-HEALTH-001): `salienceMain` awaits `bus.resetGroup("salience")` (creates a missing group at `$`, moves an existing one there: the same position start mode `latest` takes) before starting the subscription, because `bus.subscribe` resolves only on stop and offers no readiness signal. `stopping` is sent by a `beforeShutdown` hook that the shared `onShutdown` runs before the service's own callback (`packages/shared/src/lifecycle.ts`). Heartbeat semantics are owned by control-plane.

Every startup step runs under `runService` (`loadConfig`, `new Bus`, `startHeartbeat`) or inside `salienceMain` (`createScorer`, `new Salience`, group creation, subscription), so any failure exits 1 (SAL-HEALTH-003): a configuration that does not load logs the loader's message, every other step logs `fatal`; `createScorer` throws for `kind: http` with an empty `url` (`packages/modules/src/index.ts`). `runSalience` takes its collaborators (`loadConfig`, `createBus`, `createScorer`, `onShutdown`, `exit`, `log`) as an optional parameter, which is how tests run it against a fake bus. A failed tick or `attention.focus` publish is logged and the next tick runs (SAL-HEALTH-002). The teardown step registered with `onStop` clears the tick `setInterval`; the bootstrap then calls `bus.stop()` and the shared helper calls `process.exit(0)`.

## Open Questions & Future Decisions

- **A viewer who is answered again and again.** The count is per decision, so one viewer who mentions the co-host every few seconds is answered once per decision, at most once per cooldown, and a different phrasing each time defeats the identical-text rule. Readings: leave it (a mention is meant to be answered, and cortex's repetition check stops the co-host repeating itself); or discount a viewer for a period after they were answered, which needs a clock, a per-viewer record that salience does not keep, and a new key. Not decided.
- **Several viewers named `unknown`.** The burst rule counts every viewer with no user id whose name bounded to nothing as one viewer per platform; the question and its readings are in [chat](../chat/chat-design.md) Open Questions.
- **Re-evaluation at cooldown or valve expiry.** Deferred (SAL-TRIG-010): a speech line that arrives during the cooldown or while the cortex is busy waits for the next poll after the gate opens.
- **The co-host hearing itself.** Salience does not recognise the co-host's own voice: a `speech.heard` that echoes it is an ordinary speech line. Echo is handled upstream, by the source choice of `brain.salience.barge_in_sources` and by ears' echo gate (EARS-ECHO-001 to EARS-ECHO-009), not here.
- **Barge-in during a think.** Barge-in applies when the cortex is `speaking`. A line spoken by the operator (`say`) while the cortex is thinking also sets salience's state to `speaking`; interrupting it then leaves the think running (cortex CTX-GATE-010), and salience has no record of the think. Whether that case needs a rule of its own is undecided.
- **Interrupting an operator line.** An operator `say` line is interruptible like a cortex line; whether it should be exempt as an explicit override is undecided.
- **Stopping an interjected line sooner.** The line yields to the final of the utterance, which can arrive many seconds after the person resumed. Whether a resumption should stop it sooner is not decided.
