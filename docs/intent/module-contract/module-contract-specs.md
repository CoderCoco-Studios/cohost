# module-contract specs

Segment `module-contract` (prefix `MOD`). LLD: [module-contract-design.md](module-contract-design.md). Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred. Specs are `[x]` unless marked. A spec that names a place in the UI by a generic noun (the services list, the test panel) holds for the current page and for the React UI of the dashboard design alike and stays `[x]` while the page does it; a spec whose behaviour differs in the React UI is `[ ]` until that UI is built.

Terms: a "unit" is an application unit of the control plane's manifest (a unit with a `pnpmFilter`: chat, eyes, ears, salience, affect, memory, cortex, voice, mouth, avatar, connector-discord, tools). A "section" is a dotted path into the config schema declared by some unit (or `dashboard` or `renderer`, the two sections the dashboard alone reads). The "tracker" is the control plane's `HealthTracker`; a unit's "derived state" is the state it computes (control-plane CTRL-HEALTH-*). "Gated" means guarded by the control token when `CONTROL_ENABLED=1`, like the dashboard's other mutating routes (dashboard DASH-CTRL-*); a `PUT /config/:section` that changes a sensitive key is guarded in both modes (dashboard DASH-CTRL-009).

A "key" of a section is a scalar or an array (an array of objects included) under it, named by its dotted path relative to the section (`openai.api_key` in `llm`); a section that is itself a scalar or an array (`brain.working_memory_events`) has one key, named for the section's last path segment. `secrets` lists secret keys by that same relative name. Arrays are never split into elements.

## Settings editor (MOD-CFG)

- [ ] **MOD-CFG-001**: When `GET /config/schema` is requested, the dashboard shall answer `200` with `groups` (the config package's `GROUPS`, in order) and one entry per declared section (and `dashboard` and `renderer`) carrying `path`, `services` (the units that declare it), `schema` (JSON Schema generated from the section's zod schema), `secrets` (the relative names of its secret keys) and the presentation fields of MOD-CFG-019 and MOD-CFG-020, ungated. <!-- test: services/dashboard/test/settings.test.ts --> <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-002**: The config package shall mark the secret keys of CFG-SEC-003 as secret, and the settings editor shall treat exactly the marked keys as secret. <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-003**: When `GET /config/:section` is requested for a declared section, the dashboard shall answer `200` with `etag` (the SHA-256 of `config.yaml` as read), `keys` and `unknown`, ungated; for any other `:section` it shall answer `404`. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-004**: `keys` shall be a map from each key's relative name to an entry that, for a key that is not secret, carries `source` (`literal` when the file holds the key, `default` when it does not), `editable` (true for every key except a secret), `value` (the effective value, the file's value or the schema default, absent for secrets), `raw` (the file text of a `literal` key) and, for a key that is a value of `ISOLATION_OVERRIDES` (CFG-ISO-006), `isolation: { name, overriddenBy }`, where `name` is the key's override name and `overriddenBy` lists the ids of the running units whose container was started with that override (MOD-CFG-018, an empty list when none); an entry for a secret key carries instead `secret: true`, `set` and `editable: false` and none of `source`, `value` or `raw` (MOD-CFG-005). <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-005**: For a secret key, `GET /config/:section` shall return only `secret: true` and `set`, whether the key is set in `secrets.yaml` (CFG-SEC-002; a value in `config.yaml` at a secret path is never used and does not make it set, CFG-SEC-011), never the value or raw text. <!-- test: packages/config/test/editor.test.ts --> <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-006**: `unknown` shall list the dotted paths of keys present in the file under the section that the schema does not define. <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-007**: `PUT /config/:section` shall be gated as DASH-CTRL-004 states and, for a request that changes a sensitive key, as DASH-CTRL-009 states, take a JSON body `{ etag, values }` capped at 64 KiB, and answer `413` for a larger body with nothing written. <!-- test: services/dashboard/test/settings.test.ts, services/dashboard/test/sensitive.test.ts -->
- [x] **MOD-CFG-008**: If the `etag` in a `PUT` differs from the SHA-256 of `config.yaml` as it is when the request is handled, then the dashboard shall answer `409 { ok: false, etag }` with the current etag and write nothing. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-009**: If `values` names a key that is not in the section's schema, or one whose `editable` is false, then the dashboard shall answer `400 { ok: false, issues }` naming each such key and write nothing. <!-- test: packages/config/test/editor.test.ts --> <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-010**: When applying `values`, the dashboard shall set a `literal` or `default` key to the given value as a YAML scalar (keeping the existing quote style of a replaced string) whatever the key is, and leave every comment, the key order, every other section and every unknown key unchanged; a key absent from the file shall be added under its section, and an absent section shall be appended at the end of the file. <!-- test: packages/config/test/editor.test.ts --> <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-011**: When applying `values` to an array-valued key, the dashboard shall replace the whole array with the given array. <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-012**: Before writing, the dashboard shall run the edited text through the configuration loader's placeholder check, null-dropping and `ConfigSchema` validation (CFG-LOAD-001, applying no isolation override), and if validation fails it shall answer `400 { ok: false, issues: [{ path, message }] }` and write nothing; a file that was already invalid before the edit therefore accepts only an edit that makes it valid. <!-- test: packages/config/test/editor.test.ts --> <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-013**: Where the request carries `?dryRun=1`, the dashboard shall perform MOD-CFG-008 to MOD-CFG-012, write nothing, apply no sensitive-key gate (DASH-CTRL-009), and answer `200 { ok: true, dryRun: true, warnings }` when they pass, with the warnings MOD-CFG-015 lists for the edited keys. <!-- test: services/dashboard/test/settings.test.ts, services/dashboard/test/sensitive.test.ts -->
- [x] **MOD-CFG-014**: When validation passes without `dryRun`, the dashboard shall write the edited text to a temporary file in the config directory and rename it over `config.yaml`, and if the write or rename fails it shall answer `500` with the error text and leave `config.yaml` unchanged. <!-- test: services/dashboard/test/settings.test.ts --> <!-- test: packages/config/test/editor.test.ts -->
- [x] **MOD-CFG-015**: After a successful write, the dashboard shall answer `200 { ok: true, etag, restart, warnings }`, where `restart` lists, in manifest order, the units that declare the section and that the latest stack status shows running (none when Docker is unavailable), and `warnings` names each edited key whose `isolation.overriddenBy` is non-empty (a unit running isolated reads the new value only after it is started again without isolation) and, when the section is `dashboard`, that the change applies at the dashboard's next start and, where `dashboard.port` or `dashboard.lan_port` is among the edited keys, that the dashboard's page address changes to the new port once it is restarted. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-016**: The settings editor shall never read or write `.env`, shall never write `secrets.yaml` (a secret key in a `PUT` is refused, MOD-CFG-009; credentials are written only through the dashboard's write-only secret path), and `PUT /config/:section` shall never start, stop or restart a unit. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-017**: No response of a `/config/*` route, an error or an issue message included, shall contain the value of a secret key, or a hash of `secrets.yaml` or of a secret value; the `etag` is the SHA-256 of `config.yaml` alone (MOD-CFG-003), which holds no secret the loader uses (CFG-SEC-011), and a secret key is reported only as `secret: true` with `set`. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-018**: Where the latest stack status reports, for a running unit that declares the section, an isolation override its container was started with (control-plane CTRL-STACK-016), `GET /config/:section` shall list that unit's id in `isolation.overriddenBy` of the key the override name selects (`ISOLATION_OVERRIDES`, CFG-ISO-006), and shall list none while Docker is unavailable or no unit overrides it. <!-- test: services/dashboard/test/settings.test.ts -->
- [x] **MOD-CFG-019**: Each section entry of `GET /config/schema` shall carry `title`, `group` and `about` from the config package's presentation table (CFG-PRES-002) and, where the table gives one, `page` (CFG-PRES-003), so the page names and groups sections from the answer and holds no section name of its own. <!-- test: services/dashboard/test/settings.test.ts --> <!-- test: packages/config/test/presentation.test.ts -->
- [x] **MOD-CFG-020**: Each section entry of `GET /config/schema` shall carry `keys`, a map from each key's relative name (the names `GET /config/:section` uses) to `{ help, label?, unit?, widget?, items?, sensitive? }` from the presentation table, with `help` present for every key and, for an array of objects, `items` mapping each item property to `{ help, label?, unit? }` (CFG-PRES-009), and each key's `description`, and each item property's, in the section's JSON Schema shall equal its `help`. <!-- test: services/dashboard/test/settings.test.ts --> <!-- test: packages/config/test/presentation.test.ts -->
- [ ] **MOD-CFG-021**: A key's `widget` in `GET /config/schema` shall be `{ type: "timezone" }`, `{ type: "voice" }`, `{ type: "sources" }`, `{ type: "textarea" }`, `{ type: "mcp-servers" }`, `{ type: "tool-list" }`, `{ type: "avatar-model" }`, `{ type: "slider" }`, `{ type: "model", kind }` with `kind` one of `chat`, `small`, `vision`, `embed` or `stt`, or `{ type: "options", options: [{ value, label }] }`, as CFG-PRES-005 allows. <!-- test: services/dashboard/test/settings.test.ts --> <!-- test: packages/config/test/presentation.test.ts -->
- [ ] **MOD-CFG-022**: A section entry of `GET /config/schema` shall carry `live: true` where the presentation table gives the section `live` (CFG-PRES-019), and no `live` field otherwise.
