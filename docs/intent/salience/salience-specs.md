# salience specs

Prefix `SAL`. Design: [salience-design.md](salience-design.md). Code: `services/salience/`. Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred.

## Intake (IN)

- [x] **SAL-IN-001**: When the salience service starts, it shall subscribe with consumer group `salience` in start mode `latest` (the group is moved to the stream tail on every start, so events published while salience was down are never delivered) to `chat.message`, `chat.removed`, `speech.heard`, `speech.early`, `speech.retracted`, `vision.summary`, `brain.say`, `voice.playing`, `voice.done`, `brain.status`, `affect.state`, `tool.timer` and `control`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/main.test.ts -->
- [x] **SAL-IN-002**: When salience receives a `chat.message` or `speech.heard` event, it shall push the event into its working-memory `Context` (sized `brain.working_memory_events`, default 24) and reset the scheduler's idle timer. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-003**: When salience receives a `vision.summary` event, it shall push the event into its `Context` without resetting the idle timer. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-004**: When salience receives an `affect.state` event, it shall store the event's `arousal` for threshold adjustment and for the scorer input. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-005**: When salience receives a `brain.status` event, it shall record the reported state and the time received for busy detection. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-IN-006**: Until salience has received an `affect.state` event it shall use arousal 0, and until it has received a `brain.status` or `brain.say` event it shall treat the cortex as `idle`. <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-007**: The salience service shall not subscribe to `speech.partial`, and a `speech.partial` shall never enter its `Context`, reset its idle timer, match a reflex or become the focus of an `attention.focus`: `speech.heard` is the only event salience records as speech and scores as heard, and a `speech.early` starts only the provisional pass of SAL-PROV-001.
- [x] **SAL-IN-008**: When salience receives a `chat.removed` event, it shall call `forget` of its working-memory `Context` with it, so the removed chat leaves the window.
- [x] **SAL-IN-009**: While salience is paused, it shall still call `forget` for a received `chat.removed`, so a line removed during a pause is not scored after `resume`.

## Scoring (SCORE)

- [x] **SAL-SCORE-001**: When salience scores an event with the built-in `rules` scorer, it shall assign speech 0.9; a chat mention 1.0 while `reply_on_mention` is true; chat containing `?` 0.55; chat from a mod or sub 0.35; other chat 0.15; changed vision 0.3; unchanged vision 0. <!-- openspec: salience § Rule-based scoring --> <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-SCORE-002**: Where `brain.salience.reply_on_mention` is false, the salience rules scorer shall treat a chat mention as ordinary chat (scored by question mark, mod/sub, then 0.15). <!-- openspec: salience § Rule-based scoring --> <!-- test: services/salience/test/scorer.test.ts -->
- [x] **SAL-SCORE-003**: When salience prepares scorer input, it shall flatten the unseen non-`self` working-memory events in order into `{kind, who, text, mention, isMod, isSub, changed}` entries together with the current arousal. <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-SCORE-004**: Where `brain.salience.module.kind` is `llm` or `http`, salience shall accept the module's output only if it is an object whose `scores` is an array of finite numbers with exactly one entry per input event, clamping each score to 0..1. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts -->
- [x] **SAL-SCORE-005**: If the llm or http scorer fails or returns output that violates the scores contract, then salience shall score the batch with the rules weights (fallback implemented by the `salience.scorer` module in region-hooks). <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts -->
- [x] **SAL-SCORE-006**: When a scheduler decision runs, salience shall send only events not yet scored to the scorer and reuse the cached score for events that remain unseen across ticks. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-SCORE-007**: The salience service shall build its scorer as the region-hooks module `salience.scorer` from `brain.salience.module`, with kind `rules`, `llm` or `http`. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts -->
- [x] **SAL-SCORE-008**: Where the scorer kind is `llm`, salience shall send a JSON-only system prompt naming the co-host and the streamer and asking for `{"scores":[...]}` with one 0..1 number per event, and a user prompt listing the current arousal and the numbered events with their kind, a mention marker, a mod marker and a sub marker, capped at 120 output tokens. <!-- test: services/salience/test/scorer.test.ts -->
- [x] **SAL-SCORE-009**: Where the scorer kind is `llm`, salience shall carry in the system prompt the `@cohost/shared/untrusted` `untrustedNotice` with the subject `what a viewer typed in chat`, and a statement that a score judges how much an event deserves a reaction and that a request inside a quoted line is not a reason for a score.
- [x] **SAL-SCORE-010**: Where the scorer kind is `llm`, salience shall render each event as one line `<n>. [<kind><, mentions co-host><, mod><, sub>] <label>: <text>`, with `<n>` counting from 1, `<kind>` the literal `chat`, `speech` or `vision`, and each mark present only when it holds, spelled `, mentions co-host`, `, mod` or `, sub`, inside the brackets and before the label.
- [x] **SAL-SCORE-011**: Where the scorer kind is `llm`, salience shall render the label of an event as `speakerLabel(who, viewer_text.max_name_chars)`, and shall omit the label and its colon for a `vision` event.
- [x] **SAL-SCORE-012**: Where the scorer kind is `llm`, salience shall render the text of a `chat` event as `quoteUntrusted(text, viewer_text.max_chars)`, quoted exactly once.
- [x] **SAL-SCORE-013**: Where the scorer kind is `llm`, salience shall render the text of a `speech` or `vision` event as the bounded text it holds, not quoted.
- [x] **SAL-SCORE-014**: Where the scorer kind is `http`, salience shall send the events with the bounded text the working-memory window holds and no `«`, `»` or notice added.

## Speak Decision (DECIDE)

- [x] **SAL-DECIDE-001**: When the scheduler decides, it shall return no-speak with reason `muted` if muted, else `cortex busy` if the cortex is busy, else `cooldown` if less than `cooldown_ms` (default 6000) has passed since the last line, else the due reminder of SAL-REM-005 if one is due, else `nothing new` if there are no unseen non-`self` events, in that order. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts --> <!-- test: services/salience/test/salience.reminders.test.ts -->
- [x] **SAL-DECIDE-002**: When unseen events exist, the scheduler shall compute the total score as the sum of the scores of the counted events (SAL-DECIDE-009 to SAL-DECIDE-014) and choose as the focus the first counted event whose score is above 0, or none. <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-DECIDE-003**: When the total score is at least `max(0.1, speak_threshold - arousal_bias * arousal)` (defaults 0.6 and 0.2), the scheduler shall decide to speak, with the reason given by SAL-DECIDE-008. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-DECIDE-004**: When the total score is below threshold, `idle_chatter_ms` is greater than 0, and more than `idle_chatter_ms` has elapsed since the last chat, speech or spoken line, the scheduler shall decide to speak with reason `idle chatter`. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-DECIDE-005**: If there are no unseen non-`self` events and no due reminder, then the scheduler shall decide not to speak with reason `nothing new` even when `idle_chatter_ms` has elapsed, so a fully silent stream stays silent (idle chatter needs at least one unseen event). <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.dispositions.test.ts --> <!-- test: services/salience/test/salience.reminders.test.ts -->
- [x] **SAL-DECIDE-006**: If the total score is below threshold and idle chatter does not apply, then the scheduler shall decide not to speak with reason `score <total> < <threshold>`. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-DECIDE-007**: When a decision to speak is made, the scheduler shall report as `scored` exactly the unseen events of that decision, counted or not (SAL-DECIDE-015), so that events arriving while an async scorer runs are not marked seen. <!-- test: services/salience/test/salience.test.ts -->
- [x] **SAL-DECIDE-008**: When the scheduler decides to speak because the total score reached the threshold, it shall give reason `mentioned` only if the focus is a chat mention and `brain.salience.reply_on_mention` is true, and reason `engaged` otherwise. <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-DECIDE-009**: When the scheduler counts events for a decision, it shall take the unseen non-`self` events in order of cached score, highest first, and among equal scores the later event in working-memory window order first.
- [x] **SAL-DECIDE-010**: When the scheduler counts events for a decision, it shall count every speech and vision event.
- [x] **SAL-DECIDE-011**: When the scheduler counts events for a decision, it shall count a chat event only if `admit(viewerKey, text)` of a `createOnceCounter` created without `windowMs` for that decision returns true, with `viewerKey` the `@cohost/shared/untrusted` `viewerKey` of the event's `platform`, `userId` and `user`, and `text` its text, in the order of SAL-DECIDE-009.
- [x] **SAL-DECIDE-012**: The scheduler shall compare viewers for a decision with the `@cohost/shared/untrusted` `viewerKey` (platform and user id) and texts with `normalizeKey`, so that two chat lines are from the same viewer when their keys are equal and have the same text when their text keys are equal.
- [x] **SAL-DECIDE-013**: When a chat event is not counted for a decision, the scheduler shall add nothing for it to the total score and shall not choose it as the focus.
- [x] **SAL-DECIDE-014**: When the scheduler counts events for a decision, it shall choose as the focus the first counted event in the order of SAL-DECIDE-009 whose score is above 0, and no focus when none is.
- [x] **SAL-DECIDE-015**: When a decision to speak is made, the scheduler shall report every unseen event of that decision as `scored`, including the chat events that were not counted.
- [x] **SAL-DECIDE-016**: While the scheduler counts events, it shall neither read nor change any reflex state, so that a reflex fires under its own cooldown and the shared busy and cooldown gates alone.
- [x] **SAL-DECIDE-017**: When two chat events in a decision have the same display name but different platforms, or the same platform and different user ids, the scheduler shall treat them as two viewers.
- [x] **SAL-DECIDE-018**: When two chat events in a decision have the same platform and user id but different display names, the scheduler shall treat them as one viewer.
- [x] **SAL-DECIDE-019**: When two chat events in a decision have no user id, the scheduler shall treat them as one viewer only when they have the same platform and the same lowercased name.

## Focus Publication (FOCUS)

- [x] **SAL-FOCUS-001**: While the salience service is running and not paused, it shall run a decision every `brain.salience.tick_ms` (default 1500), whether or not `brain.salience.trigger_on_speech` is set; this poll is the fallback for the speech trigger (SAL-TRIG-001) and the only thing that starts a decision for chat, vision or idle chatter. <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/main.test.ts -->
- [x] **SAL-FOCUS-002**: While a previous scheduler decision is still in flight, salience shall skip the next tick without calling the scorer again. <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-FOCUS-003**: When a decision is to speak, salience shall publish `attention.focus` with `reason`, `score` and a focus of `{kind:"chat", who, platform, userId (when the chat event has one), text, mention}`, `{kind:"speech", who, text, source (the source of the `speech.heard`, when it has one)}`, `{kind:"vision", text}`, `{kind:"reminder", text}` (SAL-REM-005) or none (the bus schema fills a missing `mention` with false). <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-FOCUS-004**: When salience publishes `attention.focus`, it shall mark only the scored events seen (a provisional focus marks none, SAL-PROV-011), and shall treat the cortex as `thinking` until a new `brain.status` or valve expiry. <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-FOCUS-005**: When a scheduler decision to speak returns from the scorer, salience shall re-check muted, paused and cortex busy, and if any of them now holds it shall publish no `attention.focus` for that decision. <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-FOCUS-006**: When the focus of a speak decision is a `speech` event that carries `timing.audioEndedAt`, salience shall publish `attention.focus` with `timing` holding that `audioEndedAt`, that `closedAt` when the event carries one, and `heardAt` set to the `ts` of that event's `speech.heard` envelope; when the focus is a `vision` event that carries `timing.capturedAt` and `timing.describedAt`, salience shall publish `attention.focus` with `timing` holding those two stamps; for a focus of any other kind, or a speech or vision event without those stamps, it shall publish no `timing`; it shall not alter any stamp it copies.
- [x] **SAL-FOCUS-007**: When a scheduler decision to speak returns from the scorer and a `chat.removed` has taken the focused chat event out of the window meanwhile, salience shall publish no `attention.focus` for that decision, shall leave that decision's events unseen and shall not mark the cortex `thinking`.

## Speech Trigger (TRIG)

- [x] **SAL-TRIG-001**: Where `brain.salience.trigger_on_speech` is true, when salience receives a `speech.heard` event and it is not paused and no reflex fired for that line, and the line is not resolved by SAL-PROV-013 or skipped by SAL-INTJ-010, it shall start one decision pass (the same pass the poll runs) at once, without waiting for the next `tick_ms` poll.
- [x] **SAL-TRIG-002**: The salience service shall start a trigger decision only for a `speech.heard` event (a `speech.early` starts only the early pass of SAL-PROV-001): a `speech.partial`, `chat.message`, `vision.summary`, `brain.say`, `brain.status`, `affect.state` or `control` event shall start none.
- [x] **SAL-TRIG-003**: When a reflex fired for a `speech.heard` line, salience shall not start a trigger decision for that line.
- [x] **SAL-TRIG-004**: When salience starts a trigger decision, its event handler shall return without waiting for the decision to finish, so a slow `llm` or `http` scorer never delays the intake of the next event.
- [x] **SAL-TRIG-005**: While a decision is in flight and a trigger arrives, salience shall record one pending rerun and, when that decision ends, run exactly one further decision pass; any number of triggers that arrive during the same decision shall produce that one rerun.
- [x] **SAL-TRIG-006**: While salience is paused, a `speech.heard` event shall start no trigger decision and record no pending rerun; a pending rerun recorded before a `pause` shall run no decision while the pause holds.
- [x] **SAL-TRIG-007**: Where `brain.salience.trigger_on_speech` is false, salience shall start no decision on a `speech.heard` event, and decisions shall start only from the `tick_ms` poll.
- [x] **SAL-TRIG-008**: A trigger decision and a rerun shall go through the same decision as the poll (SAL-DECIDE-001 to SAL-DECIDE-008, SAL-FOCUS-002 to SAL-FOCUS-005), so a trigger shall publish no `attention.focus` that the poll would not publish for the same state, and no event shall be the focus of two published `attention.focus` events.
- [x] **SAL-TRIG-009**: If a trigger decision or its `attention.focus` publish fails, then salience shall log the error and keep running without rejecting out of the event handler (SAL-HEALTH-002), and a pending rerun shall still run once.
- [D] **SAL-TRIG-010**: When a trigger decision returns no-speak because of `cooldown` or `cortex busy`, salience shall evaluate again when the cooldown or the busy valve ends, without waiting for the poll. Deferred: until then the next poll after expiry is the only re-evaluation.

## Busy Gating (BUSY)

- [x] **SAL-BUSY-001**: While the last observed cortex state is `thinking` and was set less than `brain.salience.thinking_timeout_ms` (default 60000) ago, salience shall treat the cortex as busy. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-BUSY-002**: While the last observed cortex state is `speaking` and was set (or, for a streamed line, last renewed by SAL-BUSY-006) less than `brain.cortex.speaking_timeout_ms` (default 20000) ago, salience shall treat the cortex as busy. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-BUSY-003**: When salience receives a `brain.say` event from any source (cortex, reflex echo or operator), it shall start the speaking cooldown and set the cortex state to `speaking`. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-BUSY-004**: While the last observed cortex state is `idle` or `muted`, salience shall not treat the cortex as busy (salience's own mute, SAL-CTRL-004, is what stops it speaking). <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Barge-in (BARGE)

- [x] **SAL-BARGE-001**: Where `brain.salience.barge_in` is true, when salience receives a `speech.heard` and it is not paused or muted, the cortex state is `speaking` and busy (SAL-BUSY-002), the speaking line is not a reflex line (SAL-BARGE-006), the event's `source` is in `brain.salience.barge_in_sources` (SAL-BARGE-004) and its text meets `brain.salience.barge_in_min_words` (SAL-BARGE-005), salience shall, unless SAL-INTJ-009 or SAL-INTJ-010 applies to the line, publish one `voice.stop` with reason `barge-in` and no `ids`, before it evaluates reflexes for that line.
- [x] **SAL-BARGE-002**: When salience publishes a `voice.stop` under SAL-BARGE-001, it shall set its cortex state to `idle` and clear its cooldown, so that neither SAL-DECIDE-001's busy and cooldown gates nor SAL-REFLEX-005's hold back the interrupter's line.
- [x] **SAL-BARGE-003**: After a barge-in, salience shall handle the interrupting `speech.heard` as any other: reflex evaluation (SAL-REFLEX-001), the speech trigger (SAL-TRIG-001) and the decision (SAL-DECIDE-001 to SAL-DECIDE-008) all apply unchanged, and the barge-in itself shall publish no `attention.focus` and no `brain.say`.
- [x] **SAL-BARGE-004**: If a `speech.heard` carries no `source`, or a `source` that is not in `brain.salience.barge_in_sources`, then salience shall not treat it as a barge-in.
- [x] **SAL-BARGE-005**: When salience counts the words of a transcript for SAL-BARGE-001, it shall count whitespace-separated tokens that contain at least one letter or number in any script, so that a transcript of fewer than `brain.salience.barge_in_min_words` such tokens is not a barge-in.
- [x] **SAL-BARGE-006**: While the line that last set the cortex state to `speaking` is a reflex line, salience shall not treat a `speech.heard` as a barge-in; a line is a reflex line from the moment salience publishes the reflex `brain.say` (SAL-REFLEX-007), before its echo arrives, and when a `brain.say` arrives with a `reason` beginning `reflex:`; a later `brain.say` whose `reason` does not begin `reflex:` shall end that exemption.
- [x] **SAL-BARGE-007**: If the cortex state is not `speaking`, or is `speaking` but was set (or, for a streamed line, last renewed by SAL-BUSY-006) longer ago than `brain.cortex.speaking_timeout_ms` (SAL-BUSY-002), then salience shall not treat a `speech.heard` as a barge-in and shall publish no `voice.stop`.
- [x] **SAL-BARGE-008**: While salience is paused or muted, it shall publish no `voice.stop`.
- [x] **SAL-BARGE-009**: If publishing the `voice.stop` of SAL-BARGE-001 fails, then salience shall log the error and leave its cortex state and cooldown unchanged, so the line takes the ordinary busy-gated path.
- [x] **SAL-BARGE-010**: After a barge-in, while no new `brain.say` has arrived, salience shall publish no further `voice.stop` for any later `speech.heard`, whatever its speaker.
- [x] **SAL-BARGE-011**: Where `brain.salience.barge_in` is false, salience shall publish no `voice.stop` and its handling of `speech.heard` shall be as without barge-in.

## Reflexes (REFLEX)

- [x] **SAL-REFLEX-001**: When a chat, speech or changed-vision event's text matches a configured reflex rule's case-insensitive regex and the event's sense is listed in the rule's `on`, salience shall publish `brain.say` with a randomly chosen `say` line, the rule's emotion and gesture, and `reason` `reflex: <match>`. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-REFLEX-002**: When salience receives a `vision.summary` with `changed` false, it shall not evaluate reflex rules against it. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-REFLEX-003**: When a reflex rule fires, salience shall not fire that same rule again until its `cooldown_ms` (default 30000) has elapsed, and the first matching rule in config order shall win. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-004**: When a reflex fires, salience shall mark only the triggering event seen, leaving other unseen events available to the next decision. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-005**: While the cortex is busy or the global `cooldown_ms` since the last line has not elapsed, salience shall not fire reflexes, and shall evaluate this gate before spending any rule's own cooldown. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-006**: While salience is muted or paused, it shall not fire reflexes. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-REFLEX-007**: When salience publishes a reflex `brain.say`, it shall immediately start its own cooldown and mark the voice as speaking, rather than waiting for the line to echo back on the bus. <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-REFLEX-008**: The salience reflex path shall take the triggering event from the `Context.push` that ingested it (WM-PUSH-009) and shall mark seen and copy injection flags from that event, never from the window's newest entry. <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Control (CTRL)

- [x] **SAL-CTRL-001**: If a `control` event carries a `target` other than `salience`, then salience shall ignore it; an absent target addresses all services. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-CTRL-002**: When salience receives `control` `pause` addressed to it, it shall publish no `attention.focus` and no reflex `brain.say` while continuing to record incoming events in its `Context`. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-CTRL-003**: When salience receives `control` `resume` addressed to it, it shall resume deciding and firing reflexes in-process without restarting. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-CTRL-004**: While salience is muted by `control` `mute` (cleared by `unmute`), the scheduler shall decide no-speak with reason `muted` and publish no `attention.focus`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-CTRL-005**: When salience receives `control` `forget_context`, it shall clear its working-memory `Context`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-CTRL-006**: The salience service shall hold its muted and paused flags in process memory only, so a restarted salience starts unmuted and unpaused. <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-CTRL-007**: When salience receives `control` `resume` addressed to it, it shall mark seen every event that its `Context` took in while it was paused, so the first decision after a pause does not score a burst that accumulated meanwhile; events that arrive after the `resume` are unseen as usual. <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Injection Flags (INJ)

- [x] **SAL-INJ-001**: When the focus event of a speak decision is an injected event, salience shall publish `attention.focus` with `injected: true` and that event's `remember` value. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts -->
- [x] **SAL-INJ-002**: When the focus event is a real event (even one carrying a stray `remember`) or there is no focus event, salience shall publish `attention.focus` with neither `injected` nor `remember`. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-INJ-003**: When a decision's batch mixes injected and real events, salience shall derive `attention.focus` flags only from the focus event. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts -->

## Provisional focus (PROV)

Design: [salience-design.md § Early transcripts](salience-design.md#early-transcripts). `attention.resolve` is keyed by `utteranceId` and `seq`; "withdraw" and "confirm" are its two outcomes.

- [x] **SAL-PROV-001**: Where `brain.salience.trigger_on_speech` is true, when salience receives a `speech.early` and it is not paused, it shall start one early pass at once without waiting for the event handler to finish, and the early pass shall never reject out of the handler.
- [x] **SAL-PROV-002**: Where `brain.salience.trigger_on_speech` is false, salience shall read `speech.early` and start no early pass.
- [x] **SAL-PROV-003**: The early pass shall do nothing while salience is paused, while a decision is in flight (recording no pending rerun), or while a provisional focus is held.
- [x] **SAL-PROV-004**: When the text of a `speech.early` matches a speech reflex rule, determined by a match test that stamps no rule's cooldown, the early pass shall issue no provisional focus, so the reflex fires on the final as SAL-REFLEX-001 says.
- [x] **SAL-PROV-005**: The early pass shall apply the gates muted, busy and cooldown in the order of SAL-DECIDE-001 and shall issue no provisional focus when one of them holds.
- [x] **SAL-PROV-006**: The early pass shall score the early text as a transient speech event beside the unseen events of the working-memory `Context`, through the scorer and the counting walk of a decision, and shall not push the early text into the `Context`.
- [x] **SAL-PROV-007**: The early pass shall keep the early text's score by `utteranceId`, `seq` and text and shall reuse it, with no further scorer call, only for a final `speech.heard` with the same `utteranceId`, an `earlySeq` equal to that `seq` and the same text.
- [x] **SAL-PROV-008**: When the total of the early pass is below the speak threshold of SAL-DECIDE-003, the early pass shall issue no provisional focus and the final shall be decided as an ordinary final.
- [x] **SAL-PROV-009**: When the early pass decides to speak, salience shall, after the scorer returns and immediately before publishing, check again that it is not muted or paused and not busy, that the `seq` was not retracted and that the utterance's final has not arrived, and shall publish no provisional focus unless every check passes; salience shall make no other repeat of the gates before a provisional focus.
- [x] **SAL-PROV-010**: When the checks of SAL-PROV-009 pass, salience shall record a provisional focus holding the `utteranceId`, the early transcript's `seq` and text, its score and the events the decision scored, and shall publish `attention.focus` with `provisional` true, `utteranceId`, `seq`, `reason`, `score`, `focus` of kind `speech` with `who`, `text` and `source`, and `timing` holding the `audioEndedAt` of the early transcript and its `closedAt` when it carries one. The focus of the early decision shall be the early transcript itself: when any other event outranks it, salience shall publish no provisional focus and the final shall take the ordinary path.
- [x] **SAL-PROV-011**: When salience publishes a provisional focus, it shall mark no event seen, start no cooldown and not reset the idle timer, and shall set its cortex state to `thinking`.
- [x] **SAL-PROV-012**: A provisional focus shall stay unresolved at most `brain.salience.unresolved_limit_ms` (default 4000) milliseconds, counted from the publication of the `attention.focus`.
- [x] **SAL-PROV-013**: When a final `speech.heard` arrives whose `earlySeq` equals the `seq` of the held provisional focus for its `utteranceId`, salience shall publish `attention.resolve` with `outcome` `confirm`, `utteranceId`, `seq`, `reason`, `score`, `focus` of kind `speech` with `who`, the final's `text` and `source`, the `injected` and `remember` of the final, and `timing` holding the final's `audioEndedAt` and `closedAt` and a `heardAt` equal to the `ts` of the final's `speech.heard` envelope (SAL-FOCUS-006).
- [x] **SAL-PROV-014**: When salience publishes a confirm of SAL-PROV-013, it shall mark seen exactly the events the provisional decision scored and the final, shall set its cortex state to `thinking`, and shall start no cooldown.
- [x] **SAL-PROV-015**: When a final `speech.heard` arrives for the utterance of a held provisional focus with an `earlySeq` other than its `seq` or with none, salience shall publish `attention.resolve` with `outcome` `withdraw` and `reason` `resumed`, and shall then take the ordinary path for the final.
- [x] **SAL-PROV-016**: When a `speech.retracted` arrives whose `seq` equals that of the held provisional focus for its `utteranceId`, salience shall publish `attention.resolve` with `outcome` `withdraw` and `reason` `resumed`, except as SAL-INTJ-001 to SAL-INTJ-006 say.
- [x] **SAL-PROV-017**: When a `speech.retracted` arrives whose `seq` differs from that of the held provisional focus, or arrives with no held provisional focus, salience shall ignore it.
- [x] **SAL-PROV-018**: When salience receives a `control` event `mute` or `pause` for it while it holds a provisional focus, it shall at once publish `attention.resolve` with `outcome` `withdraw` and `reason` `muted` or `paused`.
- [x] **SAL-PROV-019**: When salience receives a `control` event `forget_context` while it holds a provisional focus, it shall at once publish `attention.resolve` with `outcome` `withdraw` and `reason` `forgotten`.
- [x] **SAL-PROV-020**: When any `brain.say` arrives while a provisional focus is unresolved (no `attention.resolve` published for it yet), whatever its source, or salience publishes an `attention.focus` for something else, salience shall at once publish `attention.resolve` with `outcome` `withdraw` and `reason` `superseded`.
- [x] **SAL-PROV-021**: When a provisional focus has stayed unresolved for `brain.salience.unresolved_limit_ms`, salience shall publish `attention.resolve` with `outcome` `withdraw` and `reason` `timeout`.
- [x] **SAL-PROV-022**: When salience publishes a withdraw, it shall mark no event seen, start no cooldown, and drop the provisional focus and the cached score of its early text.
- [x] **SAL-PROV-023**: Salience shall publish exactly one `attention.resolve` for each provisional focus it publishes, carrying that focus's `utteranceId` and `seq`, and shall drop the record when it does.
- [x] **SAL-PROV-024**: When a final `speech.heard` or a `speech.retracted` for the `seq` of an early pass arrives while that early pass is scoring, salience shall not cancel the pass, and the pass shall publish no provisional focus when the scorer returns.
- [x] **SAL-PROV-025**: While salience holds a provisional focus, it shall treat the cortex as busy on the `thinking` valve (SAL-BUSY-001) and shall use no state of its own for the hold.
- [x] **SAL-PROV-026**: When a `brain.status` `idle` arrives while salience holds a provisional focus, salience shall set its cortex state to `idle` and keep the record.
- [x] **SAL-PROV-027**: When salience publishes an ordinary `attention.focus` for something else after a `brain.status` `idle` arrived while it held an unresolved provisional focus, SAL-PROV-020 shall apply to that provisional focus.
- [x] **SAL-PROV-028**: When salience publishes an `attention.focus` whose focus is a `speech` event that carries an `utteranceId`, it shall set the focus's `utteranceId` to it.
- [x] **SAL-PROV-029**: While an early pass is running and its total is below the speak threshold, it shall not decide idle chatter (SAL-DECIDE-004) and shall issue no provisional focus.
- [x] **SAL-PROV-030**: When salience publishes `attention.resolve` with `outcome` `withdraw` and `reason` `resumed`, `muted`, `paused`, `forgotten` or `timeout`, it shall set its cortex state to `idle` at once, without waiting for a `brain.status`, so that a final taking the ordinary path is decided immediately and is not refused as busy.
- [x] **SAL-PROV-031**: When salience publishes `attention.resolve` with `outcome` `withdraw` and `reason` `superseded`, it shall leave its cortex state as the superseding `brain.say` set it.
- [x] **SAL-PROV-032**: While an early pass is running it shall count as a decision in flight (SAL-FOCUS-002), so that a final `speech.heard` that arrives during it records one pending rerun (SAL-TRIG-005).
- [x] **SAL-PROV-033**: The pending rerun that a final starts after an early pass (SAL-TRIG-005) shall reuse the scores that early pass cached, under the same-text condition of SAL-PROV-007.
- [x] **SAL-PROV-034**: When the final of an utterance has been handled (confirmed, decided or marked seen), salience shall drop the cached score of that utterance's early text, as it does at a withdraw (SAL-PROV-022).

## Interjection (INTJ)

Design: [salience-design.md § Interjection](salience-design.md#interjection). Applies only where `ears.early.enabled` makes early transcripts exist.

- [x] **SAL-INTJ-001**: Where `brain.salience.interject` is true, when a `speech.retracted` arrives for the `utteranceId` and `seq` of an unresolved provisional focus that salience holds and salience is neither paused nor muted, salience shall consider asking for an interjection. A paused or muted salience asks for nothing: the pause or mute has already withdrawn the focus.
- [x] **SAL-INTJ-002**: A request for an interjection shall require that the early text have at least `brain.salience.interject_min_words` (default 4) words, counted as SAL-BARGE-005 counts them.
- [x] **SAL-INTJ-003**: A request for an interjection shall require that at least `brain.salience.interject_min_gap_ms` (default 120000) milliseconds have passed since the last interjection that was spoken (SAL-INTJ-007), on the clock `SalienceDeps.now` that times the cooldown. With no interjection yet spoken the first is allowed at once, whatever the clock reads, and a gap of exactly `brain.salience.interject_min_gap_ms` passes.
- [x] **SAL-INTJ-004**: A request for an interjection shall require that a random draw, made once per retraction from an injectable source, be below `brain.salience.interject_chance` (default 0.15). The source is `SalienceDeps.random`, called exactly once when SAL-INTJ-001 to SAL-INTJ-003 hold and not at all otherwise; the draw is strictly below the chance.
- [x] **SAL-INTJ-005**: When any condition of SAL-INTJ-001 to SAL-INTJ-004 fails, salience shall resolve the provisional focus as SAL-PROV-016 says.
- [x] **SAL-INTJ-006**: When salience asks for an interjection, it shall publish `attention.resolve` with `outcome` `confirm`, `interjected` true, `utteranceId`, `seq`, the focus fields of a confirm (SAL-PROV-013) and the `timing` of the provisional focus, shall set its cortex state to `thinking`, and shall hold the request pending until cortex's `brain.say` or a `brain.status` other than `thinking` arrives. If the confirm does not publish, salience logs the error, publishes `attention.resolve` with `outcome` `withdraw` and `reason` `resumed` for the same focus so that cortex holds no provisional focus, sets its state to `idle` if it is still `thinking`, makes no request and releases the held finals (SAL-INTJ-023).
- [x] **SAL-INTJ-007**: When a `brain.say` from cortex arrives while an interjection request is pending (a cortex line: neither reflex-prefixed nor `operator`; a reflex or operator line neither answers it nor is counted), salience shall record the interjection as spoken and set the time of the last interjection to the current time.
- [x] **SAL-INTJ-008**: When a `brain.status` other than `thinking` arrives while an interjection request is pending and no `brain.say` has arrived, salience shall drop the request, charge no gap, push nothing into its `Context` and mark no event seen.
- [x] **SAL-INTJ-009**: When a final `speech.heard` arrives for an utterance with a spoken interjection, adds at least `brain.salience.interject_followup_min_words` (default 3) words beyond the early text, `brain.salience.interject_yield` (default true) is true and the cortex state is `speaking` for the interjected line within its valve (SAL-BUSY-002), where the interjected line is the line that last set `speaking` (every cortex line is also the remembered cortex line, SAL-BUSY-005), so a reflex or operator line, or another cortex line, that set `speaking` later does not count, salience shall publish one `voice.stop` with reason `yield` and `ids` holding that line's `id`, set its cortex state to `idle` and clear the cooldown, whether or not `brain.salience.barge_in` is true. If the `voice.stop` does not publish, salience logs the error, leaves its cortex state and cooldown unchanged and takes no barge-in check for that final (SAL-BARGE-009).
- [x] **SAL-INTJ-010**: When a final `speech.heard` arrives for an utterance with a spoken interjection and adds fewer than `brain.salience.interject_followup_min_words` (default 3) words beyond the early text, salience shall mark the final seen and make no decision, no stop, no reflex test, no barge-in check and no trigger for it, whether `brain.salience.interject_yield` is true or false.
- [x] **SAL-INTJ-011**: The words a final adds beyond the early text shall be the difference between the word counts of the final and of the early text, never below zero, each word counted as SAL-BARGE-005 counts it.
- [x] **SAL-INTJ-012**: When a final `speech.heard` arrives for an utterance with a spoken interjection and neither SAL-INTJ-010 nor SAL-INTJ-009 applies (`brain.salience.interject_yield` is false, or the interjected line is not playing), salience shall treat it as an ordinary line: the barge-in check of SAL-BARGE-001, then the reflex test and the speech trigger.
- [x] **SAL-INTJ-013**: Salience shall evaluate a final for an utterance with a spoken interjection in the order SAL-INTJ-010, SAL-INTJ-009, SAL-INTJ-012, and shall append the final to its `Context` as an ordinary line (WM-UNF-002) in every case.
- [x] **SAL-INTJ-014**: If the final of an utterance with a spoken interjection never arrives, then salience shall take no further action for that utterance.
- [x] **SAL-INTJ-015**: When a `speech.early` arrives for an utterance with a spoken interjection and adds fewer than `brain.salience.interject_followup_min_words` words beyond the interjected text (counted as SAL-INTJ-011 counts them, against the early text recorded for the utterance), the early pass shall issue no provisional focus.
- [x] **SAL-INTJ-016**: When an interjection request ends by SAL-INTJ-008, a later `speech.early` of the same utterance shall be an ordinary early pass and may ask for an interjection again.
- [x] **SAL-INTJ-017**: Where `brain.salience.interject_yield` is false, salience shall publish no `voice.stop` with reason `yield`, and an interjected line shall stop only through the barge-in rules (SAL-BARGE-001).
- [x] **SAL-INTJ-018**: When an interjection request has been pending for `brain.salience.unresolved_limit_ms`, counted from the request, with neither a `brain.say` from cortex nor a `brain.status` other than `thinking`, salience shall set its cortex state to `idle`, charge no gap and publish nothing.
- [x] **SAL-INTJ-019**: When salience records an interjection as spoken (SAL-INTJ-007), it shall mark the events the provisional decision scored seen.
- [x] **SAL-INTJ-020**: When salience records an interjection as spoken (SAL-INTJ-007), it shall push the early text into its own `Context` as an unfinished line (WM-UNF-001).
- [x] **SAL-INTJ-021**: When salience records an interjection as spoken (SAL-INTJ-007), it shall keep a record of it holding the `utteranceId`, the early text, the line's `id` and the time, and shall keep the last eight records.
- [x] **SAL-INTJ-022**: After the `voice.stop` of SAL-INTJ-009, salience shall take the final through the reflex test and the speech trigger with no barge-in check.
- [x] **SAL-INTJ-023**: When a final `speech.heard` arrives for an utterance while an interjection request for it is pending, salience shall hold that final, neither deciding it nor refusing it as busy, until the request is answered (SAL-INTJ-007 or SAL-INTJ-008) or `brain.salience.unresolved_limit_ms` has passed since the request (SAL-INTJ-018), and shall then apply SAL-INTJ-010, SAL-INTJ-009 and SAL-INTJ-012 if the interjection was spoken and the ordinary path if it was not. The held final is appended to the window after the unfinished line that a spoken answer adds (SAL-INTJ-020). A final of another utterance while the request is pending is not held: it takes the ordinary path at once.
- [x] **SAL-INTJ-024**: When salience receives a `control` command `forget_context` while an interjection request is pending, it shall drop the request with no gap charged and nothing published, discard the finals held for it, and set its cortex state to `idle` if it is `thinking`; a `brain.say` cortex sends for the dropped request afterwards is an ordinary line, and nothing of the forgotten window re-enters it.

## Playback and the speaking valve

Design: LLD Busy Gating and Cooldown. The valve of a streamed line is renewed by playback of the line the cortex is speaking; a line without `more` keeps the built valve.

- [x] **SAL-BUSY-005**: When salience receives a `brain.say` from the cortex's think, it shall remember its `id` and whether it carried `more` as the cortex line, separately from the line of a reflex or an operator `say`, which sets its own remembered id and shall not replace the cortex line's.
- [x] **SAL-BUSY-006**: When salience receives a `voice.playing` or `voice.done` for the remembered cortex line while the cortex state is `speaking` and the line carried `more`, it shall restart the age of the speaking state, from any sink.
- [x] **SAL-BUSY-007**: When salience receives a `voice.playing` or `voice.done` for another line, for a line that did not carry `more`, or while the cortex state is not `speaking`, it shall ignore it, so an event of a line that a barge-in stopped or cortex released does not make salience busy again and a line without `more` keeps the valve of SAL-BUSY-002.
- [x] **SAL-BUSY-008**: Salience shall not subscribe to `brain.clause` and shall measure the speaking cooldown from the line's `brain.say`: a clause or a playback event shall not restart it or the idle-chatter timer.
- [x] **SAL-BARGE-012**: While playback events keep renewing the speaking state (SAL-BUSY-006) of a streamed line, salience shall allow a barge-in for the whole time, however many clauses were published at once.
