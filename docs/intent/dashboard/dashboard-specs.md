# dashboard specs

Prefix `DASH`. Design: [dashboard-design.md](dashboard-design.md). Verified against the code at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`. Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred. `<!-- test: -->` points at the `test(` line that exercises the spec; `<!-- openspec: -->` names the retired OpenSpec requirement the line descends from (the LID line wins where they differ). `[proposed]` inside a line marks a value or choice awaiting the owner's confirmation (Viewers page).

## HTTP routes

- [x] **DASH-HTTP-001**: When `GET /` is requested, the dashboard shall respond 200 `text/html` with every occurrence of `__COHOST_NAME__` in `public/index.html` replaced by `cohost.name`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:37 -->
- [x] **DASH-HTTP-002**: When `/health` is requested with any method that no earlier route handles, the dashboard shall respond 200 `ok`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:82 -->
- [x] **DASH-HTTP-003**: If a request matches no route, then the dashboard shall respond 404 `not found`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:82 -->
- [x] **DASH-HTTP-004**: If an HTTP handler throws (for example invalid JSON on `POST /control` or `POST /sink`, a payload the event schema rejects, a request URL that does not parse, or a failed upstream audio fetch), then the dashboard shall log `request failed` and respond 500 with the error text without exiting. <!-- openspec: dashboard § Error handling --> <!-- test: services/dashboard/test/routes.test.ts:121 --> <!-- test: services/dashboard/test/routes.test.ts:108 --> The audio proxy shall read the whole upstream body before it chooses the status and writes headers, so a failed body read is still answered 500; an error response is never attempted once headers have been sent, and no handler failure becomes an unhandled rejection.
- [x] **DASH-HTTP-005**: When `GET /personality` is requested, the dashboard shall respond with the personality file text as `text/plain`. <!-- openspec: dashboard § Personality editing --> <!-- test: services/dashboard/test/routes.test.ts:53 -->
- [x] **DASH-HTTP-006**: When `PUT /personality` is requested, the dashboard shall save the request body as the personality file, publish `control {cmd: "reload_personality"}` and respond 204. <!-- openspec: dashboard § Personality editing --> <!-- test: services/dashboard/test/routes.test.ts:53 -->
- [x] **DASH-HTTP-007**: When `POST /control` carries `{cmd, text?, target?}`, the dashboard shall publish a `control` event with those fields and respond 204; a `cmd` outside the event schema (`mute`, `unmute`, `say`, `forget_context`, `reload_personality`, `pause`, `resume`) shall be answered 500 and nothing published. <!-- openspec: dashboard § Control commands --> <!-- test: services/dashboard/test/routes.test.ts:63 --> <!-- test: services/dashboard/test/routes.test.ts:82 -->
- [x] **DASH-HTTP-008**: When `POST /control` carries `{cmd: "pause" | "resume", target}`, the dashboard shall publish the targeted `control` event; the web page offers no control for pause or resume. <!-- openspec: dashboard § Control commands --> <!-- test: services/dashboard/test/control.test.ts:95 -->
- [x] **DASH-HTTP-009**: The dashboard shall listen on the `PORT` environment variable when set, else on `dashboard.port` (default 3000), and shall publish its `ready` heartbeat only once the server is listening. <!-- openspec: dashboard § (add-service-health) Heartbeat -->
- [x] **DASH-HTTP-010**: When the dashboard shuts down gracefully, it shall stop the upload sweeper and the feed's staleness tick, close the WebSocket and HTTP servers, and stop the bus.
- [x] **DASH-HTTP-011**: If the body of `POST /control`, `PUT /personality`, `POST /sink` or `POST /services/:id/(start|stop|restart)` exceeds 64 KiB, then the dashboard shall respond 413 and shall publish, save and run nothing. <!-- test: services/dashboard/test/routes.test.ts:93 --> <!-- test: services/dashboard/test/control.test.ts:168 -->
- [x] **DASH-HTTP-012**: If the feed cannot start at startup because Redis is unreachable (`feed.start()` rejects), then the dashboard shall log the error at `fatal` level and exit non-zero; if a client's connect replay fails, it shall log the error and close that socket while the process keeps running. <!-- test: services/dashboard/test/feed.test.ts:151 --> <!-- test: services/dashboard/test/feed.test.ts:163 -->
- [x] **DASH-HTTP-013**: If the service id in `POST /services/:id/(start|stop|restart)` contains a malformed `%` escape, then the dashboard shall respond 404 as for an unknown service. <!-- test: services/dashboard/test/control.test.ts:179 -->

## Audio proxy and sink

- [x] **DASH-SINK-001**: When `GET /audio/<path>` is requested, the dashboard shall fetch `<urls.voice()>/audio/<path>` and return the upstream status and content-type (default `audio/wav`) with `cache-control: no-store`. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:43 -->
- [x] **DASH-SINK-002**: When `POST /sink` carries `{event: "playing", id}`, the dashboard shall publish `voice.playing {id, sink: "dashboard"}`; when it carries `{event: "done", id}`, it shall publish `voice.done {id, sink: "dashboard"}`; in both cases it shall respond 204. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:71 -->
- [x] **DASH-SINK-003**: If `POST /sink` carries an `event` other than `playing` or `done`, then the dashboard shall respond 400 and publish nothing. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:84 -->
- [x] **DASH-SINK-004**: When `VOICE_URL` is not set, the dashboard shall proxy audio from voice's loopback address `http://127.0.0.1:<VOICE_PORT>` (port default 8700), as resolved by `urls.voice()`. <!-- openspec: dashboard § Audio sink --> <!-- test: packages/config/test/config.test.ts:207 -->

## WebSocket feed

- [x] **DASH-FEED-001**: When a client connects to `/ws`, the dashboard shall first send a `{type: "services", services}` snapshot and then the 60 most recent bus events, oldest first, each marked `replay: true`, skipping any `service.heartbeat` and the viewer-notes events of DASH-FEED-007. <!-- openspec: dashboard § Live event feed --> A live event that arrives while the replay is being read shall reach that client once, after the replay (not at all if the replay already contained it), and shall carry no `replay` marker; clients that are not replaying receive it immediately. <!-- test: services/dashboard/test/feed.test.ts:48, services/dashboard/test/feed.test.ts:93, services/dashboard/test/feed.test.ts:111, services/dashboard/test/feed.test.ts:142, services/dashboard/test/feed.test.ts:157 -->
- [x] **DASH-FEED-002**: While the dashboard is running, it shall forward every new event on the main bus stream, unfiltered by type except for `service.heartbeat` and the viewer-notes events of DASH-FEED-007, as JSON to every connected client whose socket is OPEN. <!-- openspec: dashboard § Live event feed --> <!-- test: services/dashboard/test/feed.test.ts:93, services/dashboard/test/feed.test.ts:111 -->
- [x] **DASH-FEED-003**: When the dashboard starts its feed, it shall seed the health tracker from the 500 most recent heartbeats and follow the health stream from the last seen id. <!-- test: services/dashboard/test/feed.test.ts:51 -->
- [x] **DASH-FEED-004**: When the tracker's derived service state changes, the dashboard shall push a `services` message to connected clients; identical repeated heartbeats shall not cause a push. <!-- test: services/dashboard/test/feed.test.ts:61 -->
- [x] **DASH-FEED-005**: While the dashboard is running, it shall re-evaluate heartbeat staleness every 1000 ms and push the result to connected clients when a state changes. <!-- test: services/dashboard/test/feed.test.ts:74 -->
- [x] **DASH-FEED-006**: When `GET /services` is requested, the dashboard shall respond 200 JSON `{services}` listing every known service with its derived state (`unknown` for services never seen). <!-- test: services/dashboard/test/routes.test.ts:95 -->
- [x] **DASH-FEED-007**: The dashboard shall never send `memory.notes.request`, `memory.notes.reply`, `memory.viewers.request` or `memory.viewers.reply` events to a `/ws` client, neither live nor in the connect replay, because they carry viewer-note text. <!-- test: services/dashboard/test/feed.test.ts:111 -->

## Control gating

- [x] **DASH-CTRL-001**: Where `CONTROL_ENABLED` is not `1`, the dashboard shall not require a bearer token on any route, shall answer `POST /services/:id/(start|stop|restart)` with 404, shall report `{enabled: false}` from `GET /services/control`, and shall listen on Node's default (all) interfaces. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:49 --> <!-- test: services/dashboard/test/inject.test.ts:150 -->
- [x] **DASH-CTRL-002**: If `CONTROL_ENABLED=1` and `CONTROL_TOKEN` is empty or unset, then the dashboard shall fail startup with an error naming `CONTROL_TOKEN`. <!-- test: services/dashboard/test/control.test.ts:63 -->
- [x] **DASH-CTRL-003**: Where `CONTROL_ENABLED=1`, the dashboard shall listen on `CONTROL_BIND` (default `127.0.0.1`) and shall log a warning when that address is not loopback because the token travels in cleartext. <!-- test: services/dashboard/test/control.test.ts:68 -->
- [x] **DASH-CTRL-004**: Where `CONTROL_ENABLED=1`, the dashboard shall require `Authorization: Bearer <CONTROL_TOKEN>`, compared in constant time, on `POST /control`, `PUT /personality`, `POST /inject/text`, `POST /inject/image`, `POST /inject/audio` and `POST /services/:id/(start|stop|restart)`, responding 401 with `www-authenticate: Bearer` and performing no action otherwise. <!-- openspec: dashboard § (add-service-control) Bearer token on mutating routes --> <!-- openspec: dashboard § (add-test-injection) Injection gating --> <!-- test: services/dashboard/test/control.test.ts:81 --> <!-- test: services/dashboard/test/control.test.ts:95 --> <!-- test: services/dashboard/test/inject.test.ts:134 -->
- [x] **DASH-CTRL-005**: Where `CONTROL_ENABLED=1`, the dashboard shall leave `GET /services/control`, `GET /services`, `GET /personality`, `GET /audio/*`, `GET /uploads/:id`, `POST /sink`, `/health` and the `/ws` feed unauthenticated: control mode guards mutations only, and an OBS Browser Source sink page, which cannot present a token, needs `/ws`, `/audio/*` and `POST /sink`. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/control.test.ts:104 --> <!-- test: services/dashboard/test/inject.test.ts:134 -->
- [x] **DASH-CTRL-007**: Where `CONTROL_ENABLED=1`, `GET /services/control` shall respond 200 JSON `{enabled: true, runtime, advanced}`, where `runtime` is always `compose` (the only runtime) and `advanced` is true only when `CONTROL_ADVANCED=1`. <!-- openspec: dashboard § (add-service-control) Service control UI --> <!-- test: services/dashboard/test/control.test.ts:104 -->
- [x] **DASH-CTRL-008**: Where `CONTROL_ENABLED=1` and `CONTROL_ADVANCED=1`, the dashboard shall log a startup warning that redis and postgres can be stopped from the dashboard.

## Service lifecycle

- [x] **DASH-SVC-001**: Where `CONTROL_ENABLED=1`, when an authorized `POST /services/:id/(start|stop|restart)` arrives, the dashboard shall delegate to the service controller, publish a `service.lifecycle` audit record with `by: "dashboard"`, and respond 200 `{ok, detail?}`. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:110 -->
- [x] **DASH-SVC-002**: When the lifecycle request body is empty, the dashboard shall treat it as `{}`; when it is not a JSON object, or `mode` is not `resume` or `fresh`, or `isolated` is not a boolean, it shall respond 400 and run nothing; only `mode` and `isolated` are read. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:121 --> <!-- test: services/dashboard/test/control.test.ts:133 -->
- [x] **DASH-SVC-003**: When the controller refuses a lifecycle request, the dashboard shall respond 404 for an unknown service, 409 for a conflict (the dashboard stopping or restarting itself) and 403 for a forbidden target (infrastructure without `CONTROL_ADVANCED=1`), each with `{ok: false, detail}`. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:140 --> <!-- test: services/dashboard/test/control.test.ts:149 -->
- [x] **DASH-SVC-004**: If publishing the `service.lifecycle` audit record fails, then the dashboard shall log a warning and still answer the lifecycle request normally. <!-- test: services/dashboard/test/control.test.ts:161 -->

## Test-input injection

- [x] **DASH-INJ-001**: When `POST /inject/text` carries a body that is not a JSON object, a `level` other than `service` or `bus`, an `as` other than `chat`, `speech` or `vision`, blank `text`, a mistyped optional field, or `level: "service"` with `as` other than `chat`, the dashboard shall respond 400 and publish nothing; a body over 64 KiB shall be answered 413. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:66 -->
- [x] **DASH-INJ-002**: When `POST /inject/text` carries `level: "bus"` and `as: "chat"` (the default), the dashboard shall publish `chat.message` with `injected: true`, the whitespace-collapsed text, platform default `twitch`, user default `injected_viewer`, `isMod`/`isSub` default false, the `remember` flag and no `userId`, leaving `mentionsCohost` uncomputed so it takes the schema default `false`, then respond 202 `{id}`. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:34 -->
- [x] **DASH-INJ-003**: When `POST /inject/text` carries `level: "bus"` and `as: "speech"` or `"vision"`, the dashboard shall publish `speech.heard` (speaker = `user` or `injected`, `durationMs` 0) or `vision.summary` (`changed: true`) respectively, with `injected: true` and the `remember` flag. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:43 -->
- [x] **DASH-INJ-004**: When `POST /inject/text` carries `level: "service"` and `as: "chat"`, the dashboard shall publish `inject.request {id, target: "chat", kind: "text", text, meta, remember}` using the unmodified text and only the supplied viewer fields in `meta`, and respond 202 with that same `id`. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:56 -->
- [x] **DASH-INJ-005**: When `POST /inject/image` or `/inject/audio` carries an allowed content type (images: PNG, JPEG, WebP; audio: WAV, x-wav, MPEG, Ogg, WebM, MP4; parameters after `;` ignored) and a non-empty body within the size cap, the dashboard shall store it, publish `inject.request {id, target: "eyes" | "ears", kind, url: "<urls.dashboard()>/uploads/<id>", meta?, remember}` with `meta.user` from `?user=` and `remember` from `?remember=1|true`, and respond 202 `{id}`; the bytes shall not be published on the bus. <!-- openspec: dashboard § (add-test-injection) Inject binary routes --> <!-- test: services/dashboard/test/inject.test.ts:83 --> <!-- test: services/dashboard/test/inject.test.ts:102 -->
- [x] **DASH-INJ-006**: If a binary injection request has an unsupported content type, then the dashboard shall respond 415; if it exceeds the per-kind cap, 413; if its body is empty, 400; if `level` is `bus` (or anything but `service`), 400; and in each case nothing shall be stored or published. <!-- openspec: dashboard § (add-test-injection) Inject binary routes --> <!-- test: services/dashboard/test/inject.test.ts:115 -->
- [x] **DASH-INJ-007**: When `GET /uploads/<id>` is requested for a live upload, the dashboard shall respond 200 with the stored bytes, the stored content type and `cache-control: no-store`; for an unknown or expired id it shall respond 404. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/inject.test.ts:83 --> <!-- test: services/dashboard/test/inject.test.ts:128 -->

## Upload store

- [x] **DASH-UPL-001**: The upload store shall assign each upload a 128-bit random hex id and enforce a per-kind size cap (default 8 MiB image, 25 MiB audio; env `INJECT_MAX_IMAGE_BYTES`, `INJECT_MAX_AUDIO_BYTES`; non-numeric or non-positive values fall back to the default). <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:10 --> <!-- test: services/dashboard/test/uploads.test.ts:21 --> <!-- test: services/dashboard/test/uploads.test.ts:67 -->
- [x] **DASH-UPL-002**: The upload store shall expire entries after `INJECT_TTL_MS` (default 600000 ms), lazily when an entry is read or a new upload is stored, and on a sweep that the dashboard runs every 60 s. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:28 --> <!-- test: services/dashboard/test/uploads.test.ts:39 --> <!-- test: services/dashboard/test/uploads.test.ts:67 -->
- [x] **DASH-UPL-003**: When the upload store holds more than 16 entries or 64 MiB, it shall evict the oldest entries first, always keeping the newest. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:48 --> <!-- test: services/dashboard/test/uploads.test.ts:57 -->

## Web page

- [x] **DASH-UI-001**: When the page loads, it shall open a WebSocket to `/ws` (using `wss` over HTTPS) and, when the socket closes, show "reconnecting…" and reconnect after 2 s. <!-- openspec: dashboard § Live event feed --> <!-- test: services/dashboard/test/page.test.ts:211 -->
- [x] **DASH-UI-002**: The page shall render a feed row only for `chat.message`, `brain.say`, `vision.summary`, `speech.heard`, `brain.status`, `control`, `service.lifecycle`, `inject.request`, `inject.result`, `voice.utterance`, `voice.playing` and `voice.done`, silently drop every other event type from the feed, keep at most 300 rows, and mark rows whose data has `injected: true` with an "injected" badge (plus "remembered" when `remember` is true). <!-- openspec: dashboard § (add-test-injection) Injected badge --> <!-- test: services/dashboard/test/page.test.ts:223 -->
- [x] **DASH-UI-003**: When a `brain.status` event arrives, the page shall set the header status pill to the event's `state` and render a feed row showing the state followed by `detail` when present. <!-- test: services/dashboard/test/page.test.ts:223 -->
- [x] **DASH-UI-004**: When an `avatar.state` event arrives, the page shall draw the avatar preview from its parameters and show the driver name with a "(disconnected)" suffix when not connected, without adding a feed row.
- [x] **DASH-UI-005**: The page shall offer mute/unmute, say, and wipe-context controls that send `POST /control`, and a personality editor that loads `GET /personality` and saves with `PUT /personality`.
- [x] **DASH-UI-006**: If a request sent through the page's authenticated fetch receives 401, then the page shall prompt once for the control token, remember it in `sessionStorage` for the tab, and retry the request with a bearer header. <!-- test: services/dashboard/test/page.test.ts:201 -->
- [x] **DASH-UI-007**: The page shall render a Services tab listing each service's state, mode, dependencies, last-seen age, restart count and detail from `services` messages, with a count of down, crash-looping and stale services on the tab label. <!-- openspec: dashboard § (add-service-health) Heartbeat -->
- [x] **DASH-UI-008**: Where `GET /services/control` reports `enabled: true`, the page shall show per-service Start/Stop/Restart buttons (the dashboard row offering only Start), a start-mode select and an isolated checkbox, and shall ask for confirmation before sending any lifecycle request. <!-- openspec: dashboard § (add-service-control) Service control UI -->
- [x] **DASH-UI-009**: The page shall provide a test-inputs panel with text and viewer fields, a service/bus level toggle (bus disables the image and audio controls and shows the chat/speech/vision selector), a `remember` checkbox off by default, image and audio pickers, and, where the browser supports `MediaRecorder` and `getUserMedia`, a microphone record button. <!-- openspec: dashboard § (add-test-injection) Test inputs panel -->
- [x] **DASH-UI-010**: When a service-level injection returns `{id}`, the page shall show the status of the `inject.result` with that id (including one that arrived before the HTTP response) and, if none arrives within 10 s, report that the target did not respond; for bus-level injection it shall report that no service result is expected. <!-- openspec: dashboard § (add-test-injection) Test inputs panel -->
- [x] **DASH-UI-011**: Where the page URL carries a `sink` query parameter with any value (documented as `?sink=1`; `?sink=0` also enables it), the page shall enable audio playback without a click and hide everything except the header, so it can serve as an OBS Browser Source; otherwise audio shall stay off until the operator clicks "enable audio". <!-- openspec: dashboard § Audio sink -->
- [x] **DASH-UI-012**: While audio is enabled, when a `voice.utterance` event arrives, the page shall play `/audio/<id>.wav` after any earlier utterances, posting `{event: "playing", id}` to `/sink` when playback starts and `{event: "done", id}` when it ends or errors. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/page.test.ts:118 -->
- [x] **DASH-UI-013**: When the page loads or reconnects, it shall still show the replayed events in the feed but shall not play, or post `/sink` events for, any `voice.utterance` delivered as part of the connect replay; the page shall recognise replayed events by the server's `replay: true` marker, not by comparing the publisher's `ts` with the browser clock, and shall handle each bus event id at most once, so an event delivered both live and in a replay is shown and played once. <!-- test: services/dashboard/test/page.test.ts:108 --> <!-- test: services/dashboard/test/page.test.ts:134 -->
- [x] **DASH-UI-014**: While audio is not enabled, the page shall not accumulate `voice.utterance` events in an ever-growing queue: utterances that arrive then are not queued, and turning audio off drops what had not started. <!-- test: services/dashboard/test/page.test.ts:145 -->
- [x] **DASH-UI-015**: When the page saves the personality or toggles mute, it shall report success and flip the mute button label only after a 2xx response, and shall show a failure message otherwise. <!-- test: services/dashboard/test/page.test.ts:162 --> <!-- test: services/dashboard/test/page.test.ts:182 -->
- [x] **DASH-UI-016**: The page shall escape `&`, `<`, `>`, `"` and `'` in every value it interpolates into HTML, including attribute values such as `data-svc`. <!-- test: services/dashboard/test/page.test.ts:92 --> <!-- test: services/dashboard/test/page.test.ts:99 -->
