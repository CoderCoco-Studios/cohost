## Context and Design Philosophy

`@cohost/config` (`packages/config`) is the dependency root of the workspace: it has no workspace dependencies and every other package and service imports it (`packages/config/package.json:11-15` lists only pino, yaml, zod). It owns three things:

1. The **shape** of `config/config.yaml` and `config/expressions.yaml` (zod schemas in `packages/config/src/schema.ts`), including the nine-value `Emotion` enum that the bus event schemas also import (`schema.ts:4-8`).
2. The **loader**: locate the config directory, seed user-owned files from committed `*.example.*` templates, load `.env`, substitute `${VAR}` placeholders, validate, warn about unknown keys, and cache (`packages/config/src/index.ts`).
3. **Small runtime helpers** every service uses: `env`/`envOr`, the `urls.*` service-address functions, `createLogger`, and the personality read/write pair.

Design philosophy, as the example files' header comments state it (`config/config.example.yaml:1-4`, `.env.example:1-2`): behaviour lives in `config/config.yaml` (git-ignored, seeded from an example), secrets and per-machine values live in `.env`, and the two are joined by `${VAR}` / `${VAR:-default}` placeholders inside the YAML. Each backend that can be swapped for a mock or off variant is selected by an enum key whose example value is an env placeholder with a default, so operators flip a backend through `.env` without editing `config.yaml`; the mock variants are never the default (commit `51d5a9c`, comment `schema.ts:44`). The schema is lenient about unknown keys (warn, do not fail) and strict about enums and ranges. The shipped example config loads with no `.env` at all: every placeholder it uses either has a `:-default` or lands on a key whose schema default applies (CFG-ISO-005), while a value that is set but invalid, such as an unknown `avatar.driver`, still fails the load.

## Files, directory resolution and seeding

| File | Where | Role | Seeded from |
| --- | --- | --- | --- |
| `config.yaml` | `<configDir>/config.yaml` | all behaviour; read by `loadConfig` | `config.example.yaml` |
| `personality.md` | `<configDir>/personality.md` | co-host persona prompt; read/written by `loadPersonality` / `savePersonality` | `personality.example.md` |
| `expressions.yaml` | `<configDir>/expressions.yaml` | emotion to avatar-app name map; read by `loadExpressions` | `expressions.example.yaml` |
| `.env` | `COHOST_ENV_FILE`, else `.env` at the workspace root, else the parent of `configDir()` (CFG-ENV-010) | secrets and per-machine values; loaded by `loadDotEnv` | `.env.example` (copied by `install.sh`, not by code) |
| per-service data | `dataDir()`: `COHOST_DATA_DIR`, else `data` under the workspace root (CFG-DIR-006, CFG-DIR-007); each service writes only under `<dataDir()>/<service>/`, such as voice's fallback clip store and mouth's clip cache | generated files a service keeps across restarts; not edited by hand and ignored by version control (`data/` in `.gitignore`) | none: services create what they need |

Resolution (`index.ts`):

- `findWorkspaceRoot(start = cwd)` walks parent directories until one contains `pnpm-workspace.yaml`, returning `undefined` at the filesystem root (`index.ts:13-21`). It exists because `pnpm dev` runs each service with its package directory as cwd (comment `index.ts:9-12`).
- `configDir()` = `resolve(CONFIG_DIR ?? join(findWorkspaceRoot() ?? cwd, "config"))` (`index.ts:24-25`). Compose sets `CONFIG_DIR=/app/config` (`docker-compose.yml:20`) and bind-mounts `./config` there (`docker-compose.yml:22`).
- `dataDir()` = `resolve(COHOST_DATA_DIR ?? join(findWorkspaceRoot() ?? cwd, "data"))`, the same resolution as `configDir()` (CFG-DIR-006, CFG-DIR-007). Each service keeps its own files under `<dataDir()>/<service>/` and never reads another service's subdirectory: voice's fallback clip store is `voice/fallback-clips`, mouth's clip cache `mouth/fallback-clips`. Services exchange those files over HTTP (HLD tenet 1). In a container the workspace root is `/app`, so the default is the container's own `/app/data`, with no volume. The path is a per-machine value, so it is an environment variable with no YAML key (HLD tenet 7).
- `ensureFromExample(name, example)` returns the real path if it exists; otherwise copies the example, reports `[config] created <file> from <example>` through the config logger (CFG-LOG-001), and returns the path; if the example is also missing it throws `No <file> and no <example> to seed it from` (`index.ts:127-135`). It is called for all three user files (`index.ts:101,139,145`), so any service that starts first seeds them (README.md:82-84 says the same).
- `dotEnvPath()` is `COHOST_ENV_FILE` when set, else `.env` at the workspace root (`findWorkspaceRoot()`), else the parent of `configDir()` when there is no workspace root (CFG-ENV-010). A `CONFIG_DIR` elsewhere does not move where `.env` is looked for. In a container the workspace root is `/app`, so the path is `/app/.env`, which does not exist (it is `.dockerignore`d, `.dockerignore:6`) and does not matter because Compose injects `.env` through `env_file`. The missing-`.env` hint exempts containers through a probe (`/.dockerenv`) that `missingDotEnv` takes as a parameter, so its tests do not depend on where they run.

Personality and expressions: `loadPersonality()` and `loadExpressions()` read their file on every call (uncached by design: a service that wants a fresh copy asks again, as cortex does on `control reload_personality`) and `savePersonality(text)` replaces `personality.md` through `writeFileAtomic`, a temporary file in the same directory renamed over the target, which the settings editor's section writer shares (CFG-USR-013). `loadExpressions()` parses `expressions.yaml` with `ExpressionMapSchema`, treats an empty file as `{}`, and reports a schema failure as `Invalid <file>:` followed by `  path: message` lines, the shape `loadConfig` produces (CFG-USR-002). The consumers are cortex (loads at start, reloads on `control reload_personality`, `services/cortex/src/cortex.ts:36,104`), dashboard (GET/PUT personality, `services/dashboard/src/routes.ts:100,106`), memory reflection (`services/memory/src/reflect.ts:34,55`) and avatar (expressions, and `configDir()` as the VTube Studio token directory, `services/avatar/src/index.ts:30`).

## Loading pipeline

`loadConfig(force = false)` (`index.ts:98-119`):

1. Return the module-level cached `Config` unless `force` (`index.ts:57,99`). There is no file watching: config is read once per process; only personality has a reload path.
2. `loadDotEnv()` (`index.ts:100`), from `dotEnvPath()`. Parses `KEY=value` lines: trims each line, skips blank and `#` whole-line comments, requires `=` at index 1 or later, trims key and value, strips one layer of matching single or double quotes, and sets `process.env[key]` only when it is `undefined` (`index.ts:70-86`). Comments follow Compose's `env_file` rules (CFG-ENV-006): an unquoted value loses a whitespace-then-`#` suffix (`KEY= # note` is empty), a quoted value may be followed by a comment and keeps any `#` inside the quotes, and a `#` with no preceding whitespace (`a#b`) is part of the value.
3. `ensureFromExample("config.yaml", "config.example.yaml")` (`index.ts:101`).
4. `substituteEnv(text, env)` on the raw file text (`pipeline.ts`; `env` defaults to `process.env` and the settings editor passes the dashboard's): regex `\$\{([A-Z0-9_]+)(?::-([^}]*))?\}`; a set non-empty variable wins, otherwise the default, otherwise `""`. Substitution happens before YAML parsing, so a value like `port: ${OBS_PORT}` becomes `port:` (null) when unset.
5. `parseYaml` (a syntax error is reported as an issue like a schema failure), then `coerceEmptyNumbers` drops every `null`-valued key at any depth (`index.ts:43-55`; the name says numbers but the filter is type-blind; `null` array elements are kept) so schema defaults apply.
6. `ConfigSchema.safeParse`. Steps 4 to 6 are one function, `parseConfigText(text, env)`, which `loadConfig` and the settings editor both call, so they accept exactly the same files. On failure `loadConfig` throws `Invalid <file>:` followed by one `  path: message` line per issue, plus, when no `.env` exists at `dotEnvPath()` and the container probe says this is not a container (`missingDotEnv`), a hint to `cp .env.example .env`.
7. `unknownKeys(raw, parsed)` recursively lists dotted paths present in the raw object but missing from the parsed one; non-empty results are reported by one warning through the config logger that names only the ignored keys, and loading continues. The walk descends into array entries and reports them as `path[index].key`, so a typo inside a reflex shows up as `brain.salience.reflexes[0].cooldwn_ms` (CFG-LOAD-006).
8. Cache and return.

All diagnostics (the seeding notice and the unknown-key warning) go through a pino logger named `config`, created on first use; `setConfigLogger` replaces it so tests and hosts can capture or redirect them (CFG-LOG-001). Nothing in the package writes to `console`.

The consolidator on the cortex's model is the owner's decision. The capture model is a small, non-reasoning instruct model (`gemma3:4b`) that follows the capture JSON schema, so it can classify every chat line beside the cortex's model; the owner can swap it with `NOTES_MODEL`. The capture hook's `timeout_ms` is 20000 in the example because the first call after Ollama loads the model takes about 13 s on CPU and later calls 2 to 4 s. With the schema default (`kind: rules`) capture writes nothing and consolidation does arithmetic only.

Spoken fallback line keys: `voice.fallback.lines` is the list of lines the co-host says when a line fails to play (CFG-SCH-017), `mouth.fallback.min_interval_ms` the minimum time between two fallback lines on one output (CFG-SCH-018; owner decision, default 20000), and `brain.cortex.fallback_ack_chance` the base chance stated to the model after a fallback (CFG-SCH-019; owner decision, default 0.25). The example gains a key no earlier than its schema, because the example must load with no unknown-key warning (CFG-USR-003). `ModuleSchema` (`schema.ts:15-28`) is the shared hook config for the three region hooks (five once the memory notes hooks land): `kind` (blank to `rules`; `rules|llm|http`), `url` (default `""`), `timeout_ms` 8000, and `llm{provider?, model?}` where both blank values mean "inherit" and a provider without a model is rejected via `superRefine` (`schema.ts:24-27`). The override provider enum is `ollama|openai|anthropic|bedrock`: `mock` cannot be named on a hook, though a hook that inherits reaches the mock provider when `llm.provider` is `mock` (CFG-SCH-009). The whole object `.default({})`s. Hook behaviour itself belongs to region-hooks.

Required-ness is uneven: `brain.*` regions and `llm.openai/claude/bedrock` default to `{}`, but the nine top-level sections themselves, plus `vision.obs`, `chat.twitch`, `avatar.vtube_studio`, `avatar.vmc` and `ears.discord`, are required objects with no `.default({})`, and `avatar.vtube_studio.host` and `avatar.vmc.host` are required fields (CFG-SCH-001, CFG-SCH-010); the two avatar ports default to 8001 and 39539 (CFG-ISO-005). `vision.model` is required only while `vision.enabled` is true (a refinement on the `vision` object naming `vision.model`, CFG-SCH-025). A usable config therefore needs every section present (an empty `{}` suffices for `brain`, `voice`, `dashboard`), which the example provides.

Blank handling is uniform. An enum key wraps `z.enum` in `z.preprocess((v) => v || default, ...)` (`avatar.driver` blank means `null`; a non-empty unknown value still fails, CFG-ISO-005; `llm.claude.effort` blank means `low`), and a plain string key that has a default wraps `z.string().default(d)` in a preprocess that maps `""` to `undefined` (`cohost.timezone`, `llm.openai.base_url`, `vision.obs.host`, `vision.obs.source`, `voice.voice`, the two `plugin_*` keys and `ears.stt_model`, CFG-SCH-024), so an unset `${VAR}` that substitutes to nothing lands on the default instead of an empty string. Keys with no default and a non-empty requirement (`cohost.name`, `cohost.streamer`, `llm.model`, `llm.embed_model`) still turn a missing variable into a validation error, and secrets keep `""` as their default.

The dashboard's settings editor ([module-contract](../module-contract/module-contract-design.md), MOD-CFG-*) reads and writes `config.yaml` through `packages/config/src/editor.ts`, which this package exports: `sectionJsonSchema(path)` generates JSON Schema from the zod schema (objects, strings, numbers with their int and range checks, booleans, enums, arrays, defaults, descriptions; a small walker over zod's own type tree, so no JSON-Schema dependency is added); `SECRET_PATHS` marks the secret keys (`llm.openai.api_key`, `llm.claude.api_key`, `vision.obs.password`), which the schema output carries as `"x-secret": true` and `sectionSecrets` lists per section; `readSection(text, section, env)` returns each key's source, editability, effective value, raw text and variable, and the section's unknown keys (found by walking the file against the schema, so a file that no longer validates still reports them); `applySection(text, section, values, env)` writes edited values into the file text by splicing the edited scalar's or array's byte range (and inserting an absent key after its siblings, or an absent section at the end of the file), so every other byte, comment and alignment stays as the owner wrote it, then runs the result through `parseConfigText` and reads each edited key back to prove the text means what was asked; `writeFileAtomic` replaces the file. Configuration is still read once per process (HLD tenet 10).

## Service URLs and logger

`urls` is an object of functions, each calling `envOr` at call time so tests and late-loaded `.env` values take effect (`index.ts:166-176`). `urls.voice()` defaults to loopback built from `VOICE_PORT` and `urls.dashboard()` to `http://127.0.0.1:3000`, so host-run (`pnpm dev`) services work outside Compose, where `docker-compose.yml:18-19` sets `VOICE_URL` and `DASHBOARD_URL` to in-network hostnames. `createLogger(service)` returns `pino({ name, level: LOG_LEVEL || "info" })` and `Logger` is its type (`index.ts:179-182`); packages' tests cast fake loggers to `never`.

## Tests

`packages/config/test/config.test.ts` carries an `@spec` annotation on every test and restores `CONFIG_DIR`, `COHOST_ENV_FILE` and the environment after each one; it points `.env` at its sandbox through `COHOST_ENV_FILE` and captures loader warnings through `setConfigLogger`. `config-c3.test.ts` covers blank-to-default strings, `vision.model`, `ModuleConfig`, `.env` resolution, logger routing, `loadExpressions` errors, atomic writes and `.env.example`; `editor.test.ts` covers the schema export, secrets, section reads and in-place writes. Like the example-file specs, the shipped-example tests read `config/config.example.yaml`, `.env.example` and `config/expressions.example.yaml` from the repository root on purpose: they are the files the specs describe.

Not covered by any test: lower-case placeholder names (CFG-ENV-003), the `llm` defaults and blank `llm.provider` (CFG-SCH-002), blank-to-default for every backend key (CFG-ISO-002), the `Emotion` list and `ExpressionMapSchema` itself (CFG-SCH-007), the remaining section defaults, nested required objects (CFG-SCH-008, CFG-SCH-010), `createLogger` (CFG-URL-004) and `urls.database/ollama/tts/stt`. Several annotated tests cover only part of their spec line; the arrow doc lists them.

## Decisions & Alternatives

| Config format | YAML file with `${VAR}` / `${VAR:-default}` text substitution before parsing | env vars only; JSON; schema-aware per-key env overrides | Secrets and per-machine values stay in `.env`, everything behavioural in YAML: header comments `config/config.example.yaml:1-4` and `.env.example:1-2`. Substitution is a plain regex over the file text before YAML parsing (`index.ts:34-40`), so it works the same for every key with no schema knowledge, and the YAML itself shows which values come from the environment. Per-key env overrides would need a naming scheme mapped onto the schema tree and would hide the env dependency from a reader of `config.yaml`. |
| `:-default` form | Literal default kept in `config.yaml`, overridable from `.env` | only `${VAR}` | Doc comment `index.ts:27-32`: "lets config.yaml hold the normal value literally while still allowing a per-machine override"; used by every isolation preset (`config.example.yaml:20,40,54,116,117,135,155`; commit `51d5a9c`). |
| Blank enum values | `z.preprocess((v) => v \|\| default, z.enum(...))` | `.default()` only; `.catch()` | The shipped example quotes its enum placeholders (`source: "${CHAT_SOURCE:-twitch}"`), and a quoted placeholder whose variable is unset or empty (with no `:-` default, or with an empty one) substitutes to `""`, not to null, so the null-dropping step does not remove it and `.default()` would not apply.
