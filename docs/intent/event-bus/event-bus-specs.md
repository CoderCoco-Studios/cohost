# event-bus specs

Design: [event-bus-design.md](event-bus-design.md). Prefix `BUS`. Status at git `686cc8f`: `[x]` observed working in code, `[ ]` intended but broken or partial. Test paths are relative to the repo root.

## Publish and envelope

- [x] **BUS-STREAM-001**: When a service calls `Bus.publish(type, data)` with any event type other than `service.heartbeat`, the system shall `XADD` one entry to the Redis stream `cohost:events` with fields `type`, `ts` (publisher clock, epoch ms as a string), `source` (the `Bus` constructor's source name) and `data` (JSON of the zod-parsed payload), and shall return the Redis stream id. <!-- test: packages/bus/test/bus.test.ts:21 --> <!-- openspec: bus § Single stream with event envelope -->
- [x] **BUS-STREAM-002**: When `Bus.publish` writes to `cohost:events`, the system shall trim the stream approximately (`MAXLEN ~`) to 20000 entries. <!-- openspec: bus § Single stream with event envelope -->
- [x] **BUS-STREAM-003**: When `Bus.publish(type, data)` is called, the system shall parse `data` with the schema registered in `EventPayloads` for `type` before writing, store the parsed value (schema defaults applied), and reject the call without writing if the payload is invalid. <!-- test: packages/bus/test/bus.test.ts:45 --> <!-- openspec: bus § Typed payload validation on publish -->
- [x] **BUS-STREAM-004**: If `Bus.publish` is called with the type `service.heartbeat`, then the system shall throw an error that names `publishHealth()` and shall write nothing to any stream. <!-- test: packages/bus/test/bus.test.ts:136 --> <!-- openspec: bus § Health stream -->
- [x] **BUS-STREAM-005**: When a `Bus` is constructed without an explicit URL, the system shall connect its publish connection immediately to the URL from `urls.redis()` (the `REDIS_URL` environment variable, default `redis://127.0.0.1:6379`), and each `Bus` instance shall have a consumer name of the form `<HOSTNAME or local>-<8 hex characters>` that does not change for the life of the instance.
- [x] **BUS-STREAM-006**: When a `Bus` event is read from either stream, the system shall rebuild it as `{ id, type, ts, source, data }` where `id` is the Redis stream id, `ts` defaults to 0 and `source` defaults to `?` when the fields are missing, and `data` is the payload re-parsed with the type's schema (defaults applied).

## Event catalogue and schemas

- [x] **BUS-EVT-001**: The system shall define exactly 19 event types in `EventPayloads` (`chat.message`, `vision.summary`, `speech.heard`, `brain.say`, `brain.status`, `attention.focus`, `affect.state`, `memory.recall.request`, `memory.recall.reply`, `memory.viewer`, `voice.utterance`, `voice.playing`, `voice.done`, `avatar.state`, `control`, `inject.request`, `inject.result`, `service.lifecycle`, `service.heartbeat`) and shall export their names as `EVENT_TYPES`. <!-- test: packages/bus/test/bus.test.ts:128 --> <!-- openspec: bus § Known event catalogue -->
- [x] **BUS-EVT-002**: When a `chat.message` is validated, the system shall require `platform` to be `twitch`, `youtube` or `discord`, and shall default `isMod`, `isSub` and `mentionsCohost` to `false` when absent. <!-- openspec: bus § Known event catalogue, § Typed payload validation on publish -->
- [x] **BUS-EVT-003**: When an `affect.state` is validated, the system shall reject `valence` outside -1..1 and `arousal` outside 0..1. <!-- test: packages/bus/test/bus.test.ts:12 --> <!-- openspec: bus § Typed payload validation on publish -->
- [x] **BUS-EVT-004**: When a `control` event is validated, the system shall accept `cmd` values `mute`, `unmute`, `say`, `forget_context`, `reload_personality`, `pause` and `resume`, shall accept an optional string `target` naming the addressed service, and shall treat an absent `target` as addressed to all services. <!-- test: packages/bus/test/bus.test.ts:269 --> <!-- openspec: bus § Known event catalogue (add-service-control); add-test-injection delta lists only five commands, see design Open Questions 8 -->
- [x] **BUS-EVT-005**: When a `chat.message`, `vision.summary`, `speech.heard`, `brain.say` or `attention.focus` is validated, the system shall accept optional boolean `injected` and `remember` fields with no default, shall keep them when present, shall leave them absent when the publisher omitted them, and shall reject non-boolean values. <!-- test: packages/bus/test/bus.test.ts:300 --> <!-- openspec: bus § Injection flags on perception events, § Injection flags on brain output -->
- [x] **BUS-EVT-006**: When an `inject.request` is validated, the system shall require `id`, `target` (`eyes`, `ears` or `chat`), `kind` (`image`, `audio` or `text`) and a boolean `remember` (no default), shall accept optional `url`, `text` and `meta` (`user`, `platform`, `isMod`, `isSub`), and shall carry media only by `url` reference (no binary field exists). <!-- test: packages/bus/test/bus.test.ts:323 --> <!-- openspec: bus § Injection request and result events -->
- [x] **BUS-EVT-007**: When an `inject.result` is validated, the system shall require `id` and boolean `ok` and shall accept an optional string `detail`. <!-- test: packages/bus/test/bus.test.ts:323 --> <!-- openspec: bus § Injection request and result events -->
- [x] **BUS-EVT-008**: When a `service.lifecycle` event is validated, the system shall require string `service` and `by`, `action` of `start`, `stop` or `restart`, and boolean `ok`, and shall accept an optional string `detail`. <!-- test: packages/bus/test/bus.test.ts:260 --> <!-- openspec: bus § Known event catalogue (add-service-control) -->
- [x] **BUS-EVT-009**: When a `service.heartbeat` is validated, the system shall require `service`, `instance`, integer `pid`, `version`, `startedAt`, `state` (`starting`, `ready`, `degraded` or `stopping`), `deps` (a record of `ok`, `down` or `n/a`), string `mode` and positive integer `intervalMs`, and shall accept an optional `detail`. Heartbeat meaning is owned by control-plane. <!-- test: packages/bus/test/bus.test.ts:128 --> <!-- openspec: bus § Known event catalogue (add-service-health) -->
- [x] **BUS-EVT-010**: When the brain-region events are validated, the system shall enforce these shapes: `attention.focus` (`reason`, `score`, optional `focus` with `kind` of `chat`, `speech` or `vision`), `memory.recall.request` (`id`, `query`, optional positive-integer `k`), `memory.recall.reply` (`id` and a possibly empty `memories` array whose `kind` is `chat`, `speech`, `self` or `note`) and `memory.viewer` (`user`, `isNew`, integer `msgCount`, `notes` defaulting to the empty string). <!-- test: packages/bus/test/bus.test.ts:12 -->
- [ ] **BUS-EVT-011**: When an `inject.request` is validated, the system shall require the fields its `kind` needs (`url` for `image` and `audio`, `text` for `text`). Gap: the schema accepts any request with neither `url` nor `text` (`packages/bus/src/events.ts:171-186`); completeness is checked only by each service's `inject.ts`.

## Consumer-group subscription

- [x] **BUS-SUB-001**: When `Bus.subscribe` is called, the system shall create the consumer group on `cohost:events` with `MKSTREAM` at `$` if `fromNow` is true and at `0` otherwise, shall ignore a `BUSYGROUP` error, and shall rethrow any other group-creation error. <!-- test: packages/bus/test/bus.test.ts:21 --> <!-- openspec: bus § Consumer-group subscription -->
- [x] **BUS-SUB-002**: While a consumer group already exists, `Bus.subscribe` shall resume from the group's stored position and shall ignore the `fromNow` option.
- [x] **BUS-SUB-003**: While a subscription is running, the system shall first read the pending entries of its own consumer name (cursor `0`, batch of 50) and then switch to new entries (cursor `>`), blocking for `blockMs` (default 5000) per read. <!-- openspec: bus § Consumer-group subscription -->
- [x] **BUS-SUB-004**: When `types` is given to `Bus.subscribe` and an entry of another type is read, the system shall not call the handler and shall acknowledge the entry. <!-- test: packages/bus/test/bus.test.ts:21 --> <!-- openspec: bus § Consumer-group subscription -->
- [x] **BUS-SUB-005**: When a subscription's handler throws or rejects, the system shall log `handler failed` at error level, shall still acknowledge the entry, and shall continue with the next entry. <!-- test: packages/bus/test/bus.test.ts:52 --> <!-- openspec: bus § Consumer-group subscription -->
- [x] **BUS-SUB-006**: While a subscription is running, the system shall deliver entries to its handler one at a time in stream order, awaiting each handler before reading the next entry.
- [x] **BUS-SUB-007**: If a stream entry has an unknown `type`, a `data` field that is not JSON, or a payload that fails its schema, then the system shall not deliver it to any handler and (in `subscribe`) shall acknowledge it. <!-- test: packages/bus/test/bus.test.ts:79 (covers the recent() path only) --> <!-- openspec: bus § Malformed entries are dropped -->
- [ ] **BUS-SUB-008**: When a service process restarts after a crash that left entries delivered but unacknowledged in its consumer group, the system shall redeliver those entries to the restarted process. Gap: the consumer name carries a random per-instance suffix (`packages/bus/src/index.ts:40`), so the restarted process cannot see the dead consumer's pending list, and nothing claims it (`index.ts:135-148`). <!-- openspec: bus § Consumer-group subscription (describes the drain, not the cross-restart recovery) -->
- [x] **BUS-SUB-009**: If a blocking read in `subscribe` fails for any reason other than `stop()`, then the system shall reject the `subscribe` promise rather than retry. <!-- no test -->

## Live tail and backfill

- [x] **BUS-TAIL-001**: When `Bus.tail(handler, fromId)` is called, the system shall read `cohost:events` without a consumer group, starting at `fromId` (default `$`), call `handler` for each decodable event, and neither acknowledge nor replay entries. <!-- test: packages/bus/test/bus.test.ts:96 --> <!-- openspec: bus § Live tail and recent backfill -->
- [x] **BUS-TAIL-002**: When `Bus.recent(count)` is called, the system shall return up to `count` (default 100) of the newest decodable events from `cohost:events` in chronological order, oldest first, skipping entries that cannot be decoded. <!-- test: packages/bus/test/bus.test.ts:79 --> <!-- openspec: bus § Live tail and recent backfill -->

## Health stream and group reset

- [x] **BUS-HEALTH-001**: When a service calls `Bus.publishHealth(data)`, the system shall validate `data` against the `service.heartbeat` schema, `XADD` it to `cohost:health` (fields `type`, `ts`, `source`, `data`) trimmed approximately to 1000 entries, return the stream id, and write nothing to `cohost:events`. <!-- test: packages/bus/test/bus.test.ts:145 --> <!-- openspec: bus § Health stream -->
- [x] **BUS-HEALTH-002**: If `Bus.publishHealth` is given an invalid heartbeat (for example `state: "dead"`), then the system shall reject the call and write nothing. <!-- test: packages/bus/test/bus.test.ts:145 --> <!-- openspec: bus § Health stream -->
- [x] **BUS-HEALTH-003**: When `Bus.tailHealth(handler, fromId)` is called, the system shall read `cohost:health` without a consumer group, starting at `fromId` (default `$`), and call `handler` only for entries that decode as `service.heartbeat`. <!-- test: packages/bus/test/bus.test.ts:158 --> <!-- openspec: bus § Health stream -->
- [x] **BUS-HEALTH-004**: When `Bus.recentHealth(count)` is called, the system shall return up to `count` (default 100) of the newest decodable heartbeats from `cohost:health`, oldest first. <!-- test: packages/bus/test/bus.test.ts:158 --> <!-- openspec: bus § Health stream -->
- [x] **BUS-GROUP-001**: When `Bus.resetGroup(group)` is called, the system shall move the group on `cohost:events` to the newest entry (`XGROUP SETID ... $`); if the group does not exist, it shall create the group (and stream) at `$`; it shall ignore `BUSYGROUP` on that create and rethrow any other error. <!-- test: packages/bus/test/bus.test.ts:277 -->

## Shutdown

- [x] **BUS-STOP-001**: When `Bus.stop()` is called, the system shall mark the instance stopped, disconnect every subscribe, tail and tailHealth connection and the publish connection, and cause pending `subscribe`, `tail` and `tailHealth` promises to resolve without surfacing the resulting read error. <!-- test: packages/bus/test/bus.test.ts:112 --> <!-- openspec: bus § Shutdown -->
- [x] **BUS-STOP-002**: When a process that has called `onShutdown(fn)` receives SIGINT or SIGTERM, the system shall run every function registered with `beforeShutdown` concurrently (waiting at most 2000 ms and ignoring their failures), then run `fn`, then exit the process with code 0. <!-- test: packages/bus/test/bus.test.ts:241 --> <!-- openspec: bus § Shutdown -->
- [x] **BUS-STOP-003**: When one `onShutdown` registration receives a second signal after it has started shutting down, the system shall ignore it (each registration runs at most once).
- [x] **BUS-STOP-004**: If the callback passed to `onShutdown` throws or rejects, then the system shall still exit the process with code 0. <!-- no test -->
- [ ] **BUS-STOP-005**: When a service has registered more than one `onShutdown` callback, the system shall run all of them to completion before the process exits. Gap: each registration installs independent signal handlers and each exits the process after its own callback (`packages/bus/src/index.ts:230-245`), as in `services/eyes/src/index.ts:84,87`; inferred from the shared-helper design, not stated in any spec.

## Test double (packages/testing)

- [x] **BUS-TEST-001**: When `FakeBus.publish(type, data)` is called, the test double shall throw for `service.heartbeat`, otherwise validate `data` with the real `EventPayloads` schema, throw `publish <type> failed` if the `fail` predicate returns true for the type, and otherwise record the parsed payload in `published` and return the running count as the id. <!-- test: services/cortex/test/cortex.region.test.ts (indirect; packages/testing has no tests of its own) -->
- [x] **BUS-TEST-002**: When `FakeBus.publishHealth(data)` is called, the test double shall validate `data` as a `service.heartbeat`, throw `publishHealth failed` while `failHealth` is true, and otherwise append the parsed heartbeat to `health`. <!-- test: services/chat/test/health.test.ts (indirect) -->
- [x] **BUS-TEST-003**: When `FakeBus.recentHealth(count)` is called, the test double shall return the last `count` recorded heartbeats as `BusEvent` objects. <!-- no direct test -->
- [x] **BUS-TEST-004**: The `FakeBus` test double shall expose `of(type)` (payloads of one type), `types()` (published type sequence) and `clear()` (empties both `published` and `health`), and shall implement only the publish and health halves of `Bus` (no `subscribe`, `tail`, `tailHealth`, `recent`, `resetGroup` or `stop`).
- [x] **BUS-TEST-005**: When `testConfig(over)` is called, the test helper shall return a `ConfigSchema`-parsed `Config` built by deep-merging `over` onto a minimal valid base whose salience `cooldown_ms` and `idle_chatter_ms` are 0.
- [x] **BUS-TEST-006**: When `event(type, data, source)` is called, the test helper shall return a `BusEvent` with the payload parsed by the real schema (defaults applied), `ts` of the current time, `source` defaulting to `test`, and a random uuid as `id`.
- [x] **BUS-TEST-007**: When `runHeartbeat(spec, drive)` is called, the test helper shall start a heartbeat against a `FakeBus` with a 60-second interval, run `drive` (default: `ready()`), wait 10 ms, call `stop()`, and return every heartbeat published, in order.
- [x] **BUS-TEST-008**: If the condition passed to `waitFor` is still false after `ms` (default 2000) milliseconds, then the test helper shall throw `timed out waiting for <what>`; it shall poll every 2 ms until then.
