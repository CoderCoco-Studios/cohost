## Environment handling

- [x] **CFG-ENV-001**: When `loadConfig` reads `config.yaml`, the system shall replace every `${VAR}` placeholder in the raw YAML text with `process.env.VAR`, and with the empty string when `VAR` is unset or empty. <!-- openspec: config § Environment substitution --> <!-- test: packages/config/test/config.test.ts:10 --> <!-- test: packages/config/test/config.test.ts:119 -->
- [x] **CFG-ENV-002**: When a placeholder has the form `${VAR:-default}`, `substituteEnv` shall yield `default` when `VAR` is unset or empty and the value of `VAR` otherwise. <!-- openspec: config § Environment substitution --> <!-- test: packages/config/test/config.test.ts:10 -->
- [x] **CFG-ENV-003**: The system shall substitute only placeholders whose variable name matches `[A-Z0-9_]+`; placeholders with lower-case names shall be left in the text unchanged.
- [x] **CFG-ENV-004**: When `loadConfig` runs, the system shall first load `.env` from the workspace root (CFG-ENV-010), setting only variables that are not already defined in `process.env`. <!-- openspec: config § Dotenv loading --> <!-- test: packages/config/test/config.test.ts:90 --> <!-- test: packages/config/test/config.test.ts:160 -->
- [x] **CFG-ENV-005**: When `loadDotEnv` parses a file, it shall trim each line, skip blank lines and lines that start with `#`, split each remaining line at its first `=` (any later `=` stays in the value), trim the key and the value, strip one pair of matching surrounding double or single quotes from the value, skip lines with no `=` or an empty key, and do nothing when the file does not exist. <!-- openspec: config § Dotenv loading --> <!-- test: packages/config/test/config.test.ts:160 -->
- [x] **CFG-ENV-006**: When an unquoted `.env` value is followed by whitespace and a `#` comment (the form `.env.example` uses on its API-key lines), `loadDotEnv` shall strip that suffix, matching Compose's `env_file` parsing, so the variable is empty rather than set to the comment text; a `#` inside a quoted value is kept. <!-- test: packages/config/test/config.test.ts:355 -->
- [x] **CFG-ENV-007**: When `env(name)` is called and the variable is unset or empty, the system shall throw an error naming the variable and pointing at `.env`; `envOr(name, fallback)` shall return the fallback when the variable is unset or empty. <!-- openspec: config § Env helpers and URLs --> <!-- test: packages/config/test/config.test.ts:183 -->
- [x] **CFG-ENV-008**: The system shall read service-control settings (`CONTROL_ENABLED`, `CONTROL_TOKEN`, `CONTROL_BIND`, `CONTROL_ADVANCED`) and `HEARTBEAT_INTERVAL_MS` only from `process.env` in their owning packages; `ConfigSchema` shall have no keys for them. <!-- test: packages/config/test/config.test.ts:388 -->
- [x] **CFG-ENV-009**: The system shall read `VIEWERS_TOKEN` only from `process.env` in the dashboard; `ConfigSchema` shall have no key for it. <!-- test: services/voice/test/kokoro-request.test.ts -->
- [x] **CFG-ENV-010**: The `.env` file shall be `.env` at the workspace root (the nearest ancestor of the current working directory containing `pnpm-workspace.yaml`), and the parent of the config directory when there is no workspace root, whatever `CONFIG_DIR` says, unless `COHOST_ENV_FILE` names a file, which then wins; the container test that exempts the missing-`.env` hint shall be a function the caller can replace, so the hint's tests do not depend on the machine they run on. <!-- test: packages/config/test/config-c3.test.ts -->

## Loading and validation pipeline

- [x] **CFG-LOAD-001**: When `loadConfig()` is called, the system shall seed `config.yaml` from `config.example.yaml` if missing, substitute environment placeholders, parse the YAML, validate it with `ConfigSchema` and return the typed `Config`, and while a result is cached it shall return the same object until called with `force = true`. <!-- openspec: config § Unknown key warning and caching --> <!-- test: packages/config/test/config.test.ts:119 -->
- [x] **CFG-LOAD-002**: When a YAML value is null after substitution (for example `port: ${OBS_PORT}` with the variable unset), the system shall drop that key at any nesting depth so the schema default applies instead of a validation error. <!-- openspec: config § Schema validation and defaults --> <!-- test: packages/config/test/config.test.ts:119 -->
- [x] **CFG-LOAD-003**: If `config.yaml` fails schema validation, then `loadConfig` shall throw an error beginning `Invalid <file>:` that lists every failing key as `path: message`. <!-- openspec: config § Schema validation and defaults --> <!-- test: packages/config/test/config.test.ts:134 -->
- [x] **CFG-LOAD-004**: If `config.yaml` fails validation and no `.env` exists at the workspace root (CFG-ENV-010) and the process is not inside a container (`/.dockerenv` absent), then the thrown error shall also tell the operator to run `cp .env.example .env`; when a `.env` is present the error shall carry no `.env` hint. <!-- test: packages/config/test/config.test.ts:140 --> <!-- test: packages/config/test/config.test.ts:146 -->
- [x] **CFG-LOAD-005**: When `config.yaml` contains keys the schema does not define, `loadConfig` shall load successfully and emit exactly one warning through the config logger (CFG-LOG-001) listing the dotted paths of the ignored keys. <!-- openspec: config § Unknown key warning and caching --> <!-- test: packages/config/test/config.test.ts:52 --> <!-- test: packages/config/test/config.test.ts:152 -->
- [x] **CFG-LOAD-006**: When a key nested inside an array entry (for example a typo inside a `brain.salience.reflexes` item) is not defined by the schema, `loadConfig` shall include it in the unknown-keys warning (as `path[index].key`), and the warning text shall name the ignored keys. <!-- test: packages/config/test/config.test.ts:371 --> <!-- test: packages/config/test/config.test.ts:378 -->
