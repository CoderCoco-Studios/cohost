# deployment specs

Prefix `DEPLOY`. Design: [deployment-design.md](deployment-design.md). No spec below carries an OpenSpec reference.

Verified against the files at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`.

The docs site's structure, publishing boundary, build checks and the README's shape are specified in the [docs-site](../docs-site/docs-site-specs.md) segment; the specs below that name a site page say what that page must tell the operator about this segment's files.

Markers: `[x]` implemented; `[ ]` intended but not yet implemented (gap); `[D]` deferred.

Annotations: `@spec DEPLOY-…` comments sit in the deployment files themselves. In `docker-compose.yml` and `docker-compose.gpu.yml` they are trailing comments on mapping keys, and in `Dockerfile` and `scripts/install.sh` they are appended to existing comment lines; everywhere else they are full comment lines. `<!-- impl: path -->` points at an implementation in a file that carries no annotation (a file owned elsewhere, or plain data such as `.gitignore`). `<!-- test: path -->` names the test file that carries the matching `@spec` annotation.

## Compose topology

- [x] **DEPLOY-COMPOSE-001**: The base `docker-compose.yml` shall define the infrastructure services `redis`, `postgres`, `ollama`, `tts`, `stt`, the engine servers `tts-pocket`, `stt-nemotron` and `stt-kyutai`, the one-shot `models`, the one-shot `consolidate`, the one-shot `reembed`, and one application service per directory under `services/` except `dashboard` (`chat`, `salience`, `affect`, `memory`, `cortex`, `tools`, `voice`, `avatar`, `eyes`, `ears`, `mouth`, `connector-discord`), and no `dashboard` service, because the dashboard runs on the host. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-002**: Each application service shall be built from the single root `Dockerfile` with the build argument `SERVICE` set to its directory name, and shall inherit the shared settings of the `x-ts-service` anchors: `restart: unless-stopped`, the `host.docker.internal:host-gateway` extra host, a dependency on `redis` being healthy and the container healthcheck (DEPLOY-HC-001), and shall mount its own unit's projection directory read-only at `/app/config` (DEPLOY-COMPOSE-025); every application service except `tools` also inherits `env_file: .env`, the `./data/logs:/app/data/logs` bind mount (DEPLOY-COMPOSE-029) and the `x-ts-service` environment block, the in-network URLs `REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `CONFIG_DIR=/app/config` (no dashboard address: injected uploads reach eyes and ears over Redis), which `tools` does not receive (DEPLOY-COMPOSE-026). The optional engine servers of DEPLOY-ENG-001..003 are not application services: they are built from their own sources and do not use the `x-ts-service` anchor. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-003**: While a variable is set in a service's `environment` block (`REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `CONFIG_DIR`, `COHOST_DATA_DIR`), the Compose stack shall use that value over the same name in `.env`, so those addresses cannot be changed through `.env` for containerised services. Each service's `environment` block carries the literals that service is given: every application service except `tools` carries all eight, `COHOST_DATA_DIR` as `/app/data` so each program's log file lands in the `./data/logs` mount (DEPLOY-COMPOSE-029); of these eight `tools` carries only `REDIS_URL` and `CONFIG_DIR`, and its full block, `COHOST_ISOLATION` included, is DEPLOY-COMPOSE-026's. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-004**: The `eyes` service shall belong only to the `eyes` profile, the `ears` service only to the `ears` profile, the `mouth` service only to the `mouth` profile, the `connector-discord` service only to the `discord` profile, the `tts-pocket` service only to the `pocket` profile, the `stt-nemotron` service only to the `nemotron` profile, the `stt-kyutai` service only to the `kyutai` profile and the `consolidate` and `reembed` services only to the `maintenance` profile; every other service, including `models`, `tts`, `stt` and `tools`, has no profile, so a plain `docker compose up -d` starts everything except `eyes`, `ears`, `mouth`, `connector-discord`, `tts-pocket`, `stt-nemotron`, `stt-kyutai`, `consolidate` and `reembed`. <!-- test: packages/config/test/compose-consolidate.test.ts -->
- [x] **DEPLOY-COMPOSE-005**: Where a service has dependencies beyond redis, Compose shall order startup as follows: `memory` waits for `redis` and `postgres` healthy and `ollama` started; `cortex` for `redis` healthy and `ollama` started; `voice` for `redis` healthy and `tts` started; `ears` for `redis` healthy and `stt` started; the engine servers each of them also waits for are those of DEPLOY-ENG-013.
- [x] **DEPLOY-COMPOSE-006**: The infrastructure ports `redis` 6379, `postgres` 5432, `ollama` 11434, `tts` 8880 and `stt` 8000, the `voice` port 8700 and the engine servers' ports `tts-pocket` 8881, `stt-nemotron` 8081 and `stt-kyutai` 8082 (DEPLOY-ENG-008) shall be published on `127.0.0.1` only, and no Compose service shall publish a port on any other interface. <!-- test: packages/config/test/compose-standalone.test.ts -->
