# dashboard specs

Prefix `DASH`. Design: [dashboard-design.md](dashboard-design.md). Verified against the code at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`. Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred. `<!-- test: -->` points at the `test(` line that exercises the spec; `<!-- openspec: -->` names the retired OpenSpec requirement the line descends from (the LID line wins where they differ). DASH-CTRL-006 is retired; the number is not reused.

## HTTP routes

- [x] **DASH-HTTP-001**: When `GET /` is requested, the dashboard shall respond 200 `text/html` with every occurrence of `__COHOST_NAME__` in `public/index.html` replaced by `cohost.name`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:39 -->
- [x] **DASH-HTTP-002**: When `/health` is requested with any method that no earlier route handles, the dashboard shall respond 200 `ok`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:123 -->
- [x] **DASH-HTTP-003**: If a request matches no route, then the dashboard shall respond 404 `not found`. <!-- openspec: dashboard § Page and health --> <!-- test: services/dashboard/test/routes.test.ts:123 -->
- [x] **DASH-HTTP-004**: If an HTTP handler throws (for example invalid JSON on `POST /control` or `POST /sink`, a payload the event schema rejects, a request URL that does not parse, or a failed upstream audio fetch), then the dashboard shall log `request failed` and respond 500 with the error text without exiting. <!-- openspec: dashboard § Error handling --> The audio proxy shall read the whole upstream body before it chooses the status and writes headers, so a failed body read is still answered 500; an error response is never attempted once headers have been sent, and no handler failure becomes an unhandled rejection. <!-- test: services/dashboard/test/routes.test.ts:110, services/dashboard/test/routes.test.ts:123 -->
- [x] **DASH-HTTP-005**: When `GET /personality` is requested, the dashboard shall respond with the personality file text as `text/plain`. <!-- openspec: dashboard § Personality editing --> <!-- test: services/dashboard/test/routes.test.ts:57 -->
- [x] **DASH-HTTP-006**: When `PUT /personality` is requested, the dashboard shall save the request body as the personality file, publish `control {cmd: "reload_personality"}` and respond 204. <!-- openspec: dashboard § Personality editing --> <!-- test: services/dashboard/test/routes.test.ts:57 -->
- [x] **DASH-HTTP-007**: When `POST /control` carries `{cmd, text?, target?}`, the dashboard shall publish a `control` event with those fields and respond 204; a `cmd` outside the event schema (`mute`, `unmute`, `say`, `forget_context`, `reload_personality`, `pause`, `resume`) shall be answered 500 and nothing published. <!-- openspec: dashboard § Control commands --> <!-- test: services/dashboard/test/routes.test.ts:67, services/dashboard/test/routes.test.ts:123 -->
- [x] **DASH-HTTP-008**: When `POST /control` carries `{cmd: "pause" | "resume", target}`, the dashboard shall publish the targeted `control` event; the web page offers no control for pause or resume. <!-- openspec: dashboard § Control commands --> <!-- test: services/dashboard/test/control.test.ts:126 -->
- [x] **DASH-HTTP-009**: The dashboard shall listen with its full surface on the `PORT` environment variable when set, else on `DASHBOARD_PORT` when set, else on `dashboard.port` (default 3000), and shall publish its `ready` heartbeat only once both the full-surface listener and the LAN listener (DASH-HOST-001) are listening; the full-surface bind address is DASH-CTRL-001 and DASH-CTRL-003. <!-- openspec: dashboard § (add-service-health) Heartbeat --> <!-- test: services/dashboard/test/host.test.ts:47, services/dashboard/test/host.test.ts:238 -->
- [x] **DASH-HTTP-010**: When the dashboard shuts down gracefully, it shall stop the upload sweeper, the feed's staleness tick and the stack probe, close the WebSocket server and both HTTP listeners, and stop the bus, without stopping or changing any Compose container and without waiting for or killing a `docker compose` command a running stack action started. <!-- test: services/dashboard/test/host.test.ts:244 -->
- [x] **DASH-HTTP-011**: If the body of `POST /control`, `PUT /personality`, `POST /sink` or `POST /services/:id/(start|stop|restart)` exceeds 64 KiB, then the dashboard shall respond 413 and shall publish, save and run nothing. <!-- test: services/dashboard/test/control.test.ts:205, services/dashboard/test/routes.test.ts:95 -->
- [x] **DASH-HTTP-012**: If the feed's health seed fails because Redis is unreachable, then the dashboard shall log a warning, keep serving every route, and retry the seed with the bus backoff (250 ms, doubling per consecutive failure, capped at 30 s) until it succeeds, without exiting; if a client's connect replay fails, it shall log the error and keep that socket open without the replay, so the client still receives the `services` and `stack` snapshots and every later push. <!-- test: services/dashboard/test/feed.test.ts:199, services/dashboard/test/feed.test.ts:209, services/dashboard/test/feed.test.ts:224, services/dashboard/test/feed.test.ts:251 -->
- [x] **DASH-HTTP-013**: If the service id in `POST /services/:id/(start|stop|restart)` contains a malformed `%` escape, then the dashboard shall respond 404 as for an unknown service. <!-- test: services/dashboard/test/control.test.ts:216 -->

## Audio proxy and sink

- [x] **DASH-SINK-001**: When `GET /audio/<path>` is requested, the dashboard shall fetch `<urls.voice()>/audio/<path>` and return the upstream status and content-type (default `audio/wav`) with `cache-control: no-store`. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:47 -->
- [x] **DASH-SINK-002**: When `POST /sink` carries `{event: "playing", id}`, the dashboard shall publish `voice.playing {id, sink: "dashboard"}`; when it carries `{event: "done", id}`, it shall publish `voice.done {id, sink: "dashboard"}`; in both cases it shall respond 204. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:75 -->
- [x] **DASH-SINK-003**: If `POST /sink` carries an `event` other than `playing` or `done`, then the dashboard shall respond 400 and publish nothing. <!-- openspec: dashboard § Audio sink --> <!-- test: services/dashboard/test/routes.test.ts:86 -->
- [x] **DASH-SINK-004**: When `VOICE_URL` is not set, the dashboard shall proxy audio from voice's loopback address `http://127.0.0.1:<VOICE_PORT>` (port default 8700), as resolved by `urls.voice()`. <!-- openspec: dashboard § Audio sink --> <!-- test: packages/config/test/config.test.ts:207 -->

## WebSocket feed

- [x] **DASH-FEED-001**: When a client connects to `/ws`, the dashboard shall first send a `{type: "services", services}` snapshot, then the `{type: "stack"}` snapshot (DASH-FEED-008), and then the 60 most recent bus events, oldest first, each marked `replay: true`, skipping any `service.heartbeat` and the viewer-notes events of DASH-FEED-007. <!-- openspec: dashboard § Live event feed --> A live event that arrives while the replay is being read shall reach that client once, after the replay (not at all if the replay already contained it), and shall carry no `replay` marker; clients that are not replaying receive it immediately. <!-- test: services/dashboard/test/feed.test.ts:68, services/dashboard/test/feed.test.ts:113, services/dashboard/test/feed.test.ts:131, services/dashboard/test/feed.test.ts:162, services/dashboard/test/feed.test.ts:177, services/dashboard/test/feed.test.ts:275, services/dashboard/test/feed.test.ts:307 -->
- [x] **DASH-FEED-002**: While the dashboard is running, it shall forward every new event on the main bus stream, unfiltered by type except for `service.heartbeat` and the viewer-notes events of DASH-FEED-007, as JSON to every connected client whose socket is OPEN. <!-- openspec: dashboard § Live event feed --> <!-- test: services/dashboard/test/feed.test.ts:113, services/dashboard/test/feed.test.ts:131, services/dashboard/test/feed.test.ts:307 -->
- [x] **DASH-FEED-003**: When the dashboard starts its feed, it shall seed the health tracker from the 500 most recent heartbeats and follow the health stream from the last seen id. <!-- test: services/dashboard/test/feed.test.ts:77 -->
- [x] **DASH-FEED-004**: When the tracker's derived service state changes, the dashboard shall push a `services` message to connected clients; identical repeated heartbeats shall not cause a push. <!-- test: services/dashboard/test/feed.test.ts:87 -->
- [x] **DASH-FEED-005**: While the dashboard is running, it shall re-evaluate heartbeat staleness every 1000 ms and push the result to connected clients when a state changes. <!-- test: services/dashboard/test/feed.test.ts:100 -->
- [x] **DASH-FEED-006**: When `GET /services` is requested, the dashboard shall respond 200 JSON `{services}` listing every known service with its derived state (`unknown` for services never seen). <!-- test: services/dashboard/test/routes.test.ts:136 -->
- [x] **DASH-FEED-008**: When a client connects to `/ws`, the dashboard shall send it a `{type: "stack", ...}` message carrying the `GET /stack` body (DASH-STACK-001) after the `services` snapshot and before the event replay, also when the replay cannot be read; while running, it shall push such a message to every OPEN client whenever the stack state, Docker reachability, any container's status or health, the running action or its phase, `last`, or bus reachability changes (containers compared by service name, ignoring the order Compose lists them in), and at no other time. <!-- test: services/dashboard/test/feed.test.ts:275, services/dashboard/test/feed.test.ts:285, services/dashboard/test/stack.test.ts:218 -->
- [x] **DASH-FEED-009**: The dashboard shall report the bus as `unreachable` from the first failed health seed or tail read until the next read that completes without an error (an empty blocking read counts), and as `connected` otherwise. <!-- test: services/dashboard/test/feed.test.ts:209, services/dashboard/test/feed.test.ts:234 -->
- [x] **DASH-FEED-007**: The dashboard shall never send `memory.notes.request`, `memory.notes.reply`, `memory.viewers.request` or `memory.viewers.reply` events to a `/ws` client, neither live nor in the connect replay, because they carry viewer-note text. <!-- test: services/dashboard/test/feed.test.ts:131, services/dashboard/test/feed.test.ts:307 -->

## Control gating

- [x] **DASH-CTRL-001**: Where `CONTROL_ENABLED` is not `1`, the dashboard shall not require a bearer token on any route except the `/viewers` routes (DASH-VIEWERS-007), shall answer `POST /services/:id/(start|stop|restart)` and every `POST /stack/*` route with 404, and shall report `{enabled: false}` from `GET /services/control`; its full-surface address is DASH-CTRL-003 and DASH-HOST-007. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:50, services/dashboard/test/inject.test.ts:182, services/dashboard/test/stack.test.ts:288 -->
- [x] **DASH-CTRL-002**: If `CONTROL_ENABLED=1` and `CONTROL_TOKEN` is empty or unset, then the dashboard shall fail startup with an error naming `CONTROL_TOKEN`. <!-- test: services/dashboard/test/control.test.ts:65 -->
- [x] **DASH-CTRL-003**: The dashboard shall bind its full surface to `DASHBOARD_HOST` when set and non-empty, else to `CONTROL_BIND` when set and non-empty, else to `127.0.0.1`, in both control modes, and shall log a warning when that address is not loopback because the tokens travel in cleartext over plain HTTP. <!-- test: services/dashboard/test/control.test.ts:70 -->
- [x] **DASH-CTRL-004**: Where `CONTROL_ENABLED=1`, the dashboard shall require `Authorization: Bearer <CONTROL_TOKEN>`, compared in constant time, on `POST /control`, `PUT /personality`, `POST /inject/text`, `POST /inject/image`, `POST /inject/audio`, `POST /services/:id/(start|stop|restart)` and `POST /stack/(launch|stop|restart|consolidate)`, responding 401 with `www-authenticate: Bearer` and performing no action otherwise. <!-- openspec: dashboard § (add-service-control) Bearer token on mutating routes --> <!-- openspec: dashboard § (add-test-injection) Injection gating --> <!-- test: services/dashboard/test/control.test.ts:112, services/dashboard/test/control.test.ts:126, services/dashboard/test/inject.test.ts:166, services/dashboard/test/stack.test.ts:295 -->
- [x] **DASH-CTRL-005**: Where `CONTROL_ENABLED=1`, the dashboard shall leave `GET /services/control`, `GET /services`, `GET /stack`, `GET /personality`, `GET /audio/*`, `GET /uploads/:id`, `POST /sink`, `/health` and the `/ws` feed unauthenticated: control mode guards mutations only, and an OBS Browser Source sink page, which cannot present a token, needs `/ws`, `/audio/*` and `POST /sink`. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/control.test.ts:135, services/dashboard/test/inject.test.ts:166, services/dashboard/test/stack.test.ts:277 -->
- [x] **DASH-CTRL-007**: Where `CONTROL_ENABLED=1`, `GET /services/control` shall respond 200 JSON `{enabled: true, runtime, advanced}`, where `runtime` is always `compose` (the only runtime) and `advanced` is true only when `CONTROL_ADVANCED=1`. <!-- openspec: dashboard § (add-service-control) Service control UI --> <!-- test: services/dashboard/test/control.test.ts:135, services/dashboard/test/control.test.ts:141 -->
- [x] **DASH-CTRL-008**: Where `CONTROL_ENABLED=1` and `CONTROL_ADVANCED=1`, the dashboard shall log a startup warning that redis and postgres can be stopped from the dashboard.

## Service lifecycle

- [x] **DASH-SVC-001**: Where `CONTROL_ENABLED=1`, when an authorized `POST /services/:id/(start|stop|restart)` arrives, the dashboard shall delegate to the service controller, publish a `service.lifecycle` audit record with `by: "dashboard"`, and respond 200 `{ok, detail?}`. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:147 -->
- [x] **DASH-SVC-002**: When the lifecycle request body is empty, the dashboard shall treat it as `{}`; when it is not a JSON object, or `mode` is not `resume` or `fresh`, or `isolated` is not a boolean, it shall respond 400 and run nothing; only `mode` and `isolated` are read. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:158, services/dashboard/test/control.test.ts:170 -->
- [x] **DASH-SVC-003**: When the controller refuses a lifecycle request, the dashboard shall respond 404 for an unknown service (including `dashboard`, which is not a manifest unit) and 403 for a forbidden target (infrastructure without `CONTROL_ADVANCED=1`), each with `{ok: false, detail}`. <!-- openspec: dashboard § (add-service-control) Service lifecycle routes --> <!-- test: services/dashboard/test/control.test.ts:177, services/dashboard/test/control.test.ts:186 -->
- [x] **DASH-SVC-004**: If publishing the `service.lifecycle` audit record fails, then the dashboard shall log a warning and still answer the lifecycle request normally. <!-- test: services/dashboard/test/control.test.ts:198 -->

## Test-input injection

- [x] **DASH-INJ-001**: When `POST /inject/text` carries a body that is not a JSON object, a `level` other than `service` or `bus`, an `as` other than `chat`, `speech` or `vision`, blank `text`, a mistyped optional field, or `level: "service"` with `as` other than `chat`, the dashboard shall respond 400 and publish nothing; a body over 64 KiB shall be answered 413. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:68 -->

- [x] **DASH-INJ-004**: When `POST /inject/text` carries `level: "service"` and `as: "chat"`, the dashboard shall publish `inject.request {id, target: "chat", kind: "text", text, meta, remember}` using the unmodified text and only the supplied viewer fields in `meta`, and respond 202 with that same `id`. <!-- openspec: dashboard § (add-test-injection) Inject text route --> <!-- test: services/dashboard/test/inject.test.ts:58 -->

- [x] **DASH-INJ-006**: If a binary injection request has an unsupported content type, then the dashboard shall respond 415; if it exceeds the per-kind cap, 413; if its body is empty, 400; if `level` is `bus` (or anything but `service`), 400; and in each case nothing shall be stored or published. <!-- openspec: dashboard § (add-test-injection) Inject binary routes --> <!-- test: services/dashboard/test/inject.test.ts:147 -->
- [x] **DASH-INJ-007**: When `GET /uploads/<id>` is requested for a live upload, the dashboard shall respond 200 with the stored bytes, the stored content type and `cache-control: no-store`; for an unknown or expired id it shall respond 404. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/inject.test.ts:85, services/dashboard/test/inject.test.ts:160 -->

## Upload store

- [x] **DASH-UPL-001**: The upload store shall assign each upload a 128-bit random hex id and enforce a per-kind size cap (default 8 MiB image, 25 MiB audio; env `INJECT_MAX_IMAGE_BYTES`, `INJECT_MAX_AUDIO_BYTES`; non-numeric or non-positive values fall back to the default). <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:10, services/dashboard/test/uploads.test.ts:21, services/dashboard/test/uploads.test.ts:67 -->
- [x] **DASH-UPL-002**: The upload store shall expire entries after `INJECT_TTL_MS` (default 600000 ms), lazily when an entry is read or a new upload is stored, and on a sweep that the dashboard runs every 60 s. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:28, services/dashboard/test/uploads.test.ts:39, services/dashboard/test/uploads.test.ts:67 -->
- [x] **DASH-UPL-003**: When the upload store holds more than 16 entries or 64 MiB, it shall evict the oldest entries first, always keeping the newest. <!-- openspec: dashboard § (add-test-injection) Upload store and serving --> <!-- test: services/dashboard/test/uploads.test.ts:48, services/dashboard/test/uploads.test.ts:57 -->
