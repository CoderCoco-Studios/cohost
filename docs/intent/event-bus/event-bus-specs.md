## Publish and envelope

- [x] **BUS-STREAM-001**: When a service calls `Bus.publish(type, data)` with any event type other than `service.heartbeat`, the system shall `XADD` one entry to the Redis stream `cohost:events` with fields `type`, `ts` (publisher clock, epoch ms as a string), `source` (the `Bus` constructor's source name) and `data` (JSON of the zod-parsed payload), and shall return the Redis stream id. <!-- openspec: bus § Single stream with event envelope --> <!-- test: packages/bus/test/bus.test.ts:23 -->
- [x] **BUS-STREAM-002**: When `Bus.publish` writes to `cohost:events`, the system shall trim the stream approximately (`MAXLEN ~`) to 20000 entries. <!-- openspec: bus § Single stream with event envelope -->
- [x] **BUS-STREAM-003**: When `Bus.publish(type, data)` is called, the system shall parse `data` with the schema registered in `EventPayloads` for `type` before writing, store the parsed value (schema defaults applied, keys the schema does not define removed), and reject the call without writing if the payload is invalid. <!-- openspec: bus § Typed payload validation on publish --> <!-- test: packages/bus/test/bus.test.ts:48 -->
- [x] **BUS-STREAM-004**: If `Bus.publish` is called with the type `service.heartbeat`, then the system shall throw an error that names `publishHealth()` and shall write nothing to any stream. <!-- openspec: bus § Health stream --> <!-- test: packages/bus/test/bus.test.ts:145 -->
- [ ] **BUS-STREAM-005**: When a `Bus` is constructed without an explicit URL, the system shall have its transport open the shared connection immediately to the URL from `urls.redis()` (the `REDIS_URL` environment variable, default `redis://127.0.0.1:6379`), and each `Bus` instance shall have a consumer name of the form `<HOSTNAME or local>-<8 hex characters>` that does not change for the life of the instance.
- [x] **BUS-STREAM-006**: When a `Bus` event is read from either stream, the system shall rebuild it as `{ id, type, ts, source, data }` where `id` is the Redis stream id, `ts` defaults to 0 and `source` defaults to `?` when the fields are missing, and `data` is the payload re-parsed with the type's schema (defaults applied). <!-- test: packages/bus/test/bus.test.ts:84 -->
- [x] **BUS-STREAM-007**: If the stream write in `Bus.publish` or `Bus.publishHealth` fails (the `XADD` rejects, for example because Redis is unreachable), then the system shall log the failure at warn level with the event type and reject the returned promise with the original error, and shall never exit the process itself; every caller that does not await the promise shall attach a rejection handler that logs and continues, so that no failed publish becomes an unhandled rejection (Node 22 terminates the process on one), as the HLD failure posture requires.
- [x] **BUS-STREAM-008**: Where a `Bus` is constructed with the option `streamPrefix`, the system shall use `<prefix>:events` and `<prefix>:health` in place of `cohost:events` and `cohost:health` for every stream command of that instance (publish, publishHealth, subscribe, resetGroup, tail, tailHealth, recent, recentHealth); the default prefix is `cohost`. A test uses it to keep its traffic off the production streams. <!-- test: packages/bus/test/resilience.test.ts -->
- [ ] **BUS-STREAM-009**: Where a `Bus` is constructed with the option `failFast`, the system shall never re-establish the transport's shared connection, so that an unreachable Redis makes the first command reject with an error whose `code` is `BUS_CONNECTION` as soon as the first connect attempt fails, with no retries and no output on stdout or stderr: a command issued while that attempt is in flight waits for it (at most 10 s, BUS-NAT-CONN-006, BUS-NAT-CONN-007), and every command after it failed rejects at once. <!-- test: packages/bus/test/failfast.test.ts -->

## Connector audio streams and registry

Live connector audio and connector registrations sit in Redis beside the event stream, never on it. The keys and streams use the prefix of BUS-STREAM-008 (default `cohost`); their layout and frame format are owned by [connections](../connections/connections-specs.md) (CONN-REG-*, CONN-AUD-*).

- [x] **BUS-AUD-001**: The system shall carry live connector audio only on the capped Redis streams `<prefix>:audio.in.<source>` and `<prefix>:audio.out.<sink>`, never on `<prefix>:events` or `<prefix>:health`, and `Bus.publish` shall neither write nor trim them. <!-- test: packages/bus/test/connector.test.ts -->
- [x] **BUS-AUD-002**: The system shall hold each connector registration only in the expiring Redis key `<prefix>:connector:<id>`, which is not a stream entry, so a registration never counts against a stream's `MAXLEN`, is never delivered to a consumer group and never appears in a `/ws` backfill. <!-- test: packages/bus/test/connector.test.ts -->

## Upload store

Injected test uploads sit in Redis beside the stream, never on it. The key is `<prefix>:upload:<id>` with the prefix of BUS-STREAM-008 (default `cohost`).

- [x] **BUS-UPL-001**: When `Bus.putUpload(id, bytes, ttlMs)` is called, the system shall `SET <prefix>:upload:<id>` to the bytes with an expiry of `ttlMs` milliseconds, and reject if the write fails. <!-- test: packages/bus/test/upload.test.ts -->
- [x] **BUS-UPL-002**: When `Bus.takeUpload(id)` is called, the system shall read and delete `<prefix>:upload:<id>` in one step (`GETDEL`) and return its bytes as a `Buffer`, or `null` when the key does not exist or has expired. <!-- test: packages/bus/test/upload.test.ts -->
- [x] **BUS-UPL-003**: The upload key shall hold only the bytes: it shall not be a stream entry, so an upload never counts against the stream's `MAXLEN`, is never delivered to a consumer group and never appears in a `/ws` backfill. <!-- test: packages/bus/test/upload.test.ts -->

## Consumer-group subscription

- [x] **BUS-SUB-001**: When `Bus.subscribe` is called and its consumer group does not exist on `cohost:events`, the system shall create it with `MKSTREAM` at the newest entry (`$`) in either start mode, shall ignore a `BUSYGROUP` error, and shall rethrow any other group-creation error. <!-- openspec: bus § Consumer-group subscription --> <!-- test: packages/bus/test/bus.test.ts:23 --> <!-- test: packages/bus/test/resilience.test.ts:55 --> <!-- test: packages/bus/test/resilience.test.ts:91 -->
- [x] **BUS-SUB-002**: Where a subscription's start mode is `resume`, `Bus.subscribe` shall keep an existing consumer group's stored position, so entries published while the service was down and still held by the stream are delivered after the restart. <!-- test: packages/bus/test/resilience.test.ts:80 -->
- [x] **BUS-SUB-003**: While a subscription is running, the system shall first drain its own consumer name's pending entries (cursor `0`), reading batches of up to 50 and continuing after the last id of each batch until a read returns none, and then read new entries (cursor `>`) in batches of up to 50, blocking for `blockMs` (default 5000) per read. An entry whose `XACK` failed stays pending but is not read again by the drain, so the drain ends. <!-- test: packages/bus/test/resilience.test.ts -->
- [x] **BUS-SUB-004**: When `types` is given to `Bus.subscribe` and an entry of another type is read, the system shall not call the handler and shall acknowledge the entry. <!-- openspec: bus § Consumer-group subscription --> <!-- test: packages/bus/test/bus.test.ts:23 -->
- [x] **BUS-SUB-005**: When a subscription's handler throws or rejects, the system shall log `handler failed` at error level, shall still acknowledge the entry, and shall continue with the next entry. <!-- openspec: bus § Consumer-group subscription --> <!-- test: packages/bus/test/bus.test.ts:56 -->
- [x] **BUS-SUB-006**: While a subscription is running, the system shall deliver entries to its handler one at a time in stream order, awaiting each handler before reading the next entry.
- [x] **BUS-SUB-007**: If a stream entry has an unknown `type`, a `data` field that is not JSON, or a payload that fails its schema, then the system shall not deliver it to any handler and (in `subscribe`) shall acknowledge it. <!-- openspec: bus § Malformed entries are dropped --> <!-- test: packages/bus/test/bus.test.ts:84 -->
- [ ] **BUS-SUB-008**: The system shall deliver `cohost:events` entries to a consumer group at most once, with one exception: entries that a previous process read but did not acknowledge shall not be redelivered to its successor (each `Bus` instance reads under its own consumer name and nothing claims another consumer's pending entries), an entry whose handler failed is acknowledged (BUS-SUB-005), and within one process an entry whose handler has run is not delivered again, except that an entry whose acknowledgement Redis refused (reported in `ackErrors`, BUS-NAT-ACK-003) stays pending and is redelivered at most once, by a later drain (BUS-NAT-CONN-003); if the acknowledgement of that redelivery is refused too, the entry is dropped and never delivered again (BUS-NAT-ACK-008). <!-- openspec: bus § Consumer-group subscription (describes the in-process pending drain only) --> <!-- test: packages/bus/test/resilience.test.ts:116 -->
- [ ] **BUS-SUB-009**: If a blocking read in `subscribe` fails for any reason other than `stop()`, then the system shall log the error at warn level and retry the read after a delay that grows with each consecutive failure up to a fixed cap, resetting the delay after a successful read, and shall not reject the `subscribe` promise; if Redis refuses an acknowledgement (`XACK`), the system shall log it at warn level and continue without retrying the acknowledgement and without delivering the entry again within the current read or drain; the entry stays pending and a later drain redelivers it at most once; if Redis refuses the acknowledgement of that redelivery, the system shall log it at warn level as dropped and never deliver the entry again (BUS-SUB-008, BUS-NAT-ACK-008). <!-- test: packages/bus/test/resilience.test.ts:129 --> <!-- test: packages/bus/test/resilience.test.ts:143 -->
- [x] **BUS-SUB-010**: Where a subscription's start mode is `latest`, `Bus.subscribe` shall move an existing consumer group to the newest entry (`$`) on every start before its first read (creating a missing group at `$`), so a restarted subscriber skips entries published while it was down. <!-- test: packages/bus/test/resilience.test.ts:66 -->
- [x] **BUS-SUB-011**: The system shall require every `Bus.subscribe` call to name its start mode explicitly, `latest` or `resume`, in place of the `fromNow` option.
- [x] **BUS-SUB-012**: Where a `Bus.subscribe` call supplies `onReady`, the system shall invoke it once, after the consumer group has been created or positioned for the call's start mode and before the subscription's first read, so a caller can tell when its group is live.
- [x] **BUS-SUB-013**: If `Bus.stop()` is called while a subscription's handler is running, then the system shall let that handler finish, shall not `XACK` that entry, and shall neither call the handler for nor acknowledge any later entry of the batch; the `subscribe` promise resolves. <!-- test: packages/bus/test/resilience.test.ts -->

## Live tail and backfill

- [x] **BUS-TAIL-001**: When `Bus.tail(handler, fromId)` is called, the system shall read `cohost:events` without a consumer group, starting at `fromId` (default `$`), call `handler` for each decodable event, and neither acknowledge nor replay entries. <!-- openspec: bus § Live tail and recent backfill --> <!-- test: packages/bus/test/bus.test.ts:102 -->
- [x] **BUS-TAIL-002**: When `Bus.recent(count)` is called, the system shall return up to `count` (default 100) of the newest decodable events from `cohost:events` in chronological order, oldest first, skipping entries that cannot be decoded. <!-- openspec: bus § Live tail and recent backfill --> <!-- test: packages/bus/test/bus.test.ts:84 -->
- [x] **BUS-TAIL-003**: If a blocking read in `tail` or `tailHealth` fails for any reason other than `stop()`, then the system shall log the error at warn level and retry from the last id it delivered after a delay that grows with each consecutive failure up to a fixed cap, and shall not reject the returned promise. <!-- test: packages/bus/test/resilience.test.ts:180 --> <!-- test: packages/bus/test/resilience.test.ts:194 -->
- [x] **BUS-TAIL-004**: If the handler passed to `tail` or `tailHealth` throws, then the system shall log the error and continue with the next entry. <!-- test: packages/bus/test/resilience.test.ts:212 --> <!-- test: packages/bus/test/resilience.test.ts:229 -->
- [x] **BUS-TAIL-005**: Where `tail` or `tailHealth` is given an `onRead` callback (third argument), the system shall call it after every blocking read: with no argument when the read completed without an error (a read that returned no entries counts), and with the error when it failed for any reason other than `stop()`, before the failure's retry delay begins. A throw from `onRead` shall be caught and ignored. <!-- test: packages/bus/test/resilience.test.ts:238, packages/bus/test/resilience.test.ts:250 -->

## Health stream and group reset

- [x] **BUS-HEALTH-001**: When a service calls `Bus.publishHealth(data)`, the system shall validate `data` against the `service.heartbeat` schema, `XADD` it to `cohost:health` (fields `type`, `ts`, `source`, `data`) trimmed approximately to 1000 entries, return the stream id, and write nothing to `cohost:events`. <!-- openspec: bus § Health stream --> <!-- test: packages/bus/test/bus.test.ts:155 -->
- [x] **BUS-HEALTH-002**: If `Bus.publishHealth` is given an invalid heartbeat (for example `state: "dead"`), then the system shall reject the call and write nothing. <!-- openspec: bus § Health stream --> <!-- test: packages/bus/test/bus.test.ts:155 -->
- [x] **BUS-HEALTH-003**: When `Bus.tailHealth(handler, fromId)` is called, the system shall read `cohost:health` without a consumer group, starting at `fromId` (default `$`), and call `handler` only for entries that decode as `service.heartbeat`. <!-- openspec: bus § Health stream --> <!-- test: packages/bus/test/bus.test.ts:169 -->
- [x] **BUS-HEALTH-004**: When `Bus.recentHealth(count)` is called, the system shall return up to `count` (default 100) of the newest decodable heartbeats from `cohost:health`, oldest first. <!-- openspec: bus § Health stream --> <!-- test: packages/bus/test/bus.test.ts:169 -->
- [x] **BUS-GROUP-001**: When `Bus.resetGroup(group)` is called, the system shall leave the group on `cohost:events` at the newest entry (`$`) whether or not the group or the stream key already exists: a missing group or stream (including a fresh Redis 7+ where `XGROUP SETID` answers `ERR The XGROUP subcommand requires the key to exist`) shall be created at `$` with `MKSTREAM`; an existing group shall be moved with `XGROUP SETID ... $` (a `BUSYGROUP` from a concurrent create is treated as existing); the system shall rethrow any other error. <!-- test: packages/bus/test/bus.test.ts:297 --> <!-- test: packages/bus/test/resilience.test.ts:293 -->

## Shutdown

The process shutdown sequence (`onShutdown`, `beforeShutdown`) lives in `@cohost/shared`: BUS-STOP-002 to BUS-STOP-006 are retired, now shared-runtime SHARED-LIFE-001 to SHARED-LIFE-005; the numbers are not reused. This section keeps the transport's own stop.

- [ ] **BUS-STOP-001**: When `Bus.stop()` is called, the system shall mark the instance stopped, wake every retry backoff sleep, close its transport (the shared connection and every reader of `subscribe`, `tail`, `tailHealth` and `tailAudio`), return a `Promise<void>` that resolves once the transport has closed, and cause pending `subscribe`, `tail` and `tailHealth` promises to resolve without surfacing the resulting read error. <!-- openspec: bus § Shutdown --> <!-- test: packages/bus/test/bus.test.ts:119 -->

## Native transport

The bus transport is the Rust crate `crates/cohost-bus` behind the napi-rs binding `crates/cohost-bus-node`, adapted to the `BusTransport` interface by `packages/bus/src/native.ts`; the TypeScript `Bus` facade keeps validation, decode, the envelope and every loop's control flow. Error codes named here (`BUS_CONNECTION`, `BUS_REDIS`, `BUS_CLOSED`, `BUS_INVALID`, `BUS_INTERNAL`) are the `code` property of the JS `Error` the binding rejects with.

### Facade API

- [ ] **BUS-NAT-API-001**: The `@cohost/bus` package shall export `class Bus` with the constructor `(source, log?, url?, options?)` and the members `consumer`, `publish`, `publishHealth`, `subscribe`, `tail`, `tailHealth`, `recent`, `recentHealth`, `resetGroup`, `serverTime`, `putUpload`, `takeUpload`, `connectorKey`, `audioStream`, `writeRegistration`, `readRegistration`, `deleteRegistration`, `listConnectors`, `publishFrame`, `tailAudio` and `stop`, with the call signatures they have on the TypeScript transport, except that `stop()` returns `Promise<void>`.
- [ ] **BUS-NAT-API-002**: The `@cohost/bus` package shall export `STREAM`, `HEALTH_STREAM`, `HEALTH_MAXLEN`, `SubscribeStart`, `SubscribeOptions`, `Handler`, `Publisher`, `ReadOutcome`, `HeartbeatEvent`, `BusOptions`, `BusTransport`, `BusReader` and `TransportFactory`, and everything `events.ts`, `connector.ts` and `registrar.ts` export.
- [ ] **BUS-NAT-API-003**: Where a `Bus` is constructed without the `transport` option, the system shall run every operation of that instance on the native transport, and no runtime package shall import a Redis client other than through the native transport: no `src/` file of any package or service imports `ioredis` or another Redis client, which may appear only as a devDependency used by tests and `scripts/dev/bus-bench.ts`.
- [ ] **BUS-NAT-API-004**: Where a `Bus` is constructed with `BusOptions.transport`, the system shall call that factory once with the Redis URL and `{ prefix, failFast }` and run every operation of that instance on the `BusTransport` it returns; `BusOptions` shall have no connection-level option (no `connect`).
- [ ] **BUS-NAT-API-005**: When `Bus.publish` or `Bus.publishHealth` writes an entry, the facade shall validate the payload with zod and stamp `ts` with `Date.now()` before calling the transport's `append`, which receives only the four string envelope fields `type`, `ts`, `source` and `data`.
- [ ] **BUS-NAT-API-006**: When an entry is read from `<prefix>:events` or `<prefix>:health`, the facade shall build the `BusEvent` from the transport's `RawEntry` with `decode` (BUS-STREAM-006, BUS-SUB-007); the transport shall not parse `data`.
- [ ] **BUS-NAT-API-007**: When `Bus.subscribe` is called with start mode `latest` and the transport's `createGroup` resolves `false` (the group exists), the facade shall call `moveGroupToLatest` for the group before invoking `onReady` and before the first read.
- [ ] **BUS-NAT-API-008**: When `Bus.resetGroup(group)` is called, the facade shall call the transport's `createGroup` and, when it resolves `false`, `moveGroupToLatest`, and shall rethrow any rejection of either.
- [ ] **BUS-NAT-API-009**: `Bus.serverTime()` shall return the Redis server's `TIME` as epoch milliseconds read on the shared connection, and the system shall never use it as an envelope `ts`.
- [ ] **BUS-NAT-API-010**: `packages/bus/src/native.ts` shall be the only TypeScript file that imports the native addon.
- [ ] **BUS-NAT-API-011**: The Bus resilience tests (`packages/bus/test/resilience.test.ts`) and every other test that needs a `Bus` without a Redis server shall supply a scripted fake `BusTransport` through `BusOptions.transport`.

### Transport interface and boundary

BUS-NAT-TRN-006 (no calls into JavaScript) and BUS-NAT-TRN-012 (one tokio runtime per process) are retired, moved to the LLD's [Native design constraints](event-bus-design.md#native-design-constraints) (constraints N1 and N3); the numbers are not reused.

- [ ] **BUS-NAT-TRN-001**: The `BusTransport` interface shall provide `append`, `recent`, `createGroup`, `moveGroupToLatest`, `putUpload`, `takeUpload`, `writeRegistration`, `readRegistration`, `deleteRegistration`, `listRegistrations`, `appendFrame`, `serverTime`, `openReader` and `close`, and the `BusReader` it opens shall provide `readGroup`, `ack`, `read`, `readFrames` and `close`, each issuing the Redis commands the event-bus design lists for it under the instance's prefix.
- [ ] **BUS-NAT-TRN-002**: When the transport's `createGroup(group)` is called, it shall resolve `true` when `XGROUP CREATE <prefix>:events <group> $ MKSTREAM` created the group, `false` when Redis answered `BUSYGROUP`, and reject with `BUS_REDIS` for any other Redis error.
- [ ] **BUS-NAT-TRN-003**: The native transport shall not retry any command or read itself; every retry of a bus operation shall come from the facade's backoff.
- [ ] **BUS-NAT-TRN-004**: When a `Bus` is constructed, the native transport shall begin opening its one shared multiplexed connection without blocking or throwing, even when Redis is unreachable.
- [ ] **BUS-NAT-TRN-005**: While a `subscribe`, `tail`, `tailHealth` or `tailAudio` loop runs, the system shall issue its reads on a `BusReader` with a connection of its own, and every non-blocking command of the instance shall use the shared connection, so a process holds one connection plus one per running loop.
- [ ] **BUS-NAT-TRN-007**: While a `subscribe` handler is running, the facade shall not issue the next `readGroup` of that subscription until the handler of every entry of the current batch has settled or the batch was cut short by `stop()`.
- [ ] **BUS-NAT-TRN-008**: When one `Bus` issues several commands on the shared connection without awaiting them, the system shall send them to Redis in call order, so entries one `Bus` appends to a stream appear in call order.
- [ ] **BUS-NAT-TRN-009**: When `publishFrame` or `putUpload` is called with a `Buffer`, the binding shall copy its bytes before the call returns, so a caller that changes or reuses the `Buffer` after the call returns does not change what is written.
- [ ] **BUS-NAT-TRN-010**: When `readFrames` or `takeUpload` returns bytes in a `Buffer`, the content of that `Buffer` shall stay unchanged for as long as it is referenced, including after later reads and calls on the same reader and transport and after the reader or transport is closed.
- [ ] **BUS-NAT-TRN-011**: The native layer (`crates/cohost-bus` and `crates/cohost-bus-node`) shall never write to stdout or stderr; it shall return every failure to its caller as an error value.
- [ ] **BUS-NAT-TRN-013**: The binding's codec helpers `encodeFrame`, `decodeFrame` and `tagProblem` shall be synchronous.
- [ ] **BUS-NAT-TRN-014**: When a read returns an entry, the transport shall return only its id and the envelope fields `type`, `ts`, `source` and `data`, leaving a missing field undefined, and shall return a pending entry whose stream entry was trimmed as an id with no fields.

### Ack batching

- [ ] **BUS-NAT-ACK-001**: When the facade acknowledges a `subscribe` entry, it shall call the reader's synchronous `ack`, which only queues the id, and the reader shall send its queued `XACK`s in the same pipeline as, and ahead of, its next `XREADGROUP`.
- [ ] **BUS-NAT-ACK-002**: The facade shall queue an entry's ack only after its handler has returned or thrown, or after the entry was filtered out by `types` or found undecodable, so delivery stays at most once (BUS-SUB-005, BUS-SUB-008).
- [ ] **BUS-NAT-ACK-003**: If Redis refuses a queued `XACK`, then `readGroup` shall report the ids and error in its result's `ackErrors`, and the facade shall log `ack failed` at warn with the ids and continue without retrying the ack, leaving the entry pending so that a later drain redelivers it once (BUS-SUB-008), and shall record the ids as refused once for the life of the subscription.
- [ ] **BUS-NAT-ACK-004**: If the pipeline that carries queued acks fails on the connection, then the reader shall keep those acks queued and send them with its next pipeline that reaches Redis.
- [ ] **BUS-NAT-ACK-005**: When the transport's `close()` runs and any reader has queued acks, it shall send every reader's queued acks on the shared connection in one pipeline before it closes any connection; with no queued acks it shall send nothing.
- [ ] **BUS-NAT-ACK-006**: If the ack flush of `close()` fails, then the transport shall not retry or log it, shall still close every connection, and `Bus.stop()` shall resolve.
- [ ] **BUS-NAT-ACK-007**: If the ack flush of `close()` has not completed within 2000 ms of `close()` being called, then the transport shall abandon the flush without logging it, close every connection and resolve, so `Bus.stop()` resolves within about 2 s whatever state Redis is in.
- [ ] **BUS-NAT-ACK-008**: If Redis refuses the `XACK` of an entry whose acknowledgement it had already refused once in the same subscription, then the facade shall log `ack failed, entry dropped` at warn with the ids, and whenever a later drain reads that entry the facade shall neither call the handler for it nor queue its ack, so the entry is never delivered a third time.

### Connections and reconnect

- [ ] **BUS-NAT-CONN-001**: If a reader's connection fails or cannot be opened, then the read shall reject at once with `BUS_CONNECTION`, the reader shall not retry, and the reader's next call shall open a new connection.
- [ ] **BUS-NAT-CONN-002**: When a `subscribe`, `tail`, `tailHealth` or `tailAudio` read fails while the `Bus` is not stopped, the facade shall log exactly one warn line, report the error once to `onRead` where one was given (BUS-TAIL-005), and wait `min(30000, 250 * 2^(failures-1))` ms (with the base and cap from `BusOptions`) before the next read, resetting the failure count after a successful read.
- [ ] **BUS-NAT-CONN-003**: When a read of `subscribe` has failed and its backoff sleep has ended, the facade shall restart the read loop at cursor `0` and drain this consumer's pending entries as BUS-SUB-003 specifies before reading with cursor `>` again.
- [ ] **BUS-NAT-CONN-004**: Where the `Bus` is not `failFast`, when the shared connection's first connect attempt fails or an established shared connection fails, the native transport shall reconnect it in the background, waiting a delay that starts at 250 ms and doubles per failed attempt up to 30000 ms.
- [ ] **BUS-NAT-CONN-005**: While the shared connection is down after its first connect attempt has settled (that attempt failed, or an established connection failed) and until a reconnect succeeds, including while a background reconnect attempt is in flight, every command on it (`publish`, `publishHealth`, `publishFrame`, `putUpload`, `takeUpload`, `writeRegistration`, `readRegistration`, `deleteRegistration`, `listConnectors`, `recent`, `recentHealth`, `resetGroup`, the group creation of `subscribe`, `serverTime`) shall reject at once with `BUS_CONNECTION`, and the transport shall not queue it.
- [ ] **BUS-NAT-CONN-006**: While the first connect attempt of the shared connection after construction is in flight (at most 10 s, BUS-NAT-CONN-007), a command on the shared connection shall wait for that attempt and then run if it succeeded, or reject with `BUS_CONNECTION` if it failed; no command shall wait for any later connect attempt.
- [ ] **BUS-NAT-CONN-007**: The native transport shall abandon any connect attempt (the shared connection's first attempt, its background reconnects, and a reader's connect) that has not completed within 10 seconds and treat it as failed.

### Errors

- [ ] **BUS-NAT-ERR-001**: When a binding call fails, it shall reject with a JS `Error` whose `code` is one of `BUS_CONNECTION` (connect failure, reset, peer close, connect timeout), `BUS_REDIS` (Redis answered with an error), `BUS_CLOSED` (the transport or reader was closed), `BUS_INVALID` (an argument the codec refuses) or `BUS_INTERNAL` (a caught panic or a reply of an unexpected shape).
- [ ] **BUS-NAT-ERR-002**: When the binding rejects with `BUS_REDIS`, the error message shall be Redis's error text.
- [ ] **BUS-NAT-ERR-003**: When a read loop's read rejects with `BUS_CONNECTION`, `BUS_REDIS` or `BUS_INTERNAL` while the `Bus` is not stopped, the facade shall treat it as a read failure (BUS-SUB-009, BUS-TAIL-003, BUS-NAT-CONN-002).
- [ ] **BUS-NAT-ERR-004**: If a read or the group creation of `subscribe` rejects after `stop()` was called, then the facade shall resolve the `subscribe`, `tail`, `tailHealth` or `tailAudio` promise without logging and without rethrowing.
- [ ] **BUS-NAT-ERR-005**: When a transport method is called after the transport was closed, it shall reject with `BUS_CLOSED`, and `publish` and `publishHealth` shall log that rejection at warn and rethrow it (BUS-STREAM-007).
- [ ] **BUS-NAT-ERR-006**: If Rust code panics inside a binding call, then the binding shall catch the panic and reject that call with `BUS_INTERNAL`, and the process shall not abort.
- [ ] **BUS-NAT-ERR-007**: If an envelope field (`type`, `ts`, `source` or `data`) of a read entry is not valid UTF-8, then the transport shall return that entry as an id with no fields, so the facade drops it without delivering or logging it and, in `subscribe`, acknowledges it.
- [ ] **BUS-NAT-ERR-008**: When the transport's `close()` is called after an earlier call, it shall resolve once the earlier close has completed and shall not reject, so a repeated `Bus.stop()` resolves.
- [ ] **BUS-NAT-ERR-009**: When the binding rejects with `BUS_CONNECTION`, the error message shall name the underlying cause (the operating system's error text, such as a refused connection or an unknown host, or `connect timeout`).
- [ ] **BUS-NAT-ERR-010**: When the transport's `close()` runs while the shared connection's first connect attempt is in flight, it shall abandon that attempt and reject every command waiting on it with `BUS_CLOSED`.
- [ ] **BUS-NAT-ERR-011**: Where `crates/cohost-bus-node` is built with the test-only cargo feature `test-panic`, the binding shall export a call that panics inside its Rust future, so a test can check BUS-NAT-ERR-006; `build:native`, the Docker `native` stage and `cargo build --release` without that feature shall not export it.

### Frames

- [ ] **BUS-NAT-FRM-001**: If `Bus.publishFrame` is called with a frame whose `pcm` is longer than `MAX_FRAME_BYTES`, then the system shall reject with `BUS_INVALID` and write nothing.
- [ ] **BUS-NAT-FRM-002**: If `Bus.publishFrame` is called with a frame whose `pcm` has an odd byte count, then the system shall reject with `BUS_INVALID` and write nothing.
- [ ] **BUS-NAT-FRM-003**: When the transport's `appendFrame(dir, tag, frame)` writes a frame, it shall send the encoded `XADD <prefix>:audio.<dir>.<tag> MAXLEN ~ <AUDIO_MAXLEN[dir]>` and `PEXPIRE <stream> 60000` in one pipeline.
- [ ] **BUS-NAT-FRM-004**: When the reader's `readFrames` returns entries, it shall decode each with the frame codec and return `{ ok: false, reason }` for an entry the codec rejects instead of rejecting the read.
