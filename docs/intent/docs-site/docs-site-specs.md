# docs-site specs

Prefix `DOCS`. Design: [docs-site-design.md](docs-site-design.md).

Markers: `[x]` implemented; `[ ]` intended but not yet implemented (gap); `[D]` deferred.

Terms used below: a *hand-written page* is a published `.md` file under `docs/` that is not a dynamic-route template (a file named `[param].md`); a *design-excerpt page* is a page a route template and its `*.paths.mjs` loader produce under `docs/advanced/architecture/`; *the docs check* is `scripts/docs-check.mjs`, whose source pass runs with no argument and whose built-site pass runs with `--dist`; *prose* is the text of a page outside its frontmatter, code spans, fenced code blocks, headings and link text, and includes table cells and the text of `:::` containers; a *shell fence* is a fenced code block whose language is `sh`, `bash`, `shell`, `zsh` or `console`; a *command line* in a shell fence is, in a `console` fence, a line starting with `$ ` (with that prefix removed) and, in the other languages, a non-blank line that does not start with `#`; *the theme CSS* is `docs/.vitepress/theme/tokens.css` and `docs/.vitepress/theme/style.css` together; *the Palette table* and *the Contrast pairs table* are the tables of those names in the docs-site LLD's Theme and personality section; a *doc-layout page* is a built page rendered with VitePress's doc layout (every published page except the home page and the 404 page); a *resource reference* is a URL the browser fetches without the reader clicking it: an HTML `src`, `srcset`, `poster` or `data` attribute, the `href` of a `<link>` element whose `rel` is not `canonical`, `alternate` or `me`, the `href` or `xlink:href` of an SVG `image` or `use` element, a CSS `@import` or `url()`, in a `.css` file or in a `<style>` element or `style` attribute (inside inline SVG included); an *external* URL is one starting `http:`, `https:` or `//`.

## Extension guides

Terms used in this section: an *Extend page* is a hand-written page under `docs/advanced/extend/`; an *Extend guide* is an Extend page other than `index.md`, `hooks.md` and `connector-protocol.md`; a *snippet import* is a line of a hand-written page, outside any fenced code block (backtick or tilde), that begins, after at most three spaces, with `<<< ` (VitePress's code import), whose *path* is the text after `<<< ` up to the first `#`, `{` or whitespace, and whose *region* is the name after a `#`, when there is one; an *example file* is a file under `examples/`; a page *imports* a file when it has a snippet import whose path resolves to that file; *the Extension guides table*, *the Tested examples table* and *the Example layout table* are the tables of those names in the docs-site LLD's Extension guides section; a *workspace Rust package* is a directory named, directly or by a glob, in `workspace.members` of the root `Cargo.toml` or of `examples/Cargo.toml` that holds a `Cargo.toml` with a `package.name`; an *example Rust package* is one of `examples/Cargo.toml`. Unless a spec names another verifier, the docs check's source pass enforces a DOCS-GUIDE spec, with a test in `packages/config/test/docs-check.test.ts`. Where a spec says a page shall *say* something, the docs check verifies only the quoted words (case-insensitively) and the named code spans (literally); the rest of the statement is held by review. A path is relative to the repository root. Words of a command line are split as a POSIX shell splits them (quotes respected); a command line that ends in `\` continues on the next line, and each command a command line separates with `&&`, `||`, `|` or `;` is judged on its own. A fence's *language* is its info string up to the first `{`, `:`, `[` or whitespace, compared case-insensitively. A link names the Extend page it targets once its `#` fragment and any `.md` or `.html` suffix are removed, resolved against the linking page.
