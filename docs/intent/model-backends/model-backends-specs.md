# model-backends specs

Design: [model-backends-design.md](model-backends-design.md). Prefix `LLM`. Verified against the code at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`. `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred. Test paths are relative to the repo root.

## Interface and factory

- [x] **LLM-IF-001**: The `@cohost/llm` package shall expose every chat backend as a `ChatProvider` with `name`, `model`, `chat(messages, opts)`, `ping()` and an optional `lastError`, and every embedding source as an `Embedder` with `embed(text)`. <!-- openspec: llm § Provider factory --> <!-- no runtime test: a type-level contract that tsc enforces through `implements ChatProvider` / `implements Embedder` -->
- [x] **LLM-IF-002**: When `createChatProvider` is called with `llm.provider` of `ollama`, `openai`, `anthropic`, `bedrock` or `mock`, the model-backends package shall return a provider whose `name` is that same string. <!-- openspec: llm § Provider factory --> <!-- test: packages/llm/test/llm.test.ts:63, packages/llm/test/llm.test.ts:232 (mock) -->
- [x] **LLM-IF-003**: The model-backends package shall construct a `MockProvider` only through the explicit `mock` case of `createChatProvider`, with no fallback path from any other provider value to mock. <!-- openspec: llm § Provider factory --> <!-- no test: a structural property of the `switch` in createChatProvider, which has no default branch -->
- [x] **LLM-IF-004**: When `chat()` completes on any provider, the model-backends package shall resolve to the reply text with leading and trailing whitespace removed. <!-- test: packages/llm/test/llm.test.ts:72 (openai), packages/llm/test/llm.test.ts:143 (Claude) -->

## Ollama and OpenAI-compatible chat

- [x] **LLM-CHAT-001**: When `Ollama.chat` is called, the package shall send a non-streaming `POST` to `/api/chat` at `OLLAMA_URL` (default `http://127.0.0.1:11434`) with `keep_alive` `24h` and `options` carrying `temperature`, `num_ctx` and `num_predict`. <!-- openspec: llm § Ollama and OpenAI-compatible chat --> <!-- no test: no test asserts the Ollama chat body -->
- [x] **LLM-CHAT-002**: When `OpenAICompatible.chat` is called, the package shall send a non-streaming `POST` to `<openai.base_url>/chat/completions` with any trailing slashes on `base_url` removed. <!-- openspec: llm § Ollama and OpenAI-compatible chat --> <!-- test: packages/llm/test/llm.test.ts:72 -->
- [x] **LLM-CHAT-003**: Where `llm.openai.api_key` is non-empty, the OpenAI-compatible provider shall send `Authorization: Bearer <key>`, and where it is empty the provider shall send no authorization header. <!-- openspec: llm § Ollama and OpenAI-compatible chat --> <!-- test: packages/llm/test/llm.test.ts:72 -->
- [x] **LLM-CHAT-004**: When the caller supplies no `temperature` or `maxTokens`, the Ollama and OpenAI-compatible providers shall use `llm.temperature` and `llm.max_tokens`, and when the caller supplies them the providers shall use the caller's values. <!-- openspec: llm § Ollama and OpenAI-compatible chat --> <!-- test: packages/llm/test/llm.test.ts:72 (openai only) -->
- [x] **LLM-CHAT-005**: If an Ollama or OpenAI-compatible chat request returns a non-2xx status, then the provider shall throw an error containing the provider name, the status and the response body. <!-- openspec: llm § Ollama and OpenAI-compatible chat --> <!-- test: packages/llm/test/llm.test.ts:72 (openai), packages/llm/test/llm.test.ts:101 (ollama) -->
- [x] **LLM-CHAT-006**: When the supplied `AbortSignal` is aborted, the Ollama, OpenAI-compatible and Claude providers shall reject or abandon the in-flight request. <!-- test: packages/llm/test/llm.test.ts:56 (openai, already-aborted signal only); Claude forwarding is LLM-CLAUDE-010 -->
- [x] **LLM-CHAT-007**: If an Ollama or OpenAI-compatible response contains no message content, then the provider shall return an empty string rather than throw. <!-- no test -->
- [ ] **LLM-CHAT-008**: Where the caller passes no `AbortSignal`, the model-backends package shall bound every `chat()`, `embed()` and `ping()` request with a default timeout read from the `llm` config block, aborting the Ollama and OpenAI-compatible `fetch` and passing the same timeout to the Claude SDK request, so a black-holed backend fails the call instead of hanging it. Gap: no request carries a timeout unless the caller passes a signal (`packages/llm/src/index.ts:74`, `:97`, `:112`, `:141`, `:162`), the Claude SDK uses its own default, and cortex calls `llm.chat(messages)` with no signal (`services/cortex/src/cortex.ts:135`).

## Stop sequences

- [x] **LLM-STOP-001**: When `Ollama.chat` is called without `json: true`, the package shall send `options.stop` equal to `["\n\n", "\n[chat]", "\n[voice]", "\n[screen]"]`. <!-- openspec: llm § Stop sequences --> <!-- test: packages/llm/test/llm.test.ts:33 (asserts only that the list includes "\n\n") -->
- [x] **LLM-STOP-002**: When `OpenAICompatible.chat` is called without `json: true`, the package shall send `stop` equal to `["\n\n", "\n[chat]", "\n[voice]", "\n[screen]"]`. <!-- openspec: llm § Stop sequences --> <!-- test: packages/llm/test/llm.test.ts:24 -->
- [x] **LLM-STOP-003**: When any real provider's `chat` is called with `json: true`, the package shall omit stop sequences from the request entirely. <!-- openspec: llm § Stop sequences --> <!-- test: packages/llm/test/llm.test.ts:24 (openai), packages/llm/test/llm.test.ts:33 (ollama), packages/llm/test/llm.test.ts:180 (Claude) -->
- [x] **LLM-STOP-004**: When a Claude provider's `chat` is called without `json: true`, the package shall send `stop_sequences` equal to `["\n[chat]", "\n[voice]", "\n[screen]"]` and shall not include `"\n\n"`. <!-- openspec: llm § Stop sequences --> <!-- test: packages/llm/test/llm.test.ts:180 -->
- [x] **LLM-STOP-005**: The reply stop list sent to Ollama and OpenAI-compatible providers shall contain at most four entries. <!-- openspec: llm § Stop sequences --> <!-- test: packages/llm/test/llm.test.ts:24 -->
- [x] **LLM-STOP-006**: The transcript stop strings shall be `"\n"` followed by each tag that working-memory's `Context.transcript` renders for chat, voice and screen entries (`\n[chat]`, `\n[voice]`, `\n[screen]`); working-memory owns the tag list (WM-TRANS-006) and this list mirrors it. The stops are a token and latency saver, not the correctness guard for the spoken line (cortex keeps only the first reply line), and the co-host's own `<name>:` line is not a stop. <!-- no test spans both packages: packages/llm/test/llm.test.ts:27 pins the stop list and packages/working-memory/test/context.test.ts:86 pins the tags; the cross-package check is a cortex-level test -->

## Claude providers

- [x] **LLM-CLAUDE-001**: When a Claude provider's `chat` is called, the package shall join all `system` messages with a blank line into the request `system` field, and shall omit `system` when there are none. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:143, packages/llm/test/llm.test.ts:161 (omitted when none) -->
- [x] **LLM-CLAUDE-002**: If the non-system turns are empty or do not begin with a `user` turn, then a Claude provider shall prepend a `user` turn with content `(begin)`. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:161 -->
- [x] **LLM-CLAUDE-003**: When a Claude provider's `chat` is called, the package shall send `max_tokens` equal to the larger of the caller's `maxTokens` and `llm.claude.max_tokens`. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:172 -->
- [x] **LLM-CLAUDE-004**: When a Claude provider's `chat` is called, the package shall send `output_config.effort` from `llm.claude.effort` and shall send no `temperature`. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:143 (asserts effort; does not assert that temperature is absent) -->
- [x] **LLM-CLAUDE-005**: When a Claude response is received, the package shall return only the concatenated text blocks, trimmed, and shall discard thinking blocks. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:143 -->
- [x] **LLM-CLAUDE-006**: When a Claude response has `stop_reason` of `refusal`, the provider shall return an empty string. <!-- openspec: llm § Claude message handling --> <!-- test: packages/llm/test/llm.test.ts:196 -->
- [x] **LLM-CLAUDE-007**: Where the provider is `anthropic` and `llm.claude.fallbacks` is true, the package shall add the beta `server-side-fallback-2026-07-01` and `fallbacks: "default"` to the request, and where `fallbacks` is false it shall add neither. Both names match the installed `@anthropic-ai/sdk` 1.1.0 request types; no test calls the live API (see the LLD Open Questions). <!-- openspec: llm § Server-side fallbacks --> <!-- test: packages/llm/test/llm.test.ts:180 (the off case asserts only that `fallbacks` is absent, not `betas`) -->
- [x] **LLM-CLAUDE-008**: The `bedrock` provider shall not send `betas` or `fallbacks` on any request. <!-- openspec: llm § Server-side fallbacks --> <!-- test: packages/llm/test/llm.test.ts:217 -->
- [x] **LLM-CLAUDE-009**: Where `llm.claude.api_key` is empty, the `anthropic` provider shall construct its client without an explicit key so that the SDK default credential resolution applies, and where `llm.bedrock.region` is empty the `bedrock` provider shall likewise construct its client without a region. <!-- no test: every test constructs the clients with a key or region set -->
- [x] **LLM-CLAUDE-010**: When a Claude provider's `chat` is called with an `AbortSignal`, the package shall pass that signal to the SDK request. <!-- test: packages/llm/test/llm.test.ts:180 -->

## Health ping

- [x] **LLM-PING-001**: When `Ollama.ping` is called, the package shall `GET /api/tags` and return true only on a 2xx response, otherwise returning false with `lastError` naming the status or the unreachable URL. <!-- openspec: llm § Health ping --> <!-- test: packages/llm/test/llm.test.ts:101 (failure paths only; no Ollama ping success case) -->
- [x] **LLM-PING-002**: When `OpenAICompatible.ping` is called, the package shall `GET <base_url>/models` with the configured authorization and return true only on a 2xx response; on any other status it shall set `lastError` to `<base_url>/models answered <status>`, adding a pointer at `llm.openai.api_key` for 401 or 403, and if the request throws it shall set `lastError` to `cannot reach <base_url>: <error>`. <!-- openspec: llm § Health ping --> <!-- test: packages/llm/test/llm.test.ts:42 -->
- [x] **LLM-PING-003**: When `AnthropicProvider.ping` is called, the package shall retrieve the configured model and, on failure, set `lastError` to a credentials hint for status 401 or 403, an unknown-model hint for status 404, and the stringified error otherwise. <!-- openspec: llm § Health ping --> <!-- test: packages/llm/test/llm.test.ts:202 -->
- [x] **LLM-PING-004**: The `bedrock` provider's `ping` shall always return true without any network call (Bedrock has no cheap probe; credential and model errors surface on the first `chat()`, and cortex says so in its heartbeat `detail`). <!-- openspec: llm § Health ping --> <!-- test: packages/llm/test/llm.test.ts:217 -->
- [x] **LLM-PING-005**: When a ping succeeds after an earlier failure, the provider shall reset `lastError` to undefined. <!-- test: packages/llm/test/llm.test.ts:42 (openai), packages/llm/test/llm.test.ts:202 (anthropic) -->

## Embeddings

- [x] **LLM-EMBED-001**: When `Ollama.embed` is called, the package shall `POST /api/embed` with `model` set to `llm.embed_model`, the input text and `keep_alive` `24h`, and return the first vector of the response. <!-- openspec: llm § Embeddings are always Ollama --> <!-- test: packages/llm/test/llm.test.ts:101 -->
- [x] **LLM-EMBED-002**: If the embed response is non-2xx or contains no vector, then `Ollama.embed` shall throw (`ollama embed <status>` or `ollama embed returned no vector`). <!-- openspec: llm § Embeddings are always Ollama --> <!-- test: packages/llm/test/llm.test.ts:101 -->
- [x] **LLM-EMBED-003**: When `createEmbedder` is called, the package shall return a `HashEmbedder` if `llm.provider` is `mock` and an `Ollama` client for every other provider. <!-- openspec: llm § Embeddings are always Ollama --> <!-- test: packages/llm/test/llm.test.ts:267, packages/llm/test/llm.test.ts:63 (anthropic) -->
- [x] **LLM-EMBED-004**: Where `llm.provider` is `mock`, the chat provider choice shall not select memory's embedder: memory picks its embedder with its own `brain.memory.embedder` key (`MEMORY_EMBEDDER`, `ollama` or `hash`), so an isolated run that also wants offline embeddings sets `MEMORY_EMBEDDER=hash` separately (`services/memory/src/backend.ts:8-10`). `createEmbedder` (LLM-EMBED-003) has no production caller. <!-- openspec: llm § Embeddings are always Ollama (superseded: memory keeps its own switch) --> <!-- no test in this segment; memory's switch is MEM-BACKEND-003 -->
- [x] **LLM-EMBED-005**: The `HashEmbedder` shall map text to a deterministic 64-element unit vector by adding +1 or -1 per lowercased Unicode letter/digit token into one of 64 FNV-1a hash buckets, so that identical text gives identical vectors. Texts that share tokens tend to score a higher cosine similarity than unrelated texts, but bucket collisions make this an expectation, not a guarantee (`dog cat`·`dog park` = 0.50 < `dog cat`·`fight` = 0.71); the hash embedder is an isolated-run stand-in, not a similarity model. <!-- openspec: llm § Hash embedder --> <!-- test: packages/llm/test/llm.test.ts:253 (one example triple) -->
- [x] **LLM-EMBED-006**: If the text given to `HashEmbedder.embed` is empty or has no tokens, then the embedder shall return a fixed valid unit vector rather than throw or produce NaN. <!-- openspec: llm § Hash embedder --> <!-- test: packages/llm/test/llm.test.ts:253 -->

- [x] **LLM-MOCK-003**: If the supplied `AbortSignal` is already aborted, then `MockProvider.chat` shall throw. <!-- openspec: llm § Mock provider --> <!-- test: packages/llm/test/llm.test.ts:247 -->
- [x] **LLM-MOCK-004**: The `MockProvider` shall perform no network I/O, `ping` shall return true, and `lastError` shall remain undefined. <!-- openspec: llm § Mock provider --> <!-- test: packages/llm/test/llm.test.ts:232 -->
- [ ] **LLM-MOCK-005**: Where a consumer constructs a chat provider whose `name` is `mock`, the consumer shall log one warn-level message naming the mock backend: cortex at startup (CTX-START-002), each `llm`-kind hook when its `Module` is built (HOOK-WARN-004), and the memory reflect job when it builds its provider. Gap: only cortex warns (`services/cortex/src/index.ts:34`); `llm`-kind hooks (`packages/modules/src/index.ts:43`) and the reflect job (`services/memory/src/reflect.ts:17`) build a mock provider silently. <!-- openspec: llm § Mock is reported, not hidden -->
