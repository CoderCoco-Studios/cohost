# voice specs

Design: [voice-design.md](voice-design.md). Prefix `VOICE`. Audited against the code on 2026-11-02; owner decisions of 2026-11-01 applied at git `1b57790`. `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred. Test paths are relative to the repo root.

## Synthesis

- [ ] **VOICE-SYN-001**: When the voice service starts, it shall subscribe with consumer group `voice` and the event-bus `latest` start mode (BUS-SUB-010) to `brain.say` and `voice.playing`, handling events one at a time, so that the group is moved to the newest stream entry on every start and no `brain.say` published while voice was down is spoken. Gap: the subscription passes `fromNow: true` (`services/voice/src/index.ts:30`), which positions only a newly created group (`packages/bus/src/index.ts:133-138`); an existing group resumes after its last-delivered entry, so a compose restart speaks the backlog. <!-- openspec: voice § Synthesis --> <!-- untested: boot wiring (services/voice/src/index.ts:30) -->
- [x] **VOICE-SYN-002**: When `voice.engine` is `kokoro` and a `brain.say` arrives, the voice service shall POST JSON `{model: "kokoro", input: <text>, voice: voice.voice, speed: voice.speed, response_format: "wav"}` to `<TTS_URL>/v1/audio/speech` and use the response body as the utterance WAV. <!-- openspec: voice § Synthesis --> <!-- test: services/voice/test/voice.test.ts:105 -->
- [x] **VOICE-SYN-003**: If the TTS server returns a non-2xx status, then the voice service shall raise the error "tts <status>: <body>", which is handled as a synthesis failure. <!-- openspec: voice § Synthesis --> <!-- test: services/voice/test/voice.test.ts:105 -->
- [x] **VOICE-SYN-004**: When a `brain.say` has been synthesized, the voice service shall store the WAV under the event `id` before publishing `voice.utterance`. <!-- untested: the ordering is visible only in code (services/voice/src/voice.ts:96-98); voice.test.ts:71 shows the WAV is stored but not that it was stored first -->
- [x] **VOICE-SYN-005**: The voice service shall synthesize every `brain.say` it reads, whatever its `reason`, `injected` or `remember` fields, and shall not subscribe to `control`: mute and pause are applied upstream by cortex and salience. <!-- untested -->
- [ ] **VOICE-SYN-006**: If the voice service's bus subscription rejects (a failure the bus's own retry, BUS-SUB-009, does not absorb), then the voice service shall log the error with message `fatal` and exit with a non-zero status instead of leaving an unhandled rejection. Gap: `void bus.subscribe(...)` at `services/voice/src/index.ts:30` has no `.catch`.

## Stub engine

- [x] **VOICE-STUB-001**: Where `voice.engine` is `stub`, the voice service shall make no HTTP request to the TTS service and shall synthesize a zero-filled mono 16-bit WAV at `voice.sample_rate` lasting `max(400, 60 * text.length)` milliseconds. <!-- openspec: voice § Stub engine --> <!-- test: services/voice/test/stub.test.ts:11 --> <!-- test: services/voice/test/stub.test.ts:21 --> <!-- test: services/voice/test/stub.test.ts:30 -->
- [x] **VOICE-STUB-002**: Where `voice.engine` is `stub`, when a `brain.say` arrives, the voice service shall publish a real `voice.utterance` with `durationMs`, `sampleRate`, an all-zero 30 Hz `envelope` and a fetchable `audioUrl`. <!-- openspec: voice § Stub engine --> <!-- test: services/voice/test/stub.test.ts:30 -->
- [x] **VOICE-STUB-003**: Where `voice.engine` is `stub`, the voice service shall log a startup warning that utterances are silent. <!-- openspec: voice § Isolation preset and mode --> <!-- untested: boot wiring (services/voice/src/index.ts:23) -->

## Utterance publication

- [x] **VOICE-UTT-001**: When a `brain.say` is synthesized, the voice service shall publish `voice.utterance` carrying `id`, `text`, `emotion`, `gesture`, `durationMs` (rounded from the WAV), `envelopeHz` 30, `envelope`, `audioUrl` and `sampleRate` (from the WAV). <!-- openspec: voice § voice.utterance publication --> <!-- test: services/voice/test/voice.test.ts:21 -->
- [x] **VOICE-UTT-002**: The voice service shall set `audioUrl` to `<urls.voice()>/audio/<id>.wav`, where `urls.voice()` is `VOICE_URL` or else `http://127.0.0.1:<VOICE_PORT>` (default port 8700). <!-- openspec: voice § voice.utterance publication --> <!-- test: services/voice/test/voice.test.ts:21 --> <!-- note: the loopback default is deliberate (commit e53badc, tested at packages/config/test/config.test.ts:207); compose sets VOICE_URL=http://voice:8700. The frozen OpenSpec baseline still says http://voice:<VOICE_PORT>. -->
- [x] **VOICE-UTT-003**: If synthesis, WAV parsing, envelope extraction or publishing of `voice.utterance` fails for a `brain.say`, then the voice service shall log the error "tts failed", publish `voice.done` with that `id` and `sink` `error`, and publish no `voice.utterance`. <!-- openspec: voice § Failure handling --> <!-- test: services/voice/test/voice.test.ts:61 (synthesis and parse failures only) -->

## WAV and lip-sync envelope

- [x] **VOICE-ENV-001**: When parsing a WAV, the voice service shall require a `RIFF`/`WAVE` header, skip unknown and odd-sized chunks, read channels, sample rate and bit depth from `fmt `, clamp the data length to the bytes present, and compute duration in milliseconds from the frame count. <!-- test: services/voice/test/wav.test.ts:26 --> <!-- test: services/voice/test/wav.test.ts:37 --> <!-- test: services/voice/test/wav.test.ts:43 -->
- [x] **VOICE-ENV-002**: If a buffer is not RIFF/WAVE or has no data chunk, then `parseWav` shall throw "not a RIFF/WAVE file" or "no data chunk" respectively. <!-- openspec: voice § Envelope extraction --> <!-- test: services/voice/test/wav.test.ts:49 -->
- [x] **VOICE-ENV-003**: When computing a lip-sync envelope, the voice service shall emit one value per window of `floor(sampleRate / 30)` frames of the first channel (including a partial last window), each `min(1, (rms / 0.22) ^ 0.8)`, smoothed so each value is at least 0.6 times the previous one, rounded to 2 decimals. <!-- openspec: voice § Envelope extraction --> <!-- test: services/voice/test/wav.test.ts:55 --> <!-- test: services/voice/test/wav.test.ts:69 -->
- [x] **VOICE-ENV-004**: If a WAV is not 16-bit, then envelope extraction shall throw "unsupported bit depth <n>". <!-- openspec: voice § Envelope extraction --> <!-- test: services/voice/test/wav.test.ts:89 -->

## Sink arbitration

- [x] **VOICE-SINK-001**: When the voice service reads a `voice.playing` whose `sink` is not `virtual`, it shall record the event `id` as claimed by a real sink. <!-- openspec: voice § Virtual sink --> <!-- test: services/voice/test/voice.test.ts:51 -->
- [x] **VOICE-SINK-002**: When 1500 ms have passed since the voice service published a `voice.utterance` and its `id` has not been claimed, the voice service shall publish `voice.playing` with that `id` and `sink` `virtual`. <!-- openspec: voice § Virtual sink --> <!-- test: services/voice/test/voice.test.ts:37 -->
- [x] **VOICE-SINK-003**: When the voice service has published a virtual `voice.playing`, it shall publish `voice.done` with the same `id` and `sink` `virtual` after the utterance `durationMs`. <!-- openspec: voice § Virtual sink --> <!-- test: services/voice/test/voice.test.ts:37 -->
- [x] **VOICE-SINK-004**: If an utterance `id` has been claimed by a non-virtual sink when its 1500 ms claim window ends, then the voice service shall publish no virtual `voice.playing` or `voice.done` for it. <!-- openspec: voice § Virtual sink --> <!-- test: services/voice/test/voice.test.ts:51 -->
- [x] **VOICE-SINK-005**: The voice service shall not treat its own `sink: "virtual"` `voice.playing` as a claim. <!-- untested: not observable unless an id is re-used, because the virtual voice.playing is only published after the claim check (services/voice/src/voice.ts:107-109); voice.test.ts:55 sends a virtual echo for an id that was never said -->
- [x] **VOICE-SINK-006**: If synthesis fails for an utterance, then the voice service shall publish `voice.done` with `sink` `error` and shall arm no virtual-sink timers, so that cortex is released without any audio. <!-- openspec: voice § Failure handling --> <!-- test: services/voice/test/voice.test.ts:61 -->
- [ ] **VOICE-SINK-007**: While the voice service is running, it shall bound the set of claimed utterance ids (for example by dropping a claim when its audio is evicted from the store). <!-- gap: voice.ts:70,84 add to claimed and never remove, while the audio store is capped at 50 (voice.ts:77) -->
- [ ] **VOICE-SINK-008**: When a non-virtual sink's `voice.playing` for an utterance `id` arrives after the voice service has published its virtual `voice.playing` for that `id` and before the virtual `voice.done`, the voice service shall cancel the pending virtual `voice.done`, so that the only `voice.done` published for the `id` afterwards is the real sink's own. Gap: the virtual `voice.done` timer is armed unconditionally (`services/voice/src/voice.ts:110`) and the claim set is read only once, when the 1.5 s timer fires (`voice.ts:108`); a sink that starts late (ears queues behind earlier audio, `services/ears/src/playback.ts:39-46`) gets a second `voice.done` from `virtual`, which releases cortex while the real audio is still playing. <!-- openspec: voice § Virtual sink -->
- [ ] **VOICE-SINK-009**: If publishing a virtual `voice.playing` or `voice.done` fails, then the voice service shall log the failure and keep running. Gap: the timer callbacks publish with no `.catch` (`services/voice/src/voice.ts:109-110`), so a failure (for example a Redis outage that outlasts the publisher's retries) is an unhandled rejection that ends the process.

## Audio store and HTTP

- [x] **VOICE-HTTP-001**: The voice service shall keep at most the newest 50 synthesized WAVs in memory, evicting the oldest first. <!-- openspec: voice § Audio store and HTTP --> <!-- test: services/voice/test/voice.test.ts:91 -->
- [x] **VOICE-HTTP-002**: When `GET /audio/<id>.wav` is requested for a stored id, the voice service shall respond 200 with `content-type: audio/wav`, the WAV length and `access-control-allow-origin: *`. <!-- openspec: voice § Audio store and HTTP --> <!-- test: services/voice/test/voice.test.ts:71 -->
- [x] **VOICE-HTTP-003**: If `GET /audio/<id>.wav` names an unknown or evicted id (ids are limited to word characters and hyphens), then the voice service shall respond 404 with body `gone`, and for any other path it shall respond 404 with an empty body. <!-- openspec: voice § Audio store and HTTP --> <!-- test: services/voice/test/voice.test.ts:71 --> <!-- test: services/voice/test/voice.test.ts:91 (status codes only; no test reads the 404 bodies) -->
- [x] **VOICE-HTTP-004**: When `GET /health` is requested, the voice service shall respond 200 with body `ok`. <!-- openspec: voice § Audio store and HTTP --> <!-- test: services/voice/test/voice.test.ts:71 -->
- [x] **VOICE-HTTP-005**: The voice service shall listen for HTTP on `VOICE_PORT` (default 8700). <!-- openspec: voice § voice.utterance publication --> <!-- untested: boot wiring (services/voice/src/index.ts:21,27-28) -->

## Health

- [x] **VOICE-HLTH-001**: When the voice service's HTTP server is listening, it shall report heartbeat state `ready` with `service` `voice` and `deps` `{kokoro}`; with the `kokoro` engine, mode shall be `live`. <!-- openspec: voice § Heartbeat (add-service-health) --> <!-- test: services/voice/test/health.test.ts:6 (heartbeat spec only; the listen-then-ready wiring at index.ts:28 is untested) -->
- [x] **VOICE-HLTH-002**: When a Kokoro synthesis fails, the voice service shall set `deps.kokoro` to `down` (heartbeat `degraded`) and set it back to `ok` when the next synthesis succeeds. <!-- openspec: voice § Heartbeat (add-service-health) --> <!-- test: services/voice/test/health.test.ts:13 -->
- [x] **VOICE-HLTH-003**: Where `voice.engine` is `stub`, the voice service shall report heartbeat mode `mock` with `deps.kokoro` `n/a` and state `ready`. <!-- openspec: voice § Isolation preset and mode --> <!-- test: services/voice/test/stub.test.ts:52 -->
- [x] **VOICE-HLTH-004**: When the voice service receives SIGINT or SIGTERM, it shall publish one `stopping` heartbeat, close its HTTP server, stop the bus and exit with code 0. <!-- openspec: voice § Heartbeat (add-service-health) --> <!-- test: services/voice/test/health.test.ts:6 (the single stopping heartbeat only; signal handling, server close and exit are untested) -->
