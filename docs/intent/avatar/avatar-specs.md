# avatar specs

Mapped 2026-10-31 at git `686cc8f`; audited against the code on 2026-11-02; owner decisions of 2026-11-01 applied at git `1b57790`. Prefix `AVATAR`. Design: [avatar-design.md](avatar-design.md). `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred.

## Bus wiring

- [ ] **AVATAR-BUS-001**: When the avatar service has started its engine, the system shall subscribe to the event bus with consumer group `avatar` and the event-bus `latest` start mode (BUS-SUB-010) for `voice.utterance`, `voice.playing`, `voice.done`, `brain.say` and `affect.state`, so that the group is moved to the newest stream entry on every start and events published while avatar was down are not replayed. Gap: the subscription passes `fromNow: true` (`services/avatar/src/index.ts:34-35`), which positions only a newly created group (`packages/bus/src/index.ts:133-138`); an existing group resumes and a compose restart replays stale expressions and lip-sync. <!-- openspec: avatar § Bus events consumed --> <!-- untested: no test of services/avatar/src/index.ts -->
- [x] **AVATAR-BUS-002**: When a `brain.say` event arrives, the avatar service shall set the animation engine's emotion to the event's emotion with a 6000 ms hold, before any audio exists. <!-- openspec: avatar § Bus events consumed --> <!-- untested -->
- [x] **AVATAR-BUS-003**: When a `voice.utterance` event arrives, the avatar service shall register the utterance's id, emotion, gesture, mouth envelope, envelope rate and duration with the engine without starting playback. <!-- openspec: avatar § Bus events consumed --> <!-- untested -->
- [x] **AVATAR-BUS-004**: When a `voice.playing` event arrives (from any sink; the `sink` field is not examined), the avatar service shall start lip-sync playback of the utterance with that id. <!-- openspec: avatar § Bus events consumed --> <!-- untested -->
- [x] **AVATAR-BUS-005**: When a `voice.done` event arrives, the avatar service shall tell the engine that utterance finished. <!-- openspec: avatar § Bus events consumed --> <!-- untested -->
- [x] **AVATAR-BUS-006**: When an `affect.state` event arrives, the avatar service shall pass its `mood` to the engine as the resting face. <!-- openspec: avatar § Lip-sync and mood --> <!-- untested -->
- [ ] **AVATAR-BUS-007**: If any avatar service startup step fails (config load, driver creation, expressions load, or a rejecting `driver.connect`), then the service shall log the error with message `fatal` and exit with status 1. Gap: config loading, driver creation, the heartbeat and the expressions load run at module level (`services/avatar/src/index.ts:12-19`), outside `main()` and its `.catch` (`index.ts:57`), so their failures end the process without the `fatal` log. <!-- untested -->
- [ ] **AVATAR-BUS-008**: If the avatar service's bus subscription loop rejects (a Redis error other than a dropped connection, such as its consumer group being deleted), then the service shall log the failure and exit non-zero instead of leaving an unhandled rejection. (Gap: `void bus.subscribe(...)` at `services/avatar/src/index.ts:34` is outside `main().catch`. A dropped connection does not reject the loop: the subscriber waits for the reconnect, `packages/bus/src/index.ts:124`.)

## Animation engine

- [x] **AVATAR-ENG-001**: While the engine is started, the system shall compute one animation frame every `1000 / avatar.fps` ms and, in each frame, call `driver.setParams` with the smoothed parameters and report the state to the `onState` callback. <!-- openspec: avatar § Animation loop --> <!-- test: services/avatar/test/engine.test.ts:46 -->
- [x] **AVATAR-ENG-002**: When the engine's `prepare` is called, the engine shall store the utterance by id and keep at most 20, evicting the earliest-inserted id first; re-preparing a stored id shall replace its data without changing its eviction order. <!-- openspec: avatar § Bus events consumed --> <!-- test: services/avatar/test/engine.test.ts:75 (eviction of distinct ids only) -->
- [x] **AVATAR-ENG-003**: When the engine's `play` is called with a prepared utterance id, the engine shall start lip-sync from that moment, set the utterance's emotion at intensity 1 with a hold of `durationMs + 4000` ms, and trigger the utterance's gesture on the driver if it has one. <!-- openspec: avatar § Bus events consumed --> <!-- test: services/avatar/test/engine.test.ts:67 -->
- [x] **AVATAR-ENG-004**: If the engine's `play` is called with an id that was never prepared or has been evicted, then the engine shall ignore it. <!-- openspec: avatar § Bus events consumed --> <!-- test: services/avatar/test/engine.test.ts:75 -->
- [x] **AVATAR-ENG-005**: While an utterance is playing, the engine shall set the mouth-open target to `envelope[floor(elapsedSeconds * envelopeHz)]`, and to 0 once the index is past the end of the envelope. <!-- openspec: avatar § Lip-sync and mood --> <!-- test: services/avatar/test/engine.test.ts:56 -->
- [x] **AVATAR-ENG-006**: When the envelope index is past the end of the envelope and more than `durationMs + 500` ms have elapsed since playback started, the engine shall clear the playing utterance even if no `done` was received. <!-- openspec: avatar § Lip-sync and mood --> <!-- untested -->
- [x] **AVATAR-ENG-007**: When the engine's `done` is called with the id of the playing utterance, the engine shall stop playback so that the mouth-open target is 0 from the next frame; when called with any other id it shall have no effect. <!-- test: services/avatar/test/engine.test.ts:85 -->
- [x] **AVATAR-ENG-008**: When the engine's `setEmotion` is called, the engine shall make that emotion current, hold it for the given duration (default 4000 ms) and immediately call `driver.setExpression(emotion, 1)`. <!-- test: services/avatar/test/engine.test.ts:98 --> <!-- test: services/avatar/test/engine.test.ts:111 -->
- [x] **AVATAR-ENG-009**: When the engine's `setMood` is called with a mood different from the current mood while no emotion hold is active, the engine shall show the mood immediately via `driver.setExpression` at intensity 0.5, or 0 for `neutral`. <!-- openspec: avatar § Lip-sync and mood --> <!-- test: services/avatar/test/engine.test.ts:98 --> <!-- test: services/avatar/test/engine.test.ts:121 -->
- [x] **AVATAR-ENG-010**: While an emotion hold is active, the engine shall store a changed mood without changing the displayed expression until the hold expires; calling `setMood` with the unchanged mood shall do nothing. <!-- openspec: avatar § Lip-sync and mood --> <!-- test: services/avatar/test/engine.test.ts:111 -->
- [x] **AVATAR-ENG-011**: When an emotion hold expires and the current emotion differs from the mood, the engine shall return to the mood via `driver.setExpression` at intensity 0.5, or 0 for `neutral`. <!-- openspec: avatar § Lip-sync and mood --> <!-- test: services/avatar/test/engine.test.ts:98 -->
- [x] **AVATAR-ENG-012**: In each frame, the engine shall set the smile target to 0.7 when the current emotion is `happy`, `laugh` or `smug`, and to 0.15 otherwise. <!-- openspec: avatar § Animation loop --> <!-- test: services/avatar/test/engine.test.ts:130 -->
- [x] **AVATAR-ENG-013**: Where `avatar.idle_motion` is enabled, the engine shall drift head yaw/pitch/roll and eye position with slow sine waves, with head yaw and pitch amplified by 1.6 while an utterance is playing; where it is disabled the engine shall leave head and eye targets at neutral. <!-- openspec: avatar § Animation loop --> <!-- test: services/avatar/test/engine.test.ts:145 -->
- [x] **AVATAR-ENG-014**: The engine shall blink for 120 ms, the first time about 3 s after construction and thereafter after a random 2.5 to 6 s interval. <!-- openspec: avatar § Animation loop --> <!-- test: services/avatar/test/engine.test.ts:157 -->
- [x] **AVATAR-ENG-015**: In each frame, the engine shall move every parameter toward its target by `avatar.smoothing`, except mouth-open at `min(1, smoothing * 3)` and blink at 1 (no smoothing). <!-- openspec: avatar § Animation loop --> <!-- test: services/avatar/test/engine.test.ts:168 -->
- [x] **AVATAR-ENG-016**: In each frame, the engine shall report an intensity of 0 when the current emotion is `neutral`, 1 while an emotion hold is active, and 0.5 otherwise. <!-- openspec: avatar § State publication --> <!-- test: services/avatar/test/engine.test.ts:98 --> <!-- test: services/avatar/test/engine.test.ts:121 -->

## Driver contract and selection

- [ ] **AVATAR-DRV-001**: The system shall define an avatar driver contract of `name`, `connect`, `disconnect`, `connected`, `setParams` (every frame), `setExpression` (on emotion change) and `trigger` (fire-and-forget gesture), operating on canonical parameters (angles in degrees, other values 0..1, eyes -1..1), with no capability declaration. Gap: the interface still declares `capabilities()` (`services/avatar/src/types.ts:37`), which every driver implements and only the startup log reads (`services/avatar/src/index.ts:31`). <!-- openspec: avatar § Driver contract and selection --> <!-- held by the type checker (each driver `implements AvatarDriver`), not by a test -->
- [x] **AVATAR-DRV-002**: When the avatar service starts, it shall create the driver named by `avatar.driver` (`vtube-studio`, `vmc` or `null`) with that driver's host, port and plugin settings from config. <!-- openspec: avatar § Driver contract and selection --> <!-- test: services/avatar/test/drivers.test.ts:30 -->
- [ ] **AVATAR-DRV-003**: The avatar driver factory shall accept only `vtube-studio`, `vmc` and `null`, with no fallback for any other name, because config validation rejects an unrecognised `avatar.driver` before the service starts (AVATAR-DRV-004). Gap: `createDriver` keeps a `default:` branch that returns a null driver (`services/avatar/src/drivers/index.ts:24-25`), unreachable through `loadConfig`. <!-- untested -->
- [ ] **AVATAR-DRV-004**: If `AVATAR_DRIVER` holds a value other than `vtube-studio`, `vmc` or `null`, then loading the configuration shall fail with a validation error naming `avatar.driver` before any service starts; an unset or empty `AVATAR_DRIVER` shall select the null driver. Gap: unknown values already fail (`packages/config/src/schema.ts:167`, `packages/config/src/index.ts:103-108`), but an unset or empty variable fails the same way, because the example YAML writes `driver: "${AVATAR_DRIVER}"` with no default (`config/config.example.yaml:134`) and `""` is not in the enum; the fix (`${AVATAR_DRIVER:-null}`, a blank-safe driver value, port defaults) is in config.
- [x] **AVATAR-DRV-005**: When the avatar service starts, it shall load `expressions.yaml`, use the block named after the active driver (an empty map when the block is absent), and split its `gestures` sub-map from the emotion-to-expression map. <!-- openspec: avatar § Driver contract and selection --> <!-- untested -->
- [x] **AVATAR-DRV-006**: When the avatar service connects its driver, it shall pass the emotion map, the gesture map, a logger and the config directory as the driver's state directory. <!-- untested -->
- [x] **AVATAR-DRV-007**: The null driver shall report itself connected, ignore parameters, and only log expression and gesture requests. <!-- openspec: avatar § Driver contract and selection --> <!-- test: services/avatar/test/drivers.test.ts:37 -->

## VTube Studio driver

- [x] **AVATAR-VTS-001**: When the VTube Studio driver connects, it shall open a WebSocket to `vtube_studio.host:port`, authenticate, load the current model's hotkeys, and only then report itself connected. <!-- openspec: avatar § VTube Studio driver --> <!-- test: services/avatar/test/drivers.test.ts:133 -->
- [ ] **AVATAR-VTS-002**: While the VTube Studio driver's first connection attempt is in progress or has failed (VTube Studio unreachable, slow, or waiting for the operator to allow the plugin), the avatar service shall already run its engine and bus subscription, the driver's `connect` shall not reject, and the driver shall report itself disconnected until it authenticates. Gap: `connect()` never rejects, but `main()` awaits the first attempt before `engine.start()` and the subscription (`services/avatar/src/index.ts:30-34`): up to 60 s while a first-time token request waits for the operator (`services/avatar/src/drivers/vtube-studio.ts:146`), and the operating system's TCP connect timeout for a host that drops packets, since the socket has no handshake timeout (`vtube-studio.ts:109`). <!-- test: services/avatar/test/drivers.test.ts:172 (connect resolves on connection refused; the non-blocking start is untested) -->
- [x] **AVATAR-VTS-003**: When no plugin token is saved in `<config dir>/.vts-token`, the VTube Studio driver shall request one (waiting up to 60 s for the operator to allow it in VTube Studio), save it, and then authenticate with it; when a token is saved it shall authenticate without requesting a new one. <!-- openspec: avatar § VTube Studio driver --> <!-- test: services/avatar/test/drivers.test.ts:133 -->
- [x] **AVATAR-VTS-004**: If VTube Studio rejects the saved token, then the driver shall blank the token file, treat the attempt as failed and close the socket so the next attempt requests a fresh token. <!-- openspec: avatar § VTube Studio driver --> <!-- test: services/avatar/test/drivers.test.ts:153 -->
- [x] **AVATAR-VTS-005**: If any authentication or hotkey-loading request fails (API error, timeout or closed socket), then the driver shall log the error and close the socket. <!-- test: services/avatar/test/drivers.test.ts:164 -->
- [x] **AVATAR-VTS-006**: If a VTube Studio request receives no reply within its timeout (5 s unless stated), then the driver shall reject that request with a "timed out" error. <!-- openspec: avatar § VTube Studio driver --> <!-- untested -->
- [x] **AVATAR-VTS-007**: If the VTube Studio socket closes while the driver has not been asked to disconnect, then the driver shall mark itself disconnected, reject all pending requests and reconnect after 5 s; a requested `disconnect` shall cancel any pending reconnect. <!-- openspec: avatar § VTube Studio driver --> <!-- untested: drivers.test.ts:153 passes through the close handler but asserts neither the reconnect nor its cancellation -->
- [x] **AVATAR-VTS-008**: While the driver is connected, each `setParams` call shall send an `InjectParameterDataRequest` (mode `set`, `faceFound` true) with mouth open/smile, head angle X/Y/Z, eye X/Y for both eyes and eye-open (one minus blink) for both eyes, clamped to the VTube Studio ranges, without waiting for a reply. <!-- test: services/avatar/test/drivers.test.ts:179 -->
- [x] **AVATAR-VTS-009**: When the driver is asked to show an emotion, it shall take the emotion's mapped name as the target when the intensity is above 0.05 and no expression otherwise; if the target equals the active expression it shall send nothing, otherwise it shall deactivate the active expression (if any), activate the target (if any) and record the target as the active expression. <!-- test: services/avatar/test/drivers.test.ts:195 -->
- [x] **AVATAR-VTS-010**: When the mapped expression name ends in `.exp3.json`, the driver shall activate or deactivate it with `ExpressionActivationRequest`; for any other name it shall look the name up case-insensitively among the model's hotkeys and send `HotkeyTriggerRequest` for both activation and deactivation (hotkeys toggle). <!-- test: services/avatar/test/drivers.test.ts:195 -->
- [x] **AVATAR-VTS-011**: When the driver is asked to trigger a gesture, it shall map it through the gesture map, find the hotkey case-insensitively and trigger it; an unmapped gesture shall be ignored silently and a mapped gesture with no matching hotkey shall log a warning. <!-- test: services/avatar/test/drivers.test.ts:215 -->
- [x] **AVATAR-VTS-012**: While the driver is not connected (not yet authenticated or after a close), `setParams`, `setExpression` and `trigger` shall send nothing and not throw. <!-- test: services/avatar/test/drivers.test.ts:230 (before authentication only) -->
- [ ] **AVATAR-VTS-013**: When the VTube Studio connection closes or is re-established, the driver shall clear its record of the active expression so that hotkey toggle bookkeeping matches the freshly connected application. (Gap: `activeExpr` (`services/avatar/src/drivers/vtube-studio.ts:28`) is never reset in `open()` or the close handler, `:106-133`.)
- [ ] **AVATAR-VTS-014**: If a fire-and-forget VTube Studio request (parameter injection, expression activation, gesture trigger) fails or times out, then the driver shall absorb and log the failure instead of leaving an unhandled promise rejection. (Gap: `void this.send(...)` / `void this.activate(...)` at `drivers/vtube-studio.ts:55, 78-79, 89`.)
- [x] **AVATAR-VTS-015**: If an expression's mapped name is not a `.exp3.json` file and matches none of the model's hotkeys, then the VTube Studio driver shall log a warning and send nothing for it. <!-- untested; services/avatar/src/drivers/vtube-studio.ts:98-99 -->

## VMC driver

- [x] **AVATAR-VMC-001**: When the VMC driver connects, it shall open a UDP socket and report itself connected without a handshake; while it is not connected, `setParams` shall send nothing. <!-- test: services/avatar/test/drivers.test.ts:63 -->
- [x] **AVATAR-VMC-002**: While connected, each `setParams` call shall send to `vmc.host:port`, in order, the head bone rotation as a quaternion, the mouth-open value as blendshapes `A` and `aa`, the blink value as `Blink` and `blink`, the active expression value if any, `/VMC/Ext/Blend/Apply`, and `/VMC/Ext/OK` with int32 1. <!-- openspec: avatar § VMC driver --> <!-- test: services/avatar/test/drivers.test.ts:63 -->
- [x] **AVATAR-VMC-003**: When the VMC driver is asked to show an emotion, it shall clamp the intensity to 0..1, send the previous expression's blendshape at 0 if the mapped name changed, and then include the new expression's blendshape in every following frame. <!-- test: services/avatar/test/drivers.test.ts:63 -->
- [x] **AVATAR-VMC-004**: The VMC driver shall not support gestures: it shall ignore `trigger`. <!-- untested -->
- [ ] **AVATAR-VMC-005**: If sending a VMC UDP datagram fails (for example the configured host does not resolve), then the driver shall log the failure and keep running. (Gap: no `error` listener or send callback at `drivers/vmc.ts:32, 50, 56`; an unresolvable host raises an unhandled socket `error`.)
- [x] **AVATAR-VMC-006**: When the VMC driver disconnects, it shall close its UDP socket and report itself disconnected. <!-- test: services/avatar/test/drivers.test.ts:63 -->

## State publication

- [ ] **AVATAR-STATE-001**: While the engine is running, the avatar service shall publish `avatar.state` carrying every canonical parameter (`mouthOpen`, `mouthSmile`, `headX`, `headY`, `headZ`, `eyeX`, `eyeY`, `blink`), `emotion`, `intensity`, the driver name and the driver's connected flag, at most once every 200 ms. Gap: the service passes `mouthSmile` (`services/avatar/src/index.ts:26`), but the `avatar.state` schema has no such field and publish strips it (`packages/bus/src/events.ts:159-171`; BUS-EVT-018), so the dashboard preview reads `undefined`. <!-- openspec: avatar § State publication --> <!-- untested -->
- [ ] **AVATAR-STATE-002**: If publishing `avatar.state` fails, then the avatar service shall drop that state, log the failure at most once per interval rather than once per frame, and keep running. Gap: `void bus.publish("avatar.state", ...)` (`services/avatar/src/index.ts:26`) has no `.catch`; once the publisher's three retries run out (`packages/bus/src/index.ts:44`), about a second into a Redis outage, the rejection is unhandled and ends the process.

## Health

- [x] **AVATAR-HEALTH-001**: When the avatar service has selected its driver (before the driver connects), it shall mark its `avatar` heartbeat ready. <!-- openspec: avatar § Heartbeat (add-service-health) --> <!-- untested: boot wiring (services/avatar/src/index.ts:16) -->
- [x] **AVATAR-HEALTH-002**: Where the null driver is selected, the avatar heartbeat shall report mode `off` and dependency `driver` as `n/a`. <!-- openspec: avatar § Heartbeat (add-service-health) --> <!-- test: services/avatar/test/health.test.ts:6 -->
- [x] **AVATAR-HEALTH-003**: Where a real driver is selected, the avatar heartbeat shall report mode `live` and dependency `driver` as `ok` while the driver is connected and `down` otherwise (making the service state `degraded`). <!-- openspec: avatar § Heartbeat (add-service-health) --> <!-- test: services/avatar/test/health.test.ts:13 -->
- [x] **AVATAR-HEALTH-004**: When the avatar service receives SIGINT or SIGTERM, it shall publish one `stopping` heartbeat, stop the engine, disconnect the driver, stop the bus and exit with code 0. <!-- untested: boot wiring (services/avatar/src/index.ts:58) -->
