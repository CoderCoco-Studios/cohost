# affect specs

Prefix `AFF`. Design: [affect-design.md](affect-design.md). Code: `services/affect/`. Verified against the code at git `49ba935` (audit pass 2026-11-02). Owner decisions of 2026-11-01 applied at git `1b57790`. Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred.

## Event Intake (IN)

- [ ] **AFF-IN-001**: When the affect service starts, it shall subscribe with consumer group `affect` in start mode `latest` (the group is moved to the stream tail on every start, so lines published while affect was down never nudge the mood) to `chat.message`, `chat.removed`, `speech.heard`, `vision.summary`, `brain.say` and `control`. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/main.test.ts -->
- [ ] **AFF-IN-002**: When affect receives a `chat.message` that its counter admits, it shall appraise the line as source `chat` (passing `mentionsCohost`) and set the mood cause to `chat: <user>`, with the bounded user name. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/affect.region.test.ts -->
- [ ] **AFF-IN-003**: When affect receives a `speech.heard` event, it shall appraise the line as source `speech` with `mention` false (a voice line addressed to the co-host gets no mention boost; speech already has the higher base arousal of AFF-APPR-001) and set the mood cause to `voice: <speaker>` with the speaker as bounded by AFF-IN-009. <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-IN-004**: When affect receives a `chat.message` with `isSub` true, it shall additionally nudge valence by `brain.affect.nudge_sub_valence` (default +0.05) and arousal by `nudge_sub_arousal` (default +0.05) with cause `sub: <user>`. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-IN-005**: When affect receives a `vision.summary` with `changed` true, it shall nudge arousal by `brain.affect.nudge_screen_arousal` (default +0.08) with cause `screen changed`; when `changed` is false it shall not change the mood. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/affect.region.test.ts --><!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-IN-006**: When affect receives a `brain.say`, it shall nudge valence by `brain.affect.nudge_said_valence` (default +0.08) for emotion `happy`, `laugh` or `smug`, by the same amount negated for `sad` or `angry`, by 0 for any other emotion, and arousal by `nudge_said_arousal` (default +0.05), with cause `said: <emotion>`. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-IN-007**: When affect receives `control` `forget_context` addressed to it, it shall apply the pending decay first and then set valence to `baseline_valence` and arousal to the resting arousal (AFF-MOOD-006) with cause `reset`, so the mood lands exactly on baseline. <!-- openspec: affect § Event subscriptions and nudges --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/affect.region.test.ts -->
- [ ] **AFF-IN-008**: When affect receives a `chat.message`, it shall bound the text with `boundText(text, viewer_text.max_chars)` and the user name with `boundText(user, viewer_text.max_name_chars)`, using `unknown` when the name bounds to nothing, before any other use of them.
- [ ] **AFF-IN-009**: When affect receives a `speech.heard`, it shall bound the text with `boundText(text, brain.input_limits.speech_max_chars)` and the speaker name with `boundText(speaker, viewer_text.max_name_chars)`, using `unknown` when the name bounds to nothing, before any other use of them.
- [ ] **AFF-IN-010**: When the affect service starts, it shall create one `createOnceCounter` with `windowMs` equal to `brain.affect.count_window_ms` for counting chat toward the mood.
- [ ] **AFF-IN-011**: When affect receives a `chat.message` while not paused, it shall call `admit(viewerKey, text, now)` of its counter in the event handler at receipt, with the `@cohost/shared/untrusted` `viewerKey` of the event's `platform`, `userId` and bounded `user`, the bounded text and its monotonic clock, before any appraiser job is queued.
- [ ] **AFF-IN-012**: If `admit` refuses a `chat.message`, then affect shall not appraise the line, shall not apply the subscriber nudge and shall not change the mood cause.
- [ ] **AFF-IN-013**: If `admit` refuses a `chat.message`, then affect shall leave the counter's recorded times unchanged, so a viewer who keeps posting moves the mood once per window.
- [ ] **AFF-IN-014**: When affect receives a `chat.message` that mentions the co-host, it shall count it through the counter like any other chat line, with no exemption for a mention.
- [ ] **AFF-IN-015**: Affect shall not pass a `speech.heard` line through the chat counter.
- [ ] **AFF-IN-016**: When affect handles `forget_context`, it shall replace its counter with a new one.
- [ ] **AFF-IN-017**: When affect receives a `chat.removed`, it shall drop every queued appraisal job, not yet started, for a chat line that the removal covers (by `platform` and `messageId` for `scope` `message`, by `platform` and `userId` for `user`, by `platform` for `all`).
- [ ] **AFF-IN-018**: When affect receives a `chat.removed`, it shall leave the mood, its cause and the counter's recorded keys unchanged.
- [ ] **AFF-IN-019**: When affect receives a `chat.removed` that covers an appraisal job already running, it shall let that job finish.
- [ ] **AFF-IN-020**: When affect counts two chat lines with the same display name and different platforms, or the same platform and different user ids, it shall admit both as two viewers.

## Mood Model (MOOD)

- [x] **AFF-MOOD-001**: The affect mood shall start at valence `brain.affect.baseline_valence` (default 0.15) and at the resting arousal (AFF-MOOD-006, default 0.1). <!-- openspec: affect § Mood model and decay --> <!-- test: services/affect/test/affect.test.ts -->
- [x] **AFF-MOOD-002**: When the mood is nudged, affect shall clamp valence to [-1, 1] and arousal to [0, 1]. <!-- openspec: affect § Mood model and decay --> <!-- test: services/affect/test/affect.test.ts -->
- [x] **AFF-MOOD-003**: When time elapses, affect shall decay valence toward `baseline_valence` and arousal toward the resting arousal (AFF-MOOD-006) exponentially, halving the distance every `brain.affect.half_life_ms` (default 45000), applying the decay lazily whenever the mood is nudged, appraised or published. <!-- openspec: affect § Mood model and decay --> <!-- test: services/affect/test/affect.test.ts -->
- [x] **AFF-MOOD-004**: When affect labels a mood, it shall map arousal above 0.6 to `laugh` (valence above 0.3), `angry` (valence below -0.3) or `surprised`; arousal above 0.3 to `happy` (valence above 0.2), `confused` (valence below -0.2) or `think`; otherwise to `smug` (valence above 0.35), `sad` (valence below -0.3) or `neutral`. <!-- openspec: affect § Mood label --> <!-- test: services/affect/test/affect.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-MOOD-005**: When affect reports its state, it shall round valence and arousal to 3 decimals and include the label and the most recent cause. <!-- openspec: affect § Publishing affect.state --> <!-- test: services/affect/test/affect.test.ts -->
- [x] **AFF-MOOD-006**: The affect service shall take its resting arousal from `brain.affect.baseline_arousal` (0..1, default 0.1) and use it as the initial arousal, the decay target and the `forget_context` reset value. <!-- test: services/affect/test/affect.region.test.ts -->

## Rule Appraisal (APPR)

- [x] **AFF-APPR-001**: When the rules appraiser appraises a line, it shall start from an arousal delta of +0.15 for speech or +0.03 for chat, and add +0.2 arousal when the line mentions the co-host. <!-- openspec: affect § Rule-based appraisal --> <!-- test: services/affect/test/affect.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-APPR-002**: When a line contains a whole word from the positive list (including the single-letter stream slang `w`) or a positive emoji, the rules appraiser shall add +0.12 valence and +0.05 arousal; when it contains a whole word from the negative list (including the single-letter slang `l` and `f`) or a negative emoji, it shall add -0.15 valence and +0.08 arousal; when both match the deltas net together. <!-- openspec: affect § Rule-based appraisal --> <!-- test: services/affect/test/appraiser.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-APPR-003**: When a line contains two or more consecutive `!` or five or more consecutive ASCII capital letters (`A`-`Z`), the rules appraiser shall add +0.05 arousal; when it contains `?` it shall add +0.03 arousal. <!-- openspec: affect § Rule-based appraisal --> <!-- test: services/affect/test/affect.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-APPR-004**: When a line contains a single emoji, the rules appraiser shall match it against exactly one of the positive or negative lists, and a bare variation selector shall match neither. <!-- test: services/affect/test/affect.test.ts -->

## Appraiser Hook and Queue (HOOK)

- [x] **AFF-HOOK-001**: The affect service shall build its appraiser as module `affect.appraiser` from `brain.affect.module` with kind `rules`, `llm` or `http`. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/appraiser.test.ts -->
- [x] **AFF-HOOK-002**: Where the appraiser kind is `llm` or `http`, affect shall accept the module output only if both `valence_delta` and `arousal_delta` are finite numbers, clamping each to [-0.5, 0.5]. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/appraiser.test.ts -->
- [x] **AFF-HOOK-003**: If the llm or http appraiser fails or returns output that violates the deltas contract, then affect shall appraise the line with the rules (fallback implemented by the module in region-hooks). <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/appraiser.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-HOOK-004**: Where the appraiser kind is `rules`, affect shall apply the appraisal inline in the event handler without queueing. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-HOOK-005**: Where the appraiser kind is `llm` or `http`, affect shall queue each line to a single worker that appraises one line at a time, so the bus handler never waits on the module, and shall appraise a queued line against the mood current when the job runs. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-HOOK-006**: While more than 8 appraisal jobs are waiting for an llm or http appraiser, affect shall discard the oldest waiting jobs. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-HOOK-007**: Where the appraiser kind is `llm` or `http`, affect shall appraise a line shorter than `brain.affect.short_line_chars` (default 4) characters (after trimming) that does not mention the co-host with the rules inline, and shall always send a mention to the module. <!-- openspec: affect § Appraiser module kinds and queueing --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-HOOK-008**: When affect handles `control` `forget_context` addressed to it, it shall discard every queued llm/http appraisal job; while affect is paused, the appraisal worker shall drop each queued job without applying it; so no job queued before a pause or reset changes the mood afterwards. <!-- openspec: affect § Targeted pause and resume --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-HOOK-009**: Where the appraiser kind is `llm`, affect shall send a JSON-only system prompt naming the co-host and the streamer that asks for `{"valence_delta":n,"arousal_delta":n}` with each delta within -0.5..0.5 (the validator range of AFF-HOOK-002), and a user prompt carrying the current valence and arousal and the line with its source, mention marker and speaker, capped at 60 output tokens. <!-- test: services/affect/test/appraiser.test.ts -->
- [ ] **AFF-HOOK-010**: Where the appraiser kind is `llm`, affect shall carry the `@cohost/shared/untrusted` `untrustedNotice` with the subject `what a viewer typed in chat` in the system prompt, with a statement that a request inside the line to move the mood a certain way is not a reason to.
- [ ] **AFF-HOOK-011**: Where the appraiser kind is `llm`, affect shall write the text of a `chat` line in the user prompt as `quoteUntrusted(text, viewer_text.max_chars)`, quoted exactly once.
- [ ] **AFF-HOOK-012**: Where the appraiser kind is `llm`, affect shall write the text of a `speech` line in the user prompt as the bounded text, not quoted.
- [ ] **AFF-HOOK-013**: Where the appraiser kind is `llm`, affect shall write the speaker of a line in the user prompt as `speakerLabel(name, viewer_text.max_name_chars)`.
- [ ] **AFF-HOOK-014**: Where the appraiser kind is `http`, affect shall send the line with its bounded text and no `«`, `»` or notice added.

## Publishing (PUB)

- [x] **AFF-PUB-001**: While the affect service is running, it shall evaluate whether to publish `affect.state` every `brain.affect.publish_ms` (default 2000); the first evaluation after start shall publish. <!-- openspec: affect § Publishing affect.state --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/main.test.ts -->
- [x] **AFF-PUB-002**: When the publish interval fires and the key of mood label plus 2-decimal valence and arousal equals the last published key and less than `brain.affect.republish_ms` (default 15000) has passed, affect shall not publish. <!-- openspec: affect § Publishing affect.state --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-PUB-003**: When the state key has changed, or `brain.affect.republish_ms` has passed since the last publish, affect shall publish `affect.state` with `valence`, `arousal`, `mood` and `cause`. <!-- openspec: affect § Publishing affect.state --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-PUB-004**: If publishing `affect.state` fails, then the affect service shall log the failure and continue. <!-- test: services/affect/test/affect.region.test.ts -->

## Control (CTRL)

- [x] **AFF-CTRL-001**: If a `control` event carries a `target` other than `affect`, then affect shall ignore it; an absent target addresses all services. <!-- openspec: affect § Targeted pause and resume --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-CTRL-002**: While affect is paused by `control` `pause`, it shall not nudge the mood from any non-control event. <!-- openspec: affect § Targeted pause and resume --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-CTRL-003**: While affect is paused, it shall continue to decay the mood and publish `affect.state`, so consumers keep a live, decaying mood. <!-- openspec: affect § Targeted pause and resume --> <!-- test: services/affect/test/affect.region.test.ts --> <!-- test: services/affect/test/affect.dispositions.test.ts -->
- [x] **AFF-CTRL-004**: When affect receives `control` `resume` addressed to it, it shall resume nudging the mood in-process without restarting. <!-- openspec: affect § Targeted pause and resume --> <!-- test: services/affect/test/affect.region.test.ts -->
- [x] **AFF-CTRL-005**: The affect service shall hold its mood and paused flag in process memory only, so a restarted affect starts from the baseline mood and unpaused. <!-- test: services/affect/test/affect.dispositions.test.ts -->

## Health and Lifecycle (HEALTH)

- [x] **AFF-HEALTH-001**: The affect service shall publish `service.heartbeat` with `service` `affect` and `deps` from HOOK-HEALTH-004 (empty for a `rules` appraiser) via `startHeartbeat`, with the mode of AFF-HEALTH-003, emitting `starting` at boot, `ready` once its consumer group has been created and the publish timer set, and one `stopping` on graceful shutdown. <!-- openspec: affect § Heartbeat --> <!-- test: services/affect/test/health.test.ts --> <!-- test: services/affect/test/main.test.ts -->
- [x] **AFF-HEALTH-002**: If any affect startup step fails (loading config, constructing the bus, heartbeat, appraiser or `Affect`, or starting the subscription), then the service shall end with exit code 1 through the shared bootstrap (SHARED-BOOT-002, SHARED-BOOT-003): a step after the configuration loads logs the error with message `fatal`, a configuration that does not load logs the loader's message. <!-- test: services/affect/test/main.test.ts -->
- [x] **AFF-HEALTH-003**: The affect heartbeat `mode` shall be `mock` where `brain.affect.module.kind` is `llm`, `brain.affect.module.llm.provider` is unset and `llm.provider` is `mock` (the appraiser hook inherits the mock provider and falls back to the rules on every call), and `live` otherwise. <!-- test: services/affect/test/health.test.ts -->
- [x] **AFF-HEALTH-004**: While affect is paused by `control` `pause`, its heartbeat `detail` shall be `paused`, through the shared control reader (SHARED-CTRL-007), and shall be cleared by `resume`. <!-- test: services/affect/test/affect.dispositions.test.ts -->
