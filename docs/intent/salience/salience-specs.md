# salience specs

Prefix `SAL`. Design: [salience-design.md](salience-design.md). Code: `services/salience/`. Markers: `[x]` implemented, `[ ]` intended but not yet implemented (gap), `[D]` deferred.

## Intake (IN)

- [x] **SAL-IN-001**: When the salience service starts, it shall subscribe with consumer group `salience` in start mode `latest` (the group is moved to the stream tail on every start, so events published while salience was down are never delivered) to `chat.message`, `speech.heard`, `vision.summary`, `brain.say`, `brain.status`, `affect.state` and `control`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/main.test.ts -->
- [x] **SAL-IN-002**: When salience receives a `chat.message` or `speech.heard` event, it shall push the event into its working-memory `Context` (sized `brain.working_memory_events`, default 24) and reset the scheduler's idle timer. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-003**: When salience receives a `vision.summary` event, it shall push the event into its `Context` without resetting the idle timer. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-004**: When salience receives an `affect.state` event, it shall store the event's `arousal` for threshold adjustment and for the scorer input. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts:98 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-005**: When salience receives a `brain.status` event, it shall record the reported state and the time received for busy detection. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts:52 -->
- [x] **SAL-IN-006**: Until salience has received an `affect.state` event it shall use arousal 0, and until it has received a `brain.status` or `brain.say` event it shall treat the cortex as `idle`. <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-IN-007**: The salience service shall not subscribe to `speech.partial`, and a `speech.partial` shall never enter its `Context`, reset its idle timer, match a reflex or become the focus of an `attention.focus`: only `speech.heard` is speech to salience.

## Scoring (SCORE)

- [x] **SAL-SCORE-001**: When salience scores an event with the built-in `rules` scorer, it shall assign speech 0.9; a chat mention 1.0 while `reply_on_mention` is true; chat containing `?` 0.55; chat from a mod or sub 0.35; other chat 0.15; changed vision 0.3; unchanged vision 0. <!-- openspec: salience § Rule-based scoring --> <!-- test: services/salience/test/salience.test.ts:21 -->
- [x] **SAL-SCORE-002**: Where `brain.salience.reply_on_mention` is false, the salience rules scorer shall treat a chat mention as ordinary chat (scored by question mark, mod/sub, then 0.15). <!-- openspec: salience § Rule-based scoring --> <!-- test: services/salience/test/scorer.test.ts:32 -->
- [x] **SAL-SCORE-003**: When salience prepares scorer input, it shall flatten the unseen non-`self` working-memory events in order into `{kind, who, text, mention, isMod, isSub, changed}` entries together with the current arousal. <!-- test: services/salience/test/salience.test.ts:38 -->
- [x] **SAL-SCORE-004**: Where `brain.salience.module.kind` is `llm` or `http`, salience shall accept the module's output only if it is an object whose `scores` is an array of finite numbers with exactly one entry per input event, clamping each score to 0..1. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts:37 -->
- [x] **SAL-SCORE-005**: If the llm or http scorer fails or returns output that violates the scores contract, then salience shall score the batch with the rules weights (fallback implemented by the `salience.scorer` module in region-hooks). <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts:42 -->
- [x] **SAL-SCORE-006**: When a scheduler decision runs, salience shall send only events not yet scored to the scorer and reuse the cached score for events that remain unseen across ticks. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/salience.test.ts:101 -->
- [x] **SAL-SCORE-007**: The salience service shall build its scorer as the region-hooks module `salience.scorer` from `brain.salience.module`, with kind `rules`, `llm` or `http`. <!-- openspec: salience § Scorer module kinds --> <!-- test: services/salience/test/scorer.test.ts:37 -->
- [x] **SAL-SCORE-008**: Where the scorer kind is `llm`, salience shall send a JSON-only system prompt naming the co-host and the streamer and asking for `{"scores":[...]}` with one 0..1 number per event, and a user prompt listing the current arousal and the numbered events with their kind, a mention marker, a mod marker and a sub marker, capped at 120 output tokens. <!-- test: services/salience/test/scorer.test.ts:62 -->

## Speak Decision (DECIDE)

- [x] **SAL-DECIDE-001**: When the scheduler decides, it shall return no-speak with reason `muted` if muted, else `cortex busy` if the cortex is busy, else `cooldown` if less than `cooldown_ms` (default 6000) has passed since the last line, else `nothing new` if there are no unseen non-`self` events, in that order. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts:63 -->
- [x] **SAL-DECIDE-002**: When unseen events exist, the scheduler shall compute the total score as the sum of all unseen events' scores and choose the highest-scoring event as the focus. <!-- test: services/salience/test/salience.region.test.ts:28 -->
- [x] **SAL-DECIDE-003**: When the total score is at least `max(0.1, speak_threshold - arousal_bias * arousal)` (defaults 0.6 and 0.2), the scheduler shall decide to speak, with the reason given by SAL-DECIDE-008. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts:83 -->
- [x] **SAL-DECIDE-004**: When the total score is below threshold, `idle_chatter_ms` is greater than 0, and more than `idle_chatter_ms` has elapsed since the last chat, speech or spoken line, the scheduler shall decide to speak with reason `idle chatter`. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts:83 -->
- [x] **SAL-DECIDE-005**: If there are no unseen non-`self` events, then the scheduler shall decide not to speak with reason `nothing new` even when `idle_chatter_ms` has elapsed, so a fully silent stream stays silent (idle chatter needs at least one unseen event). <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-DECIDE-006**: If the total score is below threshold and idle chatter does not apply, then the scheduler shall decide not to speak with reason `score <total> < <threshold>`. <!-- openspec: salience § Speak decision --> <!-- test: services/salience/test/salience.test.ts:63 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-DECIDE-007**: When a decision to speak is made, the scheduler shall report as `scored` exactly the events it evaluated, so that events arriving while an async scorer runs are not marked seen. <!-- test: services/salience/test/salience.test.ts:117 -->
- [x] **SAL-DECIDE-008**: When the scheduler decides to speak because the total score reached the threshold, it shall give reason `mentioned` only if the focus is a chat mention and `brain.salience.reply_on_mention` is true, and reason `engaged` otherwise. <!-- test: services/salience/test/salience.region.test.ts:309 -->

## Focus Publication (FOCUS)

- [x] **SAL-FOCUS-001**: While the salience service is running and not paused, it shall run a decision every `brain.salience.tick_ms` (default 1500). <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/main.test.ts:67 -->
- [x] **SAL-FOCUS-002**: While a previous scheduler decision is still in flight, salience shall skip the next tick without calling the scorer again. <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts:108 -->
- [x] **SAL-FOCUS-003**: When a decision is to speak, salience shall publish `attention.focus` with `reason`, `score` and a focus of `{kind:"chat", who, text, mention}`, `{kind:"speech", who, text}`, `{kind:"vision", text}` or none (the bus schema fills a missing `mention` with false). <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts:28 -->
- [x] **SAL-FOCUS-004**: When salience publishes `attention.focus`, it shall mark only the scored events seen and treat the cortex as `thinking` until a new `brain.status` or valve expiry. <!-- openspec: salience § Publishing attention.focus --> <!-- test: services/salience/test/salience.region.test.ts:52 -->
- [x] **SAL-FOCUS-005**: When a scheduler decision to speak returns from the scorer, salience shall re-check muted, paused and cortex busy, and if any of them now holds it shall publish no `attention.focus` for that decision. <!-- test: services/salience/test/salience.region.test.ts:233 --> <!-- test: services/salience/test/salience.region.test.ts:252 -->
- [x] **SAL-FOCUS-006**: When the focus of a speak decision is a `speech` event that carries `timing.audioEndedAt`, salience shall publish `attention.focus` with `timing` holding that `audioEndedAt` and `heardAt` set to the `ts` of that event's `speech.heard` envelope; for a focus of any other kind, or a speech event without `timing`, it shall publish no `timing`; it shall not alter the `audioEndedAt` it copies.

## Busy Gating (BUSY)

- [x] **SAL-BUSY-001**: While the last observed cortex state is `thinking` and was set less than `brain.salience.thinking_timeout_ms` (default 60000) ago, salience shall treat the cortex as busy. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts:141 --> <!-- test: services/salience/test/salience.region.test.ts:263 -->
- [x] **SAL-BUSY-002**: While the last observed cortex state is `speaking` and was set less than `brain.cortex.speaking_timeout_ms` (default 20000) ago, salience shall treat the cortex as busy. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts:64 -->
- [x] **SAL-BUSY-003**: When salience receives a `brain.say` event from any source (cortex, reflex echo or operator), it shall start the speaking cooldown and set the cortex state to `speaking`. <!-- openspec: salience § Busy detection --> <!-- test: services/salience/test/salience.region.test.ts:75 -->
- [x] **SAL-BUSY-004**: While the last observed cortex state is `idle` or `muted`, salience shall not treat the cortex as busy (salience's own mute, SAL-CTRL-004, is what stops it speaking). <!-- test: services/salience/test/salience.region.test.ts:52 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Reflexes (REFLEX)

- [x] **SAL-REFLEX-001**: When a chat, speech or changed-vision event's text matches a configured reflex rule's case-insensitive regex and the event's sense is listed in the rule's `on`, salience shall publish `brain.say` with a randomly chosen `say` line, the rule's emotion and gesture, and `reason` `reflex: <match>`. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts:121 -->
- [x] **SAL-REFLEX-002**: When salience receives a `vision.summary` with `changed` false, it shall not evaluate reflex rules against it. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts:130 -->
- [x] **SAL-REFLEX-003**: When a reflex rule fires, salience shall not fire that same rule again until its `cooldown_ms` (default 30000) has elapsed, and the first matching rule in config order shall win. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.test.ts:48 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-004**: When a reflex fires, salience shall mark only the triggering event seen, leaving other unseen events available to the next decision. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts:121 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-005**: While the cortex is busy or the global `cooldown_ms` since the last line has not elapsed, salience shall not fire reflexes, and shall evaluate this gate before spending any rule's own cooldown. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts:141 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-REFLEX-006**: While salience is muted or paused, it shall not fire reflexes. <!-- openspec: salience § Reflex fast path --> <!-- test: services/salience/test/salience.region.test.ts:141 -->
- [x] **SAL-REFLEX-007**: When salience publishes a reflex `brain.say`, it shall immediately start its own cooldown and mark the voice as speaking, rather than waiting for the line to echo back on the bus. <!-- test: services/salience/test/salience.region.test.ts:288 --> <!-- test: services/salience/test/salience.region.test.ts:301 -->
- [x] **SAL-REFLEX-008**: The salience reflex path shall take the triggering event from the `Context.push` that ingested it (WM-PUSH-009) and shall mark seen and copy injection flags from that event, never from the window's newest entry. <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Control (CTRL)

- [x] **SAL-CTRL-001**: If a `control` event carries a `target` other than `salience`, then salience shall ignore it; an absent target addresses all services. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts:183 -->
- [x] **SAL-CTRL-002**: When salience receives `control` `pause` addressed to it, it shall publish no `attention.focus` and no reflex `brain.say` while continuing to record incoming events in its `Context`. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts:162 -->
- [x] **SAL-CTRL-003**: When salience receives `control` `resume` addressed to it, it shall resume deciding and firing reflexes in-process without restarting. <!-- openspec: salience § Targeted pause and resume --> <!-- test: services/salience/test/salience.region.test.ts:162 -->
- [x] **SAL-CTRL-004**: While salience is muted by `control` `mute` (cleared by `unmute`), the scheduler shall decide no-speak with reason `muted` and publish no `attention.focus`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts:84 -->
- [x] **SAL-CTRL-005**: When salience receives `control` `forget_context`, it shall clear its working-memory `Context`. <!-- openspec: salience § Inputs and working memory --> <!-- test: services/salience/test/salience.region.test.ts:84 -->
- [x] **SAL-CTRL-006**: The salience service shall hold its muted and paused flags in process memory only, so a restarted salience starts unmuted and unpaused. <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-CTRL-007**: When salience receives `control` `resume` addressed to it, it shall mark seen every event that its `Context` took in while it was paused, so the first decision after a pause does not score a burst that accumulated meanwhile; events that arrive after the `resume` are unseen as usual. <!-- test: services/salience/test/salience.dispositions.test.ts -->

## Injection Flags (INJ)

- [x] **SAL-INJ-001**: When the focus event of a speak decision is an injected event, salience shall publish `attention.focus` with `injected: true` and that event's `remember` value. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts:193 -->
- [x] **SAL-INJ-002**: When the focus event is a real event (even one carrying a stray `remember`) or there is no focus event, salience shall publish `attention.focus` with neither `injected` nor `remember`. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts:202 --> <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-INJ-003**: When a decision's batch mixes injected and real events, salience shall derive `attention.focus` flags only from the focus event. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts:210 -->
- [x] **SAL-INJ-004**: When a reflex is triggered by an injected event, salience shall copy `injected` and `remember` onto the reflex `brain.say`; when triggered by a real event it shall omit both. <!-- openspec: salience § Injection flag propagation --> <!-- test: services/salience/test/salience.region.test.ts:220 -->

## Health and Lifecycle (HEALTH)

- [x] **SAL-HEALTH-001**: The salience service shall publish `service.heartbeat` with `service` `salience` and empty `deps` via `startHeartbeat`, with the mode of SAL-HEALTH-005, emitting `starting` at boot, `ready` once its consumer group has been created and the tick timer set, and one `stopping` on graceful shutdown. <!-- openspec: salience § Heartbeat --> <!-- test: services/salience/test/health.test.ts --> <!-- test: services/salience/test/main.test.ts -->
- [x] **SAL-HEALTH-002**: If a scheduler tick or an `attention.focus` publish fails, then the salience service shall log the error and keep running, and the next tick shall run as scheduled. <!-- test: services/salience/test/salience.region.test.ts:321 -->
- [x] **SAL-HEALTH-003**: If any salience startup step fails (loading config, constructing the bus, heartbeat, scorer or `Salience`, or starting the subscription), then the service shall end with exit code 1 through the shared bootstrap (SHARED-BOOT-002, SHARED-BOOT-003): a step after the configuration loads logs the error with message `fatal`, a configuration that does not load logs the loader's message. <!-- test: services/salience/test/main.test.ts -->
- [x] **SAL-HEALTH-004**: While salience is paused by `control` `pause`, its heartbeat `detail` shall be `paused`, through the shared control reader (SHARED-CTRL-007), and shall be cleared by `resume`. <!-- test: services/salience/test/salience.dispositions.test.ts -->
- [x] **SAL-HEALTH-005**: The salience heartbeat `mode` shall be `mock` where `brain.salience.module.kind` is `llm`, `brain.salience.module.llm.provider` is unset and `llm.provider` is `mock` (the scorer hook inherits the mock provider and falls back to the rules on every call), and `live` otherwise. <!-- test: services/salience/test/health.test.ts -->
