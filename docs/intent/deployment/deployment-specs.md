# deployment specs

Prefix `DEPLOY`. Design: [deployment-design.md](deployment-design.md). No OpenSpec capability covers this segment (the retired `openspec/specs/` baseline has none for Compose, the Dockerfile, the installer, CI, the docs site or licensing), so no spec below carries an OpenSpec reference.

Markers: `[x]` implemented; `[ ]` gap, meaning intended by the files' own comments, the README or `CONTRIBUTING.md` but broken, missing or inconsistent; `[D]` deferred.

Annotations: `@spec DEPLOY-…` comments sit in the deployment files themselves. In `docker-compose.yml` and `docker-compose.gpu.yml` they are trailing comments on mapping keys, and in `Dockerfile` and `scripts/install.sh` they are appended to existing comment lines, so the line numbers other segments cite in those files stay stable; everywhere else they are full comment lines. `<!-- impl: path:line -->` points at an implementation in a file that carries no annotation (a file owned elsewhere, or plain data such as `.gitignore`). `<!-- test: path:line -->` points at a test that exercises the line.

## Compose topology

- [x] **DEPLOY-COMPOSE-001**: The base `docker-compose.yml` shall define the infrastructure services `redis`, `postgres`, `ollama`, `tts`, `stt` and the one-shot `models`, and one application service per directory under `services/` (`chat`, `salience`, `affect`, `memory`, `cortex`, `voice`, `avatar`, `dashboard`, `eyes`, `ears`).
- [x] **DEPLOY-COMPOSE-002**: Each application service shall be built from the single root `Dockerfile` with the build argument `SERVICE` set to its directory name, and shall inherit the shared `x-ts-service` settings: `restart: unless-stopped`, `env_file: .env`, the in-network URLs `REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `DASHBOARD_URL` and `CONFIG_DIR=/app/config`, the `./config:/app/config` bind mount, the `host.docker.internal:host-gateway` extra host, a dependency on `redis` being healthy, and the container healthcheck (DEPLOY-HC-001).
- [x] **DEPLOY-COMPOSE-003**: While a variable is set in a service's `environment` block (`REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `DASHBOARD_URL`, `CONFIG_DIR`), the Compose stack shall use that value over the same name in `.env`, so those addresses cannot be changed through `.env` for containerised services.
- [x] **DEPLOY-COMPOSE-004**: The `eyes` service shall belong only to the `eyes` profile and the `ears` service only to the `ears` profile; every other service, including `models`, `tts` and `stt`, has no profile, so a plain `docker compose up -d` starts everything except `eyes` and `ears`.
- [x] **DEPLOY-COMPOSE-005**: Where a service has dependencies beyond redis, Compose shall order startup as follows: `memory` waits for `redis` and `postgres` healthy and `ollama` started; `cortex` for `redis` healthy and `ollama` started; `voice` for `redis` healthy and `tts` started; `ears` for `redis` healthy and `stt` started.
- [x] **DEPLOY-COMPOSE-006**: The infrastructure ports `redis` 6379, `postgres` 5432, `ollama` 11434, `tts` 8880 and `stt` 8000 shall be published on `127.0.0.1` only, and only `dashboard` shall be published on all interfaces, at host port `DASHBOARD_PORT` (default 3000) mapped to container port 3000.
- [x] **DEPLOY-COMPOSE-007**: The `voice` service shall publish no host port; its HTTP server (`VOICE_PORT`, default 8700) shall be reachable only on the Compose network, and the dashboard shall serve audio to browsers by proxying `/audio/` requests to `VOICE_URL`.
- [x] **DEPLOY-COMPOSE-008**: When the `models` service starts, it shall wait for `ollama` to answer `/api/tags`, then request `/api/pull` for `LLM_MODEL`, `VISION_MODEL` and `EMBED_MODEL` from `.env` one after another, printing the last 200 bytes of each response, and exit; it shall not pull `STT_MODEL`.
- [x] **DEPLOY-COMPOSE-009**: The stack shall persist data in the named volumes `redis-data`, `pg-data`, `ollama-data` and `stt-cache`; `redis` and `postgres` shall expose healthchecks (`redis-cli ping`, `pg_isready -U cohost`; every 5 s, 3 s timeout, 10 retries) used by `depends_on`.
- [x] **DEPLOY-COMPOSE-010**: Where `docker-compose.gpu.yml` is layered over the base file (via `-f` or `COMPOSE_FILE`), the overlay shall add an NVIDIA device reservation (`count: all`) to `ollama`, `tts` and `stt` and switch `tts` and `stt` to the GPU images `kokoro-fastapi-gpu` and `speaches:latest-cuda` unless `KOKORO_IMAGE` / `SPEACHES_IMAGE` are set.
- [ ] **DEPLOY-COMPOSE-011**: If a model pull requested by the `models` service fails, then the `models` container shall report failure (non-zero exit) instead of exiting successfully. (Gap: pulls are `curl -s ... | tail -c 200` without `-f`, and the loop's exit status is that of the final `echo`, `docker-compose.yml:82-85`; the failure is only visible in the log text.)
- [x] **DEPLOY-COMPOSE-012**: The `ollama` service shall keep loaded models resident for 24 h (`OLLAMA_KEEP_ALIVE=24h`) and run with flash attention (`OLLAMA_FLASH_ATTENTION=1`) and a `q8_0` KV cache (`OLLAMA_KV_CACHE_TYPE`).
- [x] **DEPLOY-COMPOSE-013**: The `redis` service shall snapshot to the `redis-data` volume when at least one key changed in the last 60 s (`--save 60 1`) and shall keep no append-only file (`--appendonly no`).
- [x] **DEPLOY-COMPOSE-014**: The base file shall run `redis` from `redis:7-alpine`, `postgres` from `pgvector/pgvector:pg16`, `ollama` from `ollama/ollama:latest`, `models` from `curlimages/curl:latest`, `tts` from `KOKORO_IMAGE` (default `ghcr.io/remsky/kokoro-fastapi-cpu:latest`) and `stt` from `SPEACHES_IMAGE` (default `ghcr.io/speaches-ai/speaches:latest-cpu`).
- [x] **DEPLOY-COMPOSE-015**: The application services, `ollama`, `tts` and `stt` shall restart unless stopped; `redis`, `postgres` and the one-shot `models` shall carry no restart policy.

## Container health

- [x] **DEPLOY-HC-001**: Every application service container shall run the healthcheck `node packages/control/dist/healthcheck.js $SERVICE` every 10 s with a 5 s timeout, 3 retries and a 30 s start period, with `SERVICE` taken from the image environment (`Dockerfile:20`).
- [x] **DEPLOY-HC-002**: When the healthcheck runs, it shall exit 0 only if the newest `service.heartbeat` for that service among the last 200 entries of `cohost:health` is younger than 3 times its declared interval and its state is not `stopping`, and shall exit 1 when no heartbeat is found, the heartbeat is stale, Redis cannot be read, or 4 s elapse. ## Image build

- [x] **DEPLOY-IMG-001**: The `Dockerfile` shall build in three stages on `node:22-slim` (`base` with corepack-activated `pnpm@10.0.0`, `build`, `runtime`), where `build` copies the workspace manifests, `packages/` and `services/`, runs `pnpm install --frozen-lockfile` and `pnpm exec tsc -b`, and `runtime` copies the entire `/app` from `build`.
- [x] **DEPLOY-IMG-002**: The image shall set `NODE_ENV=production` and `SERVICE` from the build argument and start with `exec node services/${SERVICE}/dist/index.js`; it shall contain every service's built code regardless of `SERVICE`. <!-- test: scripts/compose-smoke.sh:19 -->
- [x] **DEPLOY-IMG-003**: The `Dockerfile` shall not run `pnpm prune --prod` (it removes the `@cohost/*` workspace links under pnpm 10 and crash-loops every service, issue #6); the smoke script shall guard this regression. <!-- test: scripts/compose-smoke.sh:19 -->
- [x] **DEPLOY-IMG-004**: The `.dockerignore` shall exclude `node_modules`, `**/dist`, `.git`, `data`, `.env`, `**/*.tsbuildinfo` and `**/*.log` from the build context, so stale incremental-build state cannot stop `tsc -b` from emitting output in the image and secrets in `.env` are not sent to the daemon.

## Installer

- [x] **DEPLOY-INST-001**: When `scripts/install.sh` runs, it shall detect WSL2 from `/proc/version`, read `/etc/os-release`, warn but continue on a distribution other than Ubuntu or Debian, and report whether an NVIDIA GPU is visible through `nvidia-smi`.
- [x] **DEPLOY-INST-002**: Where `docker` is not installed, the installer shall install `docker-ce`, the CLI, containerd, buildx and the compose plugin from Docker's apt repository, add the user to the `docker` group and start the daemon (`service docker start` on WSL, `systemctl enable --now docker` otherwise); on every run it shall then abort unless `docker compose version` succeeds.
- [x] **DEPLOY-INST-003**: Where an NVIDIA GPU is detected and `docker info` does not list an NVIDIA runtime, the installer shall install `nvidia-container-toolkit` if absent, run `nvidia-ctk runtime configure --runtime=docker` and restart Docker.
- [x] **DEPLOY-INST-004**: Where Node is missing or older than 22, the installer shall install Node 22 from NodeSource; where `pnpm` is missing it shall enable corepack and prepare `pnpm@10.0.0`.
- [x] **DEPLOY-INST-005**: When `.env`, `config/config.yaml`, `config/personality.md` or `config/expressions.yaml` is missing, the installer shall copy it from `.env.example` or the matching `config/*.example.*` file, and shall never overwrite an existing one.
- [x] **DEPLOY-INST-006**: When the installer runs, it shall rewrite the `COMPOSE_FILE=` line in `.env` to `docker-compose.yml:docker-compose.gpu.yml` if an NVIDIA GPU was detected and to `docker-compose.yml` otherwise, on every run and replacing any value the operator set; a `.env` without a `COMPOSE_FILE=` line is left without one.
- [x] **DEPLOY-INST-007**: When the installer runs, it shall install workspace dependencies and typecheck; unless `--no-pull` is given it shall pull images (`--ignore-buildable`), start `ollama` and `models` and wait for `models` to exit while following its log; it shall then start `redis` and `postgres`, wait 2 s, and print `redis ok`, `postgres ok` and (when pulling) `ollama ok` for each probe (`redis-cli ping`, `pg_isready`, Ollama `/api/tags`) that passes. A failing probe prints nothing and does not stop the script.
- [ ] **DEPLOY-INST-008**: When the installer finishes, it shall print the dashboard URL using the `DASHBOARD_PORT` from `.env`. (Gap: `.env` is never sourced by the script, so `${DASHBOARD_PORT:-3000}` prints 3000 unless the variable is exported in the calling shell, `scripts/install.sh:135`.)
- [ ] **DEPLOY-INST-009**: When the installer decides whether Node is recent enough, it shall compare the numeric major version correctly. (Gap: `node -v | cut -c2-3` is used as an integer at `scripts/install.sh:76`. On Node 9 the value `9.` makes the `[[ … -lt 22 ]]` test error out as false, so Node 22 is not installed; a three-digit major such as 100 is cut to `10` and Node 22 is installed over it.)
- [ ] **DEPLOY-INST-010**: If `docker` was installed during the same run, then the installer shall continue to work without a re-login. (Gap: the user is only added to the `docker` group at `scripts/install.sh:52`, so later `docker compose pull` / `up` calls (`:111`, `:113`, `:122`) in the same shell run without the group and, under `set -e`, abort the script; the script itself only warns at `:54`. `[inferred]` from reading, not executed.)
- [ ] **DEPLOY-INST-011**: When the installer prints the Docker-free dev loop, it shall list the same infrastructure containers the README lists (`redis postgres ollama tts stt`). (Gap: `scripts/install.sh:139` omits `stt`; README.md:337 includes it.)
- [x] **DEPLOY-INST-012**: If `pnpm install --frozen-lockfile` fails, then the installer shall discard that attempt's error output and retry with a plain `pnpm install`, which may update `pnpm-lock.yaml`.

## Continuous integration

- [x] **DEPLOY-CI-001**: When a pull request is opened or `main` is pushed, the `test` workflow shall start a `redis:7-alpine` service, set `REDIS_URL`, run `pnpm install --frozen-lockfile` and `pnpm test` on Node 22 with the pnpm version from `packageManager` and a 10 minute timeout, and cancel an older run of the same ref.
- [x] **DEPLOY-CI-002**: When a pull request is opened or `main` is pushed, the `compose-smoke` workflow shall run `scripts/compose-smoke.sh`, which seeds `.env` from `.env.example` if absent, builds and starts `redis` plus the named services (default `salience affect avatar dashboard`) with `docker compose up -d --build`, waits `SMOKE_WAIT` seconds (default 15), fails unless each named service's container is `running` with `restarts=0`, prints the last 20 log lines of a failing service, and always runs `docker compose down -v` on exit.
- [x] **DEPLOY-CI-003**: When `main` is pushed or the workflow is dispatched manually, the `pages` workflow shall run `pnpm docs:build`, upload `docs/.vitepress/dist` and deploy it to the `github-pages` environment, serialising runs without cancelling an in-flight deploy.
- [ ] **DEPLOY-CI-004**: When a pull request changes documentation or `README.md`, CI shall build the docs site so a broken link or template error is caught before merge. (Gap: `pages.yml` runs only on push to `main` and manual dispatch, `.github/workflows/pages.yml:4-7`; with `ignoreDeadLinks` limited to localhost, a dead link first fails on `main`.)
- [ ] **DEPLOY-CI-005**: When a pull request is opened, CI shall reject commits that lack a DCO `Signed-off-by` line. (Gap: `CONTRIBUTING.md:6-16` makes sign-off mandatory, but no workflow or app enforces it; `.github/workflows/` holds only `test`, `compose-smoke` and `pages`.)

## Workspace and repository hygiene

- [x] **DEPLOY-REPO-001**: The pnpm workspace shall consist of `packages/*` and `services/*`, and the root `tsconfig.json` shall be a solution file with a project reference for every one of the 7 packages and 10 services and no extras. <!-- impl: pnpm-workspace.yaml:1-3 --> <!-- impl: tsconfig.json:1-23 -->
- [x] **DEPLOY-REPO-002**: The root `package.json` shall provide `build` (`tsc -b`), `typecheck` (`tsc -b --noEmit`), `lint` (the same command as `typecheck`; there is no linter), `test` (`tsc -b` then Node's test runner via `tsx` over `packages/*/test/*.test.ts` and `services/*/test/*.test.ts`), `test:only` (same without the build), `dev` (every service with `tsx watch`), `reflect`, `clean` and the `docs:*` scripts, and pin `pnpm@10.0.0` through `packageManager` with `node >=22`. <!-- impl: package.json:8-25 -->
- [x] **DEPLOY-REPO-003**: The `.gitignore` shall exclude `node_modules/`, `dist/`, `*.tsbuildinfo`, `.env`, `data/`, `*.log`, `.DS_Store` and the three user-owned files `config/config.yaml`, `config/personality.md` and `config/expressions.yaml`. <!-- impl: .gitignore:1-10 -->
- [ ] **DEPLOY-REPO-004**: The `.gitignore` shall exclude the VTube Studio auth token that the avatar service writes to `config/.vts-token`. (Gap: `services/avatar/src/index.ts:30` and `services/avatar/src/drivers/vtube-studio.ts:104` write `<configDir>/.vts-token`; `.gitignore` has no entry for it, so `git add -A` would stage a credential.)
- [x] **DEPLOY-REPO-005**: The workspace shall allow dependency install scripts only for `esbuild`, `@snazzah/davey`, `libsodium-wrappers` and `opusscript` (`pnpm.onlyBuiltDependencies`). <!-- impl: package.json:32-39 -->
- [x] **DEPLOY-REPO-006**: `tsc -b` (and so `pnpm build`, `pnpm typecheck`, `pnpm lint` and the build step of `pnpm test`) shall type-check only each project's `src/`; test files under `packages/*/test` and `services/*/test` run through `tsx`, which strips types without checking them. <!-- impl: tsconfig.base.json:1-18 --> <!-- impl: services/dashboard/tsconfig.json:4 -->

## Dev helpers

- [x] **DEPLOY-DEV-001**: When `scripts/dev/bus-pub.ts <type> <json>` runs, it shall validate the payload through the bus event schema, publish it, and exit 1 with the rejection message on an invalid payload and 2 for an unknown type, unparsable JSON or no arguments; `--list` shall print the known event types.
- [x] **DEPLOY-DEV-002**: When `scripts/dev/bus-tail.ts` runs, it shall tail the bus with a non-group read (so it never consumes a service's events), optionally replay the last N events (`--replay`, default 20), filter by event type (exit 2 on an unknown type), and print JSON lines with `--json`.
- [x] **DEPLOY-DEV-003**: When `scripts/dev/stub-llm.ts` runs, it shall serve `GET /api/tags` and `POST /api/chat` on `STUB_LLM_PORT` (default 11434) with a canned reply echoing the last line of the last user message, and when `scripts/dev/stub-tts.ts` runs it shall serve `POST /v1/audio/speech` on `STUB_TTS_PORT` (default 8880) returning a 24 kHz mono 16-bit WAV about 65 ms per character long (0.4 s to 8 s); any other route shall be answered 404.
