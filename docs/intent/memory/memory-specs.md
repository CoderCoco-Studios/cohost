# memory specs

Design: [memory-design.md](memory-design.md). Prefix `MEM`. Verified against the code at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`. `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred. Test paths are relative to the repo root; a `<!-- test: -->` pointer names the test that carries the matching `@spec` annotation.

## Event handling

- [x] **MEM-EVT-001**: The memory service shall consume the bus in two consumer groups subscribed with start mode `resume` (a group created by this subscription starts at the stream's newest entry; a group that already exists resumes after its last delivered entry, so events published while memory was down are stored after a restart): group `memory` for `chat.message`, `speech.heard` and `brain.say`, and group `memory-recall` for `memory.recall.request`, so that a recall never queues behind a slow embed plus INSERT. <!-- openspec: memory § Event handling and consumer groups --> <!-- test: services/memory/test/startup.test.ts:28 -->
- [x] **MEM-EVT-002**: When the memory handler receives an event type it does not act on (for example `affect.state`), the memory service shall do nothing and publish nothing. <!-- test: services/memory/test/region.test.ts:64 -->

## Storing memories

- [x] **MEM-WRITE-001**: When a `chat.message` arrives, the memory service shall remember it as kind `chat` (who = the message `user`) only if `mentionsCohost` is true, and shall store nothing for unaddressed chat. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:27, services/memory/test/region.test.ts:37 -->
- [x] **MEM-WRITE-002**: When a `speech.heard` arrives, the memory service shall remember it as kind `speech` with who = the `speaker`. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:46 -->
- [x] **MEM-WRITE-003**: When a `brain.say` arrives from any publisher, the memory service shall remember it as kind `self` (who = `cfg.cohost.name`) only if its text is two or more characters. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:46 -->
- [x] **MEM-WRITE-004**: When the Postgres store remembers a line, it shall embed the string `"<who>: <text>"` and insert `kind`, `who`, `text` and the embedding as a pgvector literal into table `memories`. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/memory.test.ts:76 -->
- [x] **MEM-WRITE-005**: If embedding or INSERT throws while remembering, the Postgres store shall log a warning and not propagate the error. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/memory.test.ts:85 -->

## Test injection

- [x] **MEM-INJ-001**: When a `chat.message`, `speech.heard` or `brain.say` arrives with `injected` true and `remember` not true, the memory service shall store no memory, touch no viewer row and publish no `memory.viewer`. <!-- openspec: memory § Storing memories; memory § Injected chat and viewers --> <!-- test: services/memory/test/region.test.ts:73 -->
- [x] **MEM-INJ-002**: When a `chat.message`, `speech.heard` or `brain.say` arrives with `injected` true and `remember` true, the memory service shall handle it exactly like a real event. <!-- openspec: memory § Injected chat and viewers --> <!-- test: services/memory/test/region.test.ts:85 -->
- [x] **MEM-INJ-003**: When an event without `injected` true carries `remember` false, the memory service shall ignore the `remember` flag and handle the event normally. <!-- openspec: memory § Storing memories (Flag ignored on real events) --> <!-- test: services/memory/test/region.test.ts:96 -->

## Viewers

- [x] **MEM-VIEWER-001**: When a `chat.message` is handled (mentioning the co-host or not), the memory service shall upsert the viewer row keyed by the lowercased `userId`, or the `user` name when no `userId` is present, updating `display`; a newly inserted row shall start at `msg_count` 1 and each later message shall add 1, in both stores (in-memory store: MEM-BACKEND-005). <!-- openspec: memory § Viewer tracking and announcement (scenario "First message" expects msgCount 1) --> <!-- test: services/memory/test/region.test.ts:27, services/memory/test/memory.test.ts:123, services/memory/test/memory.test.ts:154 -->
- [x] **MEM-VIEWER-002**: When a handled `chat.message` mentions the co-host, the memory service shall publish `memory.viewer` with `{user, isNew, msgCount, notes}` before it embeds and stores the message, and shall publish none when it does not mention the co-host. <!-- openspec: memory § Viewer tracking and announcement --> <!-- test: services/memory/test/region.test.ts:27, services/memory/test/region.test.ts:37 -->
- [x] **MEM-VIEWER-003**: The memory service shall report a viewer as new (`isNew` true) exactly when the viewer's `msg_count` after the upsert is 1 or less. <!-- openspec: memory § Viewer tracking and announcement --> <!-- test: services/memory/test/memory.test.ts:123 -->
- [x] **MEM-VIEWER-004**: The memory service shall return the stored `notes` text of the viewer row in `memory.viewer`, defaulting to the empty string. <!-- code: store.ts:88 notes DEFAULT '' --> <!-- test: services/memory/test/region.test.ts:37, services/memory/test/memory.test.ts:123 -->
- [D] **MEM-VIEWER-005**: The memory service shall have a way for viewer `notes` to be written, so that the "Notes:" shown to the cortex for regular viewers can be non-empty. Deferred: no writer (reflection, dashboard or hand-edited SQL) is chosen yet; today nothing writes `viewers.notes` (`services/memory/src/store.ts:88,142-152`; `fake-store.ts:52-58`).
- [x] **MEM-VIEWER-006**: If upserting the viewer row fails while a `chat.message` is handled, the memory service shall log a warning, publish no `memory.viewer` for that message, and still remember the message when it mentions the co-host. <!-- test: services/memory/test/region.test.ts:106 -->

## Recall

- [x] **MEM-RECALL-001**: When a `memory.recall.request` arrives, the memory service shall publish `memory.recall.reply` carrying the same `id` and the recalled memories as `{ts (epoch ms), kind, who, text, similarity}`; an empty list is a valid answer. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/region.test.ts:55, services/memory/test/backend.test.ts:18 -->
- [x] **MEM-RECALL-002**: Where a `memory.recall.request` omits `k`, the memory service shall use `brain.memory.recall_k` (default 6). <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:96 -->
- [x] **MEM-RECALL-003**: When the Postgres store recalls, it shall embed the query and return up to `k` rows ordered by cosine distance, excluding rows whose `ts` is within the last 2 minutes. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:96 -->
- [x] **MEM-RECALL-004**: When recalling, the memory service shall drop any result whose similarity is below `brain.memory.min_similarity` (default 0.35), keeping results equal to it. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:96, services/memory/test/fake-store.test.ts:22 -->
- [x] **MEM-RECALL-005**: If `k` is 0 or less, the memory store shall return an empty list without embedding or querying. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:113, services/memory/test/fake-store.test.ts:22 -->
- [x] **MEM-RECALL-006**: If embedding or the recall query fails, the Postgres store shall log a warning and return an empty list, so the memory service still publishes a `memory.recall.reply`. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:113 -->

## Stores and schema

- [x] **MEM-STORE-001**: When the Postgres store initialises, it shall probe the embedding dimension, create extension `vector`, create tables `memories` (with `embedding vector(dims)`), `viewers` and `meta`, and create an hnsw cosine index, treating failure to create the index as a warning only. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/memory.test.ts:65 -->
- [x] **MEM-STORE-002**: When the Postgres store initialises against an existing `memories` table whose vector dimension differs from the configured embedder's dimension, it shall fail initialisation with an error naming both dimensions, and the memory service shall not retry that error, so startup ends in the fatal exit of MEM-START-006 (and `reflect` in `reflect failed`) instead of every later write and recall failing silently with health `ok`. <!-- intent: packages/config/src/schema.ts:39-40 ("the memory table's vector size never changes when the chat model does") --> <!-- test: services/memory/test/memory.test.ts:161, services/memory/test/startup.test.ts:71 -->
- [x] **MEM-STORE-003**: The Postgres store shall keep key/value metadata in table `meta` with upsert semantics, and shall list memories strictly after a `(ts, id)` cursor in `(ts, id)` order with a default limit of 400. <!-- openspec: memory § Reflection (last_reflection meta) --> <!-- test: services/memory/test/memory.test.ts:134 -->

## Backend selection

- [x] **MEM-BACKEND-001**: Where `brain.memory.store` is `memory`, the memory service shall use the in-process `InMemoryStore`, shall not open a Postgres connection, and shall not use the supplied embedder. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/backend.test.ts:12 -->
- [x] **MEM-BACKEND-002**: Where `brain.memory.store` is `postgres` (the default), the memory service shall use the Postgres `MemoryStore`. <!-- openspec: memory § Schema initialization and startup --> <!-- test: none -->
- [x] **MEM-BACKEND-003**: Where `brain.memory.embedder` is `hash`, the memory service shall embed with `@cohost/llm`'s `HashEmbedder` and make no network request; otherwise it shall use the Ollama client from `llm` config regardless of `llm.provider`. <!-- openspec: memory § Hash embedder selection --> <!-- test: services/memory/test/backend.test.ts:36 (the Ollama-regardless-of-provider branch is untested) -->
- [x] **MEM-BACKEND-004**: While the in-memory store is active, recall shall rank by cosine similarity over its own hashed bag-of-words vectors, exclude entries newer than 2 minutes, drop results under `min_similarity` and return at most `k`. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/fake-store.test.ts:13, services/memory/test/fake-store.test.ts:22, services/memory/test/fake-store.test.ts:40, services/memory/test/backend.test.ts:18 -->
- [x] **MEM-BACKEND-005**: While the in-memory store is active, viewer tracking shall count per lowercased key, report `isNew` when the count is 1 or less, always return empty notes, and lose all data on process exit. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/fake-store.test.ts:48 -->
- [x] **MEM-BACKEND-006**: While the in-memory store is active, it shall keep `meta` key/values in process and list memories strictly after a `(ts, id)` cursor in `(ts, id)` order with a default limit of 400. <!-- code: fake-store.ts:61-71 --> <!-- test: services/memory/test/fake-store.test.ts:55, services/memory/test/fake-store.test.ts:69 -->

## Startup and shutdown

- [x] **MEM-START-001**: Where the store is `postgres` and the embedder is `ollama`, the memory service shall ping Ollama every 3 seconds until it answers before initialising the store, marking `deps.ollama` down while it waits. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/startup.test.ts:39 -->
- [x] **MEM-START-002**: Where the store is `postgres`, the memory service shall retry store initialisation every 3 seconds and exit fatally when the 21st attempt fails; a vector-dimension mismatch (MEM-STORE-002) is not retried and exits at once. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/startup.test.ts:50, services/memory/test/startup.test.ts:62, services/memory/test/startup.test.ts:71 -->
- [x] **MEM-START-003**: Where the store is `memory`, the memory service shall initialise once with no Ollama ping, no Postgres connection and no retry loop. <!-- openspec: memory § Schema initialization and startup (Redis-only start) --> <!-- test: services/memory/test/startup.test.ts:81 -->
- [x] **MEM-START-004**: Where either `brain.memory.store` or `brain.memory.embedder` is non-default, the memory service shall log a warning that it runs in mode mock with non-durable data. <!-- openspec: memory § Isolation preset and mode --> <!-- test: services/memory/test/startup.test.ts:81 -->
- [x] **MEM-START-005**: When the memory service has finished initializing its store, it shall start both consumer-group subscriptions and report `ready` in its heartbeat only once both consumer groups exist; a subscription that fails before its group is ready fails startup. <!-- openspec: memory § Heartbeat --> <!-- test: services/memory/test/startup.test.ts:97, services/memory/test/startup.test.ts:115 -->
- [x] **MEM-START-006**: If startup throws (including the 21st failed Postgres initialisation), the memory service shall log a fatal error and exit with code 1; on shutdown it shall stop the bus and then close the store. <!-- code: index.ts:45-47 --> <!-- test: none -->

## Health

- [x] **MEM-HEALTH-001**: The memory heartbeat shall report service `memory` with mode `live` only when the store is `postgres` and the embedder is `ollama`, and mode `mock` otherwise. <!-- openspec: memory § Isolation preset and mode --> <!-- test: services/memory/test/health.test.ts:34, services/memory/test/health.test.ts:43, services/memory/test/backend.test.ts:36 -->
- [x] **MEM-HEALTH-002**: The memory heartbeat shall report `deps.postgres` as `n/a` unless the store is `postgres`, and `deps.ollama` as `n/a` unless the store is `postgres` and the embedder is `ollama`. <!-- openspec: memory § Heartbeat (deps), § Isolation preset and mode --> <!-- test: services/memory/test/health.test.ts:7, services/memory/test/health.test.ts:34, services/memory/test/health.test.ts:43 -->
- [x] **MEM-HEALTH-003**: While the Ollama embedder is tracked, a failed `embed` shall set `deps.ollama` to `down` (state `degraded` once ready) and the next successful `embed` shall restore it to `ok`. <!-- openspec: memory § Heartbeat (Ollama down) --> <!-- test: services/memory/test/health.test.ts:18 -->
- [x] **MEM-HEALTH-004**: When the Postgres store initialisation succeeds, the memory service shall set `deps.postgres` to `ok`. <!-- openspec: memory § Heartbeat --> <!-- test: services/memory/test/startup.test.ts:50 -->
- [x] **MEM-HEALTH-005**: While the Postgres store is in use, `deps.postgres` shall follow the outcome of the latest Postgres query (each pool query wrapped with `tracked()`), becoming `down` when queries fail after startup and `ok` again when they succeed. <!-- openspec: add-service-health "ok or down according to the last successful connection or embedding call" --> <!-- test: services/memory/test/memory.test.ts:177 -->
- [x] **MEM-HEALTH-006**: While Postgres store initialisation is failing at startup, the memory service shall report `deps.postgres` as `down`. <!-- code: startup.ts:45; heartbeat state is derived in packages/bus/src/heartbeat.ts:68-85 --> <!-- test: services/memory/test/startup.test.ts:50 -->
- [x] **MEM-HEALTH-007**: While the memory service is waiting for Ollama or retrying Postgres initialisation at startup, it shall report heartbeat state `degraded` with a detail naming the dependency it is waiting for. <!-- test: services/memory/test/startup.test.ts:39, services/memory/test/startup.test.ts:50 -->

## Reflection

- [x] **MEM-REFLECT-001**: When `reflect` runs with `brain.memory.store` set to `memory`, it shall log a warning and exit without reading memories or changing personality. <!-- openspec: memory § In-memory store (reflection is a logged no-op) --> <!-- test: services/memory/test/reflect.test.ts:117 -->
- [x] **MEM-REFLECT-002**: When `reflect` runs, it shall read at most 600 memories oldest-first whose `(ts, id)` is after the cursor in `meta.last_reflection` (MEM-REFLECT-008; default: before the first row). <!-- openspec: memory § Reflection --> <!-- test: services/memory/test/reflect.test.ts:47 -->
- [x] **MEM-REFLECT-003**: If fewer than 5 new memories exist, `reflect` shall log and exit without calling the LLM, changing personality or moving the `meta.last_reflection` cursor, so those rows are read in a later pass together with the memories that arrive meanwhile; a final batch of 5 to 599 rows reflects normally. <!-- openspec: memory § Reflection (Too few memories) --> <!-- test: services/memory/test/reflect.test.ts:84 -->
- [x] **MEM-REFLECT-004**: When enough memories exist, `reflect` shall ask the chat LLM (max 400 tokens, temperature 0.5) for 3 to 6 bullet points given the current personality and a `who: text` transcript. <!-- openspec: memory § Reflection --> <!-- test: services/memory/test/reflect.test.ts:97 -->
- [x] **MEM-REFLECT-005**: The reflection parser shall keep only reply lines that start with `- ` after trimming, discarding preamble and other bullet styles. <!-- openspec: memory § Reflection (Preamble stripped) --> <!-- test: services/memory/test/memory.test.ts:11 -->
- [x] **MEM-REFLECT-006**: If the LLM reply contains no bullet lines, `reflect` shall log a warning and neither save personality nor update `last_reflection`. <!-- openspec: memory § Reflection (No bullets) --> <!-- test: services/memory/test/reflect.test.ts:106 -->
- [x] **MEM-REFLECT-007**: When bullets are produced, `reflect` shall insert them as a `### YYYY-MM-DD` (UTC) block at the end of the `## Learned` section (before the next `## ` heading, or at the end of the text when `## Learned` is the last section), adding a `## Learned` heading at the end of the text when the text has none, then save personality, advance `meta.last_reflection` (MEM-REFLECT-008) and print the block. <!-- openspec: memory § Reflection ("in the `## Learned` section") --> <!-- test: services/memory/test/memory.test.ts:18, services/memory/test/memory.test.ts:29, services/memory/test/reflect.test.ts:97 -->
- [x] **MEM-REFLECT-008**: When `reflect` saves a Learned block, it shall set `meta.last_reflection` to the `(ts, id)` of the newest memory it read, and `recentSince` shall read rows strictly after that cursor in `(ts, id)` order (`ORDER BY ts, id`, `WHERE (ts, id) > ($1, $2)`), so that when more than 600 memories are newer than the cursor the rows beyond the first 600 are reflected on in the next pass, including rows that share the last row's timestamp. The cursor keeps the stored timestamp at full database precision, so the newest row read is never read again. A legacy `meta.last_reflection` that is a plain ISO timestamp is read as that timestamp with the lowest id. <!-- test: services/memory/test/reflect.test.ts:47, services/memory/test/reflect.test.ts:62, services/memory/test/reflect.test.ts:74, services/memory/test/reflect.test.ts:38, services/memory/test/fake-store.test.ts:69, services/memory/test/memory.test.ts:134 -->
- [x] **MEM-REFLECT-009**: If any step of `reflect` throws (including store initialisation, which embeds a probe string and so needs a reachable embedder), `reflect` shall log `reflect failed`, set exit code 1 and still close the store. <!-- code: reflect-run.ts:30, reflect.ts:22-25, store.ts:69 --> <!-- test: none -->
- [x] **MEM-REFLECT-010**: Where `reflect` builds a chat provider whose `name` is `mock`, it shall log one warn-level message naming the mock backend before it reads any memory, so a canned reflection is never mistaken for a real one. <!-- intent: LLM-MOCK-005 --> <!-- test: services/memory/test/reflect.test.ts:127 -->
