# config specs

Prefix `CFG`. Verified against the code at git `49ba935` (audit pass 2026-11-01); owner decisions of 2026-11-01 applied at git `1b57790`. `[x]` = implemented and observed in code; `[ ]` = intended but not yet implemented (gap); `[D]` = deferred; a spec is `[x]` when the code performs the behaviour today and `[ ]` when the behaviour is new or changed and not yet built. A retired line keeps its number, says `Retired.`, and the number is not reused; it stays `[ ]` while code still has the behaviour. Each `<!-- test: -->` pointer names the test file that carries the matching `@spec` annotation; a line with no pointer has no direct test.

## Config directory and seeding

- [x] **CFG-DIR-001**: When the `CONFIG_DIR` environment variable is set, `@cohost/config` `configDir()` shall return that path resolved to an absolute path, taking precedence over any workspace-root lookup. <!-- openspec: config § Config directory and seeding --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-002**: When `CONFIG_DIR` is unset, `@cohost/config` `configDir()` shall return `config` under the nearest ancestor directory of the current working directory that contains `pnpm-workspace.yaml`, and `config` under the current working directory when no such ancestor exists. <!-- openspec: config § Config directory and seeding (spec says `./config`; code is a superset, see LLD Open Questions) --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-003**: When `config.yaml`, `expressions.yaml` or `personality.md` is missing from the config directory and its matching `*.example.*` file exists, `ensureFromExample` shall copy the example to the real file, emit a warning through the config logger (CFG-LOG-001) naming both, and return the real path. <!-- openspec: config § Config directory and seeding --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-004**: While the real config file already exists, `ensureFromExample` shall return its path without copying or modifying it. <!-- openspec: config § Config directory and seeding --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-005**: If a config file is missing and its example is also missing, then `ensureFromExample` shall throw an error naming both paths. <!-- openspec: config § Config directory and seeding --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-006**: When the `COHOST_DATA_DIR` environment variable is set, `@cohost/config` `dataDir()` shall return that path resolved to an absolute path. <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-DIR-007**: When `COHOST_DATA_DIR` is unset, `@cohost/config` `dataDir()` shall return `data` under the nearest ancestor directory of the current working directory that contains `pnpm-workspace.yaml`, and under the current working directory when no such ancestor exists; each service keeps its own files in a subdirectory named after the service. <!-- test: packages/config/test/config.test.ts -->

## Environment handling

- [x] **CFG-ENV-001**: Retired. `loadConfig` substitutes no environment variable into `config.yaml`: the only environment input to a setting is `COHOST_ISOLATION` (CFG-ISO-007), and a `${VAR}` placeholder fails the load (CFG-ENV-011). Number not reused. <!-- test: packages/config/test/config-env.test.ts -->
- [x] **CFG-ENV-002**: Retired. No placeholder form is substituted, `${VAR:-default}` included (CFG-ENV-011). Number not reused. <!-- test: packages/config/test/config-env.test.ts -->
- [x] **CFG-ENV-003**: Retired. A placeholder with a lower-case name is literal text, and one with an upper-case name fails the load (CFG-ENV-011). Number not reused. <!-- test: packages/config/test/config-env.test.ts -->
- [x] **CFG-ENV-004**: When `loadConfig` runs, the system shall first load `.env` from the workspace root (CFG-ENV-010), setting only variables that are not already defined in `process.env`. <!-- openspec: config § Dotenv loading --> <!-- test: packages/config/test/config.test.ts --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-ENV-005**: When `loadDotEnv` parses a file, it shall trim each line, skip blank lines and lines that start with `#`, split each remaining line at its first `=` (any later `=` stays in the value), trim the key and the value, strip one pair of matching surrounding double or single quotes from the value, skip lines with no `=` or an empty key, and do nothing when the file does not exist. <!-- openspec: config § Dotenv loading --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-ENV-006**: When an unquoted `.env` value is followed by whitespace and a `#` comment (the form `.env.example` uses on its API-key lines), `loadDotEnv` shall strip that suffix, matching Compose's `env_file` parsing, so the variable is empty rather than set to the comment text; a `#` inside a quoted value is kept. <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-ENV-007**: When `env(name)` is called and the variable is unset or empty, the system shall throw an error naming the variable and pointing at `.env`; `envOr(name, fallback)` shall return the fallback when the variable is unset or empty. <!-- openspec: config § Env helpers and URLs --> <!-- test: packages/config/test/config.test.ts -->
- [ ] **CFG-ENV-008**: The system shall read the service-control settings (`CONTROL_TOKEN`, `CONTROL_ADVANCED`) and `HEARTBEAT_INTERVAL_MS` only from `process.env`, in their owning packages and, for `CONTROL_TOKEN`, also in ears, which uses it as the bearer of its `http` audio listener (ears EARS-SRC-013); `ConfigSchema` shall have no keys for them, and no cohost source shall read `CONTROL_ENABLED`. <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-ENV-009**: The system shall read `DASHBOARD_HOST` only from `process.env` in the dashboard, once at its start; `ConfigSchema` shall have no key for it. <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-ENV-010**: The `.env` file shall be `.env` at the workspace root (the nearest ancestor of the current working directory containing `pnpm-workspace.yaml`), and the parent of the config directory when there is no workspace root, whatever `CONFIG_DIR` says, unless `COHOST_ENV_FILE` names a file, which then wins. <!-- test: packages/config/test/config-c3.test.ts -->
- [x] **CFG-ENV-011**: If `config.yaml` holds, as a string value, a `${NAME}` or `${NAME:-default}` placeholder whose `NAME` matches `[A-Z0-9_]+`, then `loadConfig` shall fail with an error beginning `Invalid <file>:` that lists, for each such placeholder, the key's dotted path (an array entry as `path[index]`) and the variable name, says to write the value as a literal in `config.yaml` (in `secrets.yaml` for a secret key), and says that `${...}` is not supported in `config.yaml` and that no escape exists (a name written in lower case is literal text, so prose that needs a literal dollar-brace is reworded); no placeholder is substituted and a placeholder in a comment is not checked. <!-- test: packages/config/test/config-env.test.ts -->
- [ ] **CFG-ENV-012**: The system shall read from the environment only `COHOST_ISOLATION` (CFG-ISO-007), `CONFIG_DIR`, `COHOST_ENV_FILE`, `COHOST_SECRETS_FILE` (CFG-SEC-001), `COHOST_DATA_DIR`, `COHOST_DOCKER_BIN`, `COHOST_VERSION`, `HEARTBEAT_INTERVAL_MS`, `REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `VOICE_PORT`, `CONTROL_TOKEN`, `CONTROL_ADVANCED`, `DASHBOARD_HOST` and the platform variables `PATH`, `HOSTNAME`, `WSLENV` and `NO_COLOR` (CFG-LOG-009), and a test shall fail when cohost source under `packages/` or `services/` (tests excepted) reads any other environment variable. The test covers cohost source only; Compose interpolation and third-party libraries are covered by CFG-ENV-011, CFG-ISO-007 and LLM-CLAUDE-009. <!-- test: packages/config/test/config-env.test.ts -->

## Loading and validation pipeline

- [x] **CFG-LOAD-001**: When `loadConfig()` is called, the system shall seed `config.yaml` from `config.example.yaml` if missing, parse the YAML, merge `secrets.yaml` (CFG-SEC-002), apply the isolation overrides (CFG-ISO-007), validate with `ConfigSchema` and return the typed `Config`, and while a result is cached it shall return the same object until called with `force = true`. <!-- openspec: config § Unknown key warning and caching --> <!-- test: packages/config/test/config.test.ts --> <!-- test: packages/config/test/config-env.test.ts --> <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-LOAD-002**: When a YAML value is null (for example `port:` written with no value), the system shall drop that key at any nesting depth so the schema default applies instead of a validation error. <!-- openspec: config § Schema validation and defaults --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-LOAD-003**: If `config.yaml` fails schema validation, then `loadConfig` shall throw an error beginning `Invalid <file>:` that lists every failing key as `path: message`. <!-- openspec: config § Schema validation and defaults --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-LOAD-004**: Retired. When `config.yaml` fails validation, `loadConfig` adds no hint about a missing `.env`: a missing `.env` cannot make a config invalid, so the error lists the failing keys and nothing else. Number not reused. <!-- test: packages/config/test/config-env.test.ts -->
- [x] **CFG-LOAD-005**: When `config.yaml` contains keys the schema does not define, `loadConfig` shall load successfully and emit exactly one warning through the config logger (CFG-LOG-001) listing the dotted paths of the ignored keys. <!-- openspec: config § Unknown key warning and caching --> <!-- test: packages/config/test/config.test.ts --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-LOAD-006**: When a key nested inside an array entry (for example a typo inside a `brain.salience.reflexes` item) is not defined by the schema, `loadConfig` shall include it in the unknown-keys warning (as `path[index].key`), and the warning text shall name the ignored keys. <!-- test: packages/config/test/config.test.ts --> <!-- test: packages/config/test/config.test.ts -->
- [x] **CFG-LOAD-007**: If `config.yaml` is not valid YAML, then the load (and the settings editor, which runs the same pipeline) shall report one issue giving the line and column of the syntax error and the parser's reason code, and shall quote no text of the file in any message, issue or log line. <!-- test: packages/config/test/config-env.test.ts -->

## Secrets file

- [x] **CFG-SEC-001**: `@cohost/config` `secretsPath()` shall return `COHOST_SECRETS_FILE` when it is set and non-empty, else `secrets/secrets.yaml` under the workspace root, else `secrets/secrets.yaml` in the parent of the config directory when there is no workspace root, whatever `CONFIG_DIR` says, and when that file does not exist `loadConfig` shall load with every secret key at its schema default, the empty string, and emit no warning; the loader shall never create the file. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-002**: When `secrets.yaml` exists, `loadConfig` shall parse it as a YAML mapping nested like `config.yaml` and, after `config.yaml` has validated, set each non-empty string it holds at a secret path (CFG-SEC-003) into the validated config, in the same read and cached with it (CFG-LOAD-001); the merge follows validation so that a credential can never create a parent object `config.yaml` is required to hold. <!-- test: packages/config/test/config-secrets.test.ts -->
- [ ] **CFG-SEC-003**: `SECRET_PATHS` shall list exactly `llm.openai.api_key`, `llm.claude.api_key`, `llm.bedrock.access_key_id`, `llm.bedrock.secret_access_key`, `vision.obs.password`, `ears.openai.api_key`, `ears.nemotron.api_key`, `ears.kyutai.api_key`, `voice.openai.api_key`, `voice.pocket.hf_token`, `chat.twitch.client_id`, `chat.twitch.client_secret`, `chat.twitch.access_token`, `chat.twitch.refresh_token`, `chat.youtube.api_key`, `connections.discord.token` and `tools.servers.*.token` (CFG-SEC-016), and the loader shall merge no other path from `secrets.yaml`. <!-- test: packages/config/test/config-secrets.test.ts --> <!-- test: packages/config/test/editor.test.ts -->
- [x] **CFG-SEC-004**: When both files hold a value at a secret path, `loadConfig` shall use the value in `secrets.yaml`. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-011**: When `config.yaml` holds a non-empty value at a secret path, `loadConfig` shall never use it, whether or not `secrets.yaml` holds a value there, and shall emit one warning through the config logger (CFG-LOG-001) naming the path and never the value. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-005**: When `secrets.yaml` holds a key whose path is not in `SECRET_PATHS`, `loadConfig` shall load successfully, ignore that key and emit one warning through the config logger (CFG-LOG-001) listing the dotted paths of the ignored keys. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-006**: If `secrets.yaml` is not valid YAML, its root is not a mapping, or a secret path holds a value that is not a string, then `loadConfig` shall throw an error beginning `Invalid <file>:` that names the line and column of a syntax error or the path of a wrong value and quotes no text of the file. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-007**: If `secrets.yaml` exists and cannot be read, then `loadConfig` shall throw an error naming the file and the operating-system error code and shall not fall back to an empty set of secrets. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-008**: While `secrets.yaml` grants any permission to group or other (`mode & 0o077` is non-zero), `loadConfig` shall load it and emit one warning naming the file and advising `chmod 600`, except that it shall emit none when `process.platform` is `win32` or the reported mode is exactly `0o777`, the mode drvfs and similar mounts report for every file. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-009**: `updateSecrets(file, changes)` shall set or clear the secret paths named in `changes`, refuse a path outside `SECRET_PATHS`, keep every other key and comment of the file and replace the file through `writeFileAtomic` (CFG-USR-013); the HTTP route that calls it belongs to the dashboard segment. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-010**: No log line, warning or error message that the loader, the editor or `updateSecrets` produces shall contain the value of a secret or any text of `secrets.yaml` beyond key paths, line numbers and column numbers. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-012**: Every write of `secrets.yaml` by `updateSecrets` shall create its temporary file with mode 0600 before any byte is written to it (`writeFileAtomic` takes the mode as an option passed at creation), so that the file has mode 0600 after a write that creates it and after a write that updates an existing file, whatever mode the previous file had; the loader shall never create or write the file. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-013**: When `updateSecrets` is asked to set a path, it shall trim leading and trailing whitespace from the value before storing it and shall refuse, naming the path, a value that is empty after trimming; a path is cleared only by a request to clear it. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-014**: When `loadConfig` reads `secrets.yaml`, it shall trim leading and trailing whitespace from every secret value (so a block scalar's trailing newline never reaches a consumer), treat a value empty after trimming as not set, and fail the load with an error that names the path and never the value when a trimmed value still contains a line break. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-015**: When the `secrets.yaml` that `updateSecrets` is asked to write is a symbolic link, it shall write the file the link resolves to (a temporary file in that file's directory with mode 0600, then a rename) and leave the link in place, and when the link resolves to no file it shall fail naming the path and write nothing. <!-- test: packages/config/test/config-secrets.test.ts -->
- [x] **CFG-SEC-016**: Where a path of `SECRET_PATHS` holds one `*` segment, the loader shall let it match exactly one key of the map that `config.yaml` holds at that place, so that `tools.servers.*.token` matches the `token` of each entry of `tools.servers`.
- [x] **CFG-SEC-017**: When `secrets.yaml` holds a token for a `tools.servers` entry that `config.yaml` does not hold, the loader shall not merge it and shall list its path, never its value, in the one warning of CFG-SEC-005 and in no other.
- [x] **CFG-SEC-018**: When `updateSecrets` is asked to clear a path that matches a wildcard path of `SECRET_PATHS`, it shall clear it whatever entries `config.yaml` holds, and the dashboard route, which knows the entries, shall refuse a set for one it does not hold (DASH-SECRET-014).
- [x] **CFG-SEC-019**: `@cohost/config` shall export `projectSecrets(root, units)`, which takes the workspace root and a list of units (each a Compose service name and its declared secret paths) and carries out the projection of deployment DEPLOY-SECRET-003, DEPLOY-SECRET-005, DEPLOY-SECRET-007 and DEPLOY-SECRET-009 (the checks on the operator's file's location and on unit names included), reading `secretsPath()` with the rules of CFG-SEC-006, CFG-SEC-007 and CFG-SEC-014, and shall reject with an error naming the file, directory or path and never a value.

## Structured errors and recovery editing (RCV)

- [x] **CFG-RCV-001**: When `loadConfig` fails for a reason of CFG-LOAD-003, CFG-LOAD-007, CFG-ENV-011 or CFG-SEC-006, it shall throw a `ConfigError` (exported by `@cohost/config`), an `Error` whose message is the text those requirements give and whose `problems` lists every issue as `{file, path, message, kind}`: `file` the path of the file, `kind` `syntax` for `config.yaml` that is not YAML, `placeholder`, `schema`, or `secrets` for every problem of `secrets.yaml`, and `path` dotted with each list index written `[i]` (empty for the file as a whole); a failure to read a file, to seed it, or to parse `COHOST_ISOLATION` shall stay a plain `Error`. <!-- test: packages/config/test/config-recovery.test.ts -->
- [x] **CFG-RCV-002**: When `checkConfig()` is called, the system shall read `secrets.yaml` and `config.yaml` as `loadConfig` reads them, without its cache, without any log line and with no isolation override, and return the problems of both in the shape of CFG-RCV-001, those of `secrets.yaml` first and `config.yaml` validated with the secrets that could be read (none when `secrets.yaml` fails), and an empty list exactly when `loadConfig(true)` would return a configuration for that environment with no `COHOST_ISOLATION`; any other failure shall be thrown. <!-- test: packages/config/test/config-recovery.test.ts -->
- [x] **CFG-RCV-003**: When `setConfigKey(text, path, value)` is called, the system shall return `{ok: true, text}` with the value at the dotted `path` set to `value` by the settings editor's splicing (a held node replaced keeping a string's quote style, a missing key inserted into the deepest mapping the text holds) and every other byte unchanged, without validating any other key; `path` names a key `ConfigSchema` defines, or a single-value entry `key[i]` that the list at `key` holds, checked against the list's element schema. It shall return `{ok: false, issues}` and no text when the path names no such key (a name that is not the schema's own, such as `__proto__`, `constructor` or `llm.toString`, included), a list entry that the text does not hold or that is not a single value, a section, or a secret path (CFG-SEC-003), when the value holds a `${NAME}` placeholder or fails its schema, or when the edited text does not read back as the value. <!-- test: packages/config/test/config-recovery.test.ts -->
- [x] **CFG-RCV-004**: When `resetConfigKey(text, path)` is called, the system shall return `{ok: true, text, path}` with the key at `path` removed, where `path` is cut before its first `[` (a list is reset whole) and is returned as removed; in a block mapping the key's lines, from the start of its key's line to the end of its value's last line, go with the comments on those lines, every other line and comment stays, and a block mapping left without keys is written `{}`; a key inside a flow mapping is cut from the text with its separator, and a flow mapping left without keys is written `{}`; a text that does not hold the key, or does not parse, shall give `{ok: false, issues}`. <!-- test: packages/config/test/config-recovery.test.ts -->
- [x] **CFG-RCV-005**: When `placeholderFallback(text, path)` is called for a key whose string value holds a `${NAME:-fallback}` placeholder, the system shall return `{value}`: the fallback read as YAML when the scalar is unquoted and is exactly the placeholder, else the string with each placeholder replaced by its fallback; it shall return undefined when a placeholder at the key has no fallback, the key holds no placeholder, or the text does not parse. <!-- test: packages/config/test/config-recovery.test.ts -->
- [x] **CFG-RCV-006**: When `secretRepair(text, path)` is called with the text of `secrets.yaml`, the system shall return `{value}`: the source text of the value at `path` when it is a plain scalar that is not a string (an all-digit token keeps its leading zeros, `true` stays `true`), for the caller to write back as a quoted string, and `null`, for the caller to clear, when the value is a list, a mapping, spans lines or the text does not parse; it shall log nothing. <!-- test: packages/config/test/config-recovery.test.ts -->

- [x] **CFG-LOG-002**: The first time a process either calls `createLogger(service)` or writes through the config logger (CFG-LOG-001), whichever comes first, the logger shall run the bootstrap read once: call `loadDotEnv()` (which never overrides a variable already set), then read the `logging` section from `config.yaml` in the config directory (CFG-DIR-001) and validate that section alone, without seeding any file, merging `secrets.yaml` or applying isolation overrides; every later `createLogger` call and config-logger write of the process shall reuse that result without reading the file again.
- [x] **CFG-LOG-003**: Where `config.yaml` is missing or is not valid YAML, or its `logging` section fails validation, the bootstrap read (CFG-LOG-002) shall use the schema defaults of CFG-SCH-113 and CFG-SCH-114 and report nothing, leaving the report to `loadConfig`.
- [x] **CFG-LOG-004**: The logger's level, terminal format and file settings shall come from the bootstrap read (CFG-LOG-002) alone, and a `LOG_LEVEL` variable in the environment or `.env` shall have no effect on them.
- [x] **CFG-LOG-005**: While `logging.terminal` is `pretty`, each entry shall print to standard output as one line beginning with the entry's time in the process's local time zone as `HH:MM:SS.mmm`, one space, the level name in upper case padded with spaces to five characters, one space, the logger's name followed by `: `, and the first line of the entry's message.
- [x] **CFG-LOG-006**: While `logging.terminal` is `pretty`, when an entry's message holds line breaks, each line after the first shall print as a line of its own, directly after the entry's first line, made of four spaces followed by the message line as written (its own leading spaces kept), and a message line that is empty shall print as an empty line with no spaces.
- [x] **CFG-LOG-007**: While `logging.terminal` is `pretty`, each field of an entry other than `time`, `level`, `name`, `msg`, `pid` and `hostname` whose value is a string, number, boolean or null shall print at the end of the entry's first line as one space and `key=value`, in the entry's field order, with a string written as JSON (quoted and escaped) when it is empty or holds whitespace, `=`, `"` or a control character, and bare otherwise.
- [x] **CFG-LOG-008**: While `logging.terminal` is `pretty`, each field whose value is an object or an array shall print after the entry's message lines as a line of four spaces, the key and `:`, followed by the value as JSON with two-space indentation, each line of it indented by six spaces; where the value is an error (an object with a string `stack`), the lines that follow shall be its stack and then, when any remain, its properties other than `type`, `message` and `stack` as JSON.
- [x] **CFG-LOG-009**: While `logging.terminal` is `pretty`, the level name shall be wrapped in an ANSI colour (red for `FATAL` and `ERROR`, yellow for `WARN`, green for `INFO`, blue for `DEBUG`, grey for `TRACE`) only when standard output is a TTY and `NO_COLOR` is unset or empty, and otherwise the output shall hold no escape sequence.
- [x] **CFG-LOG-010**: While `logging.terminal` is `pretty`, every C0 and C1 control character and `DEL` in a logged message, key or value, other than the line feeds CFG-LOG-006 lays out and the tab, and every bidirectional override or isolate (U+202A to U+202E, U+2066 to U+2069) shall print as a `\u` escape of its code point, so that no logged text can move the cursor, clear the screen, change the terminal's colours or reorder the characters a line shows.
- [x] **CFG-LOG-011**: While `logging.terminal` is `json`, each entry shall print to standard output as exactly the JSON line pino serialised for it, followed by a line feed.
- [x] **CFG-LOG-012**: While `logging.file.enabled` is true and the process's sink was not created with the file off (CFG-LOG-022), each entry at or above `logging.level` shall be appended to `<dataDir()>/logs/<service>.log` as exactly the JSON line pino serialised for it (every field it holds) followed by a line feed, whatever `logging.terminal` says, creating the `logs` directory with mode 0755 when missing and the file with mode 0644.
- [x] **CFG-LOG-013**: The logger shall write each entry to the file and to standard output before the logging call returns, so that an entry logged immediately before `process.exit` is in the file.
- [x] **CFG-LOG-014**: Before writing each entry to the file, the logger shall stat `<service>.log` and, where the path is missing or names a different file from the one it holds open, open `<service>.log` afresh (creating it) and write the entry there; the size that stat reports shall be the size the rotation check (CFG-LOG-015) uses.
- [x] **CFG-LOG-015**: When `<service>.log` is non-empty and appending the next entry would make it larger than `logging.file.max_size_mb` mebibytes, the logger shall first, where `<service>.1.log` exists, rename each `<service>.<n>.log` to `<service>.<n+1>.log` from the highest `n` down (so a retry after a failed rename of `<service>.log` does not shift the numbered files twice), then rename `<service>.log` to `<service>.1.log`, and write the entry to a new `<service>.log`; an empty `<service>.log` shall never be rotated, so an entry larger than the limit is written whole.
- [x] **CFG-LOG-016**: When a rotation (CFG-LOG-015) leaves a `<service>.<n>.log` with `n` greater than `logging.file.max_files`, the logger shall delete it, so that a program's log files never number more than `logging.file.max_files` plus one.
- [x] **CFG-LOG-017**: The first `createLogger(service)` call of a process shall create the process's one logging sink and name its file for that `service`; every later `createLogger` call of the process shall return a logger that writes to the same terminal stream and file with its own `name`.
