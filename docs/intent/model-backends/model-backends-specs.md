# model-backends specs

Design: [model-backends-design.md](model-backends-design.md). Prefix `LLM`. `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred. Test paths are relative to the repo root.

## Interface and factory

- [x] **LLM-IF-001**: The `@cohost/llm` package shall expose every chat backend as a `ChatProvider` with `name`, `model`, `chat(messages, opts)`, `ping()` and an optional `lastError`, and every embedding source as an `Embedder` with `embed(text)`. <!-- openspec: llm § Provider factory --> <!-- no runtime test: a type-level contract that tsc enforces through `implements ChatProvider` / `implements Embedder` -->
- [x] **LLM-IF-002**: When `createChatProvider` is called with `llm.provider` of `ollama`, `openai`, `anthropic`, `bedrock` or `mock`, the model-backends package shall return a provider whose `name` is that same string. <!-- openspec: llm § Provider factory --> <!-- test: packages/llm/test/llm.test.ts, packages/llm/test/llm.test.ts (mock) -->
- [x] **LLM-IF-003**: The model-backends package shall construct a `MockProvider` only through the explicit `mock` case of `createChatProvider`, with no fallback path from any other provider value to mock. <!-- openspec: llm § Provider factory --> <!-- test: packages/llm/test/llm.test.ts -->
- [x] **LLM-IF-004**: When `chat()` completes on any provider, the model-backends package shall resolve to the reply text with leading and trailing whitespace removed. <!-- test: packages/llm/test/llm.test.ts (openai), packages/llm/test/llm.test.ts (Claude) -->
- [ ] **LLM-IF-005**: When `complete()` is called on any provider, the package shall send a non-streamed request and resolve to a `ChatResult` with `text`, `toolCalls`, `finish` and `message`.
- [ ] **LLM-IF-006**: When `complete()` resolves on any provider, `result.text` shall be the reply text with leading and trailing whitespace removed, and shall be an empty string when the model wrote no text, including when it only asked for tools.
- [ ] **LLM-IF-007**: When `complete()` resolves on any provider, `result.message` shall be an assistant message whose `content` equals `result.text` and which carries the reply's tool calls as `toolCalls` when there are any.
- [ ] **LLM-IF-008**: When `stream()` is called on any provider, the package shall return an async iterable that sends no request until it is first read.
- [ ] **LLM-IF-009**: When a `stream()` iterable completes without failure, the package shall deliver exactly one `done` event carrying a `ChatResult`, and shall deliver it last.
- [ ] **LLM-IF-010**: When the caller ends a `stream()` loop early (`break`, or `return()` on the iterator), the package shall cancel the request and shall not throw an error.
- [ ] **LLM-IF-011**: When `chat()` is called on any provider, the package shall offer the model no tools, shall ignore any tool call the model emits, and shall resolve to the reply text.
- [ ] **LLM-IF-012**: If the history passed to `chat()` contains a `tool` message or an assistant message with a non-empty `toolCalls`, then `chat()` shall reject with a `TypeError` before sending any request.
- [ ] **LLM-IF-013**: When the model asks for tools in a reply to `complete()` or `stream()` that neither the token cap nor a refusal ended, the `finish` of the result shall be `tool_calls`, whether or not the model also wrote text.
- [ ] **LLM-IF-014**: When the token cap ends a reply to `complete()` or `stream()`, the `finish` of the result shall be `length`.
- [ ] **LLM-IF-015**: When a reply to `complete()` or `stream()` ends for none of the reasons that give `tool_calls`, `length` or `refusal`, the `finish` of the result shall be `stop`.
- [ ] **LLM-IF-016**: When the token cap ends a reply to `complete()` or `stream()` that also asked for tools, the `finish` of the result shall be `length` and not `tool_calls`.
- [ ] **LLM-IF-017**: When the OpenAI-compatible provider reads a reply to `complete()` or `stream()`, it shall map `finish_reason` `tool_calls` to `finish` `tool_calls` and `finish_reason` `length` to `finish` `length`.
- [ ] **LLM-IF-018**: When a Claude provider reads a reply to `complete()` or `stream()`, it shall map `stop_reason` `tool_use` to `finish` `tool_calls`, `max_tokens` to `length` and `refusal` to `refusal`.
- [ ] **LLM-IF-019**: When the Ollama provider reads a reply to `complete()` or `stream()`, it shall map any `tool_calls` in the message to `finish` `tool_calls` and `done_reason` `length` to `finish` `length`.
- [ ] **LLM-IF-020**: The `ChatProvider` of every provider shall expose `complete(messages, req)` and `stream(messages, req)` beside `chat(messages, opts)`.
- [ ] **LLM-IF-021**: When `stream()` is called on any provider, the call shall not throw synchronously: every failure, including a `TypeError` for a wrongly built request and `not_configured`, shall surface from the iterator on its first read.
- [ ] **LLM-IF-022**: When the model asked for no tool calls in a reply to `complete()`, `result.message` shall carry no `toolCalls` property.

## Errors

- [ ] **LLM-ERR-001**: Every failure of `chat()`, `complete()` or `stream()` on any real provider that is not a timeout (LLM-ERR-005), a caller's abort (LLM-ERR-006) or a programming error shall be raised as a `ChatError` whose `kind` is `http`, `connect`, `stream` or `not_configured`.
- [ ] **LLM-ERR-002**: If an SDK request made by `chat()` or `complete()` on the `anthropic` or `bedrock` provider fails with an HTTP status, or a `stream()` request on it fails with an HTTP status before the response began, then the provider shall throw a `ChatError` of kind `http` that carries that status.
- [ ] **LLM-ERR-003**: If `chat()`, `complete()` or `stream()` is called on a provider whose credentials are not set, then the provider shall throw a `ChatError` of kind `not_configured`.
- [ ] **LLM-ERR-004**: If a backend answers a `chat()`, `complete()` or `stream()` request with HTTP 400 and a body that names tools, images or vision, then the provider shall throw a `ChatError` of kind `http` with that status, exactly as for any other non-2xx answer.
- [ ] **LLM-ERR-005**: When the default timeout `llm.timeout_ms` elapses on a `chat()` or `complete()` request to the Ollama or OpenAI-compatible provider, the call shall reject with the `TimeoutError` that `AbortSignal.timeout` gives and not with a `ChatError`.
- [ ] **LLM-ERR-006**: When the caller aborts the `signal` passed to `chat()`, `complete()` or `stream()`, the call shall fail with the caller's abort reason and not with a `ChatError`.
- [ ] **LLM-ERR-007**: If an Ollama or OpenAI-compatible request made by `chat()` or `complete()` returns a non-2xx status, then the provider shall throw a `ChatError` of kind `http` that carries the status and whose message is `<provider> chat <status>: <response body>`.
- [ ] **LLM-ERR-008**: If the connection of an Ollama or OpenAI-compatible request made by `chat()`, `complete()` or `stream()` fails before any reply (the backend cannot be reached or refuses the connection), then the provider shall throw a `ChatError` of kind `connect` that carries no `status`.
- [ ] **LLM-ERR-009**: If the connection of an SDK request made by `chat()`, `complete()` or `stream()` on the `anthropic` or `bedrock` provider fails before any reply, then the provider shall throw a `ChatError` of kind `connect` that carries no `status`.

## Streamed replies and tool calls

Each line names the provider and the call it applies to; `stream()` is the streamed call and `complete()` the non-streamed one that also returns tool calls.

- [ ] **LLM-STREAM-001**: When `stream()` is called on the Ollama provider, the package shall send `POST /api/chat` with `stream` true and the other request fields that `chat()` sends.
- [ ] **LLM-STREAM-002**: When the Ollama provider reads a `stream()` response, it shall read newline-delimited JSON lines of the form `{message: {content, tool_calls?}, done, done_reason}` and shall deliver each non-empty `content` piece as a `text` event.
- [ ] **LLM-STREAM-003**: When the Ollama provider has read a `stream()` response to its end, it shall deliver one `tool_call` event for each call that the response's `message.tool_calls` carried, in the order given, after every `text` event.
- [ ] **LLM-STREAM-004**: When `stream()` is called on the OpenAI-compatible provider, the package shall send `stream` true and shall read the response as server-sent `data:` chunks until `[DONE]`.
- [ ] **LLM-STREAM-005**: When the OpenAI-compatible provider reads a `stream()` chunk with `delta.content`, it shall deliver that content as a `text` event.
- [ ] **LLM-STREAM-006**: When the OpenAI-compatible provider reads `delta.tool_calls` fragments in a `stream()` response, it shall assemble them by `index` and, once `finish_reason` has arrived, shall deliver each call as one `tool_call` event in the order of `index`, after every `text` event.
- [ ] **LLM-STREAM-007**: When `stream()` is called on a Claude provider, the package shall use the SDK's streaming request and shall deliver each `text_delta` as a `text` event.
- [ ] **LLM-STREAM-008**: When a Claude provider reads a `stream()` response, it shall deliver no event for `thinking` deltas.
- [ ] **LLM-STREAM-009**: When a `stream()` iterable delivers its `done` event on any provider, `done.result.text` shall equal the concatenation of all `text` deltas delivered, which is the reply's text as a whole trimmed as `chat()` trims it.
- [ ] **LLM-STREAM-010**: When a `stream()` reply begins with whitespace, the provider shall deliver no `text` event until the first non-whitespace character and shall start the first delta at that character.
- [ ] **LLM-STREAM-011**: When whitespace ends the text delivered so far in a `stream()` reply, the provider shall hold that whitespace back and shall release it before the next text delta if more text follows, and shall never deliver it when no more text follows.
- [ ] **LLM-STREAM-012**: When a `stream()` reply holds tool calls, the provider shall deliver the `tool_call` events only once the backend has reported how the reply ended, after every `text` event, in the order the model asked and immediately before `done`.
- [ ] **LLM-STREAM-013**: When a Claude reply to `stream()` or `complete()` holds text in several blocks, the provider shall join the text of the blocks with no separator.
- [ ] **LLM-STREAM-014**: When `stream()` is called on any real provider, the package shall send the stop sequences that a non-streamed call would send and shall perform no cut of the streamed text of its own.
- [ ] **LLM-STREAM-015**: When `stream()` is called on any real provider, the package shall fail the call with a `TimeoutError` if `llm.timeout_ms` elapses between sending the request and the backend first sending reply text (including whitespace that is held back), a tool-call fragment, or the end of the reply, whether or not the caller passes a `signal`.
- [ ] **LLM-STREAM-016**: When `stream()` is called on any real provider, the package shall fail the call with a `TimeoutError` if `llm.timeout_ms` elapses between one backend event and the next after the first output has been received, counting a thinking delta or a keepalive as an event, whether or not the caller passes a `signal`.
- [ ] **LLM-STREAM-017**: When a Claude provider reads a `stream()` response, a `thinking` delta shall not satisfy the first-output bound of LLM-STREAM-015, so a model that thinks longer than `llm.timeout_ms` before any output fails the call with a `TimeoutError`.
- [ ] **LLM-STREAM-018**: When the caller passes a `signal` to `stream()`, the package shall still apply the first-output bound and the between-events bound, and the `signal` shall only add a way to cancel.
- [ ] **LLM-STREAM-019**: While a `stream()` reply keeps producing events within `llm.timeout_ms` of each other, the package shall not end it for its total duration.
- [ ] **LLM-STREAM-020**: If the backend answers a `stream()` request with a non-2xx status before any event, then the iterator shall throw a `ChatError` of kind `http`.
- [ ] **LLM-STREAM-021**: If a `stream()` call fails after the response began (a dropped connection, or an SDK error such as a Claude `error` event), then the iterator shall throw a `ChatError` of kind `stream`.
- [ ] **LLM-STREAM-022**: If the backend ends a `stream()` response without a final event, then the iterator shall throw a `ChatError` of kind `stream`.
- [ ] **LLM-STREAM-023**: If a chunk of a `stream()` response cannot be parsed, then the iterator shall throw a `ChatError` of kind `stream`.
- [ ] **LLM-STREAM-024**: If a `stream()` iterable fails, then the package shall deliver no `done` event.
- [ ] **LLM-STREAM-025**: If a `stream()` iterable fails after it has delivered an event, then the package shall not retry the request.
- [ ] **LLM-STREAM-026**: If the caller aborts the `signal` of a `stream()` call, then the iterator shall throw the caller's abort reason.
- [ ] **LLM-STREAM-027**: When a Claude provider reads a `stream()` response whose `stop_reason` is `refusal`, it shall deliver `done` with `finish` `refusal`.
- [ ] **LLM-STREAM-028**: When the model writes no text in a `stream()` reply, the provider shall deliver no `text` event and shall deliver `done` with an empty `result.text`.
- [ ] **LLM-STREAM-029**: When a backend answers a `stream()` request on the Ollama or OpenAI-compatible provider with one JSON body instead of a stream, the provider shall deliver its text as one `text` event, one `tool_call` event for each call, and then `done`.
- [ ] **LLM-STREAM-030**: When a Claude provider reads a `tool_use` block in a `stream()` response, it shall assemble the `input_json_delta` fragments and, once the final message delta has reported `stop_reason`, shall deliver the call as one `tool_call` event after every `text` event.
- [ ] **LLM-STREAM-031**: When a Claude provider reads a `stream()` response, it shall take the finish reason from the `stop_reason` in the final message delta.
- [ ] **LLM-STREAM-032**: When a `stream()` iterable delivers its `done` event on any provider, `done.result.toolCalls` shall equal the calls delivered as `tool_call` events, in the order delivered.
- [ ] **LLM-STREAM-033**: When a Claude reply is refused, `stream()` shall deliver `done` whose `result.text` is the text already delivered, which may differ from the empty `text` that `complete()` resolves with for the same reply.
- [ ] **LLM-STREAM-034**: While a `stream()` read is not pending, the package shall not run the first-output clock of LLM-STREAM-015; it shall run it only while the caller waits on a pending read of the iterator.
- [ ] **LLM-STREAM-035**: While a `stream()` read is not pending, the package shall not run the between-events clock of LLM-STREAM-016; it shall run it only while the caller waits on a pending read of the iterator.
- [ ] **LLM-STREAM-036**: When the OpenAI-compatible provider reads the chunk carrying `finish_reason` in a `stream()` response and the response then ends without `[DONE]`, the provider shall complete the stream normally.
- [ ] **LLM-STREAM-037**: If an OpenAI-compatible `stream()` response ends before the chunk carrying `finish_reason`, then the iterator shall throw a `ChatError` of kind `stream`.

## Tool calls

- [ ] **LLM-TOOL-001**: If a `ToolSpec` passed to `complete()` or `stream()` has a `name` outside `[A-Za-z0-9_-]{1,64}`, then the call shall fail with a `TypeError` before any request is sent.
- [ ] **LLM-TOOL-002**: If `complete()` or `stream()` is called with `json: true` together with a non-empty `tools` array, then the call shall fail with a `TypeError` before any request is sent.
- [ ] **LLM-TOOL-003**: When `complete()` or `stream()` is called on the Ollama provider with `tools`, the package shall send `tools` as `[{type: "function", function: {name, description, parameters}}]`.
- [ ] **LLM-TOOL-004**: When the Ollama provider reads a tool call in a reply to `complete()` or `stream()`, it shall take `name` and the `arguments` object from `message.tool_calls[].function` and shall give the call an id that is unique within the reply.
- [ ] **LLM-TOOL-005**: When the Ollama provider sends a `tool` message, it shall send it as `{role: "tool", tool_name, content}`.
- [ ] **LLM-TOOL-006**: When `complete()` or `stream()` is called on the OpenAI-compatible provider with `tools`, the package shall send `tools` as `[{type: "function", function}]`.
- [ ] **LLM-TOOL-007**: When the OpenAI-compatible provider reads a tool call in a reply to `complete()` or `stream()`, it shall parse the JSON string in `arguments` into an object.
- [ ] **LLM-TOOL-008**: When the OpenAI-compatible provider sends a `tool` message, it shall send it as `{role: "tool", tool_call_id, content}`.
- [ ] **LLM-TOOL-009**: When the OpenAI-compatible provider sends an assistant message that has `toolCalls`, it shall send each call with its `arguments` serialized as a JSON string.
- [ ] **LLM-TOOL-010**: When `complete()` or `stream()` is called on a Claude provider with `tools`, the package shall send `tools` as `[{name, description, input_schema}]`.
- [ ] **LLM-TOOL-011**: When a Claude provider reads a `tool_use` block in a reply to `complete()` or `stream()`, it shall take the call's `id`, `name` and `input` from it.
- [ ] **LLM-TOOL-012**: When a Claude provider sends consecutive `tool` messages, it shall send them as `tool_result` blocks (`tool_use_id`, `is_error`) in one user turn, in the order given.
- [ ] **LLM-TOOL-013**: When a Claude provider sends an assistant message that has `toolCalls`, it shall send the thinking blocks kept in its `continuation`, then one `tool_use` block per call, and shall send a text block before the `tool_use` blocks only when the message's `content` is non-empty.
- [ ] **LLM-TOOL-014**: When a Claude provider resolves `complete()` or delivers `done` for `stream()`, it shall keep the reply's thinking blocks and tool calls in the `continuation` of `result.message`.
- [ ] **LLM-TOOL-015**: When a provider reads an assistant message whose `continuation` names a provider other than its own, it shall treat the message as having no `continuation`, so that `anthropic` and `bedrock` do not read each other's.
