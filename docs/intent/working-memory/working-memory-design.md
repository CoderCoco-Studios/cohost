# working-memory

Status: AUDITED. Describes the intended design. Parent: [high-level-design](../../high-level-design.md). Specs: [working-memory-specs.md](working-memory-specs.md). Arrow: [docs/arrows/working-memory.md](../../arrows/working-memory.md).

## Context and Design Philosophy

`@cohost/working-memory` (`packages/working-memory/src/index.ts`) is a small, pure, in-process library: a rolling window of the most recent perception events, with per-event "seen" tracking and a renderer that turns the window into the transcript text that goes into the LLM prompt. It has no I/O, timers or Redis access.

It exists because two brain regions need the same view of "what has happened lately" and each keeps its own instance of this one implementation, fed by the same bus events:

- [salience](../salience/salience-design.md) builds a `Context` (`services/salience/src/salience.ts`) to decide whether anything unseen is worth responding to; its scorer also imports the `ContextEvent` type (`services/salience/src/scoring.ts`).
- [cortex](../cortex/cortex-design.md) builds a `Context` (`services/cortex/src/cortex.ts`) to render the prompt transcript and the "on screen right now" line.
- affect does not use it: `services/affect/package.json` and `services/affect/tsconfig.json` list it with no importing file; the affect segment owns that cleanup.

Both windows are sized by the same config key `brain.working_memory_events` (default 24, in `packages/config/src/schema.ts`; config segment), read in one place, `Context.forBrain` (WM-WIN-008). `Context.forBrain(brain, viewerText)` takes the brain section and the config's `viewer_text` section as its two arguments, so the first argument and its result are as WM-WIN-008 states and the second carries the viewer-text limits (WM-WIN-011). A `Context` built directly, without `forBrain`, protects no `self` entries unless it is told to (WM-WIN-012). The same function reads `brain.working_memory_own_lines` (how many of the co-host's own lines the window protects, see Keeping the co-host's own lines in the window) and the text limits `push` and the renderer pass to the untrusted text guard (`viewer_text.max_chars`, `viewer_text.max_name_chars`, `brain.input_limits.speech_max_chars`, `brain.input_limits.vision_max_chars`; config owns the keys and defaults), so no region reads them separately. The two instances are independent; nothing synchronizes them except receiving the same events.

The package also owns the plumbing for **test-injection flags** : contexts retain `injected` / `remember` on the events they store, and `propagatedFlags` copies them onto derived bus events so a reply to an injected input is itself marked injected. The flags are defined on the bus schemas in [event-bus](../event-bus/event-bus-design.md); the policy of what to do with them lives in [memory](../memory/memory-design.md) (`services/memory/src/region.ts`), [salience](../salience/salience-design.md) and [cortex](../cortex/cortex-design.md).

## The `Context` window

`ContextEvent` is a discriminated union on `kind` (`index.ts`):

| kind | Built from | Fields | Seen on arrival |
|---|---|---|---|
| `chat` | bus `chat.message` | `eventId` (bus event id), `ts` (bus event ts), `user`, `text`, `mention` (from `mentionsCohost`), `isMod`, `isSub`, `seen`, plus `InjectionFlags` | no |
| `vision` | bus `vision.summary` | `eventId`, `ts`, `text`, `changed`, `timing?` (the event's `timing`, WM-PUSH-013), `seen`, plus `InjectionFlags` | `seen = !changed` |
| `speech` | bus `speech.heard` | `eventId`, `ts`, `speaker`, `text`, `timing?` (the event's `timing`, WM-PUSH-011), `seen`, plus `InjectionFlags` | no |
| `self` | `pushSelf(text, emotion, ts, id?)` (not a bus event) | `ts` (the bus `ts` of the `brain.say` it records), `text`, `emotion`, `seen: true` (literal type), no flags; `id` (the `brain.say` id), `fallback` (the text heard instead) for the spoken fallback line (WM-PUSH-007, WM-PUSH-008) and `heard` (the part the audience heard, `markHeard`) | always |

`Context` holds a private `events` array, the public string `lastVision`, and a `max` count from the constructor.

- **`push(ev: BusEvent)`** switches on `ev.type` (one cast to a type narrowed per event type at the entry, so each case reads its own payload) and returns the context entry it appended, or `undefined` when the type is ignored (WM-PUSH-009); callers that react to what they just pushed hold the entry instead of reading `last()` afterwards. `chat.message`, `vision.summary` and `speech.heard` are converted and appended, each with its text and names bounded as it enters the window (below); every other type hits `default: return` and leaves the window untouched (a `speech.partial` among them, WM-PUSH-012) (WM-PUSH-003). `brain.say` is therefore not ingested here; own and other speakers' lines enter only via `pushSelf`, which the owning region calls (`services/cortex/src/cortex.ts` for every `brain.say`, including reflexes and operator lines from other sources).
- **Text is bounded on entry.** `push` applies the shared guard's `boundText` ([shared-runtime](../shared-runtime/shared-runtime-design.md) Untrusted text guard) to what it stores: a `chat` entry's text with `viewer_text.max_chars` and its `user` with `viewer_text.max_name_chars`, a `speech` entry's text with `brain.input_limits.speech_max_chars` and its `speaker` with the name limit, a `vision` entry's text, and so `lastVision`, with `brain.input_limits.vision_max_chars`. A name that bounds to nothing is stored as `unknown` (`UNKNOWN_NAME`). The window is where salience and cortex both take events in, so everything either of them scores, renders or hands to a hook (an `http` hook included) is bounded, whatever put the event on the bus. `mention`, `isMod` and `isSub` are stored as the event carries them; the window computes none of them (WM-PUSH-014 to WM-PUSH-018).
- **Vision is special-cased**: `lastVision` is set to the new text, every earlier `vision` entry is removed from the window, and the new one is appended. Only the newest screen description is ever present in the window. `changed: false` entries arrive already seen, so an unchanged screen does not count as new input, but still updates `lastVision`.
- **Trimming** is by count only: when the window exceeds `max`, the oldest entries are spliced off, except that the newest `brain.working_memory_own_lines` `self` entries are never the ones removed (below). There is no time-based eviction. Self lines count against `max` (`pushSelf` also trims). Note the vision filter removes an old vision entry before the new one is pushed, so a vision update can lower the window length.
- **Seen tracking:** `unseen()` returns entries with `seen === false`; `markSeen()` marks all; `markSeenEvents(events)` marks only the given entries, matched by **event id** (`eventId`, WM-SEEN-002): a copy of an entry marks its original, while entries already trimmed, `self` entries and ids the window does not hold are ignored silently. This is what lets salience mark only the events it scored while newer arrivals stay unseen (`services/salience/src/salience.ts`).
- **Arrivals hold** (WM-SEEN-004): `holdArrivals()` starts recording the entry that each `push` returns (at most `max` of them, oldest dropped first; `clear()` empties the record but keeps holding); `releaseArrivals()` stops recording and marks every recorded entry seen. Salience holds while paused, so the first decision after `resume` does not score a burst that accumulated meanwhile (SAL-CTRL-007); the record is window state, so it lives here and not in the region.
- **Latency stamps.** A `speech` entry keeps the `speech.heard`'s `timing` object, and a `vision` entry the `vision.summary`'s, when it has one, so salience can copy `audioEndedAt` (speech) or `capturedAt` and `describedAt` (vision) onto `attention.focus` ([salience](../salience/salience-design.md), SAL-FOCUS-006). The window only carries it: it is never rendered into the transcript and never read by the window's own logic.
- **`last()`** returns the newest entry. Salience and cortex hold the entry that `push` returns instead of reading `last()` after a push.
- **`clear()`** empties the window and resets `lastVision` to the empty string, so `forget_context` forgets the screen too (WM-WIN-003). Both services call it on the `forget_context` control command (`salience.ts`, `cortex.ts`).
- **`all()`** returns a shallow copy of the window, oldest first: a new array whose elements are the window's own objects, so `markSeenEvents` still matches them and a caller cannot mutate the window (WM-WIN-006). The return type stays `readonly ContextEvent[]`. Outside this package the cortex calls it in production (`services/cortex/src/cortex.ts`, to find the `self` line for a `brain.say` id and to build the transcript input) and salience tests call it.

### Transcript rendering and the stop-string contract

`transcript(cohostName)` maps each event to one line and joins with `"\n"`:

| kind | Line |
|---|---|
| `chat` | `[chat] <label>` + ` (mod)` if `isMod` + `: «<text>»`, where `<label>` is `speakerLabel(user, viewer_text.max_name_chars)` and `«<text>»` is `quoteUntrusted(text, viewer_text.max_chars)` |
| `speech` | `[voice] <label>: <text>`, where `<label>` is `speakerLabel(speaker, viewer_text.max_name_chars)` and `<text>` is the bounded text as stored, not quoted |
| `vision` | `[screen] <text>`, the bounded text as stored, not quoted |
| `self` | `<cohostName>: [<emotion>] <text>` |

`isSub`, `mention`, `changed`, timestamps, and the injection flags are **not** rendered, so an injected event is indistinguishable from a real one in the prompt: injection exists to drive the real code path (WM-TRANS-007).

Each event renders as exactly one line, because no bus text field is constrained to one line (`packages/bus/src/events.ts`) and a line break inside a field would let bus text forge a `[chat]`-style line or a co-host line (WM-TRANS-008). A `chat` line is built by the shared untrusted text guard ([shared-runtime](../shared-runtime/shared-runtime-design.md) Untrusted text guard): the name is a label with transcript syntax removed, and the message is quoted in `«` and `»` with any `«` or `»` typed by the viewer replaced, so it cannot close the quotes. `Context.transcript` is the one renderer of these lines and quotes each exactly once; the cortex prompt and the critic receive the rendered lines. Speech and screen text are viewer-independent text a speech engine or a vision model produced: they were bounded and flattened on entry and are rendered unquoted, so the co-host answers what the streamer says as it answers any speech. Every name, a speaker's included, goes through `speakerLabel`, because a name sits where the transcript's syntax is. The co-host's own line is flattened by `oneLine` (CR and LF become a single space; WM-TRANS-011), because its text comes from `brain.say` events that an operator or a configured reflex line can fill with a newline (WM-TRANS-002, WM-TRANS-003, WM-TRANS-012 to WM-TRANS-014).

The quotes sit inside the coupling with model-backends. Every line starts with its tag, so every line after the first starts with `"\n"` and the tag, which is what the stop sequences match; the delimiters come after the tag and the name, and the guard guarantees no line break inside them. A model that continues the transcript writes `\n[chat]` and is stopped. The self line is not a stop, and cortex's first-line reply parse reads the model's output, not the transcript.

**Cross-segment contract:** this segment owns the tags `[chat]`, `[voice]`, `[screen]` (WM-TRANS-006); the package exports the list as `TRANSCRIPT_TAGS` (WM-TRANS-009), and the LLM stop sequences are derived from it (LLM-STOP-006, LLM-STOP-007). `packages/llm/src/index.ts` defines `TRANSCRIPT_STOPS = ["\n[chat]", "\n[voice]", "\n[screen]"]` (derived from `TRANSCRIPT_TAGS`) with the comment "Lines that mean 'the model started writing the next transcript entry': stop there"; Ollama and OpenAI-compatible reply calls send `REPLY_STOPS = ["\n\n", ...TRANSCRIPT_STOPS]` (the comment caps the list at four because OpenAI-style APIs reject more), Claude reply calls send `TRANSCRIPT_STOPS` alone, and `json: true` calls send none. Because this renderer joins lines with `"\n"`, every entry after the first starts with `"\n" + tag`, which is exactly what the stops match. The cortex frames the transcript (`services/cortex/src/prompt.ts`) so the model writes the co-host's next line after a closing `<name>:` (`prompt.ts`), in the `[emotion] text` form the system turn asks for (`prompt.ts`), and `parseReply` keeps only the first line of the reply and strips a leading `Name:` (`parseReply` in `prompt.ts`). The full four-part contract is written up in [model-backends](../model-backends/model-backends-design.md) under "Stop sequences and the transcript coupling".

What follows for this package:

- A change to a tag, or a new line kind, changes `TRANSCRIPT_TAGS` here and the stops follow because they derive from it; otherwise a model that continues the transcript is no longer cut at that line by any provider (the cortex still drops everything after the first line, after the tokens are generated).
- The stops are a token and latency saver; the correctness guard for the spoken line is the cortex's first-line parse.
- The `self` line `<name>: [<emotion>] <text>` is deliberately not a stop: the four-stop cap leaves no room, and `parseReply` already cuts a model that runs on into another `<name>:` line.
- The pair is checked by a cortex-level test that renders a transcript with this package and asserts every line after the first starts with a stop (cortex segment); within this package `context.test.ts` pins the exported list against the rendered lines.

Consumers of `transcript`: `services/cortex/src/prompt.ts` (the prompt) and `services/cortex/src/cortex.ts` (passed to the critic). Consumers of `lastVision`: `services/cortex/src/prompt.ts` and the recall query fallback in `cortex.ts`.

### Keeping the co-host's own lines in the window

The window is one count shared by everything, so a flood of chat would push the co-host's own recent lines out of it, and with them out of cortex's prompt and the critic's transcript, where the model and the editor see what it just said. The window therefore protects them: when a push takes the count above `max`, the oldest event that is not among the newest `brain.working_memory_own_lines` `self` entries is removed (the key is at least 1, so at least the last line survives; config owns its default and bounds). Chat, speech and vision events compete for the remaining slots; the protected self lines keep their place in time order, so the transcript stays chronological and the co-host's recent lines stay inline with what they answered, never in a separate block. Protected lines are every `self` entry, whatever its source (cortex, a reflex, an operator `say`), because a reflex that just said something is as repeatable as a reply. The config schema keeps the key below `brain.working_memory_events`; the class itself protects at most `max - 1` lines, so the window always has a slot for other events. A `self` entry older than the newest few is evicted like any other, but while it remains in the window it is as visible as any: cortex's repetition check compares against every `self` entry the window holds ([cortex](../cortex/cortex-design.md) Repetition check), not only the protected ones (WM-WIN-001, WM-WIN-009 to WM-WIN-011).

A flood still evicts other people's lines, only not the co-host's. `clear()` empties protected lines too (`forget_context`). The salience instance never receives `self` lines, so protection has no effect there.

### Fallback lines

When a line the co-host meant to say fails to play and a pre-generated fallback line is said in its place ([mouth](../mouth/mouth-design.md) Fallback Line), the transcript must show what was actually heard and that the intended line glitched, so the co-host knows she glitched. The owner decided the fallback goes into the transcript as something she said, together with a note that the line she meant failed to play; the format below is.

- `pushSelf(text, emotion, ts, id?)` keeps the optional `id` on the `self` event; it is not rendered (WM-PUSH-007). cortex passes the `brain.say` id.
- `markFallback(id, fallbackText)` finds the `self` event with that id still in the window and records the fallback text on it; with no such event it changes nothing and reports that it marked nothing (WM-PUSH-008). Marking does not move the event or change its `seen` state.
- `markHeard(id, heard)` records on the `self` event with that id the part of it the audience heard: the spoken part of an interrupted line, or the empty string when nobody heard it; `heard` undefined clears the record. With no such event it changes nothing and returns false. It moves nothing, changes no `seen` state and does not change what `transcript` renders (the transcript keeps the line as the co-host meant it). cortex reads `heard`, then `fallback`, then `text` as what was heard (WM-PUSH-019, WM-PUSH-020).
- `hasSelf(id)` reports whether a `self` event with that id is still in the window (WM-WIN-007); cortex uses it to drop an acknowledgement hint whose line has scrolled out.
- A marked `self` event renders as one line: `<cohostName>: [<emotion>] <fallback text> [your line "<intended text>" failed to play; this came out instead]`, with CR and LF in both texts flattened to a space (WM-TRANS-010).

The note rides on the co-host's own line rather than a new tagged line. Every tag in `TRANSCRIPT_TAGS` is an LLM stop sequence, and the reply-stop list is already at the four entries OpenAI-style APIs accept (model-backends), so a fifth tag could not be a stop. A bracketed note after the text is safe on the output side too: `parseReply` strips every `[...]` from a reply (cortex), so a model that imitates the note cannot put it on stream. The fallback is shown as the spoken text because it is what viewers heard; the intended line stays visible inside the note so the co-host knows what she meant.

### Interrupted thoughts (deferred)

When a line is stopped mid-sentence ([mouth](../mouth/mouth-design.md) Stopping a line) the transcript still shows it as the co-host meant to say it: `voice.done` flagged `interrupted` carries `spokenText` and `unsaidText`, and nothing in the window reads them. The ideal state ([HLD](../../high-level-design.md) Future / ideal state) lets the co-host return to an interrupted thought ("as I was saying"). That needs a place to keep what was left unsaid: a bounded stack of interrupted thoughts in the window, each with its line id, spoken part and unsaid part, that the cortex can resume or discard (WM-STACK-001). It is deferred; no stack exists and the window changes nothing on an interruption.

## Injection flags

Defined in `packages/working-memory/src/index.ts`.

- `InjectionFlags { injected?: boolean; remember?: boolean }` is exported and intersected onto the `chat`, `vision` and `speech` variants only. `self` never carries them.
- `flagsOf(d)` (private) copies only the flags that are actually defined on the bus event's data, so real events yield entries with neither key (asserted by `context.test.ts`: `"injected" in real` is false).
- `propagatedFlags(src)` (exported) returns `{}` unless `src.injected` is truthy (`if (!e?.injected) return {}`); for an injected source it returns `{ injected: true }` plus `remember` when defined. A stray `remember` on a real (non-injected) event is dropped. `src` may be `undefined` (the cast comment says "`self` events have no flags"). Callers spread the result into a publish: salience reflex reply and focus (`salience.ts`), cortex reply (`cortex.ts`, via `propagatedFlags(focus)`). `focus` there is the bus `attention.focus` payload, so flags flow chat.message/etc. -> context entry -> `attention.focus` -> `brain.say`.
- Because a real vision update replaces an injected one (and vice versa), the single vision slot can switch between injected and real provenance.

## Decisions & Alternatives

| Decision | Chosen | Alternatives Considered | Rationale |
|----------|--------|------------------------|-----------|
| Where the window lives | One window implementation in this package; each region (salience, cortex) holds its own instance, built by `Context.forBrain(cfg.brain)` and fed from the bus. Window size, eviction, seen-marking and the arrivals hold (WM-SEEN-004) exist only here | A shared service or Redis-backed window; each region carrying its own window code | Services "only ever talk through these events — never directly to each other" (`packages/bus/src/events.ts`, header comment), so a region cannot query another region's window and the instances stay separate processes' state (WM-WIN-005). An in-process instance costs no I/O on the reply path and each region keeps working while the other is paused or restarting; a shared service or Redis-backed window would add a network hop to every decision and a new dependency between regions. Behaviour that both regions need lives in the package, so the two instances differ only in what each feeds them: the same bus events converge them, and `forget_context` is one `clear()` call in each region. |
| Eviction | Count-based (`max` from `brain.working_memory_events`), oldest first, except that the newest `brain.working_memory_own_lines` `self` entries are kept | Time-based or token-based; plain oldest-first for every kind | A count is the simplest bound on prompt size and needs no clock or tokenizer (config default 24 in `packages/config/src/schema.ts`; WM-WIN-001, WM-WIN-002). Time-based eviction would empty the window during a quiet stretch and lose the context a reply needs; token-based eviction would need a tokenizer for every backend. Older context beyond the window is long-term memory's job. Plain oldest-first lets chat evict the co-host's own lines, so the model stops seeing what it just said and the repetition check has nothing to compare with. |
| Keeping own lines in context | Protect the newest `brain.working_memory_own_lines` `self` entries from eviction (at least one); they stay inline in time order | A reserved slice of the window for chat versus everything else; a separate "what you just said" block built from a second record; a limit on how much of the window chat may occupy | Protection needs no second record and no new prompt block, keeps the transcript chronological, and puts the lines in front of the critic as well as the reply model. A reserved slice leaves unused slots when there is little chat and still needs a rule for which self lines survive; a separate block would show a line twice while it is also in the window, or need deduplication; a cap on chat's share evicts chat that is relevant while a quiet stretch needed no cap. A minimum of one means a flood can never leave the model with no memory of its last line. |
| Vision handling | Keep only the newest vision entry; `clear()` also resets `lastVision` | Keep all vision lines; keep `lastVision` across `clear()` | Older vision lines "are noise" (comment in `push`). Owner decision 2026-11-01: `forget_context` forgets the screen as well, so neither the prompt nor the recall fallback carries a pre-reset screen line (WM-WIN-003). |
| Seen tracking | Per-entry `seen` flag; `markSeenEvents` by bus event id | Object identity; index/ts-based marking; mark-all only | "Mark only these events seen (not ones that arrived while a decision was in flight)" (comment on `markSeenEvents`); commit `969f6d7` fixed "a mention that lands mid-await is no longer marked seen unscored". Entries are matched by the bus event id each sense entry keeps as `eventId` (WM-SEEN-002, WM-PUSH-010): ids are unique where `ts` can repeat, and a caller that clones an entry (or holds a copy) can still mark it. Object identity silently ignores any clone. |
| Self lines | Not derived from bus events; the region calls `pushSelf(text, emotion, ts, id?)` with the `brain.say` event's bus `ts` | Ingest `brain.say` in `push`; stamp with the consumer's `Date.now()` | `push` ingests perception only and ignores every other event type (WM-PUSH-003), so a region that shares it, such as salience, never sees its own speech as new input. Recording own lines is the region's choice through `pushSelf` (WM-PUSH-006); the caller passes the `brain.say` event's bus `ts`, so all four kinds share the publisher's clock and the package reads no clock of its own: cortex records every `brain.say`, whatever its source, with the emotion it was spoken with, so the prompt shows what was actually said. |
| Transcript tags | `[chat]`, `[voice]`, `[screen]` prefixes; own lines as `Name: [emotion] text` | Role-based chat messages; structured JSON | The transcript is plain text in one user turn so that every backend, including small local models, gets the same prompt shape. A short bracketed tag per source tells the model where a line came from (viewer chat, someone speaking, the screen) without role semantics that would make each viewer a "user" turn, and gives the LLM layer a fixed prefix to stop on when the model starts the next entry (`packages/llm/src/index.ts`). The co-host's own line uses `Name: [emotion] text`, the same form the cortex asks the model to produce, so the transcript shows the model its own past lines in the format it is to continue. |
| Tag ownership | This segment owns the tag list and exports it as `TRANSCRIPT_TAGS`; model-backends derives its stops from the export; a cortex-level test checks the pair; the self line is not a stop | A third shared-constants package; model-backends owns the tags and this segment mirrors them; a self-line stop | Owner decision 2026-11-01: the segment that renders the lines owns their format, and the stops are a token saver rather than the correctness guard (WM-TRANS-006, LLM-STOP-006). |
| Text in a line | A `chat` line is built by the shared guard: a name label, the message quoted in `«` `»` with the delimiter replaced inside the text. Speech and screen lines are bounded on entry and rendered unquoted; every name is a `speakerLabel`; the co-host's own lines are flattened by `oneLine` | Backslash-escape the delimiter and the tags; reject multi-line text at ingest; leave chat as plain flattened text; quote every kind | `transcript` is the one place lines are built, so it is the one place the transcript's own syntax is protected (WM-TRANS-008). Quotes tell the model a viewer's words are data (HLD tenet 13). Escaping would make viewers' text harder for small models to read and still leave a line the model is not told to distrust; a plain flatten marks nothing. Quoting speech would make the co-host wary of what the streamer says (owner decision). |
| Bounding on entry | `push` bounds text and names, each with its own limit | Bound only when rendering; rely on the sense | Salience and cortex both read the window, so one bound in `push` covers scorer input, hook payloads and the transcript. A render-only bound leaves the scorer and the `http` hook unbounded; the sense does not see bus-injected chat. |
| `all()` result | A shallow copy, elements identical | The live array | Owner decision 2026-11-01: callers cannot mutate the window, and identity-based `markSeenEvents` keeps working (WM-WIN-006). |
| Injected events in the prompt | Rendered exactly like real ones | A visible marker for the model or critic | Owner decision 2026-11-01: injection exists to exercise the real path (WM-TRANS-007). |
| Fallback line in the transcript | The co-host's `self` line shows the fallback text, followed by a bracketed note quoting the line that failed (WM-TRANS-010) | A new `[glitch]` tagged line; replace the text silently; drop the failed line | The owner decided both must appear: what she said and that the intended line failed. A new tag would need a fifth stop sequence where the provider cap allows four; a silent replacement hides the glitch from her; dropping the line loses what she meant. |
| Interrupted-thought stack (deferred) | Recorded as a deferred spec (WM-STACK-001); the window ignores interruptions today | Rewrite or drop the interrupted self line now | A resumed thought needs the unsaid text kept apart from the line that was said, and a decision by the cortex about when to resume it (CTX-REPLAN-001); neither exists, and rewriting the self line without them would only hide what the co-host meant to say. |
| Injection flag propagation | Free function `propagatedFlags(src)` in this package; copy only when `injected` is truthy | Each region copies flags itself; always copy | Copy "only for injected inputs, never for real ones (a stray `remember` is dropped)" (comment on `propagatedFlags`); commit `3fae9f7` "flags propagate via working-memory → salience/cortex". The helper lives here because this package already keeps the flags on its context entries (WM-FLAG-001, WM-FLAG-002) and both salience and cortex need the same rule; one function keeps the rule from drifting between them (WM-FLAG-003, WM-FLAG-004). |
| Vision entry position | The newest vision entry is placed last on update | Keep it at its original position | The transcript shows the current screen most recently, which is what the prompt needs; an older position would put a stale screen line before newer chat. |
| Injection flag test | `propagatedFlags` tests `injected` for truthiness | Require `true` | The bus schema types the flag as a boolean and rejects other values, so the two readings differ only for input that never reaches the package. |
| Package dependencies | `@cohost/bus` and `@cohost/config` are development dependencies; `@cohost/shared` is a runtime dependency, imported only through `@cohost/shared/untrusted` | Runtime dependencies on bus and config; a private copy of the guard | The package imports bus and config for types alone (WM-PKG-001). The guard is behaviour more than one service needs (HLD tenet 11). Its subpath is pure, so the package still has no I/O, timers or Redis access, and it does not load the shared bootstrap. |
