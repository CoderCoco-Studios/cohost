# memory specs

Design: [memory-design.md](memory-design.md). Prefix `MEM`. Verified against the code at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`. `[x]` = implemented, `[ ]` = intended but not yet implemented (gap), `[D]` = deferred. Test paths are relative to the repo root; a `<!-- test: -->` pointer names the test that carries the matching `@spec` annotation. MEM-VIEWER-004 and MEM-VIEWER-005 are retired: viewer notes are specified by the MEM-NOTE, MEM-REG, MEM-CAPTURE, MEM-CONSOL, MEM-SURF and MEM-ADMIN lines below, and `memory.viewer` no longer carries notes. Retired numbers are not reused.

## Event handling

- [x] **MEM-EVT-001**: The memory service shall consume the bus in two consumer groups subscribed with start mode `resume` (a group created by this subscription starts at the stream's newest entry; a group that already exists resumes after its last delivered entry, so events published while memory was down are stored after a restart): group `memory` for `chat.message`, `speech.heard` and `brain.say`, and group `memory-recall` for `memory.recall.request` and `memory.viewers.request`, so that a recall never queues behind a slow embed plus INSERT. <!-- openspec: memory § Event handling and consumer groups --> <!-- test: services/memory/test/startup.test.ts:36 -->
- [x] **MEM-EVT-002**: When the memory handler receives an event type it does not act on (for example `affect.state`), the memory service shall do nothing and publish nothing. <!-- test: services/memory/test/region.test.ts:65 -->

## Storing memories

- [x] **MEM-WRITE-001**: When a `chat.message` arrives, the memory service shall remember it as kind `chat` (who = the message `user`) only if `mentionsCohost` is true, and shall store nothing for unaddressed chat. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:28, services/memory/test/region.test.ts:38 -->
- [x] **MEM-WRITE-002**: When a `speech.heard` arrives, the memory service shall remember it as kind `speech` with who = the `speaker`. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:47 -->
- [x] **MEM-WRITE-003**: When a `brain.say` arrives from any publisher, the memory service shall remember it as kind `self` (who = `cfg.cohost.name`) only if its text is two or more characters. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/region.test.ts:47 -->
- [x] **MEM-WRITE-004**: When the Postgres store remembers a line, it shall embed the string `"<who>: <text>"` and insert `kind`, `who`, `text` and the embedding as a pgvector literal into table `memories`. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/memory.test.ts:101 -->
- [x] **MEM-WRITE-005**: If embedding or INSERT throws while remembering, the Postgres store shall log a warning and not propagate the error. <!-- openspec: memory § Storing memories --> <!-- test: services/memory/test/memory.test.ts:110 -->

## Test injection

- [x] **MEM-INJ-001**: When a `chat.message`, `speech.heard` or `brain.say` arrives with `injected` true and `remember` not true, the memory service shall store no memory, touch no viewer row and publish no `memory.viewer`. <!-- openspec: memory § Storing memories; memory § Injected chat and viewers --> <!-- test: services/memory/test/region.test.ts:74 -->

## Viewers

- [x] **MEM-VIEWER-001**: When a `chat.message` is handled (mentioning the co-host or not), the memory service shall upsert the viewer row keyed by the lowercased `userId`, or the `user` name when no `userId` is present, updating `display`; a newly inserted row shall start at `msg_count` 1 and each later message shall add 1, in both stores (in-memory store: MEM-BACKEND-005). <!-- openspec: memory § Viewer tracking and announcement (scenario "First message" expects msgCount 1) --> <!-- test: services/memory/test/region.test.ts:28, services/memory/test/memory.test.ts:148, services/memory/test/memory.test.ts:195 -->
- [x] **MEM-VIEWER-002**: When a handled `chat.message` mentions the co-host, the memory service shall publish `memory.viewer` with `{user, isNew, msgCount, regular}` (`regular` as in MEM-REG-001; no notes text) before it embeds and stores the message, and shall publish none when it does not mention the co-host. <!-- openspec: memory § Viewer tracking and announcement --> <!-- test: services/memory/test/region.test.ts:28, services/memory/test/region.test.ts:38 -->
- [x] **MEM-VIEWER-003**: The memory service shall report a viewer as new (`isNew` true) exactly when the viewer's `msg_count` after the upsert is 1 or less. <!-- openspec: memory § Viewer tracking and announcement --> <!-- test: services/memory/test/memory.test.ts:148 -->
- [x] **MEM-VIEWER-006**: If upserting the viewer row fails while a `chat.message` is handled, the memory service shall log a warning, publish no `memory.viewer` for that message, and still remember the message when it mentions the co-host. <!-- test: services/memory/test/region.test.ts:106 -->

## Recall

- [x] **MEM-RECALL-001**: When a `memory.recall.request` arrives, the memory service shall publish `memory.recall.reply` carrying the same `id` and the recalled memories as `{ts (epoch ms), kind, who, text, similarity}`; an empty list is a valid answer. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/region.test.ts:56, services/memory/test/backend.test.ts:18 -->
- [x] **MEM-RECALL-002**: Where a `memory.recall.request` omits `k`, the memory service shall use `brain.memory.recall_k` (default 6). <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:121 -->
- [x] **MEM-RECALL-003**: When the Postgres store recalls, it shall embed the query and return up to `k` rows ordered by cosine distance, excluding rows whose `ts` is within the last 2 minutes. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:121 -->
- [x] **MEM-RECALL-004**: When recalling, the memory service shall drop any result whose similarity is below `brain.memory.min_similarity` (default 0.35), keeping results equal to it. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:121, services/memory/test/fake-store.test.ts:23 -->
- [x] **MEM-RECALL-005**: If `k` is 0 or less, the memory store shall return an empty list without embedding or querying. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:138, services/memory/test/fake-store.test.ts:23 -->
- [x] **MEM-RECALL-006**: If embedding or the recall query fails, the Postgres store shall log a warning and return an empty list, so the memory service still publishes a `memory.recall.reply`. <!-- openspec: memory § Recall --> <!-- test: services/memory/test/memory.test.ts:138 -->

## Stores and schema

- [x] **MEM-STORE-001**: When the Postgres store initialises, it shall probe the embedding dimension, create extension `vector`, create tables `memories` (with `embedding vector(dims)`), `viewers` (including the columns `regular_manual`, `is_sub` and `placeholder`), `viewer_notes` and `viewer_note_deletions` (each with an `embedding vector(dims)`) and `meta`, adding missing columns to an existing `viewers` table without dropping any, and create an hnsw cosine index, treating failure to create the index as a warning only. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/memory.test.ts:70, services/memory/test/memory.test.ts:81 -->
- [x] **MEM-STORE-002**: When the Postgres store initialises against an existing `memories` table whose vector dimension differs from the configured embedder's dimension, it shall fail initialisation with an error naming both dimensions, and the memory service shall not retry that error, so startup ends in the fatal exit of MEM-START-006 (and `reflect` in `reflect failed`) instead of every later write and recall failing silently with health `ok`. <!-- intent: packages/config/src/schema.ts:39-40 ("the memory table's vector size never changes when the chat model does") --> <!-- test: services/memory/test/memory.test.ts:202, services/memory/test/startup.test.ts:79 -->
- [x] **MEM-STORE-003**: The Postgres store shall keep key/value metadata in table `meta` with upsert semantics, and shall list memories strictly after a `(ts, id)` cursor in `(ts, id)` order with a default limit of 400. <!-- openspec: memory § Reflection (last_reflection meta) --> <!-- test: services/memory/test/memory.test.ts:175 -->

## Backend selection

- [x] **MEM-BACKEND-001**: Where `brain.memory.store` is `memory`, the memory service shall use the in-process `InMemoryStore`, shall not open a Postgres connection, and shall not use the supplied embedder. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/backend.test.ts:12 -->
- [x] **MEM-BACKEND-002**: Where `brain.memory.store` is `postgres` (the default), the memory service shall use the Postgres `MemoryStore`. <!-- openspec: memory § Schema initialization and startup --> <!-- test: none -->
- [x] **MEM-BACKEND-003**: Where `brain.memory.embedder` is `hash`, the memory service shall embed with `@cohost/llm`'s `HashEmbedder` and make no network request; otherwise it shall use the Ollama client from `llm` config regardless of `llm.provider`. <!-- openspec: memory § Hash embedder selection --> <!-- test: services/memory/test/backend.test.ts:36 (the Ollama-regardless-of-provider branch is untested) -->
- [x] **MEM-BACKEND-004**: While the in-memory store is active, recall shall rank by cosine similarity over its own hashed bag-of-words vectors, exclude entries newer than 2 minutes, drop results under `min_similarity` and return at most `k`. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/fake-store.test.ts:14, services/memory/test/fake-store.test.ts:23, services/memory/test/fake-store.test.ts:41, services/memory/test/backend.test.ts:18 -->
- [x] **MEM-BACKEND-005**: While the in-memory store is active, viewer tracking shall count per lowercased key, report `isNew` when the count is 1 or less, keep viewer notes, deletion records, the regular and subscriber flags in process with the same behaviour as the Postgres store, and lose all data on process exit. <!-- openspec: memory § In-memory store --> <!-- test: services/memory/test/fake-store.test.ts:49 -->
- [x] **MEM-BACKEND-006**: While the in-memory store is active, it shall keep `meta` key/values in process and list memories strictly after a `(ts, id)` cursor in `(ts, id)` order with a default limit of 400. <!-- code: fake-store.ts:61-71 --> <!-- test: services/memory/test/fake-store.test.ts:56, services/memory/test/fake-store.test.ts:70 -->

## Startup and shutdown

- [x] **MEM-START-001**: Where the store is `postgres` and the embedder is `ollama`, the memory service shall ping Ollama every 3 seconds until it answers before initialising the store, marking `deps.ollama` down while it waits. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/startup.test.ts:47 -->
- [x] **MEM-START-002**: Where the store is `postgres`, the memory service shall retry store initialisation every 3 seconds and exit fatally when the 21st attempt fails; a vector-dimension mismatch (MEM-STORE-002) is not retried and exits at once. <!-- openspec: memory § Schema initialization and startup --> <!-- test: services/memory/test/startup.test.ts:58, services/memory/test/startup.test.ts:70, services/memory/test/startup.test.ts:79 -->
- [x] **MEM-START-003**: Where the store is `memory`, the memory service shall initialise once with no Ollama ping, no Postgres connection and no retry loop. <!-- openspec: memory § Schema initialization and startup (Redis-only start) --> <!-- test: services/memory/test/startup.test.ts:89 -->
- [x] **MEM-START-004**: Where either `brain.memory.store` or `brain.memory.embedder` is non-default, the memory service shall log a warning that it runs in mode mock with non-durable data. <!-- openspec: memory § Isolation preset and mode --> <!-- test: services/memory/test/startup.test.ts:89 -->
- [x] **MEM-START-005**: When the memory service has finished initializing its store, it shall start both consumer-group subscriptions and report `ready` in its heartbeat only once both consumer groups exist; a subscription that fails before its group is ready fails startup. <!-- openspec: memory § Heartbeat --> <!-- test: services/memory/test/startup.test.ts:98, services/memory/test/startup.test.ts:115 -->
- [x] **MEM-START-006**: If startup throws (including the 21st failed Postgres initialisation), the memory service shall log a fatal error and exit with code 1; on shutdown it shall stop the bus and then close the store. <!-- code: index.ts:45-47 --> <!-- test: none -->

## Reflection

- [x] **MEM-REFLECT-001**: When `reflect` runs with `brain.memory.store` set to `memory`, it shall log a warning and exit without reading memories or changing personality. <!-- openspec: memory § In-memory store (reflection is a logged no-op) --> <!-- test: services/memory/test/reflect.test.ts:117 -->
- [x] **MEM-REFLECT-002**: When `reflect` runs, it shall read at most 600 memories oldest-first whose `(ts, id)` is after the cursor in `meta.last_reflection` (MEM-REFLECT-008; default: before the first row). <!-- openspec: memory § Reflection --> <!-- test: services/memory/test/reflect.test.ts:47 -->
- [x] **MEM-REFLECT-003**: If fewer than 5 new memories exist, `reflect` shall log and exit without calling the LLM, changing personality or moving the `meta.last_reflection` cursor, so those rows are read in a later pass together with the memories that arrive meanwhile; a final batch of 5 to 599 rows reflects normally. <!-- openspec: memory § Reflection (Too few memories) --> <!-- test: services/memory/test/reflect.test.ts:84 -->
- [x] **MEM-REFLECT-004**: When enough memories exist, `reflect` shall ask the chat LLM (max 400 tokens, temperature 0.5) for 3 to 6 bullet points given the current personality and a `who: text` transcript. <!-- openspec: memory § Reflection --> <!-- test: services/memory/test/reflect.test.ts:97 -->
- [x] **MEM-REFLECT-005**: The reflection parser shall keep only reply lines that start with `- ` after trimming, discarding preamble and other bullet styles. <!-- openspec: memory § Reflection (Preamble stripped) --> <!-- test: services/memory/test/memory.test.ts:11 -->
- [x] **MEM-REFLECT-006**: If the LLM reply contains no bullet lines, `reflect` shall log a warning and neither save personality nor update `last_reflection`. <!-- openspec: memory § Reflection (No bullets) --> <!-- test: services/memory/test/reflect.test.ts:106 -->
- [x] **MEM-REFLECT-007**: When bullets are produced, `reflect` shall insert them as a `### YYYY-MM-DD` (UTC) block at the end of the `## Learned` section (before the next `## ` heading, or at the end of the text when `## Learned` is the last section), adding a `## Learned` heading at the end of the text when the text has none, then save personality, advance `meta.last_reflection` (MEM-REFLECT-008) and print the block. <!-- openspec: memory § Reflection ("in the `## Learned` section") --> <!-- test: services/memory/test/memory.test.ts:18, services/memory/test/memory.test.ts:29, services/memory/test/reflect.test.ts:97 -->
- [x] **MEM-REFLECT-008**: When `reflect` saves a Learned block, it shall set `meta.last_reflection` to the `(ts, id)` of the newest memory it read, and `recentSince` shall read rows strictly after that cursor in `(ts, id)` order (`ORDER BY ts, id`, `WHERE (ts, id) > ($1, $2)`), so that when more than 600 memories are newer than the cursor the rows beyond the first 600 are reflected on in the next pass, including rows that share the last row's timestamp. A legacy `meta.last_reflection` that is a plain ISO timestamp is read as that timestamp with the lowest id. <!-- test: services/memory/test/reflect.test.ts:47, services/memory/test/reflect.test.ts:62, services/memory/test/reflect.test.ts:74, services/memory/test/reflect.test.ts:38, services/memory/test/fake-store.test.ts:70, services/memory/test/memory.test.ts:175 -->
- [x] **MEM-REFLECT-009**: If any step of `reflect` throws (including store initialisation, which embeds a probe string and so needs a reachable embedder), `reflect` shall log `reflect failed`, set exit code 1 and still close the store. <!-- code: reflect-run.ts:30, reflect.ts:22-25, store.ts:69 --> <!-- test: none -->
- [x] **MEM-REFLECT-010**: Where `reflect` builds a chat provider whose `name` is `mock`, it shall log one warn-level message naming the mock backend before it reads any memory, so a canned reflection is never mistaken for a real one. <!-- intent: LLM-MOCK-005 --> <!-- test: services/memory/test/reflect.test.ts:127 -->

## Viewer notes: notes and strength

- [x] **MEM-NOTE-001**: The memory service shall keep viewer notes, each belonging to one viewer row and holding a layer (`core` or `recent`), a category (`general`, `health` or `family`), a short text, an optional handling hint, a strength between 0 and 1 with the time it was set, the number of mentions that reinforced it, a dirty flag, and a version. <!-- test: services/memory/test/memory.test.ts:304, services/memory/test/store-contract.ts:102, services/memory/test/store-contract.ts:133 -->
- [x] **MEM-NOTE-002**: The memory service shall compute a note's effective strength at time `t` as `strength × 0.5 ^ ((t − strength_at) / half_life)`, where `half_life` is `brain.memory.notes.recent_half_life_days` (default 7) for a recent note and `brain.memory.notes.core_half_life_days` (default 60) for a core note. <!-- test: services/memory/test/notes.test.ts:14 -->
- [x] **MEM-NOTE-003**: If a computed effective strength is not finite or lies outside 0 to 1, then the memory service shall use 0 for a non-finite or negative value and 1 for a value above 1, and shall never store a strength outside 0 to 1. <!-- test: services/memory/test/notes.test.ts:25 -->
- [x] **MEM-NOTE-004**: When the memory service writes a note (insert, reinforcement, layer move, rewrite or restore), it shall increment that note's version. <!-- test: services/memory/test/store-contract.ts -->
- [x] **MEM-NOTE-005**: When a mention reinforces a note, the memory service shall set the note's stored strength to `e + (1 − e) × brain.memory.notes.reinforce` (default 0.6), where `e` is its effective strength at that moment, set `strength_at` to now, add 1 to its mentions and mark it dirty. <!-- test: services/memory/test/memory.test.ts:283, services/memory/test/notes.test.ts:38, services/memory/test/store-contract.ts:121 -->
- [x] **MEM-NOTE-006**: When a consolidation pass finds a recent note whose mentions are at least `brain.memory.notes.promote_mentions` (default 3), it shall move the note to the core layer, keeping its strength. <!-- test: services/memory/test/consolidation.test.ts:61, services/memory/test/consolidation.test.ts:123 -->
- [x] **MEM-NOTE-007**: When a consolidation pass finds a core note whose effective strength is below `brain.memory.notes.demote_below` (default 0.3), it shall move the note to the recent layer with its stored strength set to that effective strength, `strength_at` set to now and its mentions reset to 0. <!-- test: services/memory/test/consolidation.test.ts:74, services/memory/test/consolidation.test.ts:90, services/memory/test/consolidation.test.ts:112 -->
- [x] **MEM-NOTE-008**: When a consolidation pass finds a recent note whose effective strength is below `brain.memory.notes.drop_below` (default 0.1), it shall delete the note without writing a deletion record. <!-- test: services/memory/test/consolidation.test.ts:100, services/memory/test/consolidation.test.ts:112, services/memory/test/consolidation.test.ts:123 -->
- [x] **MEM-NOTE-009**: The memory service shall never store a viewer note whose subject is the viewer's political views, or the viewer's money, wealth or spending (enforced through the capture and consolidator prompts and the validation of MEM-CAPTURE-004 and MEM-CONSOL-005); a viewer's subscriber status shall be kept only as the viewer row's subscriber flag (MEM-REG-005), never as a note. <!-- test: services/memory/test/capture.test.ts:89, services/memory/test/capture.test.ts:111, services/memory/test/capture.test.ts:127, services/memory/test/consolidation.test.ts:503 -->
- [x] **MEM-NOTE-010**: When a note of category `health` or `family` is stored without a handling hint, the memory service shall attach the category's default hint: for `health`, "only if they bring it up; never quote it", and for `family`, "check in warmly and gently; never name or quote it". <!-- test: services/memory/test/memory.test.ts:304, services/memory/test/notes.test.ts:46, services/memory/test/store-contract.ts:102, services/memory/test/store-contract.ts:203 -->
- [x] **MEM-NOTE-011**: Where the `llm.provider` override of `brain.memory.notes.capture` or `brain.memory.notes.consolidator` is empty and the top-level `llm.provider` is not `mock`, the memory service shall build that hook on the `ollama` provider instead of inheriting `llm.provider`, so notes model calls leave the LAN only when the notes hook itself names a hosted provider, even when the cortex uses a hosted model. <!-- test: services/memory/test/consolidation.test.ts:313, services/memory/test/consolidation.test.ts:326, services/memory/test/capture.test.ts:144 -->
