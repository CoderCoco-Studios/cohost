# deployment specs

Prefix `DEPLOY`. Design: [deployment-design.md](deployment-design.md). No spec below carries an OpenSpec reference.

Verified against the files at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`.

The docs site's structure, publishing boundary, build checks and the README's shape are specified in the [docs-site](../docs-site/docs-site-specs.md) segment; the specs below that name a site page say what that page must tell the operator about this segment's files.

Markers: `[x]` implemented; `[ ]` intended but not yet implemented (gap); `[D]` deferred.

Annotations: `@spec DEPLOY-…` comments sit in the deployment files themselves. In `docker-compose.yml` and `docker-compose.gpu.yml` they are trailing comments on mapping keys, and in `Dockerfile` and `scripts/install.sh` they are appended to existing comment lines; everywhere else they are full comment lines. `<!-- impl: path -->` points at an implementation in a file that carries no annotation (a file owned elsewhere, or plain data such as `.gitignore`). `<!-- test: path -->` names the test file that carries the matching `@spec` annotation.

## Secret scoping (SECRET)

Design: [deployment-design.md](deployment-design.md) § Secret scoping. "The operator's file" is `secrets/secrets.yaml` under the workspace root; "a unit's declared paths" are the secret paths its manifest entry's `secrets` list names; "the projection" writes one file per unit from the operator's file.

- [x] **DEPLOY-SECRET-001**: The operator's credentials file shall be `secrets/secrets.yaml` under the workspace root, and no Compose service shall mount `./secrets`, `./secrets/units`, the workspace root, or any other host path whose subtree holds `secrets/secrets.yaml`; `./config` shall hold no `secrets.yaml`.
- [x] **DEPLOY-SECRET-002**: Where a unit declares at least one secret path, its Compose service shall mount `./secrets/units/<composeName>` read-only at `/app/secrets` in the long syntax with `create_host_path: false`, and no other directory under `./secrets`; a unit that declares none shall mount nothing under `./secrets`; the `consolidate` and `reembed` services shall mount the `memory` unit's directory, and `models` none.
- [x] **DEPLOY-SECRET-003**: When the projection runs, it shall write, for every unit that declares a secret path, `secrets/units/<composeName>/secrets.yaml` as a YAML mapping nested as the operator's file is, holding exactly those declared paths at which the operator's file holds a string that is non-blank after trimming, each value trimmed, and no other key (an empty mapping when there is none; the wildcard `tools.servers.*.token` matching the `token` of every server entry the operator's file holds); it shall create a missing unit directory with mode 0700, write each file through a temporary file in the same directory created with mode 0600 before any byte is written and then renamed over the file, and remove each directory under `secrets/units/` that names no unit declaring a secret path.
- [x] **DEPLOY-SECRET-004**: When the control plane is about to issue a `docker compose` command that creates, starts or restarts an application container (Launch, Rebuild, Restart all, a unit's start or restart, an isolated start, a `consolidate` or `reembed` run), it shall run the projection first (control-plane CTRL-RUNTIME-014, config CFG-SEC-019), and if the projection fails it shall not issue the command and shall report the action failed with a message naming the file or directory and the reason, never a secret value.
- [x] **DEPLOY-SECRET-005**: When the projection reads the operator's file, an absent file shall make every unit's projection an empty mapping; a file that cannot be read, is not YAML or whose root is not a mapping shall fail the projection naming the file and, for a syntax error, only the line and column; a non-string value at a secret path, or a value that still holds a line break after trimming, shall fail it naming the path and not the value; and a key outside `SECRET_PATHS` shall be projected into no unit.
- [x] **DEPLOY-SECRET-006**: When the installer has seeded the user files (DEPLOY-INST-005) and built the workspace (`mise run build`, DEPLOY-INST-007), it shall run the projection (`mise run secrets:project`, which runs `node packages/control/dist/project-secrets.js` from the repository root, control-plane CTRL-RUNTIME-015), before any `docker compose` command, so every unit directory of DEPLOY-SECRET-002 exists, and shall exit non-zero with the projection's message if it fails.
- [x] **DEPLOY-SECRET-007**: If the operator's file (`secrets/secrets.yaml`, or the path `COHOST_SECRETS_FILE` names), once every symbolic link in its path is resolved, lies inside `./config`, `./data` or `./secrets/units` (each of those directories itself resolved first, so a directory that is a link counts as its target), then the projection shall fail naming the file, whether it is a link or a regular file, and shall write no unit file.
- [x] **DEPLOY-SECRET-009**: When the projection runs, it shall create a missing `secrets/units/` with mode 0700, and if `secrets/`, `secrets/units/` or a unit directory under it is a symbolic link, it shall fail naming that path and write no unit file; a unit whose `composeName` is not lower-case letters, digits and hyphens shall fail it naming the name, so no unit name can reach outside `secrets/units/`.
- [x] **DEPLOY-SECRET-010**: The projection's files shall be owned by the user who ran it with mode 0600 and read by container root; the deployment shall support a rootful Docker daemon without user-namespace remapping and Docker Desktop, and under remapping or rootless Docker a service's load shall fail naming the file (CFG-SEC-006) rather than run without its credentials.
- [x] **DEPLOY-SECRET-011**: When `scripts/compose-smoke.sh` runs, before its first `docker compose up` it shall create, for every `./secrets/units/<name>` directory the Compose file mounts, that directory with mode 0700 holding `secrets.yaml` with an empty YAML mapping, leaving an existing file untouched.
- [x] **DEPLOY-SECRET-008**: A test shall fail when the projection of an operator file that sets every path of `SECRET_PATHS` (with two `tools.servers` entries) gives any unit a path it does not declare or omits a path it declares, and a Compose test shall fail when a service mounts a directory under `./secrets` other than its own unit's (or, for `consolidate` and `reembed`, `memory`'s) or mounts a host path that holds `secrets/secrets.yaml`.
