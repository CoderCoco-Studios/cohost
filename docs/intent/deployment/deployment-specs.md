# deployment specs

Prefix `DEPLOY`. Design: [deployment-design.md](deployment-design.md). No spec below carries an OpenSpec reference.

Verified against the files at git `49ba935` (audit pass 2026-11-01). Owner decisions of 2026-11-01 applied at git `1b57790`.

The docs site's structure, publishing boundary, build checks and the README's shape are specified in the [docs-site](../docs-site/docs-site-specs.md) segment; the specs below that name a site page say what that page must tell the operator about this segment's files.

Markers: `[x]` implemented; `[ ]` intended but not yet implemented (gap); `[D]` deferred.

Annotations: `@spec DEPLOY-…` comments sit in the deployment files themselves. In `docker-compose.yml` and `docker-compose.gpu.yml` they are trailing comments on mapping keys, and in `Dockerfile` and `scripts/install.sh` they are appended to existing comment lines; everywhere else they are full comment lines. `<!-- impl: path -->` points at an implementation in a file that carries no annotation (a file owned elsewhere, or plain data such as `.gitignore`). `<!-- test: path -->` names the test file that carries the matching `@spec` annotation.

## Compose topology

- [ ] **DEPLOY-COMPOSE-001**: The base `docker-compose.yml` shall define the infrastructure services `redis`, `postgres`, `ollama`, `tts`, `stt`, the engine servers `tts-pocket`, `stt-nemotron` and `stt-kyutai`, the one-shot `models`, the one-shot `consolidate`, the one-shot `reembed`, and one application service per directory under `services/` except `dashboard` (`chat`, `salience`, `affect`, `memory`, `cortex`, `tools`, `voice`, `avatar`, `eyes`, `ears`, `mouth`, `connector-discord`), and no `dashboard` service, because the dashboard runs on the host. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-002**: Each application service shall be built from the single root `Dockerfile` with the build argument `SERVICE` set to its directory name, and shall inherit the shared `x-ts-service` settings: `restart: unless-stopped`, `env_file: .env`, the in-network URLs `REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `CONFIG_DIR=/app/config` (no dashboard address: injected uploads reach eyes and ears over Redis), the `./config:/app/config` bind mount, the `host.docker.internal:host-gateway` extra host, a dependency on `redis` being healthy, and the container healthcheck (DEPLOY-HC-001). The optional engine servers of DEPLOY-ENG-001..003 are not application services: they are built from their own sources and do not use the `x-ts-service` anchor. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-003**: While a variable is set in a service's `environment` block (`REDIS_URL`, `DATABASE_URL`, `OLLAMA_URL`, `TTS_URL`, `STT_URL`, `VOICE_URL`, `CONFIG_DIR`), the Compose stack shall use that value over the same name in `.env`, so those addresses cannot be changed through `.env` for containerised services. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [ ] **DEPLOY-COMPOSE-004**: The `eyes` service shall belong only to the `eyes` profile, the `ears` service only to the `ears` profile, the `mouth` service only to the `mouth` profile, the `connector-discord` service only to the `discord` profile, the `tts-pocket` service only to the `pocket` profile, the `stt-nemotron` service only to the `nemotron` profile, the `stt-kyutai` service only to the `kyutai` profile and the `consolidate` and `reembed` services only to the `jobs` profile; every other service, including `models`, `tts` and `stt`, has no profile, so a plain `docker compose up -d` starts everything except `eyes`, `ears`, `mouth`, `connector-discord`, `tts-pocket`, `stt-nemotron`, `stt-kyutai`, `consolidate` and `reembed`. <!-- test: packages/config/test/compose-consolidate.test.ts -->
- [x] **DEPLOY-COMPOSE-005**: Where a service has dependencies beyond redis, Compose shall order startup as follows: `memory` waits for `redis` and `postgres` healthy and `ollama` started; `cortex` for `redis` healthy and `ollama` started; `voice` for `redis` healthy and `tts` started; `ears` for `redis` healthy and `stt` started; the engine servers each of them also waits for are those of DEPLOY-ENG-013.
- [x] **DEPLOY-COMPOSE-006**: The infrastructure ports `redis` 6379, `postgres` 5432, `ollama` 11434, `tts` 8880 and `stt` 8000 and the `voice` port 8700 shall be published on `127.0.0.1` only, and no Compose service shall publish a port on any other interface. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-007**: The `voice` service shall publish its HTTP server (`VOICE_PORT`, default 8700) on `127.0.0.1:8700` only, so the host-run dashboard reaches it at its `urls.voice()` default `http://127.0.0.1:8700`, while containers keep using `http://voice:8700` and browsers keep receiving audio only through the dashboard's `/audio/` proxy. <!-- test: packages/config/test/compose-standalone.test.ts -->
- [x] **DEPLOY-COMPOSE-008**: The `models` service shall be built from the shared `Dockerfile` with the build argument `SERVICE: memory` (as `consolidate` and `reembed` are), mount `./config`, depend on `ollama` being started and not on `redis`, and run `packages/config/dist/pull-models.js`, which shall wait for `ollama` to answer `/api/tags`, then request `/api/pull` one after another for each name in `ollamaModels` of the loaded config (CFG-MODEL-001), the required names first, printing the last 200 bytes of each response, and exit; the model names shall come from `config.yaml` only, with no model-name variable in `.env` or in the service's environment, and `ears.stt_model` shall not be pulled. <!-- test: packages/config/test/compose-models.test.ts -->
- [x] **DEPLOY-COMPOSE-009**: The stack shall persist data in the named volumes `redis-data`, `pg18-data` (mounted at `/var/lib/postgresql`, the volume path of the Postgres 18 image), `ollama-data`, `stt-cache` and the engine servers' weight caches (DEPLOY-ENG-009); `redis` and `postgres` shall expose healthchecks (`redis-cli ping`, `pg_isready -U cohost`; every 5 s, 3 s timeout, 10 retries) used by `depends_on`.
- [x] **DEPLOY-COMPOSE-010**: Where `docker-compose.gpu.yml` is layered over the base file (via `-f` or `COMPOSE_FILE`), the overlay shall add an NVIDIA device reservation (`count: all`) to `ollama`, `tts` and `stt` and switch `tts` and `stt` to the GPU images `ghcr.io/remsky/kokoro-fastapi-gpu:v0.10.0` and `ghcr.io/speaches-ai/speaches:0.8.3-cuda` unless `KOKORO_IMAGE` / `SPEACHES_IMAGE` are set.
- [x] **DEPLOY-COMPOSE-011**: If a pull of a required model fails (the request errors, the server answers with an HTTP error, or the response carries an `"error"` line), then the `models` container shall exit non-zero after attempting every model, except that a failed pull of an optional model shall be logged as a warning on stderr and shall not change the exit status (the hook it serves degrades to its rules fallback, HLD tenet 3); it shall carry no restart policy. <!-- test: packages/config/test/compose-models.test.ts --> <!-- test: packages/config/test/compose-models.test.ts -->
- [x] **DEPLOY-COMPOSE-012**: The `ollama` service shall keep loaded models resident for 24 h (`OLLAMA_KEEP_ALIVE=24h`) and run with flash attention (`OLLAMA_FLASH_ATTENTION=1`) and a `q8_0` KV cache (`OLLAMA_KV_CACHE_TYPE`).
- [x] **DEPLOY-COMPOSE-013**: The `redis` service shall snapshot to the `redis-data` volume when at least one key changed in the last 60 s (`--save 60 1`) and shall keep no append-only file (`--appendonly no`).
- [x] **DEPLOY-COMPOSE-014**: Every image the Compose files name shall carry an exact version tag, never `latest` and never a floating major or minor: the base file runs `redis` from `redis:8.10.3-alpine`, `postgres` from `pgvector/pgvector:0.8.7-pg18`, `ollama` from `ollama/ollama:0.40.16`, `tts` from `KOKORO_IMAGE` (default `ghcr.io/remsky/kokoro-fastapi-cpu:v0.10.0`) and `stt` from `SPEACHES_IMAGE` (default `ghcr.io/speaches-ai/speaches:0.8.3-cpu`); `models` names no image, as it is built from the shared `Dockerfile` (DEPLOY-COMPOSE-008). <!-- test: packages/control/test/compose.test.ts -->
- [x] **DEPLOY-COMPOSE-015**: The application services, `redis`, `postgres`, `ollama`, `tts` and `stt` shall restart unless stopped; the one-shot `models` shall carry no restart policy and the one-shots `consolidate` and `reembed` shall set `restart: "no"` (DEPLOY-COMPOSE-018, DEPLOY-COMPOSE-021). <!-- test: packages/config/test/compose-consolidate.test.ts -->
- [x] **DEPLOY-COMPOSE-017**: The `x-ts-service` `environment:` block shall pass through exactly one isolation variable, `COHOST_ISOLATION: ${COHOST_ISOLATION:-}`, so that the JSON preset the control plane's isolated start sets on the `docker compose` process (`packages/control/src/runtime.ts`) reaches the container and an empty value leaves the literal values of `config.yaml` in charge (control-plane CTRL-RUNTIME-009); the block shall carry no per-override entry (`CHAT_SOURCE`, `LLM_PROVIDER`, `AVATAR_DRIVER` and the rest), and `config.yaml` shall carry no placeholder for Compose to meet (CFG-ENV-011). <!-- test: packages/control/test/compose.test.ts --> <!-- test: packages/control/test/runtime.test.ts -->

It shall not depend on `redis`, because the command never opens the bus: a pass can run with the rest of the stack stopped. (Memory MEM-CONSOL-012, MEM-CONSOL-013.) <!-- test: packages/config/test/compose-consolidate.test.ts --> <!-- test: packages/config/test/compose-consolidate.test.ts --> <!-- test: packages/config/test/compose-consolidate.test.ts --> <!-- test: packages/config/test/compose-consolidate.test.ts -->

## Speech engine servers (ENG)

Design: [deployment-design.md](deployment-design.md) § Speech engine servers. Versions were verified on 2026-11-16: Pocket TTS v4.0.1, NeMo-Speech.cpp v0.3.0, `moshi-server` 0.6.4. Where a detail of a server is not verified (its health route, its cache path, its VRAM) no spec states it as fact; the spec states what the Compose file does.

- [x] **DEPLOY-ENG-001**: The `tts-pocket` service shall build its image and not pull one, and shall be named `cohost-tts-pocket:4.0.1`.
- [x] **DEPLOY-ENG-002**: The `stt-nemotron` service shall build its image and not pull one, and shall be named `cohost-stt-nemotron:0.3.0`.
- [x] **DEPLOY-ENG-003**: The `stt-kyutai` service shall build its image and not pull one, and shall be named `cohost-stt-kyutai:0.6.4`.
- [x] **DEPLOY-ENG-004**: The `tts-pocket` build shall take its source from the Pocket TTS repository at the full commit SHA of tag `v4.0.1`, with the tag named in a comment beside it.
- [x] **DEPLOY-ENG-005**: The `stt-nemotron` build shall take its source from the NeMo-Speech.cpp repository at the full commit SHA of tag `v0.3.0`, with the tag named in a comment beside it.
- [x] **DEPLOY-ENG-006**: The `stt-kyutai` image shall be built from a Dockerfile in `docker/` that installs the `moshi-server` crate with `cargo install` at exactly version 0.6.4 and `--locked`, on an NVIDIA CUDA 12.8 development base image at an exact tag, and shall carry its server configuration file committed beside the Dockerfile.
- [x] **DEPLOY-ENG-007**: Every base image named by a Dockerfile under `docker/` shall carry an exact version tag.
- [x] **DEPLOY-ENG-008**: The `tts-pocket`, `stt-nemotron` and `stt-kyutai` services shall publish their servers on `127.0.0.1:8881` (container port 8000), `127.0.0.1:8081` (container port 8080) and `127.0.0.1:8082` (container port 8080) and on no other interface.
- [x] **DEPLOY-ENG-009**: The `tts-pocket`, `stt-nemotron` and `stt-kyutai` services shall each mount a named volume of their own (`tts-pocket-cache`, `stt-nemotron-cache`, `stt-kyutai-cache`) at the cache directory their server downloads its model weights to, so a recreated container keeps its weights.
- [x] **DEPLOY-ENG-010**: Where `docker-compose.gpu.yml` is layered over the base file, the overlay shall add the NVIDIA device reservation to `stt-nemotron` and `stt-kyutai` and none to `tts-pocket`.
- [x] **DEPLOY-ENG-011**: The `tts-pocket`, `stt-nemotron` and `stt-kyutai` services shall restart unless stopped.
- [x] **DEPLOY-ENG-012**: The `tts-pocket` service shall carry a healthcheck that requests `GET /health` of its server, the `stt-nemotron` service one that requests `GET /ready` of its server, and the `stt-kyutai` service one that opens a TCP connection to its server's port, each with a start period of 10 minutes.
- [x] **DEPLOY-ENG-013**: The `voice` service shall list `tts-pocket` in its `depends_on` with condition `service_started` and `required: false`, and the `ears` service shall list `stt-nemotron` and `stt-kyutai` the same way, so Compose starts an engine server's container before them where its profile is enabled, ignores it where it is not, and never holds `voice` or `ears` back for an engine that is unhealthy.
- [x] **DEPLOY-ENG-014**: The `tts-pocket` container's entrypoint shall be a cohost script `docker/tts-pocket/entrypoint.sh`, mounted read-only and named as the service's `entrypoint:`, that exports the content of `/run/cohost-secret/hf_token` as `HF_TOKEN` for the server process alone when that file exists and then runs the server's own command.
- [x] **DEPLOY-ENG-015**: No Compose file or Dockerfile shall carry `voice.pocket.hf_token`, or `HF_TOKEN` set from it, as an `environment:` entry, a build argument or an image layer.
- [x] **DEPLOY-ENG-016**: The Compose service names `tts-pocket`, `stt-nemotron` and `stt-kyutai` shall be the hosts of the default URLs of `voice.pocket.url`, `ears.nemotron.url` and `ears.kyutai.url` (CFG-SCH-061, CFG-SCH-066, CFG-SCH-067).
- [x] **DEPLOY-ENG-017**: Neither `docker-compose.yml` nor `docker-compose.gpu.yml` shall name the Kokoro-FastAPI tag `latest-cu128`; `.env.example` shall comment `KOKORO_IMAGE` with that tag as the image for an RTX 50-series card and say that it has not been confirmed on the owner's card.
- [ ] **DEPLOY-ENG-018**: Where `tts-pocket`, `stt-nemotron` or `stt-kyutai` has not passed its healthcheck within Launch's readiness wait, the stack controller shall report it as not ready by name (CTRL-STACK-004) and shall stop, remove and restart nothing, so the container keeps downloading its weights.
- [x] **DEPLOY-ENG-019**: The `tts-pocket` service shall not mount `./config`, and its only secret-bearing mount shall be the directory `data/tts-pocket-secret` under the workspace root, mounted read-only at `/run/cohost-secret`.
- [ ] **DEPLOY-ENG-020**: The `voice` service shall start, and Launch shall not fail, when an engine server's container is unhealthy or still downloading its weights; `voice` and `ears` shall report `deps.tts` or `deps.stt` `down` while the engine is not serving.

## Container health

- [x] **DEPLOY-HC-001**: Every application service container shall run the healthcheck `node packages/control/dist/healthcheck.js $SERVICE` every 10 s with a 5 s timeout, 3 retries and a 30 s start period, with `SERVICE` taken from the image environment (the `Dockerfile` `ENV`) and equal to the `service` the container's heartbeat publishes (the unit id, MOD-MAN-012).
- [x] **DEPLOY-HC-002**: When the healthcheck runs, it shall exit 0 only if the newest `service.heartbeat` for that service among the last 200 entries of `cohost:health` is younger than 3 times its declared interval and its state is not `stopping`, and shall exit 1 when no heartbeat is found, the heartbeat is stale, Redis cannot be read, or 4 s elapse. ## Image build

- [x] **DEPLOY-IMG-001**: The `Dockerfile` shall build a `native` stage `FROM rust:<version>-slim-trixie` (`<version>` being the exact toolchain `rust-toolchain.toml` pins) that runs `cargo build --release -p cohost-bus-node` on the Cargo workspace, with BuildKit cache mounts for Cargo's registry and `target` directory, and copies the cdylib `target/release/libcohost_bus_node.so` to the bus addon `cohost-bus.linux-x64-gnu.node` (event-bus BUS-NAT-BLD-009), with neither Node nor the napi CLI in that stage, and three stages on `node:26-slim` (`base` with pnpm activated through corepack, installed with npm because Node 26 does not bundle it, at the version `packageManager` names (DEPLOY-IMG-006), `build`, `runtime`), where `build` copies the workspace manifests, `packages/` and `services/`, runs `pnpm install --frozen-lockfile`, copies the addon from `native` into `packages/bus/native/` and then runs `pnpm exec tsc -b`, and `runtime` copies the entire `/app` from `build` and contains no Rust toolchain.
- [x] **DEPLOY-IMG-002**: The image shall set `NODE_ENV=production` and `SERVICE` from the build argument and start with `exec node services/${SERVICE}/dist/index.js`; it shall contain every service's built code regardless of `SERVICE`. <!-- test: scripts/compose-smoke.sh -->
- [x] **DEPLOY-IMG-003**: The `Dockerfile` shall not run `pnpm prune --prod` (it removes the `@cohost/*` workspace links under pnpm 10 and crash-loops every service, issue #6); the smoke script shall guard this regression. <!-- test: scripts/compose-smoke.sh -->
- [x] **DEPLOY-IMG-006**: The `Dockerfile` and `scripts/install.sh` shall take the pnpm version from the root `package.json` `packageManager` field and name no pnpm version of their own, so that field is the one place the version is written. <!-- test: packages/config/test/pnpm-version.test.ts -->
- [x] **DEPLOY-IMG-004**: The `.dockerignore` shall exclude `node_modules`, `**/dist`, `.git`, `data`, `.env`, `**/*.tsbuildinfo`, `**/*.log`, `**/*.node` and the Cargo `target` directory from the build context, so a host-built addon never replaces the one the `native` stage builds, so stale incremental-build state cannot stop `tsc -b` from emitting output in the image and secrets in `.env` are not sent to the daemon.
- [x] **DEPLOY-IMG-005**: The `.dockerignore` shall also exclude the VTube Studio token `config/.vts-token` (written by avatar to `<configDir>/.vts-token`, `services/avatar/src/drivers/vtube-studio.ts`) and the user-owned files `config/config.yaml`, `config/secrets.yaml`, `config/personality.md` and `config/expressions.yaml` from the build context, so no credential or operator file is sent to the daemon; the `config/*.example.*` files stay in the context. <!-- test: packages/config/test/compose-standalone.test.ts -->

## Installer

- [x] **DEPLOY-INST-001**: When `scripts/install.sh` runs, it shall detect WSL2 from `/proc/version`, read `/etc/os-release`, warn but continue on a distribution other than Ubuntu or Debian, and report whether an NVIDIA GPU is visible through `nvidia-smi`.
- [x] **DEPLOY-INST-002**: Where `docker` is not installed, the installer shall install `docker-ce`, the CLI, containerd, buildx and the compose plugin from Docker's apt repository, add the user to the `docker` group and start the daemon (`service docker start` on WSL, `systemctl enable --now docker` otherwise); on every run it shall then abort unless `docker compose version` succeeds.
- [x] **DEPLOY-INST-003**: Where an NVIDIA GPU is detected and `docker info` does not list an NVIDIA runtime, the installer shall install `nvidia-container-toolkit` if absent, run `nvidia-ctk runtime configure --runtime=docker` and restart Docker.
- [x] **DEPLOY-INST-004**: Where Node is missing or older than 26, the installer shall install Node 26 from NodeSource; where `pnpm` is missing it shall install corepack with npm, enable it and prepare the `packageManager` version of `package.json` (DEPLOY-IMG-006).
- [x] **DEPLOY-INST-005**: When `.env`, `config/config.yaml`, `config/secrets.yaml`, `config/personality.md` or `config/expressions.yaml` is missing, the installer shall copy it from `.env.example` or the matching `config/*.example.*` file, shall give a copied `config/secrets.yaml` mode 0600, and shall never overwrite an existing one.
